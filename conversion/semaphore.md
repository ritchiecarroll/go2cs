## Disclosed divergences

a skipped test and not a tolerance. Each one is pinned by exact failure signature in the package's
hand-owned [`go2cs_test_disclosures.json`](https://github.com/ritchiecarroll/go2cs/blob/master/src/tests/ModuleDisclosures/golang.org/x/sync@v0.19.0/semaphore/go2cs_test_disclosures.json);

| Test | Class | Pinned reason |
|:--|:--|:--|
| `TestWeightedAcquire` | `runtime-capability` | runtime-capability: the test gives each tryAcquire call a 10 ms context deadline. The go2cs test host runs Release builds with tiered compilation off by default, so the FIRST call compiles the Acquire path at full optimization before its select runs. On the machine that measured it (linux/amd64, 4 cores) that takes longer than 10 ms, so ctx.Done() is already closed: tries[0] reads false, and the second, already-compiled call reads true (tries[1]). The converted code is faithful (in semaphore_test.cs, ctx is never reassigned). With tiered compilation on (-test-tiered), on the same machine with the same converter, semaphore matches 8 of 8 tests and the module 28, the count also measured on windows/amd64, so the difference is the first call's compile time, not the conversion. Measured in 2 of 2 runs with tiering off. On a faster machine that passes the test, this entry is reported as orphaned, which changes nothing: the package still validates. This entry is removed if the test host warms up or tiers first calls. |
