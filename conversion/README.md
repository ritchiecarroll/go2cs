The module sits one directory below the root build files on purpose: `sync/Directory.Build.targets` imports the
nearest `Directory.Build.targets` above its own directory, which is the root one.

## Building

```
cd sync
dotnet build errgroup/golang.org.x.sync.errgroup.csproj -c Release -p:GoStdLibVersion=1.26.10.1
dotnet build semaphore/golang.org.x.sync.semaphore.csproj -c Release -p:GoStdLibVersion=1.26.10.1
dotnet build singleflight/golang.org.x.sync.singleflight.csproj -c Release -p:GoStdLibVersion=1.26.10.1
dotnet build syncmap/golang.org.x.sync.syncmap.csproj -c Release -p:GoStdLibVersion=1.26.10.1
```

The restore takes the `go.*` packages from nuget.org. `-p:GoStdLibVersion=1.26.10.1` pins the go2cs standard-library
release the package was built against; without it the build takes the newest `1.26.*`.

## Provenance

Converted with `go2cs -recurse=nuget -platforms linux/amd64` at go2cs commit `691c7e7eb3`, which carries the go.*
1.26.10.1 release's runtime and source generators unchanged, plus the nugetgo rebuild tools. The module's Go tests
were converted and compared at the same commit: 27 matched, 1 disclosed, across `errgroup` (5), `semaphore` (7 + 1
disclosed), `singleflight` (12) and `syncmap` (3). The disclosed test is `semaphore`'s `TestWeightedAcquire`, on
linux, a runtime-capability divergence: its first call compiles under a 10 ms deadline (see
[semaphore.md](semaphore.md)). The package ships that report as `VALIDATION.md`.
