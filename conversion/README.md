## Building

```
cd uuid
dotnet build -c Release -p:GoStdLibVersion=1.26.10.1
```

The restore takes the `go.*` packages from nuget.org. `-p:GoStdLibVersion=1.26.10.1` pins the go2cs standard-library
release the package was built against; without it the build takes the newest `1.26.*`.

## Provenance

Converted with `go2cs -recurse=nuget -platforms linux/amd64` at go2cs commit `c992731142`, which carries the go.*
1.26.10.1 release's runtime and source generators unchanged, plus the nugetgo rebuild tools. The module's Go tests
were converted and compared at the same commit, in one unretried run: 54 matched, 0 disclosed. The package ships that
report as `VALIDATION.md`.

`TestVersion6` is disclosed as timing-sensitive. In uuid v1.6.0, `NewV6` writes the version over bits 12-15 of the
timestamp, so two calls that straddle a 409.6 microsecond boundary read "time reversed". Measured on a linux/amd64
host: the converted test fails 40 of 150 runs with tiered compilation off and about 64 of 150 with .NET's default
tiering; Go fails 0 of 300 in full-suite runs and 262 of 1000 when the test runs alone. The cause of the converted
side's wider gap between the two calls is undetermined. A run reads 53 + 1 when the converted test fails and 54 + 0
when it passes, the disclosure then reported as orphaned; this run read 54 + 0.
