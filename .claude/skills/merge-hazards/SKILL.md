When several machines work one tree, the dangerous merges are the ones git reports as clean. Each rule below was paid for.

## Silent duplication — two lanes solve one problem and git marks nothing
- **TELL: a clean auto-merge between branches that both attacked one problem. Resolving the marked hunks is not resolving the merge — read the merged file WHOLE and run it**; a symbol added OUTSIDE the markers is undefined after a one-side resolution. <!-- Independently added blocks land at different offsets under different names, so git merges both as ordinary additions and marks nothing. Measured 2026-08-24: two independently written 17-element apply-set arrays in `migrate-tfm.ps1` auto-merged CLEANLY, and the result would have appended every site to `$applySites` TWICE. Mirror case: `$shadowed`, introduced outside the markers, left undefined at its use site. Neither is visible from the conflict markers. -->
- **The shape reaches CUTS, not only merges: announce before you push**, and send a coordinator-critical fix to a LIVE lane's own file as an ASK to that lane. <!-- 2026-09-02: the same two-line guard fix was written twice within one hour by two sessions, caught only because both announced before either merged — the author's branch was taken and the duplicate deleted. -->
- **Two concurrent cuts needing ONE shared predicate write it at the SAME PATH on purpose**, and the LATER cut is based on the earlier one's file before the seat. <!-- Ruled 2026-09-04, one of two refinements measured that day. A loud add/add conflict beats auto-merging two differently-named definitions of one concept: the silent-duplication shape forced into the open. Basing the later cut on the earlier means the assembly sees one definition and no conflict at all. -->
- **Read a clean auto-merge of two cuts touching ONE method for two REPRESENTATIONS of one fact, not only two definitions of one NAME**: delete the weaker, re-run every arm on the MERGED tree, state which TIP the CNR ran at. <!-- 2026-09-04: a status value from one cut and a marker list from the other arrived in the same method from edits git had no reason to conflict, and the tree failed to compile ONLY because one call named the pre-merge API — a same-NAMED helper would have compiled with one representation silently authoritative. The weaker representation is the one reaching fewer consumers. Never claim a union CNR the train will measure. -->
- **TELL: a hop release SPLITS a package, so ONE Go primitive is now DECLARED TWICE — two seats body the two copies differently, each GREEN ALONE, and the union ships one primitive in TWO behaviours with the hot path un-converted.** Rule it one primitive, one behaviour, assert the acceptance in BOTH files, and **census the PACKAGE, not the file, with a control.** <!-- batch19, 2026-09-08, C1: at the newer release `throw`/`fatal` are declared in `sync/runtime.go` AND in the new `internal/sync/runtime.go`; the five call sites split 2/3 and `sync.Mutex` DELEGATES to `internal/sync`, so every Mutex-misuse path runs through the SECOND pair. One seat re-pointed `sync`'s pair to the fatal report while another bodied `internal/sync`'s as the catchable exception — a union git has no reason to conflict on. Named by the lane whose OWN seat it NARROWS (its acceptance covers 2 of 5 sites, restated at measured scope rather than left to read as coverage) BEFORE either landed; ruled one primitive, one behaviour, with `TestMutexMisuse` at the new release as the measured gate. Census note: a FILE-scoped count read SEVEN declarations where the PACKAGE has EIGHT. This is the two-representations rule above with the RELEASE supplying both representations — the duplication is in the INPUT, not in the cuts, so neither lane's own gates can see it. -->
- **Never hand-merge goldens**: two seats extending one behavioral guard project also conflict on `main.cs`, the golden and `package_info.cs`. <!-- Measured 2026-09-05. Resolution: the LATER cut rebases onto the EARLIER, unions the Go source (deduping shared type declarations), REGENERATES the emission with a converter carrying BOTH fixes, adds a RED control against a converter carrying only the EARLIER fix (so the control names the LATER fix), and re-reads its gates at the new tip. A dispatch naming an existing guard project as the extension target tells the sub-agent which SIBLING seats also extend it. -->
- **A cross-lane attribute widening resolves by the SUPERSET; read what it REACHES first** — union CNR plus `check-solution-integrity.ps1`. <!-- 2026-09-05, and it conflicted only by luck: two lanes widened the SAME attribute's `AttributeUsage` from two different rows (`+Struct` for named arrays; `+Class|Struct` for named pointer-to-array wrappers), a TEXTUAL conflict ONLY because both edits landed on one line. Had they not, git would have merged two widenings silently. The integrity check is what proves the two stampers never double-stamp one declaration. -->
- **When a window EXPIRES and the lane arrives late, DIFF THE TWO ANSWERS rather than choosing by AUTHORSHIP**; a better comment lands as a FOLLOW-UP under the source freeze. <!-- 2026-09-06: the coordinator's landed member and the lane's announced commit were byte-identical after whitespace — same override, same value, same placement — so the running battery already carried exactly the tree the lane's commit would have produced, and only the COMMENT differed. The mid-battery source freeze binds the worktree, and documentation is never worth stopping a multi-hour gate run. -->
- **TWO CORRECT CUTS COMPUTED AGAINST TWO STATES OF ONE FILE COMPOSE SILENTLY TO THE WRONG STATE** — empty overlap, zero conflicts, union reds on whichever seat merged LAST, **so the first correct gated cut is what looks broken.** ORDER them. <!-- 2026-09-08: a converter fix whose WHOLE corpus footprint is a `.cs.auto` REVIEW SIBLING, which the build never sees, versus a hand-own RE-DERIVE that copied the THEN-CURRENT sibling's mangled stamp into the `.cs` that COMPILES. Both sides were measured on the ladder tree. Ordering is the remedy: the emission fix and its sibling hunk land FIRST, the re-derive branch takes the one-line correction on top, and the re-derive is RETAKEN from the FIXED converter's emission at the hop, which carries the right spelling by construction. -->

## Adjacent inserts, and resolutions that lose a line
- **TELL: a conflict hunk that reads like an ordinary either/or.** An INSERT adjacent to a line the other side edited folds into ONE hunk and BOTH single-side resolutions silently lose a line: keep BOTH sides, **assert the structural invariant** (row/line count before == after + known inserts), and **positive-control any re-derived aggregate against a known-good blob first.** <!-- Measured 2026-08-29: master inserted the `go/build` roster row directly above `go/build/constraint`, which the branch had annotated; `--ours` dropped the new row entirely, `--theirs` dropped the annotation. Nothing in the markers says a line vanishes, so it reads like an ordinary either/or. The derivation must reproduce the other side's banked value EXACTLY before its new value is believed — a derivation that cannot reproduce a known-good value is not a derivation. -->
- **When a hunk shows one side DELETING code the other side FIXED, verify the replacement carries the fix** — one grep; both changes can be correct, the displacement rule correct, and the fix's SITE ceases to exist. <!-- Measured 2026-09-06: one train lands a `KeepAlive` buffer pin inside a generated darwin `pipe` body; the next train's seat replaces that whole body with a `GoManualConversion` placeholder. Clean merge, compiles, and no gate is shaped to notice a `KeepAlive` that stopped existing. `syscall.Uname` runs the other way — there a registration landed without its body; here a body lands and removes a fix. Only a census that reads the HUNKS instead of applying the rule will ask. -->
- **A seat may REVERT NOTHING and a file-level resolution still lose the fix: count the fix's tokens per file at BASE, MASTER and BRANCH** — 0/N/0 with the file IN the diff ⇒ resolve BY HUNK, the same triple with the file ABSENT ⇒ nothing owed — answer from the BODY, and gate it with the INVARIANT **`pins lost <= placeholders added`**, never a constant. <!-- A darwin seat cut before the pin emission carried 0 pins where master carried 105 in one file; because the seat's diff touches that file at all (one placeholder hunk), `--theirs` at file granularity drops all 105. A hand-own that allocates native memory needs no pin, where a grep says "absent". A pin-count gate hardcoded `105` and false-redded a CORRECT resolution reading 104, because a displaced body takes its own pin with it; changing the literal to 104 re-breaks at the next displacement (the hoisted-literal lesson). The invariant is computed from master and the ref at run time, controlled on the merge (1/1 holds), on master (0/0 holds), and on the pre-displacement branch (105 lost, 1 placeholder, FAILS). That merge landed: `syscall/darwin/zsyscall_darwin_amd64.cs` reads 104 at `fd09034f5`, and the corpus carries 1,222 pins. -->
- **TELL: a 3-way that conflicts NOWHERE and leaves a file DISAGREEING WITH ITSELF** — the ATTRIBUTE line taken from one side, the FIELD it names from the other. Census per MEMBER, never per declaration: **does every stamped name resolve to a field of the declaration it stamps.** And before calling such a blob a merge artifact, run `git merge-base --is-ancestor <blob's commit> <fix commit>`: a blob PREDATING the fix is a STALE CONVERTER's own output, whose remedy is RE-EMISSION, where a genuine 3-way artifact would want the merge re-run. <!-- batch19, 2026-09-08, R and C1: applying a peer's re-derives took the hop ladder's windows leg 120 -> 1 distinct errors, the last a `GoValueClone` attribute naming a field the same blob declares under a DIFFERENT spelling (five of six members match a field, one matches none) — a re-derive's 3-way is base `.cs.auto` / ours hand file / theirs fresh emission, and it took the two halves of one fact from two sides with NO conflict: the `mfinal.cs` subtraction one file over. Census arithmetic: master 34 stamped declarations / 39 names / 0 unresolved (the negative arm), the defective blob 39 / 57 / 1, exactly that one name (the positive arm), and 0 after the fix — so the finding is ONE instance and not a class, and nobody goes looking. The applier's original check compared the DECLARATION line, which both sides shared, and never the names inside; its one false positive was a C# VERBATIM identifier, which `\w` does not match. The fix went ON TOP, never a rewrite, and is RED at the current release by construction until the hop. Ancestry half, 2026-09-08, G/C1/R: the blob carrying that stamp PREDATES the train commit whose own guard cites the case verbatim, so no cross-side mixing was needed to produce it — a mechanism AND a lane were named on a hedge ("likely, not measured") and both halves were wrong, while the two MEASURED facts (a name with no field; the review sibling spelling it correctly) were sufficient alone. -->

## Silent subtraction — the mirror, and it is worse
- **TELL: a clean merge whose result compiles nowhere.** One lane REMOVES a definition because another branch supplies the replacement and the merge drops the supplier: if `git diff --name-only <base>..<branch>` shows a `manualConversionFuncs` registration or a generated-body deletion, **assert the matching `*_impl.cs` body is in the MERGE RESULT.** **And REPAIR A DIVERGED FILE BY THE 3-WAY, never by hand** — a hand reconstruction is itself a second silent subtraction. <!-- Paid for 2026-08-29 (`syscall.Uname`): the converter registration that DISPLACES the generated wrapper merged, the hand-own `*_impl.cs` BODY it displaces to did not, and the whole linux corpus went RED at master with a clean `git status` — `kernel_version_linux.cs` CS0117 `'syscall_package' does not contain a definition for 'Uname'`, discovered days later by a lane building that flavor, not by any merge. Both diffs are pure additions/removals, so git merges them without a conflict or a warning. One step PAST the regenerate-never-merge seam rule the guilty file's own header documents: the generated side was correct, the destination missing. Same shape as the package_info.cs / stdlib-metadata.txt preflight below. Hand-repair half, batch19, 2026-09-08, R: a lane's own repair of `mfinal.cs` carried master's three finalizer-binding commits and DROPPED a peer's `AddCleanup` ENTIRELY — no conflict, no marker — while the peer's 3-way (base 747 / ours 822 / theirs 797 -> 872 lines, `AddCleanup` 3, `fingStatus` 20 = 10 + 8 + 2) reproduced to the digit and was applied instead. A hand reconstruction is a merge performed from memory, and memory is exactly what the silent-subtraction class defeats. -->
- **A WIDENING of a shared golib door keeps the PREVIOUS arity as a forwarding overload for at least one train**; mirror, **an EXACT-MATCH overload added for ONE caller CAPTURES every call that bound through an IMPLICIT conversion.** **A golib-touching seat runs GolibTests at BOTH configurations before it seats.** **A NEW MEMBER on a PUBLIC golib interface is a breaking change for EVERY implementer, TEST DOUBLES INCLUDED: put it on every implementer explicitly, carry the implementer census in the cut's PREDICTION, and never remedy it with a DEFAULT INTERFACE IMPLEMENTATION when the answer depends on state the interface cannot see.** <!-- Both measured 2026-09-05. The forwarding overload carries a remark naming its retirement condition (grep-proven zero callers), because a sibling seat cut against the old arity merges at the union with no fix-up any lane's gates measured; the silent subtraction caught one train EARLY only because a lane read another lane's post. The two-word form of `OverNativeMemory` means what `unsafe.Slice` means (cap = len). Capture: `Pointer(INilPointer box)` took every `new Pointer(box)` that had gone through ж<T> to uintptr, so overload RESOLUTION changed and not just behaviour, and only a guard asking the question saw it. A fix to a defect in a SEATED train's union lands on THAT seat's branch tip, never on a later branch that stacks on it. New-member half, batch19, 2026-09-08, i9/coordinator: `ISlice.IsNil` added with ONE implementation (`slice<T>`) failed GolibTests at BOTH configurations on CS0535 at a TEST DOUBLE (`ArrayRangeAllocationTests.NamedSliceLike`) — golib itself compiled, the CONSUMERS did not, the shape a producer-only compile cannot see, route #7's consumer gate firing as named. `ISliceBacking` is internal by design, so a default implementation would answer `false` for exactly the implementers nobody checked — a silent wrong answer wearing a compile-clean face. -->
- **TELL: a seat whose landing evidence is "it compiles at both releases".** A golib member added AHEAD of the runtime table it is DERIVED from builds everywhere and FAILS the derived guard — compiling-is-not-correctness applied to a LANDING decision — and the guard stays UN-WEAKENED. <!-- batch19, 2026-09-08, R: a `WaitReason` member for a park reason the converted 1.23.12 runtime does not carry BUILT at 878 projects and FAILED `TheWaitReasonMapIsGosOwnTableByDerivation` at both configurations; a member added ahead of its runtime table is exactly the state that guard refuses. The coordinator's split ruling rested on the compile claim and was REVERSED on the measurement. Companion, and the reason the second guard went unfound: the search was `grep | head -8` — head-limited on the ONE query whose purpose was completeness, the guard-discovery member of that family (CLAUDE.md safety floor #16). -->
- **A REGISTRY ROW WHOSE PRINCIPAL RELOCATED IS RE-KEYED, NEVER RETIRED** — retiring one for a LIVE push turns a loud refusal into a silent stub with the guard GREEN, so **a ruling's VOCABULARY ("retire") is re-derived at the sources before it is cut.** <!-- 2026-09-07. The coordinator ruled "the `internal/weak` two-row RETIREMENT" for the hop's one failing converter test; the lane re-derived from the 1.24.13 sources before cutting and found the guard's own `(renamed? deleted?)` question answers RENAMED — `internal/weak` became the PUBLIC `weak` package, both bodyless consumers (`weak/pointer.go:93,96`) and both runtime pushes (`mheap.go:2103,2108`, pusher names UNCHANGED) still exist — so the cut is two map KEYS. Deleting the rows would have reproduced the `syscall.runtime_envs` shape (a bodyless consumer indistinguishable from an ordinary stub; `os.init()` down on Linux) SILENTLY. A relocated principal moves the KEY, and the hand-own's own relocation is the corpus move's work. -->

## Seam checks: both sides of the ledger, every axis of the property
- **A seam check that verifies a displacement HAPPENED but not that its destination EXISTS passes the exact failure it was written for. Carry both sides of the ledger** — registration ⇒ displaced wrapper ⇒ body, and the reverse — in the converter's own `go test ./...`, beside `projitemsIntegrity_test`. <!-- 2026-08-29: the ten-names/zero-bodies property offered as the struct-passing merge instrument — every registered name has zero generated bodies and exactly one placeholder — was run twice over all ten names and reported as the check that would catch a lost registration. It is ONE-SIDED: a placeholder pointing at a hand-own body that does not exist passes it cleanly, which is exactly what master held, and the branch carrying the check carried the same gap. The reverse arm is a dead hand-own nothing displaces, where the shape allows it cheaply. Putting it in the tier every lane already pays for turns the class into a red converter suite at the merge rather than a red corpus later. -->
- **A witness built from ON-DISK artifacts is ENVIRONMENT-dependent**: it passes on a tree that has run that package's `-tests` and fails on every clean clone. <!-- 2026-09-02: a displacement guard whose witness is on-disk placeholders fails on a clean clone for TEST-side hand-owns, because an unbanked row has no committed test emission. Ruled remedy: a GOROOT `_test.go` witness arm, matched by CLASS rather than by name and counted separately as the weaker witness; the production arm is unchanged. -->
- **A WITNESS CARRYING FEWER AXES THAN THE PROPERTY GOES GREEN ON EXACTLY THE CASE THE PROPERTY WAS WRITTEN FOR: take the PROPERTY's axes** (name × flavour), both ways per flavour; post the corrected guard's master census as FINDINGS first and positive-control it IN THE DIRECTION OF THE FINDING; CLASSIFY flagged rows before counting; and **retire a PER-FAMILY guard only if the general one reproduces every control and is as sharp.** <!-- 2026-09-05: the registration ledger's body witness collapsed every per-GOOS folder into ONE name set, so a scope widened to a flavour with NO body passed whenever another flavour held one — route #8's shape, disarmed by the legitimate arrival of a second flavour. Direction control: the known case fires nothing at its real scope and fires on the widened flavours when the scope is simulated wider. Classification: a `partial` completion is the OTHER displacement mechanism — exempt, with its own control that stripping `partial` goes red; a bare-name regex over-collects a different member of the same name, stated at the arm, costing a false pass only. Sharpness: a receiver-discriminating witness stays beside a bare-tail one. -->
- **A NAME in a hand-owned file cannot distinguish a WRAPPER DISPLACEMENT from a CONSUMER-SIDE remedy**: remediation status takes THREE signals — a `manualConversionFuncs` key, the placeholder in the generated file, a body — and NAMES the mechanism. <!-- A consumer that transcribes a native structure MENTIONS the wrapper it is avoiding: textually identical, semantically opposite. Anything less ranks the work backwards. -->
- **Read a displacement's diff for hoisted literals that MOVE, not only for hoists that vanish** (a SHARED literal relocates into its next user's file, so a footprint applied without that hunk fails CS0103); **and a linkname destination declared in a `_test.go` lands in the INTERNAL-test class**, completed by registration plus a body in `export_impl_test.cs`. <!-- The converter hoists a body's string literals WITH the body, so a displaced body's `…ˢ` literals cease to exist and any hand-own referencing one dangles. Vanishing: 2026-09-02, the ledger's reverse arm found it before a compile did; a hand-own spells its own panic text and depends on no hoist the displacement removes. Relocating: 2026-09-05, runtime's `cannot allocate memory` leaving `malloc.cs` for `mheap.cs`, +3 — the two-seeded diff shows it as a THIRD file. Linkname: `reflect`'s `gcbits`, provided by runtime via linkname, emitted bodyless into the internal-test package and picked up by the throwing partial stub; a production-side push cannot reach it. Completion is the reflectlite pattern, witnessed by the guard's test-side arm. -->

## Stale bases and branch censuses
- **A branch behind master shows master's newer files as DELETIONS** — the stale-base illusion, not data loss. Diff from the **merge base** (`git merge-base A B`), never a moving tip, and **take the THREE-DOT `git diff master...branch` for any branch census, the SECURITY census included.** <!-- Mis-read as a lane destroying work more than once. 2026-09-04, the coordinator against itself: with a branch based on an older master the two-dot form shows master's OWN newer content REVERSED, which read as 33 "identifier hits" that were pre-scrub doc lines master had since scrubbed, five "golib files" that were other trains' landed golib, and an is-ancestor NO against master's tip — all of it looking like a lane's defects. The merge-base rule binds every branch instrument. The merge's own file count (63 = 24 + 39) was the honest number all along. Two more two-dot readings, batch19, both 2026-09-08: a branch census taken as a two-point diff against master reported a 587-LINE DELETION in CLAUDE.md itself where the three-dot form from the merge base reports ONE; and a brief's PREDICTION DERIVATION written `git diff <base>..<seat> -- src/core` returned 12 files — the previous train's landed work REVERSED, a -256-line golib file, a -77-line runtime file and six `.cs.auto` — because the base is NOT an ancestor of the seat, while the three-dot form returned the ONE file intended (a one-glyph `+1/-1`). That is the stale-base illusion INSIDE AN INSTRUMENT: the finalize instrument now implements three dots, STAMPS both numbers with the reason, and compares the lines as FILES with `cmp`, since a glyph pair is not a shell pattern. -->
- **Verify a separated stack from BOTH branches** — `git log --oneline master..<branch>` on each shows what a merge would really carry.
- **A LIST NAMES TIPS, AND TIPS CARRY ANCESTORS: audit the RANGE, `base..tip`.** Do not weaken the SHA rule; widen the audit. <!-- A RULE INTERACTION rather than anyone's mistake: announce-then-push guarantees that a tip is disproportionately the smallest, most cosmetic commit on the branch, since never rewriting a posted SHA means corrections land ON TOP and corrections are small — a six-line `gofmt` tip over a 569-line hand-own. An audit of fifteen train tips found EIGHT unlisted rider commits that would board with them, and the two worst gate lines in the batch were BOTH riders (one a count-match satisfied against a stale tree, one a gate inventory with no results); every audit and reconciliation in that campaign had been conducted at the TIP. -->
- **SHARED FILES BETWEEN TWO BRANCHES IS EVIDENCE OF ANCESTRY AS OFTEN AS OF CONFLICT** (`git merge-base --is-ancestor` settles it in one command, and a gate-line defect on a chain's TIP belongs to the whole chain) — **but ANCESTRY-INDEPENDENCE IS NOT COMPILE-INDEPENDENCE: ask whether it stands up ALONE.** <!-- Three branches appeared to collide on EIGHT files; they were one chain three deep, listed three times — twenty-two candidates were nineteen. Compile case: a seat verified NOT a descendant of a withdrawn branch (`--is-ancestor` rc=1 both ways, none of its five commits) still could not build without it — the type it overrides is declared only on that branch, so the union is `CS0246` plus an `override` with nothing to override. Three checks ran — name-prefix (wrong), ancestry (correct), and neither was the right question. The commit body stated the dependency in its own first paragraph and nobody read it. -->
- **COMPOSE A PEER'S CUT BY ITS FULL FOOTPRINT — `git show --name-only <sha>`, every path applied — NEVER by the files you remember the cut for: composition by memory is the stale-base illusion inside ONE worktree.** Assert CLOSURE, not presence. <!-- batch19, 2026-09-08, R: a first composition attempt died CS0122 on a peer's `FatalReport.cs` and read like a defect in a cut its author could not compile — it was the COMPOSITION's, since that change widens `CrashReport.WriteToCrashOutput` private -> internal in a SECOND file that had not been copied. Every assertion written checked PRESENCE; none checked CLOSURE. -->
- **A SCRATCH TREE PINNED AT A FIXED BASE GOES STALE INVISIBLY FOR EXACTLY THE FILES THAT MATTER MOST — THE HAND-OWNS.** Preflight before ANY rung is read: `git ls-tree -r master -- src/core` against a `find` over the tree, every missing file NAMED, and re-base the ladder on the landed master at each train landing. <!-- batch19, 2026-09-08, R: a hand-own landing on master AFTER a ladder's base is absent from the ladder, and because a hand-own is what BODIES a displaced or bodyless declaration, its absence presents EITHER as a phantom compile blocker indistinguishable from a real wall (`rtlGetVersion` CS0103 from a missing `zsyscall_windows_version_impl.cs`; restored, windows 34 -> 32 errors, prediction held) OR as NOTHING AT ALL (`time/sleep_impl.cs` bodies `runtimeNow`; without it the tree carries one generated throwing stub that compiles clean and throws at RUN time — blind to every error-count instrument). That seat's blocker list moved a third time in one day, each movement the finding. -->
- **A RE-BASE OWES THE STALE-FILE DELETION PASS**: a seed file the new base no longer emits sits beside its replacement and kills the build. Delete by WRITE-EVIDENCE, and expect the flavours' sets to come out IDENTICAL. <!-- batch19, 2026-09-08, R: the seed's `exp_aliastypeparams_off.cs` sitting beside the emitted `_on.cs` killed the first build at 186 dlls in 80 s; 86 stale files were deleted by write-evidence, zero conflicts, the three flavours' sets identical. Ruled with it: 1.24 hand-own edits live on ONE branch off master that never seats on a train — they cannot compile against the 1.23 corpus — and land WITH the H5 regen, with the following stage reviewing them file by file. -->

## Gate lines, corrections and records
- **Check the diffstat against the claim BEFORE the push, never after** — a merge whose file list does not match its commit message is stopped there.
- **IN A GATE LINE THE VERDICTS GET CHECKED AND THE ADJECTIVES RIDE IN FREE, and A GATE INVENTORY IS NOT A GATE RESULT: every gate line carries a number or an exit code, or it is prose.** **A STAMP THAT NAMES A CENSUS AS ITS EVIDENCE PRINTS THAT CENSUS'S POPULATION AND SCOPE BESIDE THE NUMBER**, and a CLASS-WIDE claim is computed by its own one-command derivation, never borrowed from a neighbour's narrower one. <!-- "matched 324, disclosed 55, 388/388, zero orphaned, zero mint violations" — the first three computed from the record, the last two never measured at all: one had no source anywhere in the pipeline, the other was an early-return check over a manifest with no entries of its class. A gate line is exactly where the asymmetry hides, because the verdict is the thing under scrutiny; every decoration on one is a claim owing the same provenance as the verdict. Inventory case: a commit listing "converter go test; darwin builds; linux build; CNR; integrity per GOOS" with no exit codes, no counts and no timings published nothing falsifiable — and a six-line follow-up seat can drag the whole increment in on it. Stamp case, batch19, 2026-09-08, coordinator: an assembly's FINDING line said "no seat in this train touches `src/go2cs` or `src/gen`, and G11(b) asserts that zero" while THREE seats touched `src/go2cs` — G11(b)'s zero is over the lift/dedup OWNER SET only. A template stamp restating a NARROW census as a CLASS-WIDE zero is a false reading with a TRUE NUMBER inside it, which is why the number survives every check; the derivation the class-wide claim actually owed is per-seat converter-file counts. -->
- **A STATED REASON FOR SKIPPING A GATE IS ITSELF A CLAIM, justified by CALL GRAPH, not by file** — *"one production caller, reached only through X, which `main.go` guards with `<condition>`, so no `-stdlib` run reaches it and the two-seeded diff is zero BY CONSTRUCTION"* is refutable in one grep. **Refusing to quote a MEANINGLESS green is the same discipline, cheaper.** <!-- A skipped gate leaves no artifact, so the JUSTIFICATION is the only thing standing between the reader and an unmeasured tree. "It is only a test file", "the binary is unchanged", "the guard change cannot affect emission" are unfalsifiable prose.
