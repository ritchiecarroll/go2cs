## Before the run
- **Commit the corpus edit BEFORE any sweep.** A sweep wrapper's restore step (`git checkout HEAD -- src/core`) cannot distinguish your uncommitted work from the sweep's own dirt, so hand-applied hunks vanish between two rows and the second row fails **invalidly** — a phantom red. Ordering is the fix, not the script; re-run the application's own assertions after any restore. <!-- ⚠ measured 2026-09-02, paid twice in one day. -->
- **Read the COMMITTED bytes, never the seed,** before cutting a footprint against a base — and take the BEFORE arm of any before/after at the CUT'S OWN BASE, never at an earlier landing on the reasoning that "none of the intervening merges touch it". A file that is not gofmt-clean at master leaves foreign whitespace lines in the next cut's diff: verify they are pure whitespace and NAME them. <!-- ⚠ 2026-09-02. Both halves were paid on the same arc as the whole-file-copy trap below. -->
- **While the corpus is being measured, the corpus edit is the only thing moving.** A bank-check's own `-tests` pass OVERWRITES a merged non-marked file — restore from the preserved artifact and re-run every footprint invariant after any pipeline pass. <!-- ⚠ 2026-09-03, companion to the trackedness-deletes rule in "Clean up". -->
## 1. Predict
- **Derive the prediction from the same KIND of run that will measure it — the two-seeded `-stdlib` emission — never from a single-package probe**, whose numstat carries the import-init hook closure family the driver keeps. Post the predicted number AS READ, never rounded, and score a miss against master line by line rather than explaining it away. <!-- ⚠ 2026-09-03: a probe predicted −86 where the emission read −77 plus the placeholder. -->
- **Predict the DIFFERENCE the change makes; derive every total from the tree at run time, never from a number remembered off another tree.** A count prediction that SPANS A TRAIN carries the train's own additions. **A number that surprises you is checked against the instrument before it is reported.** <!-- ⚠ two instances, 2026-09-04. - **A population prediction names the SHAPE it counts, and predicts the quantity the INSTRUMENT measures.** An A/B whose PRE arm is the PREVIOUS increment's tip measures only the new increment's delta, so a file the previous increment already lowered shows NO change. **And a source-level census cannot see EMISSION properties.** **A footprint's SHAPE can be predicted while its LOCATION cannot**, and a footprint smaller than sized and on REAL code is better evidence than a large one on guards: "every instance so far is in my own probes" is a statement about the census, not about the corpus. <!-- ⚠ same arc: a 54-file census population was predicted against an arm that read 21, all inside the set — the falsifier silent and the number wrong for a reason the data already held. SHAPE-not-LOCATION ⚠ 2026-09-03: a defect measured only in the probes built to find it landed on one production field. -->
- **Predict LINE KINDS per file against what the change DOES, never against a remembered number.** An ADDITIVE change's delta carries **zero** `GoPositionMap` lines, so any map line there is foreign drift. A change that REMOVES emitted code re-encodes the file's map and carries its OWN map lines — their ABSENCE would mean the emission had not shrunk — except where the displacement removes a file's LAST mapped content, when the converter RETIRES the record instead. State WHICH, per file, and name "a map line removed rather than re-encoded" as its own falsifier. A prediction's COUNT can hold while its KIND does not — state both. <!-- ⚠ three measurements, 2026-09-03. The class-B "zero map lines in the delta" bar is for additions only; a removal kills any lift whose only source was the removed body (`nanotime1_r`). -->

## 2. Emit — two seeded roots, every target
- **The on-disk corpus can be STALE**: the committed tree measures *that* output, not today's converter. Reconvert.
- **Blast radius = TWO seeded reconverts (pre-change, changed) diffed against EACH OTHER — never the committed-tree diff — over the WHOLE corpus.** The committed tree is a moving baseline carrying unbanked drift; a scoped census reproduces its own scope. <!-- ⚠ TWO-SEEDED DIFF, 2026-08-29, the position-table splitter fix: a naive reconvert-vs-committed diff reported 147+ files, almost all PRE-EXISTING unbanked drift from arcs that landed without their regens (the standing position-map staleness two census lanes rooted independently the same day); the two-seeded diff isolated 26 metadata files, zero production code. WHOLE-CORPUS SCOPE, 2026-09-04: the whole-corpus run found both a publication defect and fourteen sites in sync/map.cs the name-keyed census had not predicted. -->
- **ADDRESS-OF/ALIASING (`Ꮡ`) changes owe a seeded reconvert-and-BUILD; CNR alone is NOT sufficient.** The behavioral corpus is a SAMPLE of Go's shapes; the stdlib is the population. <!-- ⚠ ALIASING GATE proven 2026-08-15, the element-field-address fix: of three defects in that arc CNR caught ONE; the other two — a pointer-receiver named-array blind spot and its over-broad first fix — appeared in NO behavioral test's shape and were found only because the whole corpus was reconverted and compiled. The same census surfaced a real SHIPPED lost write: encoding/xml's attribute-namespace translation writing into a copy. This is the OTHER direction of the both-populations rule in "Census-derived footprints": a std census is blind to the behavioral corpus, and CNR is blind to the stdlib population — which is why a footprint prediction names BOTH or says which it did not measure. -->
- **A converter change's corpus footprint is measured on ALL THREE TARGETS or it is not measured**, each target into its OWN seed. The tell is the emission COUNT PER TARGET stated in the post. <!-- ⚠ 2026-09-04: an A/B run single-target on the host default posted "over the whole corpus" while its linux and darwin lines were never applied — the L3 blind spot, walked into while quoting the rule. Tell: 1,656 windows against 1,724 and 1,727. Companion (2026-09-04): an L3 package is measured on EVERY target, each into its own seed. -->
- **SEED FIRST — non-negotiable.** `cp -r src/core <tmp>/core` before reconverting, **excluding `bin`/`obj`/`Generated`**, then **verify the seeded `.cs` COUNT**. An EMPTY or PARTIAL root gives the marker nothing to detect — `<file>.cs.auto` is written only when the marked file already exists at the output path — so every hand-owned rewrite emits as plain `.cs`, the overlay rule ("copy `*.cs`, exclude `*.cs.auto`") protects NOTHING, and hand-owns are clobbered with auto conversions that COMPILE and are operationally broken. Control: untouched seeded files reproduce HEAD byte-for-byte. Seeding also hides files the converter has STOPPED emitting — classify emitted-vs-seeded by sentinel mtime and report would-be deletions. <!-- ⚠ SEED FIRST learned 2026-07-25, cost a false operational-break alarm: 14 hand-owned files got clobbered, and godebug's auto init() throws in a module initializer and takes down every dependent. PARTIAL SEED fleet-confirmed twice in one day, 2026-09-01: Copy-Item -Recurse dies on go2cs-gen's long obj\...\Generated\ paths and, under the ritual's own required $ErrorActionPreference='Continue', carries on past the death — the unseeded-root hazard through a door the rule never named. The emitted-files control is what makes a suspect seed's readings trustworthy. -->

- **Convert**: `go2cs.exe -stdlib -comments -go2cspath <tmp>/src` → output at **`<tmp>/src/core/<pkg>`** (`core` is hardcoded; `-go2cspath` is the *output* root, unrelated to MSBuild's `$(go2csPath)`). ≈ 3–4 min for the full stdlib — **batch, never per package**. <!-- ⚠ CONVERSION COST: per-file work is sub-second; the ≈3-4 min is go/packages loading the whole type graph, which is why the run must be batched rather than invoked per package. -->
- **NEVER convert twice into one temp root; never let two conversions overlap on a box.** Delete and re-seed the root for every reconvert; confirm no `go2cs.exe` is alive first. ## 3. Diff — the hunk rule and its instrument
- **The bank unit for a converter change's corpus footprint is the two-seeded diff's HUNKS, never its FILE set.** Applying the A/B's whole files onto a corpus stale in OTHER families carries those families in with them. The tell is arithmetic. Position maps and relocation hooks belong to the deliberate regen, not to a converter train. <!-- ⚠ measured 2026-09-02: the whole-file application landed six relocation hooks into one `package_info.cs` while the file that declares them — byte-identical between the two binaries, so never flagged — still declared three; result CS0111 ×3.
