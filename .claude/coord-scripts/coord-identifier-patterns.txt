# coord-identifier-patterns.txt -- the fleet's ONE identifier-census definition.
#
# The owner's standing security order (.claude/rules/docs-records.md, "The security order") forbids
# real machine names, account names, profile paths, share names and LAN addresses on ANY pushed
# surface. Before this file there were THREE definitions of that order -- COORD's post tool, C2's
# post tool and R's post tool -- with three different arm sets, and the disagreement cost C2 four
# hours of refusals over three pre-existing strings it did not write. The rule of record
# (train-assembly and mailbox skills): a refusal-pattern list is defined ONCE and read by every
# consumer. This is that list. NO TOOL CARRIES A PRIVATE COPY OF ANY ARM.
#
# RELATION TO THE TRACKED-TREE GATE. src/go2cs/internal/repoguard/fleetIdentifierCensus_test.go
# (TestNoFleetIdentifiersInTrackedFiles) is the repository's own fleet-identifier guard and runs
# under the plain `go test ./...`. It is the authority on the STRUCTURAL classes and on the denied
# name list. The arms below marked "GO GUARD" are its regexes and its sets, carried across so the
# two instruments cannot disagree; where an arm has no counterpart there it says so. The denied
# names themselves live in coord-identifier-hashes.txt, generated from that file's fleetDeniedTokens
# and carrying no plaintext. The Go guard gates the TRACKED TREE at test time; this definition and
# its shell consumer gate every POST, BEFORE it becomes a tracked or pushed anything. Two guards,
# two questions, and a clean reading from one does not certify the other.
#
# THIS FILE NAMES NO INSTANCE. Referring to the identifier class is how the population GROWS -- the
# fleet's own argument about the IPv4 arm added seven hits to the shared surface in forty minutes,
# and every one is indistinguishable to every arm from the thing being guarded. Prose here and in
# every report uses the canonical placeholders WITH PROVENANCE:
#     the «ipv4» in <lane>'s <item> line        the «unc» in <file>:<line>
#     the «profile-path» in <lane>'s <item>     the «account» in <file>:<line>
#     the «version-quad» in <lane>'s <item>     the «host» in <lane>'s <item>
# The provenance is what lets a reader tell a known negative from a leak without seeing the value.
# The only literals below are (a) the EREs an arm cannot exist without, and (b) the declared
# documentation constants, which are non-identifiers by declaration.
#
# FORMAT: one arm per line, NAME<TAB>ERE<TAB>MODE<TAB>NOTE. Blank lines and #-lines are ignored.
#
# MODE
#   refuse   a hit is a refusal. The consumer exits non-zero.
#   context  a hit is REPORTED and never refuses. Some context arms are also CONSULTED by a refuse
#            arm as its per-occurrence admit set or decision input; the NOTE says which, and in
#            WHICH CONSUMER MODE it is consulted.
#
# STRICT vs DELTA -- THE ONE PLACE THE CONSUMER MODE CHANGES AN ARM.
#   entry / subject (STRICT): the IPv4 arm runs with NO context exclusion of any kind. A lane must
#     not be able to spell an identifier by making the sentence around it sound like documentation,
#     and the cost of the strict reading falls on the writer, as one rewrite of their own post. Its
#     ONE exclusion here is the release_literal ADMIT SET (rule 5), which is read on the quad's own
#     characters -- a SHAPE, which no surrounding sentence can arrange, and so not a context rule.
#   tree (DELTA): the four IPv4 context rules below apply, and rule 6 (the position-map
#     function-literal rule, 2026-09-28) with them, so the pre-existing hits of a long shared
#     surface are CLASSIFIED in the report rather than dumped as an undifferentiated total. An
#     unclassified total is a number, never a finding.
#   Every other arm is identical in both modes.
#
# CONVERTED -- THE THIRD CONSUMER MODE (2026-09-22), AND THE ONLY OTHER PLACE A MODE MOVES AN ARM.
#   A CONVERTED GO TEST SOURCE is not a lane's prose. Its literals are Go's own test data, carried
#   across verbatim by the converter, and a lane can no more rewrite them than it can rewrite an
#   evidence record -- which is the argument that moved ipv4_doc into STRICT, applied to the other
#   half of the same class. MEASURED the day this was added, on two lanes' H10 re-bank shards: 13
#   refusals on one and 25 on the other, and every value was found verbatim in the same package's own
#   *_test.go under the pinned GOROOT (a dnsName «ipv4» in crypto/x509, NIST policy-test names, a
#   base64 position map matching the quad arm, and a loopback-name-and-port literal matching host_ctx).
#   In that mode, over files the consumer has FIRST ESTABLISHED are such a source, the arms marked
#   [CONVERTED-CONTEXT] in their NOTE are read as `context`: reported with their count, never
#   refusing. NOTHING ELSE MOVES -- the profile, home, share and run-time token arms refuse exactly as
#   in entry, because a real identifier BAKED INTO AN EMISSION is the one thing of this class that
#   reaches a converted file, and it is why the Go guard keeps its denied-token pass running over the
#   very fixtures whose structural pass it skips (fleetIsUpstreamFixture).
#   THE GATE OF RECORD for the tracked tree is still that Go guard. This mode is the PRE-POST reading
#   for a converted source, and it is STRICTER than the guard by construction: the guard skips the
#   whole structural pass for a *_test.cs, and this mode keeps every structural arm but the marked
#   two. A unc_ hit in a converted source is therefore either the escape the unc_escape admit already
#   recognises IN BOTH MODES, or it refuses and is read against the guard.
#
# CASE: every ERE here is written in LOWER CASE and is matched against a lower-cased copy of the
# input, so every arm is case-insensitive by construction. Spans are taken from the ORIGINAL text.
# (Lower-casing both sides, rather than passing a case-insensitivity flag, also sidesteps the GNU
# grep 3.0 dead combinations recorded in docs-records.md; this consumer uses awk, not grep, so that
# is belt-and-braces.)
#
# PORTABILITY: every ERE here is read by WHATEVER awk the box has, and an awk that does not implement
# a construct an arm is spelled with does not fail -- the arm matches nothing and the census reads
# CLEAN. Write only what gawk and mawk 1.3.4 were both MEASURED to implement: bracket expressions,
# the POSIX classes, grouping, alternation, ? + and *. NO INTERVAL EXPRESSION (a braced repeat count):
# mawk 1.3.4 20200120, the mawk an Ubuntu 20.04 image ships, reads the braces as literal text, and
# the ipv4 arm, spelled with one, was dead there until 2026-10-06. Write the repetition out. The
# consumer asks its awk a known-answer question over every refusing arm before it reads any text and
# REFUSES(2) on a wrong answer, so an arm that cannot fire on some awk is a refusal there and never
# a clean read -- but that probe is the net, and this rule is the floor.
#
# EXTRACTION: awk's match() has no capture groups, so the consumer derives each arm's DECISION TOKEN
# from the arm NAME prefix:
#   profile_* , home_*   the SEGMENT after the final path separator of the match
#   unc_*                the HOST -- the run after the leading doubled separator
#   host_*               the VALUE after the '=' or ':'
#   ipv4                 the quad, then its maximal surrounding token run
# An admit set is applied to the DECISION TOKEN, anchored whole (^...$), PER OCCURRENCE and NEVER
# PER LINE -- a line carrying a nickname host AND a real «host» is still refused.
#
# @RUNTIME@ marks an arm whose literals are read from the LOCAL BOX at run time and are never
# committed and never printed. The consumer expands these; this file carries no name.
#
# ------------------------------------------------------------------------------------------------
# PROFILE AND HOME PATHS (class 1) -- GO GUARD, fleetProfileRe, split into its two alternatives so
# the report can name which fired. Nothing else about them differs: the segment character class is
# that regex's, character for character.
# The admit set is profile_placeholder and NOTHING ELSE. The fleet nicknames are deliberately NOT
# admitted here -- the Go guard keeps its nickname set out of the profile arm for the same reason: a
# nickname names a HOST, so an account segment spelled with one is still an account segment.
profile_root	users[\\/]+[^\\/[:space:]"'`,;:)\]}>*|]+	refuse	[FIXTURE-CONTEXT] (COORD ruling 1, 2026-09-22: reported, never refusing, on an upstream fixture -- fleetProfileRe is in the Go gate's structural pass, which it skips there.) GO GUARD. Any profile root, either separator, either platform -- it is deliberately NOT anchored to a drive letter, so the Windows, MSYS and Darwin spellings are one arm. Admit set: profile_placeholder, on the segment.
home_unix	/home/[^\\/[:space:]"'`,;:)\]}>*|]+	refuse	[FIXTURE-CONTEXT] (COORD ruling 1, 2026-09-22: reported, never refusing, on an upstream fixture -- the /home/ half of fleetProfileRe, skipped there by the Go gate.) GO GUARD. The Linux home prefix. A lane that gains a Linux host inherits this exposure and re-controls the arm THERE; a Windows reading does not carry. Admit set: profile_placeholder.
# ------------------------------------------------------------------------------------------------
# UNC AND SHARE PATHS (class 2)
# The doubled separator must BEGIN a path token. The leading group is a hand-rolled lookbehind and
# it is POSITIVE rather than subtractive: subtracting only word characters still admitted the '%'-
# and ':'-preceded cases, so the rule is line start, whitespace, a quote, a backtick, or an opening
# delimiter. Without it every ESCAPED separator in prose, in a C#/Go literal, or in quoted `-json`
# output reads as a «unc» prefix. ERE has no lookaround and grep -P does not run on this fleet, so a
# negative lookahead here would match NOTHING and fail OPEN silently.
unc_backslash	(^|[[:space:]"'`(\[=,])[\\][\\][a-z][a-z0-9._-]+[\\]	refuse	[FIXTURE-CONTEXT] (COORD ruling 1, 2026-09-22: reported, never refusing, on an upstream fixture -- fleetNetworkRe, skipped there by the Go gate.) GO GUARD, fleetNetworkRe. The class is bracketed rather than written as a run of escapes, because a backslash run is exactly what collapses in transit. Admit set: nickname_host, on the host.
unc_slash	(^|[[:space:]"'`(\[=,])//[a-z][a-z0-9._-]+/[a-z0-9._$-]+	refuse	[FIXTURE-CONTEXT] (COORD ruling 1, 2026-09-22: reported, never refusing, on an upstream fixture. This arm has NO Go counterpart, so the gate refuses this shape nowhere; the mark stops the census being stricter than the gate on fixtures and widens nothing the gate enforces.) NO GO-GUARD COUNTERPART -- an addition of this definition, for the POSIX spelling of a share. The leading class is what keeps every scheme-relative URL out, since a scheme ends in ':'. Admit set: nickname_host, on the host.
# ------------------------------------------------------------------------------------------------
# HOSTNAMES (class 3) -- AND THE HONEST LIMIT OF THIS CLASS
# A bare <word>.<tld>-shaped «host» that is NOT a Go import path, a module path or a public URL
# CANNOT be told from one that is by any regular expression: an import path, the repository's own
# public URL and an internal box name are the same shape. Neither this definition nor the Go guard
# attempts a general hostname arm. What is covered is exactly three decidable shapes:
#   (a) the denied names themselves -- the hashed rows, matched against run-time literals below;
#   (b) an explicit assignment context -- the host_ctx arm, which the Go guard does not have;
#   (c) a host inside a doubled-separator path -- the unc_* arms above.
# WHAT IT MISSES, STATED: a real «host» written as bare prose, with no assignment context, no path
# around it, and a name neither the hash list nor this box can supply. Nothing here closes that, and
# a consumer must not claim it does.
host_ctx	(host|hostname|computername)[[:space:]]*[=:][a-z0-9][a-z0-9._-]*	refuse	[CONVERTED-CONTEXT] NO GO-GUARD COUNTERPART. Admit set: nickname_fleet, on the value, and a nickname-PREFIXED value is admitted too. NOTE THE TWO NARROWINGS, BOTH MEASURED on docs/phase4/MAILBOX.md and not guessed. (1) NO WHITESPACE after the separator: the draft arm allowed it and read 25 hits over 61k lines, and all nineteen distinct firings were an ORDINARY PROSE COLON -- "the host: a ...", "server = the ..." -- nine of them with a value of one to three characters. A guard whose steady state is dozens of false positives is a guard nobody leaves switched on. What survives is the ASSIGNMENT shape a pasted env dump or config line actually has. (2) `machine` and `server` DROPPED from the keyword list: `machine` fired on nothing at all and every one of `server`'s eight firings was prose. STATED RESIDUAL of narrowing (1): a spaced YAML-style `hostname: box` is no longer covered, and is covered only by the run-time literal arms and by the hashed rows.

# IPv4 (class 4) -- CONTEXT DECIDES, RANGE NEVER DOES, AND ONLY IN DELTA MODE
# This fleet lives on ONE private LAN, so a 10/8 or 192.168/16 quad is EXACTLY the identifier the
# order forbids when it is a real address. Exempting private ranges would blind the arm to the only
# addresses it will ever see, so there is no range exemption here at all.
# ipv4_arm_re below is C2's arm, reproduced: octet-validated, and it CAPTURES the identifier run in
# front of the quad so an assignment context can be told from a version context. ipv4_prefix_ex is
# C2's exemption, reproduced, read against that captured prefix.
# TWO MEASURED CHANGES to C2's arm, both stated as changes:
#   (i)  the CANDIDATE matcher is the bare octet-validated quad (ipv4), not ipv4_arm_re. C2's arm
#        requires a non-dot character after the quad, which makes it blind to a real «ipv4» at the
#        END OF A SENTENCE. The prefix capture is reconstructed per occurrence instead.
#   (ii) ipv4_prefix_ex is PREFIX-shaped and so cannot reach a «version-quad» that follows a plain
#        space -- C2 stated this gap itself. ipv4_vercontext closes it with a per-occurrence WINDOW.
# IN STRICT MODE (entry, subject) NONE of rules 1-4 runs: every candidate quad is a hit UNLESS the
# quad ITSELF is a Go release literal -- rule 5 below, the release_literal ADMIT SET, which is the
# one exclusion the strict reading takes. It is keyed on the quad's OWN characters and never on the
# sentence around it, so it is not the laundering surface a context exemption would be -- a lane
# cannot arrange a shape. What it costs is stated on that arm's own line.
# IN DELTA MODE (tree) the consumer decides each occurrence in this order:
#   1. PREFIX. Expand left over [a-z_]*=? and test ipv4_prefix_ex. Excluded if it fires.
#   2. TOKEN RUN. Expand to the maximal [a-z0-9._-] run around the quad and trim one trailing '.'
#      (a sentence period). If the run is not EXACTLY the quad, EXCLUDED. This is what disposes of a
#      «version-quad» carrying a package prefix, a 'v' prefix, a trailing extension, or five parts.
#   3. DOC CONSTANT. If the quad matches ipv4_doc, EXCLUDED and counted under that arm.
#   4. VERSION CONTEXT. If the 56 characters before or the 32 after the occurrence match
#      ipv4_vercontext, EXCLUDED. Per OCCURRENCE, never per line: a line carrying a «version-quad»
#      AND a real «ipv4» still refuses.
#   5. RELEASE LITERAL. If the quad matches release_literal, EXCLUDED and counted as release-literal.
#      Consulted in BOTH modes, and LAST in delta mode so every occurrence an existing rule already
#      disposes of keeps ITS reason in the EXCLUSIONS block -- a new rule must not silently
#      re-attribute what the older ones were measured on.
#   6. POSITION-MAP FUNCTION LITERAL. If the line is a GoPositionMap record (ipv4_posmap), the quad
#      lies inside the record's FOURTH string argument (its funcLits list), and the quad is EXACTLY
#      the suffix of one well-formed entry -- immediately preceded by <digits>-<digits>: that opens
#      the argument or follows a ';', and immediately followed by a ';' or the closing quote --
#      EXCLUDED and counted as position-map-funclit. DELTA MODE ONLY: it reads the record around the
#      quad, so it is a context rule, and a lane can write its sentence as a record. Consulted after
#      rule 5 for rule 5's reason.
#   7. Otherwise a HIT.
# STATED RESIDUALS OF DELTA MODE: a quad immediately preceded by a dot is excluded by rule 2, and a
# real address written within 56/32 characters of a version marker is excluded by rule 4, and a real
# address spelled as the suffix of a funcLits entry inside a well-formed GoPositionMap record is
# excluded by rule 6. None of them is closed here. What covers them is that delta mode refuses on
# what a post ADDS, never on what the surface already holds, and that the post that would add one
# is censused in STRICT mode first.
# RULE 5 IS THE ONE STRICT MODE DOES NOT BACKSTOP, because rule 5 runs in strict mode too: a real
# address spelled in exactly that shape clears both gates. That residual is taken knowingly, it is
# bounded to the one shape, and it is the whole of what this widening costs.
ipv4	(25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9])\.(25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9])\.(25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9])\.(25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9])	refuse	[CONVERTED-CONTEXT] NO GO-GUARD COUNTERPART. The candidate matcher: a dotted quad, octets 0-255. In STRICT mode the only exclusion is rule 5, the release_literal admit; in DELTA mode rules 1-5 decide, and anything they leave is a hit. In CONVERTED mode the arm still runs and still counts, and its surviving occurrences are REPORTED rather than refused: a quad in a converted Go test source is Go's own test data, and the 24 of one lane's 25 measured refusals that were this arm were every one of them found verbatim in the package's own *_test.go. RESPELLED 2026-10-06, and the language is unchanged: the interval-repeated group is written out as three explicit octet groups, as ipv4_arm_re was on 2026-09-15. MEASURED: mawk 1.3.4 20200120 -- the mawk an Ubuntu 20.04 image ships -- reads a braced interval as LITERAL TEXT, so the braced spelling matched no quad there, the arm printed occ=0 exactly as it does on a text that carries none, and every address read CLEAN. Every self-test case that needs this arm to fire was red on that awk and green on gawk, and this one respelling is the whole difference. See PORTABILITY in the header.
ipv4_arm_re	(^|[^0-9.a-z_])[a-z_]*=?(25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9])\.(25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9])\.(25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9])\.(25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9])([^0-9.]|$)	context	C2's arm, carried verbatim so the fleet has ONE copy of it and no tool re-derives it. Reported for comparison, and NOT the candidate matcher -- see change (i) above. RESPELLED 2026-09-15 22:15 for mawk 1.3.4 (C1 4aa7745fa): the interval-repeated group before the trailing alternation is expanded into three explicit octet groups and 1[0-9]{2} into 1[0-9][0-9]; semantics identical to the C2 arm as posted.
ipv4_prefix_ex	^([^0-9a-z_]?([v][0-9]|version=[0-9])|-[0-9])	context	[CONSULTED-ONLY] C2's exemption, carried verbatim. CONSULTED by ipv4 as rule 1, IN DELTA MODE ONLY, read against the reconstructed prefix-plus-quad.
ipv4_doc	(127\.0\.0\.1|0\.0\.0\.0|255\.255\.255\.255)	context	[CONSULTED-ONLY] CONSULTED by ipv4 as rule 3, IN BOTH MODES since 2026-09-20 (COORD fc4edcd8c) -- it is a SHAPE admit read anchored whole on the quad's own characters, so it cannot be arranged by the sentence a lane writes, which is rule 5's own test for what STRICT may admit; an evidence record is not the lane's prose and cannot be rewritten to satisfy a context rule. Loopback, unspecified, broadcast: documentation constants by declaration, not addresses. In STRICT mode they are hits like any other quad. Reported so a zero is still looking.
ipv4_vercontext	(version|assembly|nuget|exception|validation|sdk|dotnet|package|framework|release|toolchain)	context	[CONSULTED-ONLY] CONSULTED by ipv4 as rule 4, IN DELTA MODE ONLY, AND BY ADJACENCY -- NOT BY A WINDOW. The first draft scanned 56 characters before and 32 after, and C2's A/B showed what that buys: a routable-shaped quad ALONE is refused, and THE SAME QUAD with any version word loose in the window reads CLEAN. A window is a laundering surface -- it lets a sentence exonerate an address that has nothing to do with it. Rule 4 now fires only when the quad's OWN whitespace-delimited word carries a context word (Version=<quad>), or the IMMEDIATELY preceding or IMMEDIATELY following whitespace-separated word is one. A context word two or more words away no longer excludes anything. MEASURED CONSEQUENCE, stated: two genuine version quads on the live mailbox surface -- one in exception prose whose nearest context word is three words back, one in a census table whose neighbours are a backtick and a count -- flip from excluded to HIT. That is the intended direction of the trade: a false refusal costs its writer one rewrite, a false pass costs a scrub. MEASURED on the live mailbox surface: rule 4 excluded 5 occurrences under the window and excludes 3 under adjacency. WHICH of the eleven markers did the excluding is NOT instrumented -- the EXCLUSIONS block counts by REASON, not by marker -- so no claim is made here about which markers are live, and none should be made from this file. release and toolchain were added with this narrowing and have never been measured at all. NOTE that "documentation" is deliberately NOT a marker: an «ipv4» used as a byte-layout example is handled by the delta, never by an exemption.
ipv4_posmap	^[[:space:]]*\[assembly: (global::)?go\.gopositionmap\(	context	[CONSULTED-ONLY] CONSULTED by ipv4 as rule 6, IN DELTA MODE ONLY (2026-09-28). The RECOGNISER for a GoPositionMap record line -- the attribute prefix, anchored at the line's start, in the two spellings the converter emits (positionMapOperations.go: go.GoPositionMap, and global::go.GoPositionMap when the root namespace is shadowed; MEASURED at 15da8805b2, both occur under src/ and no other spelling does). The recogniser alone admits nothing: the consumer then parses the argument list as exactly four C# string literals joined by ", " and closed by ")]", and excludes a quad ONLY when it lies inside the FOURTH argument (the funcLits list) and is EXACTLY the closure-counter suffix of one well-formed "<startLine>-<endLine>:<suffix>" entry -- preceded by the entry's own <digits>-<digits>: prefix, which opens the argument or follows a ';', and followed by a ';' or the closing quote. Per OCCURRENCE, never per line: a quad in the Go file identity, the C# file name, the encoded table, after the ")]", or anywhere in the fourth argument that is not such a suffix still refuses. MEASURED NEED: Go names a closure nested four deep with four dotted counters, so the aead.go record in crypto/internal/cryptotest's package_info.cs read four ipv4 hits, every one a converter-generated closure counter and none an address. WHY DELTA ONLY: the rule reads the record AROUND the quad, so it is a context rule by rule 5's own test -- a lane can write its sentence as a record -- and STRICT refuses context rules. STATED RESIDUAL: a real address spelled as such a suffix inside such a record clears delta mode, backstopped as rules 1, 2 and 4 are, by the post being censused in STRICT first. NOT A RESIDUAL, and measured rather than assumed: a suffix nested FIVE or more deep is not this rule's (its leading four components are followed by a '.'), and rule 2 has already excluded it, the token run being the whole suffix -- the four such entries at the same tip (three in crypto/tls's package_info.cs, one in runtime's package_test_info.cs) read token-run in delta, and the twenty four-deep ones read position-map-funclit.

# ACCOUNT, OWNER AND MACHINE NAMES (class 5) -- RUN-TIME ONLY, NEVER COMMITTED, NEVER PRINTED
# This file must not carry what it forbids. The AUTHORITY on which names are denied is the hashed
# list in coord-identifier-hashes.txt, generated from the Go guard. The PLAINTEXT comes from the
# local box at run time; a derived literal whose hash is in that list is reported as DENIED, one
# that is not is reported as LOCAL and is still an arm. Candidates are tokenised exactly as the Go
# guard tokenises them -- maximal [a-z0-9._-] runs, plus each dot/hyphen/underscore component -- so
# a machine name and the account name inside it both match, and the two instruments cannot disagree.
# Everything printed about these arms is the ARM and the COUNT. Never a value, never a fragment.
TOKENFILE	@RUNTIME@	refuse	The never-push token file. Located, in order: $IDC_TOKEN_FILE; then coord-identifier-tokens.local beside the consumer; then $HOME/.claude/coord-identifier-tokens. One literal per line, #-comments and blanks skipped. Its CONTENTS are never printed and never committed; the consumer reports only present/absent, the literal COUNT, and how many matched a hashed row.
RUNTIME_ACCOUNT	@RUNTIME@	refuse	The «account» name, derived: basename "$HOME", then $USERNAME, then $USER. A derivation under 4 characters is ABORTED and NAMED as skipped, rather than installed as a two-character detector. [PUBLIC-HANDLE-ADMIT] CONSULTS THE ADMIT SECTION of coord-identifier-hashes.txt, ruled 2026-09-22: when this literal matches INSIDE a longer word, the ENCLOSING WORD -- the maximal [A-Za-z0-9_.-] run around the match, lowercased, with percent-escapes read as separators -- is looked up WHOLE in the admitted-handle set, and an admitted word is reported as `public-handle` in the EXCLUSIONS block instead of counted as a hit. EVERY occurrence on the line must be inside an admitted word or the line still refuses -- WITH ONE STATED RESIDUAL (2026-10-06): the walk reads WORDS, so an occurrence that is inside NO word is not met by it. The literal in a BROKEN spelling -- its letters spaced out, a hyphen or a zero-width space inside it, or hyphen-wrapped across one line break -- reads CLEAN when an admitted handle that contains it stands on the same line (for a spelling broken across a line break: on either of its two lines), whether the handle is bare, in its dotted module-path spelling or inside the public_url span; without the handle, or with the handle on a line the broken spelling does not touch, each of these refuses, and a word wrapped without a hyphen refuses beside the handle too. This is the same on every box, the one that holds the literal and the one that derives nothing, and it is older than TEXT_DENIED. It is pinned by self-test cases that assert the CLEAN reading and is QUEUED for a design of its own: a first cut, an admit that counted occurrences, was made and taken back on 2026-10-06 because it refused the handle standing first on a line after a line that ends in a word character, and read the handle glued to the public_url span differently on the two kinds of box. MEASURED NEED: the account derivation is a SUBSTRING of the owner's published organisation handle, so the reduced pass read TEN hits on docs/README.md at master -- five registry-search URLs, each also read on its joined pair -- every one of them the published handle and none of them infrastructure. WHAT IS NOT ADMITTED, and none of it moved: a BARE derivation standing alone as a word, the same word inside a profile path (profile_root and home_unix are different arms and are never consulted by this admit), and any word that merely CONTAINS an admitted handle, the lookup being an exact whole-word hash.
RUNTIME_MACHINE	@RUNTIME@	refuse	The machine name, derived: $COMPUTERNAME, then hostname. Same 4-character floor. This is the (a) half of the hostname class above, together with the hashed rows.
RUNTIME_OWNERNAME	@RUNTIME@	refuse	The owner's given name and surname in ORDINARY PROSE, derived from `git config --get user.name` split on non-alphabetics, pieces of 3+ characters kept. This is the class that gets missed: six of seven scrub hits on 2026-09-08 were the given name used as a form of address, and one lane's eleven path-and-host arms had no arm for it and passed hundreds of posts by luck. # THE ONE TOKEN ARM THAT NEEDS NOTHING FROM THE BOX (2026-10-06). The four arms above are only as
# wide as what the local box can derive: on a box whose account is a generic one they are all inert,
# and a post naming the owner read CLEAN there while the same bytes REFUSED on a box whose account is
# a denied row. TEXT_DENIED closes that from the other side -- the plaintext comes from the TEXT.
TEXT_DENIED	@RUNTIME@	refuse	A word OF THE TEXT whose (length, SHA-256) pair is a DENIED row of coord-identifier-hashes.txt. STRICT MODES ONLY (entry, subject, converted); in delta it is NOT RUN and the consumer says so on its own line. TWO ROUTES FIND IT. THE WINDOW SCAN: the consumer's census awk writes the buffers its own token passes read -- the lowercased line, and each adjacent line pair joined with the whitespace at the break removed (a CR at the break is whitespace), each WITH THE public_url SPAN BLANKED -- and ONE scanner process (python, python3 or perl with Digest::SHA; a known-answer probe on every census) hashes EVERY WINDOW of every denied row's length over each maximal [a-z0-9._-] run of a buffer and over its alphanumerics-only reduction, so a denied word is found standing alone, GLUED inside a longer word, or BROKEN by characters that are not its own, wherever PASS 1, 2 or 3 would hit it as an installed literal. THE CANDIDATES: the token arms' own -- maximal [a-z0-9._-] runs plus each dot/hyphen/underscore component, lowercased, over each line and each joined pair -- plus each SPAN of adjacent components with its separators kept; only a candidate whose LENGTH is some row's length is hashed, all of them by ONE process with a known-answer probe. A matched word becomes a literal of this arm for that one census, once, and is then read by the same three passes as any run-time literal. WHAT IS STILL NOT FOUND, EXACTLY: (1) a denied word that ITSELF CONTAINS a dot, a hyphen or an underscore, spelled any way but its exact bytes -- its separator dropped or re-spelled, or the word broken by a foreign character -- because only a row's exact bytes are hashed; it IS found whole, glued inside a longer run, and wrapped across one line break, and a box that DERIVES that word still refuses the other spellings, so on that text the verdict still depends on the box; (2) a word wrapped across THREE OR MORE LINES, which no pass joins and so no box finds; (3) a word spelled with a byte that is a letter only to one locale -- the consumer runs every program in the C locale, so a word broken by a double-byte character whose trail byte is an ASCII letter or digit (Shift-JIS, GBK, Big5; never UTF-8) and a word spelled with a capital letter outside ASCII are found by no box, where before 2026-10-06 each depended on the box's awk and locale; (4) a BROKEN spelling of a denied word -- letters spaced out, a hyphen or a zero-width space inside it, or hyphen-wrapped across one line break -- beside an admitted handle that contains the word, on the same line or, for a spelling broken across a line break, on either of its two lines, which reads CLEAN on every box: the residual stated on RUNTIME_ACCOUNT's line, older than this arm and queued for a design of its own. [PUBLIC-HANDLE-ADMIT] CONSULTS THE ADMIT SECTION exactly as RUNTIME_ACCOUNT does: an occurrence INSIDE a longer word takes that word whole, and a word that is an ADMIT row is reported as public-handle and not counted; a bare denied word is never admitted. For that the words of the text whose (length, hash) is an ADMIT row join the admit set for the census, so the rule holds on a box that cannot derive the handle -- and a handle that CONTAINS a denied word, which the scan discovers wherever it is written outside the public_url span, is cleared there exactly as on the owner's box. FAILS CLOSED, and there is NO narrowed mode: no usable hasher, no usable window scanner, an awk that read none of a text that is not empty, a scanner that did not account for every buffer or named a word the list does not confirm, a hash list that is missing or does not parse, or zero denied rows is REFUSED(2). It counts INDEPENDENTLY of the run-time arms: where a box already holds the same literal, one occurrence is a hit under both. The candidate comparison is the Go guard's own (fleetLineHasDeniedToken), run before the post instead of after the commit; THE SPAN WALK AND THE WINDOW SCAN ARE ADDITIONS the Go guard does not have.
