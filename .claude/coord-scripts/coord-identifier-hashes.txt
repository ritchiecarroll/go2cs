# since 2026-09-22, fleetPublicHandles). That Go file is the tracked-tree gate, run by
# TestNoFleetIdentifiersInTrackedFiles under the plain `go test ./...` every lane already runs. This
# file is the same two lists in a form a shell census can read, so the two instruments cannot
# disagree about WHICH names are denied or WHICH handles are admitted. When a row is added there, it
# is added here in the same commit, or the shell census is measuring an older order.

# ⚠ AND THAT IS NOW ENFORCED RATHER THAN REMEMBERED. TestFleetIdentifierHashFileMatchesTheGoLists in
# the same Go file reads THIS file and requires equality in BOTH directions, per section: a row here
# with no partner in the Go list is a failure naming this file, and a row there with no partner here
# is a failure naming the shell census. Until 2026-09-22 the only thing keeping the two in step was
# whoever remembered to edit both, which is precisely the silent-drift shape the guard exists for.
#
# FORMAT, DENIED ROWS:    LEN<TAB>SHA256-OF-THE-LOWERCASED-TOKEN<TAB>WHAT
# FORMAT, ADMITTED ROWS:  ADMIT<TAB>LEN<TAB>SHA256-OF-THE-LOWERCASED-HANDLE<TAB>WHAT
#
# The leading ADMIT keyword is what separates the sections, rather than a position in the file or a
# comment banner: a section marked by its ORDER is a section a sorted edit can silently move a row
# out of, and both readers (the shell census and the Go parity arm) dispatch on the first field.
#
# Len is carried WITH the hash in one record, exactly as the Go file insists, because a length kept
# in a second list can silently disagree with its hash and disarm the entry while every test passes.
# One line, one entry, no way to add half of it.
#
# Adding one spells nothing:   echo -n "<token>" | tr A-Z a-z | sha256sum
#
# HOW THE SHELL CENSUS USES IT, AND THE LIMIT OF THAT USE.
# TWO WAYS, since 2026-10-06. (1) In its STRICT modes (entry, subject, converted) the TEXT_DENIED arm
# does what the Go guard does: it hashes the candidate words of the text being censused -- only those
# whose length is some row's length below, all in ONE process -- and a (length, hash) pair equal to a
# denied row refuses. It also does what the Go guard does not: one scanner process hashes EVERY
# WINDOW of every row's length below over the buffers the census passes read, so a denied word glued
# inside a longer word, or broken by characters that are not its own, is found too. ONLY THE EXACT
# BYTES OF A ROW ARE HASHED, so a row whose word itself contains a dot, a hyphen or an underscore is
# found whole, glued or wrapped across one line break and NOT with its separator dropped or
# re-spelled; closing that needs a second digest per such row, of its alphanumerics-only reduction,
# and that row would be added to the Go list first. That arm needs nothing from the box, and it
# REFUSES TO RUN (rc 2) if this file is missing, has a row that does not parse (a LEN written with a
# leading zero is such a row), or yields zero denied rows. (2) The run-time arms, which
# are older and are still the only token arms in `tree` mode, invert the comparison, because hashing
# every token of a long shared surface through a subprocess is not an instrument, it is an outage.
# So THOSE arms invert the comparison. At startup the census derives a handful of candidate literals
# from the LOCAL BOX -- the never-push token file, basename "$HOME", $COMPUTERNAME, the pieces of
# `git config --get user.name` -- hashes THOSE (a handful of sha256sum calls), and reports which of
# the rows below the box could supply plaintext for. A matched literal becomes a live arm.
#
# WHAT THAT MISSES, STATED: a row below whose plaintext this box cannot derive is NOT one of the
# RUN-TIME arms on this box -- TEXT_DENIED is what covers it before a post, in the strict modes. In
# `tree` mode nothing does. The Go guard still catches it over the tracked tree at `go test`, and an
# operator who needs it live in the pre-post gate puts the plaintext in the local never-push token
# file. The census PRINTS `hashes=N matched=M unmatched=N-M` on every run, so the gap is a number on
# the record and never an assumption.
#

# SEMANTICS, and they are the narrowest that can close the measured problem. A denied token that
# matches INSIDE a longer word takes its ENCLOSING WORD -- the maximal [A-Za-z0-9_.-] run around the
