# go2cs diagnostic codes

go2cs reports problems with a `GO2CS` code from three sides. The converter (`go2cs`) prints its codes on stderr
while it converts Go to C#. The source generators and analyzer in `go2cs-gen` report theirs in the C# build of a
converted project, beside the compiler's own `CS` codes, and so do go2cs's MSBuild targets. Every code any side
can report is listed below.

The number says which side reported it:

- **`GO2CS0xxx`**: `go2cs-gen`, in the C# build.
- **`GO2CS1xxx`**: the converter, for a Go package that did not load cleanly.
- **`GO2CS2xxx`**: the converter, for a Go input it refuses to convert or a file it cannot finish.

- **`GO2CS3xxx`**: go2cs's MSBuild targets (`go.lib.targets`), in the C# build.

The converter prints each of its codes on stderr in MSBuild's canonical error format; the
[command-line options](CommandLine.md#diagnostics) page shows the line format. A `go2cs-gen` or build code
appears in the build output like any compiler diagnostic, and a warning can be suppressed the usual way
(`NoWarn`).

|:--|:--|:--|:--|:--|
| `GO2CS0001` | go2cs-gen | Warning | A package class stem contains the lifted-name marker `ᴛ`, so a forwarder class the generator mints for a struct (`<pkg>ᴛ<Struct>ᴛpkg` or `<pkg>ᴛ<Struct>ᴛxpkg`) may collide with another struct's (`CS0101`). No Go package in the standard library has such a stem. | Report it as a go2cs issue, with the package path the message names. A `CS0101` on a generated `…ᴛpkg` or `…ᴛxpkg` class is this collision. |
| `GO2CS0002` | go2cs-gen | Warning | A go2cs-gen record (an assembly or type attribute the converter emits) could not be read, so it was skipped and nothing was generated for it. The omission can only fail later and loudly, at the use site, or nothing was owed. | Re-convert the package. A record the converter emitted that the generator cannot read is a go2cs issue; a record edited by hand is fixed or removed. |
| `GO2CS0003` | go2cs-gen | Error | A go2cs-gen record cannot be generated: for example a Go comment no record can carry, a record whose key would match two methods of one type, or a module initializer that would need a generated no-inlining declaring part. The build stays red at the record, so it cannot go green with members missing at run time. | Read the message, which names the record and the reason. In converter output this is a go2cs issue; in a hand-written file, change the record it names. |
| `GO2CS0004` | go2cs-gen | Error | A C# string literal in converted code binds a type Go's string is not: an `object` or interface parameter, a type parameter inferred as `System.String`, or a `System.String` overload chosen over the Go one. The program would see a C# string where Go has a Go string. | In converter output, report it as a go2cs issue. In hand-written code inside a converted package, pass a Go string (`(@string)"text"`). A golib parameter that is meant to take a C# string is marked `[GoTakesCSharpString]`. |
| `GO2CS0005` | go2cs-gen | Error | A C# string literal in converted code reaches an `any` (object) slot of a call that go2cs-gen cannot intercept, so the callee would see `System.String` where Go has a Go string. The message names the reason: a delegate (a Go func value), a generic method or a method of a generic type, a method generated code cannot call, a by-reference return, or a literal holding a lone UTF-16 surrogate. | In converter output, report it as a go2cs issue: the converter passes a bare literal to an `any` slot only where the call can be intercepted. | `GO2CS0006` | go2cs-gen | Error | A C# string literal in converted code binds a member that does not take it as `any`, while another member of the same method group does: an overload beside the converted callee (often one taking `go.@string`, which C# prefers to `object`) has captured a call that Go makes to one function. | Remove or rename the overload the message names, or pass a Go string explicitly if that overload is the one meant. In converter output with no hand-written overload, report it as a go2cs issue. |
| `GO2CS0007` | go2cs-gen | Error | A call to golib's stack-append overload, `append(in stackAppend<T>, ...)`, does not pass the buffer as a plain local of the calling method or lambda that no lambda captures (it passes a field, a new value, a captured or foreach local, or a local of another frame). The converter never emits another shape; hand-written code that calls the overload declares its own local the same way. |
| `GO2CS0008` | go2cs-gen | Error | A `GoImplicitConv` record's operator would return a box from a value: `<T, ж<T>>`, `<T, ж<U>>`, or `<ж<T>, T>(Inverted = true)`. Go never converts a value to a pointer implicitly, so the record means the converter placed a value where Go passes a pointer. No operator is generated: such an operator would box a copy of the value, so a write through the box would never reach the original. The build fails at the record, and the site that needed the conversion fails to compile. | In converter output, report it as a go2cs issue, naming the record and the failing site: the converter must pass the pointer's box there. In hand-written code, pass the box (`Ꮡx`) instead of the value. |
| `GO2CS0009` | go2cs-gen | Error | A `[GoLazy]` holder class, which holds a Go package var built on its first read, does not hold exactly one static field named for the holder: `lazyᴛX` must hold the static field `X`, or for a var whose address is taken its box `ᏑX` (never marked `Initial`), and nothing else. The generator writes the var's `ref` accessor (or the box's) from that field, so it generates nothing for this holder, and a use of the var fails to compile while an unused var would be lost silently. | In converter output, report it as a go2cs issue, naming the holder. In hand-written code, declare the holder as `[GoLazy] partial class lazyᴛX { … static T X = …; }` with no other member. |
| `GO2CS0010` | go2cs-gen | Error | A `[GoBoundedGoroutine]` record, which marks a `go` statement whose goroutine the converter proved cannot recurse so that it starts on the bounded stack reservation, does not land on a call of an unmarked `goǃ` rung: it names no file of the compilation, or one present twice, or its line and column hold no `goǃ` call, or the call binds another method or a `GoStack`-marked rung. A stale record could otherwise start an unproved goroutine on the small reservation, whose overflow ends the process. | Re-convert the package, so that its `package_info.cs` records match its converted source. A record edited by hand is fixed or removed; a `go` statement without a record keeps the default reservation. |
| `GO2CS0011` | go2cs-gen | Warning | The assembly was converted with a converter refusal downgraded by `-warn` (today only `GO2CS2002`): its `package_info.cs` carries a `[GoRefusalDowngraded(code, site, text)]` record per refused site, and the site panics with the refusal text when it is reached. Reported in every build, so a project nobody converts again still shows it carries a known-broken path. | Expected for a package converted with `-warn`. To clear it, reshape the code so the refusal no longer applies and convert without `-warn`. |
| `GO2CS0012` | go2cs-gen | Error | A type declares more methods than the .NET runtime loads on it: 65,521 for a static class, a struct or a class that derives from `object`, counting static and instance methods, constructors, accessors and operators, fewer for a class whose base types add virtual methods, and never more than 65,524 on any type, an interface included. The message gives the type's count and its limit. The C# compiler has no such limit, so without this error the program would build and then throw `TypeLoadException` at the first use of the type. A package class holds every function and method of its Go package. The methods a struct promotes from an embedded field are not among them: each struct's are in a class of its own (`<pkg>ᴛ<Struct>ᴛpkg`). | A Go package with that many functions and methods of its own cannot be one package class: split the Go package. In converter output for a smaller package, report it as a go2cs issue, naming the type and the count in the message. In hand-written code, split the type. |
| `GO2CS0013` | go2cs-gen | Error | Inside a method-holder class (a class marked `[GoMethodHost]`, which holds the methods one Go type declares, beside the package class), a name binds another member than the package's. Either a simple name that the package class declares binds a method of the holder, a member of `go.builtin` or a type of a namespace; or a name written through the file's alias of its own package (`time.X`) binds a local or a parameter named like the alias, whose type has a member `X` as the package does. A Go method body reads its package's names directly. In the holder they arrive through `using static`, which C# reads after the holder's own members and after the types of the namespace, and merges with `go.builtin`, so such a name can compile and read a member Go does not mean. | In converter output, report it as a go2cs issue, with the message. In hand-written code, write the package's member through the package class (`time_package.X`) or the file's alias of it (`time.X`), and the other member through its own qualifier: `builtin.X`, the namespace, or the receiver for a method. A file whose methods select, through a local named like the package, a name the package also declares takes no alias of the package. |
| `GO2CS0014` | go2cs-gen | Warning | M:N, experimental (`GoTwins`): reported only in a build with twins on ([Known issues](KnownIssues.md#goroutines-on-a-shared-pool-of-threads-mn-are-experimental-and-off-unless-you-build-and-run-for-them)). A function that calls through a func value would be twinned so that its call can await a twin, but the generator refuses it one (a by-ref or ref-like parameter, `unsafe`, an iterator, and so on). It keeps calling the plain delegate, so a func value that can park blocks its carrier there. The message names the function and its refusal. Reported once per function, not per call. | Nothing to fix in converted code: the program is correct and runs the call plain, holding a carrier while it parks. Where the carrier matters, report it, naming the function and the refusal. |
| `GO2CS0015` | go2cs-gen | Warning | M:N, experimental (`GoTwins`): reported only in a build with twins on ([Known issues](KnownIssues.md#goroutines-on-a-shared-pool-of-threads-mn-are-experimental-and-off-unless-you-build-and-run-for-them)). A `go` statement the generator does not launch as a twin, where its goroutine could park, keeps its plain launch on a thread. The message names the function and the reason. Reported once per `go` statement. | The program is correct; the goroutine blocks a thread when it parks. To make it an error, add `GO2CS0015` to `WarningsAsErrors` or set its severity in `.editorconfig`. Where the thread matters, report it, naming the reason. |
| `GO2CS0016` | go2cs-gen | Error | A `GoFrame`, the defer list of a converted function, is copied, stored or captured. It is a plain struct, so the compiler does not refuse it, and a copied frame runs its deferred calls twice or loses them. A frame may only be a local initialised to `default`, a `ref` parameter or `ref` argument, or the receiver of its own members; the message names the site and what it does (a by-value, `in` or `out` parameter, a return, a field or property, an array element, a generic argument, a copy, an assignment, boxing, a ref local, a capture by a lambda or local function, or a `global using` alias). Reported from the source generator, so it also runs where `RunAnalyzers` is false, and not configurable: no severity setting, `NoWarn` or pragma turns it off. The generator does not see the other generators' output, so a use in an allowed position whose call binds only with that output is bound again by the analyzer `GoFrameRuleAnalyzer`, which reports it with the same code; with `RunAnalyzers` false that net is off and the rest of the rule stays. Not checked: code another generator writes, and F# or Visual Basic, where the rule holds by contract alone. | In converter output, report it as a go2cs issue, with the message. In hand-written code, keep the frame a local of the function it belongs to and pass it on only by `ref`. |
| `GO2CS0017` | go2cs-gen | Error | M:N, experimental (`GoTwins`): reported only in a build with twins on ([Known issues](KnownIssues.md#goroutines-on-a-shared-pool-of-threads-mn-are-experimental-and-off-unless-you-build-and-run-for-them)). In a package built with twins, every public method of its converted code gets a twin: a state machine where it can park, or a forwarder (`[GoParkForwarder]`) that calls the plain method and returns a completed task. A generic method, or a method of a generic type, is excluded (E1). A public method that gets neither and is not excluded would ship without a twin. Adding one later changes the package's surface, so the build stops. The message names the method and the reason it has no forwarder. | In converter output, report it as a go2cs issue, with the message. The rule is `docs/phase4/DESIGN-mn-twin-set.md`, sections 8 and 12. |
| `GO2CS0018` | go2cs-gen | Error | M:N, experimental (`GoTwins`): reported only in a build with twins on ([Known issues](KnownIssues.md#goroutines-on-a-shared-pool-of-threads-mn-are-experimental-and-off-unless-you-build-and-run-for-them)). A package built with twins carries the whole twin set, built one way, so a build property that changes what the twin generator writes is refused in such a build: one that selects part of the set (`GoTwinsIface`, `GoTwinsIfaceAll`, `GoTwinsIfaceUnmark`, `GoTwinsGo`, `GoTwinsPairs`, `GoTwinsCallerRule`, a `twin-refuse.txt` file), or a measurement arm's control (`GoTwinsForwarders`, `GoTwinsGuardWarn`, `GoTwinsGuardDrop` and the five `GoTwinsBox*` switches, two of which, `GoTwinsBoxCopy` and `GoTwinsBoxArgCopy`, are wrong on purpose). The message names the property and the fix. `GoTwinsSiblings` and `GoTwinsTiming` change nothing generated and are not refused. A package built with twins and none of the refused properties gets every public method's twin and the hidden twin interface for every interface member. | Remove the property. A measurement build that does not ship sets `GoTwinsArm=true`, which admits all of them. |
| `GO2CS0020` | go2cs-gen | Warning | M:N, experimental (`GoTwins`): reported only in a build with twins on ([Known issues](KnownIssues.md#goroutines-on-a-shared-pool-of-threads-mn-are-experimental-and-off-unless-you-build-and-run-for-them)). In a package built with twins, a call through a func value whose shape the twin generator cannot test for a pair (a call's result, a conditional access, a parenthesized or converted value, a signature with no twin delegate type; any other shape is named by its syntax kind) calls the plain delegate, so a stored function that parks holds its carrier there. A call through a local, a parameter, a field or an element IS tested. Not reported for a function GO2CS0014 already names, nor with `GoTwinsPairs=false`. A table built in PLAIN code (a package-level `var tests = []struct{...}`) holds plain delegates, so its calls always run plain, with no warning: only a func value created inside a twin is a pair. The message names the function, the first such shape and how many calls there are. Reported once per function. | The program is correct. Where the carrier matters, move the func value into a local before the call, or report it, naming the shape. To make it an error, add `GO2CS0020` to `WarningsAsErrors` or set its severity in `.editorconfig`. |
| `GO2CS0021` | go2cs-gen | Error | M:N, experimental (`GoTwins`): reported only in a build with twins on ([Known issues](KnownIssues.md#goroutines-on-a-shared-pool-of-threads-mn-are-experimental-and-off-unless-you-build-and-run-for-them)). A twin is written into its type reopened as `partial`, so a method that can park, in a type (or an enclosing type) that is not declared `partial`, gets no twin. Every twin that calls it then holds its carrier for the length of the call. The message names the method and the type. Converted code declares every type `partial`, so this names hand-written code. | Declare the named type `partial`. The census behind it is `docs/phase4/DATA-mn-row7-hosts.md`. |
| `GO2CS1000` | converter | Error | The package did not load cleanly: an error `go/packages` does not classify. The package still converts best-effort. | Fix the error the message names, so that `go build` succeeds for the package, then convert again. |
| `GO2CS1001` | converter | Error | The package did not load cleanly: a `go list` error, such as a missing module or no Go files for this build. | Fix the module or build setup the message names (`go.mod`, `GOOS`/`GOARCH`, build tags) so that `go list` succeeds. |
| `GO2CS1002` | converter | Error | The package did not load cleanly: a Go parse error. The package still converts best-effort. | Fix the Go syntax error at the position given. |
| `GO2CS1003` | converter | Error | The package did not fully type-check. It still converts best-effort, but code that depends on the failing expression is emitted untyped and will not compile. | Fix the type error at the position given, so that `go build` succeeds for the package, then convert again. |
| `GO2CS2001` | converter | Error | Refused: a cgo source (`import "C"`) is selected for this build without `-cgo`. Or, under `-cgo`, the package uses C in a way go2cs does not bind, or the C toolchain does not fit the target platform: the C compiler `go env CC` names targets another platform or does not answer `-dumpmachine`, the cgo flags set a sysroot or a target flag, or, when converting for another platform, the package has C++ sources (go2cs takes a C compiler only). Each such use is named on a line of its own with its reason. A single-package conversion exits non-zero and writes nothing. Under `-recurse`, the refused package is skipped and named, with each converted package that imports it; the rest of the module converts, and the run exits non-zero. | Convert with `CGO_ENABLED=0`, or exclude the file from the build. For a package whose C is calls of shared-library functions, convert it with `-cgo` ([Limitations](Limitations.md#cgo)). |
| `GO2CS2002` | converter | Error | Refused: a generic instantiation over a pointer element (`Walk[*Node]` under `N Tree[N]`) needs a C# constraint proxy, and a method of the constraint passes a value that shares the element's storage in Go (`Tree.Children (returns []N)`; a map, channel or pointer of `N`, or a generic type carrying `N`). A proxy is a separate object per pointer and cannot forward that sharing. Each site and method is named, and the run exits non-zero. | Instantiate over a value element (value-receiver methods), which needs no proxy. Or shape the method so it forwards exactly: return `N` itself, a tuple, a func or iterator (`iter.Seq[N]`), or an array `[K]N`. | `GO2CS2003` | converter | Error | Refused: a conversion to a type the converter hand-converts (runtime's `guintptr` family) takes the method's own pointer receiver through `unsafe.Pointer`, for example `guintptr(unsafe.Pointer(gp))` in a method of `*g`. | `GO2CS2004` | converter | Error | Retired: no longer reported. It refused a defined type written over an instantiated generic type, `type Q pair[int]` or `type P[T any] pair[T]`, which go2cs now converts. The number stays reserved. | Nothing: convert with a current go2cs. |
| `GO2CS2005` | converter | Error | Refused: a pointer type argument to a generic with a non-self-referential method-set constraint (`convertMapToOptions[O optionParser]` called with `&compilerOptionsParser{}`) that go2cs's constraint proxy cannot carry with Go's semantics. The proxy refuses: a generic named type; a constraint that mixes a type-term union with methods; a callee that also carries the type parameter in a slice, map, channel or pointer; a sibling type parameter whose constraint mentions it; inside the callee, its zero value used as a method receiver or converted to an interface; and the type parameter passed on to another generic under a different constraint. | `GO2CS2006` | converter | Error | Refused: a generic call passes a `[]*T` where the callee declares `[]N` (`N` constrained by a method-set interface). go2cs passes that argument as an element-wise copy through the adapter, and the callee may write the slice (the first write is named), so its writes would land on the copy, not on the caller's slice. | `GO2CS2007` | converter | Warning | One instantiation of a generic type satisfies a non-generic interface because a method the interface requires names the type's own type parameter (`box[point]` as `interface{ val() point }`, where `box[T]` declares `val() T`). go2cs carries such a pair in a closed adapter class, and this use is one the carrier does not serve: the instantiation is a type argument constrained by the interface; or the type promotes a required method from an embedded field; or a second instantiation of the same type converts to the same interface in one package. | `GO2CS2008` | converter | Error | The converter failed on a file (a fault inside go2cs itself, recovered so the rest of the package converts), so that file's output was not written: its `.cs`, or for a hand-owned file its `.cs.auto` review sibling. ## Adding a code

Each side has one registry, and a code is declared there and nowhere else:

- the converter's codes are the `const` block in `src/go2cs/diagnosticOutput.go`;
- `go2cs-gen`'s codes are the `DiagnosticDescriptor` fields of `GeneratorDiagnostics` in
  `src/gen/go2cs-gen/GeneratorDiagnostics.cs`;
- the build's codes are the properties of the `Go2csDiagnosticCodes` block in
  `src/core/golib/buildTransitive/go.lib.targets`, each raised by an `Error` or `Warning` task whose `Code` names
  the property. No other targets file raises a `GO2CS` code.

A new code takes the next free number in its side's range, and a row in the table above in the same change. The
repository test `TestGo2csDiagnosticCodeRegistry` (`src/go2cs/internal/repoguard`) fails, naming the code, when a
code is used in the source or in a user-facing page but not registered, registered twice, registered outside its
side's range, missing its row here, or (on the build side) raised by no task, and when a row names a code that is
not registered.
