Withdrawing fewer would not make the package censusable: the next member kills the run the same way at the next alphabetical position. Together they carry 22 of the Go side's 183 verdict rows.

> THE MECHANISM. awaitBlockedGoroutine (pprof_test.go:1023) polls runtime.Stack(buf, all=true) for the regexp (?m)^goroutine \d+ \[<state>\]:\n(?:.+\n\t.+\n)*runtime/pprof\.<fName> -- it waits for a FOREIGN goroutine's own INTERIOR STACK FRAMES to appear in the all-goroutine dump. The CLR offers no way to walk another thread's stack, which the converted runtime.Stack(all) already states rather than hides: a foreign goroutine renders as its header, a ForeignStackPlaceholder line and its `created by` line. So the regexp can never match on any input, the helper's `for { Gosched(); Stack() }` loop never terminates, and the time.AfterFunc(t.Deadline()-1s) timer Go arms for exactly this case fires and panics ON A GOROUTINE. golib reproduces Go's semantics faithfully -- an unrecovered panic in a goroutine kills the binary -- so the process dies and every test after it in its phase is lost. The capability is absent BY CONSTRUCTION, not unimplemented: no increment of runtime/pprof can supply it.

> WHY AN EXCLUSION RATHER THAN A DISCLOSED VERDICT. The host already attributes a verdict before it dies -- Goroutine.ObserveUnhandledPanic writes `<test> fail -- panic on a goroutine started by <test>` with the panic text -- so a verdict is not what is missing. Survival is, and no per-test capture can supply it: the polling loop keeps spinning whatever is done with the timer's panic, so containing it converts a bounded crash into an unbounded hang and a package-deadline kill that discards every verdict in the package. That is the measured reflect TestOffsetLock shape core/testing/TestHost.cs carries as the reason its own containment policy was REVERSED, and the reason golib's Goroutine.ContainUnhandledExceptions refuses a PanicException outright.
