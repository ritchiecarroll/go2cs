## Disclosed divergences

A disclosed divergence is a specific Go assertion this conversion does not satisfy — not
a skipped test and not a tolerance. Each one is pinned by exact failure signature in the package's
hand-owned [`go2cs_test_disclosures.json`](https://github.com/ritchiecarroll/go2cs/blob/master/src/core/strings/go2cs_test_disclosures.json);
a disclosed test that fails any *other* way is still a hard mismatch.

The **Class** column says which kind each one is: a `deferred` entry is an assertion the managed
CLR *can* meet, pinned against the named plan that will retire it; every other class is one it
*provably cannot* satisfy.

| Test | Class | Pinned reason |
|:--|:--|:--|
| `TestBuilderAllocs` | `deferred` | Exact-count AllocsPerRun assert (want 1): Go's issue-23382 check that copyCheck does not force the Builder to escape. The converted `var b Builder` is a heap box (ж<Builder>) because copyCheck stores and compares the Builder's own address (src/core/strings/builder.cs:26-40), an identity-keyed boundary that reducing address-take boxes cannot remove. At go1.24.13 the two counted objects per run are that box and the element-reference box String() mints (ElemRefBox); the buffer, Go's one allocation, is not counted. At go1.26.10 it reads 3 per run on windows and linux, with an identical test body. |
| `TestBuilderGrow` | `deferred` | Exact-count AllocsPerRun asserts (want 1 per growLen>0 leg, want 0 for growLen=0): every failing leg reads a count of golib-runtime objects, Go's own unit. The growLen=0 leg's addressed Builder is heap-boxed per run (ж<Builder>, strings/builder_test.cs:140) where Go's escape analysis keeps it on the stack; that box sits at an identity-keyed boundary, since copyCheck stores and compares the Builder's own address (strings/builder.cs:26-40), so reducing address-take boxes cannot remove it. String()'s element-reference box and the converted comparison operand `(@string)p` (strings/builder_test.cs:146) are counted as well. |
| `TestBuilderGrowSizeclasses` | `deferred` | Count-bound AllocsPerRun assert (want <= 1): the reading is a count, 3 per run: the ж<Builder> box, the element-reference box String() mints (ElemRefBox) and the append regrow; the byte[18] MakeNoZero allocates is not counted. Go's Grow(18) rounds up to a 24-byte size class, so its 19-byte write fits without a regrow. The Builder box sits at an identity-keyed boundary: copyCheck stores and compares the Builder's own address (strings/builder.cs:26-40), so reducing address-take boxes cannot remove it. |
| `TestIndexRune` | `deferred` | Want-zero AllocsPerRun assert: IndexRune's Index(s, string(r)) materializes a byte[] for string(r) in the managed model, where Go builds it in runtime.intstring's 4-byte stack buffer; the index-semantics legs all pass. A transient one-rune string over a stack encoding, for a string(r) the callee does not retain, removes it. |
| `TestReplace` | `deferred` | AllocsPerRun check new at go1.26.10 (strings_test.go:1480; go1.24.13's TestReplace has no allocation assertion): every Replace case must allocate at most one object (the result string), and the test fails a case with `Replace(...) allocates N objects`. The converted side reads 3.00 objects for 13 cases and 6.00 for Replace("☺☻☹", "", "<>", -1), 14 failure lines, on both OSes. The signature pins the `allocates` lines only, so a failure of TestReplace's value asserts still fails the comparison. |
