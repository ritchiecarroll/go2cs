## Disclosed divergences

A disclosed divergence is a specific Go assertion the managed CLR *provably cannot* satisfy — not
a skipped test and not a tolerance. Each one is pinned by exact failure signature in the package's
hand-owned [`go2cs_test_disclosures.json`](https://github.com/ritchiecarroll/go2cs/blob/master/src/core/crypto/tls/go2cs_test_disclosures.json);
a disclosed test that fails any *other* way is still a hard mismatch.

| Test | Class | Pinned reason |
|:--|:--|:--|
| `TestBogoSuite` | `host-limit` | The test delegates to BoringSSL's own test runner, spawned as `go test .` in the boringssl module — a child that carries Go's default 10-minute test-binary deadline, which neither the package's code nor the host controls (the test passes no -timeout, in either language). Inside that wall the runner spawns the shim once per case — 5,481 spawns in this configuration — and the shim IS the converted test host: since 2026-08-27 a self-contained single-file executable (the shape that retired the class's relocatable-executable entry), whose process start (bundle open, CLR startup, JIT over the converted-stdlib closure) measures 2.61 s where Go's statically linked test binary starts in 0.038 s -- the framework-dependent shape this entry was minted against measured 3.30 s, so the single-file publish bought ~0.7 s and the ~69x that remains is structural to the deployment shape. The ReadyToRun rung was measured 2026-08-28 (the empty-the-class commission): R2R composite publish (+161 s, 181.5 MB) cuts shim startup to 0.74 s, and driven DIRECTLY with the wall lifted the runner completes the whole configuration -- 3,242 cases, 861 PASS / 2,381 allow-unimplemented SKIP, ZERO failures, ok end to end -- in 1,316 s against the 600 s wall the test itself carries: 2.2x over on this 6-core host, down from ~20x. The wall is now THROUGHPUT-bound, not startup-bound: at the measured slot cost the zero-startup (AOT) floor computes to ~980 s here, so no startup work alone clears it on this host class -- the entry retires when managed steady-state TLS throughput on the sweep host crosses the runner's own deadline, and the interop itself is no longer in question at any width — it is what the artifact IS, not how far an implementation has got. Measured 2026-08-18: the runner reaches ~267 of 5,481 cases at its wall even with 16 parallel shim workers — a ~20x shortfall no deadline the test can express would close — then exits without writing its results JSON, which selects exactly the failure arm this signature pins. The TLS interop capability itself is not in question and is proven by value in the same suite: with `-bogo-filter Client-Verify-ECDSA-TLS1` the converted host completes a TLS handshake with certificate verification against BoringSSL as the peer, PASS in 14 s end to end including the module download and runner build. CONFIRMED INDEPENDENTLY 2026-08-29 on a second box (i9), and this is the first measurement whose numbers are produced by GO'S CONTRACT rather than partly by a harness defect: 861 PASS / 2,381 SKIP / 0 FAIL, exit 0 — identical to the record above on all three buckets — wall 1,046.3 s, about 20% faster than this box and still not crossing the 600 s deadline. So the disclosed shape was partly an artifact of the harness, and is no longer: the suite now executes exactly the cases Go executes and skips exactly the ones Go skips. Same verdict, entirely different evidence. The partition is also now known to be contract-determined and load-INVARIANT — 861 runnable / 2,381 skipped held across four runs on two machines under roughly 4x differing timeout pressure, with contention moving tests only inside the runnable set and never across the skip boundary — so a future re-measure that reports a different split is reporting a real change, not noise. Retirement condition unchanged and sharper for it: this entry retires when managed steady-state TLS throughput on the sweep host crosses the runner's own 600 s deadline. | `TestWeakCertCache` | `codegen-liveness` | RE-SIGNED AT go1.26.10 (2026-10-25, G): go1.24.13's TestCertCache, which counted references and freed through runtime.SetFinalizer, became TestWeakCertCache over weak.Make and runtime.AddCleanup. The test drops both certificates (`certA = nil`, then `certB = nil`, each followed by runtime.GC()) and polls four seconds for the cache's cleanup to delete the entry; it times out at the SECOND poll, since the first is trivially true while certB lives. weak.Make, runtime.AddCleanup and runtime.GC() are correct. A converted probe of the same cache at f8fe15c97e (11 arms, every one passing in Go 1.26.10) clears the weak pointer and runs the cleanup inside the same runtime.GC() call whenever the last strong reference lived in a frame that has returned, including after the object survived an earlier GC, under TieredCompilation on and off and with JIT inlining off. It fails only in the test's own shape: `certA, err := wcc.newCert(...)` is a two-result call, and on windows/amd64 its 16-byte (ж<Certificate>, error) ValueTuple returns through a hidden stack buffer that the JIT never clears. In JitDisasm FullOpts both calls pass that buffer (rcx=[rsp+0xC8], [rsp+0xA8]) and copy the results out to registers, and the gword slots sit in the prolog's zero-init block, untracked, so the CLR reports them live to the method's end and the certificate stays reachable until TestWeakCertCache returns. The one-result twin passes with inlining off, which isolates the tuple return as the axis. Linux's SysV ABI returns the pair in RAX:RDX, and linux PASSES (R, RWSL-1, 0.31 s), hence windows only; darwin joins only if its own re-read fails it. Same class as sync's TestOnceXGC and TestPoolGC. |

`TestBogoSuite` is **host-conditional**: The GO side is decided by network reachability of the pinned boringssl module, which `go test` downloads and builds BoringSSL's own runner from, and by how far that runner gets inside the 10-minute deadline Go's test binary carries by default — so per host and per run the Go baseline passes, expands into its 3,243-row case matrix, or fails.
The row is therefore accepted — and counted as disclosed — in two shapes: `go test` **pass**
with go2cs **fail**, the pinned divergence above; or **both sides failing**, agreement on a host
where the Go premise itself fails. Any movement on the go2cs side still fails the comparison, in
either direction — the pin stays strict on the half that is deterministic.

A disclosed test that fails at its root never reaches its own case fan-out, so the
subtest verdict rows `go test` reports underneath it have no converted counterpart to
compare. Those rows are withdrawn with their disclosed root — none is claimed by the
matched count above:

- `TestBogoSuite` — 3526 verdict rows withdrawn
