[`src/core/runtime/pprof`](https://github.com/ritchiecarroll/go2cs/tree/master/src/core/runtime/pprof).

Both runtimes skip 2 of the matched tests identically.

> Six host-fatal entries, all of one shape, each earned by its own isolation measurement: the awaitBlockedGoroutine closure described next. A seventh entry, TestGoroutineProfileLabelRace, a hang rather than a crash, was withdrawn with them and has since been retired (its record is the last note). Withdrawing the seven is what made the package measurable at all: the converted host went from 2 verdicts against 183 Go rows to 147 verdicts, 120 of them matching, in 48 seconds.

> Six host-fatal exclusions, withdrawn together, are the complete reverse-reachability closure of runtime/pprof's awaitBlockedGoroutine helper, computed with go/packages under the same conservative any-use-of-a-same-package-function rule the converter's own capability analysis uses, and each was independently measured to take the host down when run alone. Withdrawing fewer would not make the package measurable: the next member kills the run the same way at the next alphabetical position. Together they carry 22 of the Go side's 183 verdict rows.

> THE MECHANISM. awaitBlockedGoroutine (pprof_test.go:1023) polls runtime.Stack(buf, all=true) for the regexp (?m)^goroutine \d+ \[<state>\]:\n(?:.+\n\t.+\n)*runtime/pprof\.<fName> -- it waits for a FOREIGN goroutine's own INTERIOR STACK FRAMES to appear in the all-goroutine dump. The CLR offers no way to walk another thread's stack, which the converted runtime.Stack(all) already states rather than hides: a foreign goroutine renders as its header, a ForeignStackPlaceholder line and its `created by` line. So the regexp can never match on any input, the helper's `for { Gosched(); Stack() }` loop never terminates, and the time.AfterFunc(t.Deadline()-1s) timer Go arms for exactly this case fires and panics ON A GOROUTINE. golib reproduces Go's semantics faithfully -- an unrecovered panic in a goroutine kills the binary -- so the process dies and every test after it in its phase is lost. The capability is absent BY CONSTRUCTION, not unimplemented: no increment of runtime/pprof can supply it.

> WHY AN EXCLUSION RATHER THAN A DISCLOSED VERDICT. The host already attributes a verdict before it dies -- Goroutine.ObserveUnhandledPanic writes `<test> fail -- panic on a goroutine started by <test>` with the panic text -- so a verdict is not what is missing. Survival is, and no per-test capture can supply it: the polling loop keeps spinning whatever is done with the timer's panic, so containing it converts a bounded crash into an unbounded hang and a package-deadline kill that discards every verdict in the package. That is the measured reflect TestOffsetLock shape core/testing/TestHost.cs carries as the reason its own containment policy was REVERSED, and the reason golib's Goroutine.ContainUnhandledExceptions refuses a PanicException outright.

> MINT RULE, checked: no committed proof page under docs/validation/current names any of the six, so the withdrawal cannot shrink a row some platform runs successfully. SIGNATURE, deliberately empty on all six: a withdrawn test produces no verdict on either side to pin against, and the loader refuses a signature only for this class for exactly that reason. RETIREMENT: all six retire together the day runtime.Stack(all) can render a foreign goroutine's interior frames; until then the entries simply stop applying if it ever can.

> The seventh entry was a hang, the first in this class, and it is retired. TestGoroutineProfileLabelRace did not crash: its /reset subtest spun forever because the converted goroutine profile withheld labels (a measured pointer-staleness defect), and the subtest's exit condition is a label appearing in the profile text. Measured alone it produced zero verdicts and consumed the whole package deadline (exit 1 after 182 s under -timeout 3m); in the full run it left 36 rows without a C# verdict. It was host-fatal rather than an unsupported-runtime-capability exclusion because that gate admits only something provably unavailable, never something merely unimplemented, and the label half was unimplemented; the host-fatal class admits a crash or a deadline-consuming hang, since a test that never returns costs every test after it in its phase. The labels now reach the profile: golib hands a reference-bearing box's registered order token out as its unsafe.Pointer number, so the labelMap pointer resolves to its box across a collection instead of naming a moved address, and pprof_impl.cs fills labels[i] from the goroutine registry's slot. Re-measured with this entry deleted, filtered to TestGoroutineCounts and TestGoroutineProfileLabelRace, Release, tiering off, Go reference go1.23.12: TestGoroutineProfileLabelRace passes in 58 ms (/reset 42 ms, /churn 6 ms) and TestGoroutineCounts passes in 10.7 s with its label half now reached, 4/4 verdicts matching. The entry is deleted rather than annotated because host-fatal entries retire by deletion; this note keeps its record. The six above are unchanged by it: their capability (a foreign goroutine's interior frames in runtime.Stack(all)) is a different one.

## Disclosed divergences

A disclosed divergence is a specific Go assertion the managed CLR *provably cannot* satisfy — never
a tolerance, and never a test skipped to make a row pass. Each one is pinned by exact signature in the package's
hand-owned [`go2cs_test_disclosures.json`](https://github.com/ritchiecarroll/go2cs/blob/master/src/core/runtime/pprof/go2cs_test_disclosures.json);
a disclosed test that fails any *other* way is still a hard mismatch.
