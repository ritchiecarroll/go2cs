# PLAN — generated-code format: go2cs-gen's output in the project's C# style
<!-- {% raw %} — Jekyll/Liquid guard: this page quotes C# raw-string templates ({{ … }}) that Liquid would otherwise parse; the HTML comment hides the tag on GitHub. -->

> **STATUS: PROPOSED (scout), 2026-11-05, P2 on COORD's dispatch of the owner's ask. Measured at master
> `33589333b2`, linux, .NET SDK 10.0.403, `GoTargetOS=linux`. Read-only: no generator, converter or corpus file
> was changed.** Every number is a census over 2,578 files that go2cs-gen wrote during real builds (§1), read by
> three instruments, each shown red on planted input first. Writer lines are cited `file:line` at that master.
>
> **The owner's ask (verbatim):** "I noticed in the generated tab of the go2cs tour, while exploring, some of the
> generated code had bad nested brace alignments in some cases. This code should be more standard C# formatted, not
> following converted code conventions. Mabybe a scout here could check generated code against standard C# code
> formatting, as defined in project."
>
> **The standard applied:** [`coding-style.md`](coding-style.md) rules 1 (Allman braces, each brace on its own
> line), 2 (four spaces, no tabs) and 7 (never more than one blank line), and `src/.editorconfig`
> (`csharp_new_line_before_open_brace = all`, `csharp_indent_case_contents = true`, `insert_final_newline = true`,
> `indent_size = 4`). Line endings are CRLF, which every go2cs-gen writer already uses for its own literals and
> which `.gitattributes` pins for checked-out `*.cs`.

## Findings in brief

- **The brace defect the owner saw is LiteralInterceptorGenerator's.** It writes the body of a block
  `namespace go2cs.Interceptors { … }` at column 0, so the two nested classes' braces sit in the same column as
  the namespace's braces. All 8 interceptor files in the sample carry it (73 brace lines at the wrong depth, 317
  member lines at the wrong indent). The tour's Generated tab names literal interceptors among what it shows
  (`src/tour/generated.go`), and a tour program that prints a literal produces one of these files. No other
  generator has a brace or indent defect: across 2,578 files the K&R, misaligned-pair and depth arms read 0
  everywhere else.
- **Half the files fail `dotnet format`, almost all on whitespace.** 1,376 of 2,578 files (8,844 diagnostics) fail
  `dotnet format whitespace --verify-no-changes`. Most are whitespace-only lines and blank runs left by raw-string
  templates; then two statements or two attribute lists on one line, and a missing final newline.
- **The generated bytes differ between Windows and Linux.** 22 `StringBuilder.AppendLine` calls in the
  StructType and InterfaceType templates write `Environment.NewLine` into otherwise-CRLF text: LF on Linux, so
  698 files carry mixed line endings (12,965 LF lines) on Linux and none on Windows.
- **Seven root causes, all in writers, none semantic.** Every class is fixable by moving only whitespace and line
  breaks; §3 names each writer line.
- **Recommendation: two generator-only seats** (§6). Fix the structural writers at their source. Route every
  `AddSource` through one whitespace-normalizing helper, which costs about 0.05 s on runtime's compile against
  TypeGenerator's measured 296 s. Guard both with a GenTests assertion over every generator's output. Proof:
  `ildiff` reads `differing=0` and GenTests pass.

## 1. The instrument

### Corpus

Generated files were collected from real builds with `-p:EmitCompilerGeneratedFiles=true` (Release, linux),
copied with their paths, and read on the copy:

- **A stdlib closure:** `src/core/reflect/reflect.csproj` and its project references, plus `fmt`'s closure, which
  the behavioral sample pulls in. That is 2,418 files from 54 projects.
- **A behavioral sample chosen to reach every generator:** AnonymousStructs, ChanDirectionChain,
  MapCloneLinkname, ConstraintProxyEmbeddedInterface, InlineConstraintLift, EmbeddedInterfaceWitness (+ iolike),
  GenericPointerInterfaceImpl, GenericInterfaceCrossPackage (+ keylike). That is 160 files from 10 projects.

Every build returned 0. All 16 `[Generator]` classes appear (files per generator in §2). The two analyzers,
StackAppendBufferAnalyzer and StringLiteralBindingAnalyzer, write no files.

### Three arms

| arm | what it reads | authority |
|---|---|---|
| (a) `dotnet format whitespace <copy> --folder --include-generated --verify-no-changes --report r.json`, with `src/.editorconfig` copied to the folder root | the project's own formatter, with the project's own settings | primary. `--include-generated` is needed because every file carries `// <auto-generated/>` |
| (b) Roslyn `NormalizeWhitespace("    ", "\r\n")`, diffed line by line, blank lines ignored | a canonical layout | secondary, with a known noise floor (below) |
| (c) `genfmt`, a Roslyn syntax-tree check (`docs/phase4/data/gen-format-scout/genfmt/`) | brace pairs and indent depth directly | primary for layout |

`genfmt` reads brace pairs from statement-shaped nodes only (blocks, type, namespace and accessor bodies, switch
bodies), skips pairs that open and close on one line, and computes each token's expected depth as the number of
enclosing brace pairs, plus one for a switch section's statements, plus one for an embedded non-block statement
under `if`/`else`/`while`/`for`/`foreach`/`do`/`using`/`lock`/`fixed` (not `else if`, not a `using` nested
directly in a `using`, per coding-style rule 1). Its columns:

- `kr`: an opening brace that does not lead its line.
- `misalign`: both braces lead their lines but sit in different columns.
- `depth`: a brace that leads its line, at a column other than four times its depth.
- `body`: a line whose first token starts a statement, member, accessor, switch section or attribute list,
  indented other than four times its depth.
- Line facts: `tabs`, `trailing` (whitespace before the line break), `mixed_eol` (count of the minority line
  ending), `blank_runs` (two or more blank lines in a row).

**Arm (b)'s noise floor.** `NormalizeWhitespace` is not the project style. It deletes every blank line, which
rule 7 allows one of, and it places a block that is a switch section's statement at case-label level. The first
is why the diff ignores blank lines. The second shows on `good_switch` below. Arm (b) is reported but never
decides a class.

## 3. Root cause per class, with samples

Samples are real files from the corpus (CRLF shown only where it matters; long lines cut with `…`). "After" is
`dotnet format`'s output, or the fix shape where the formatter's output is not the recommended one.

### A. Block-namespace body at column 0: LiteralInterceptorGenerator

**Cause.** `LiteralInterceptorGenerator.cs:559` opens `namespace go2cs.Interceptors` as a block, but the writers
inside it emit as if the namespace were file-scoped:

- `:560` and `:563` write the two class headers at column 0;
- `:527` (the literal cache), `:575`–`:578` (attributes and signature) and `:584`/`:587` (body) write members at 4
  and statements at 8;
- `:562` and `:591` close at column 0.

A file-scoped namespace is not available: the same file first declares the block namespace
`System.Runtime.CompilerServices` (`:555`) for the polyfilled `InterceptsLocationAttribute`, and C# does not
allow both forms in one file. **Fix:** add four columns to every writer from `:560` to `:591`.

`MapCloneLinkname/…/main.63031c55.Interceptors.g.cs`, before:

```csharp

{
file static class ˢLiterals
{
    internal static readonly object ˢ0 = (global::go.@string)"orig len:"u8;
    …
}

file static class ˢInterceptors
{
    [global::System.Runtime.CompilerServices.InterceptsLocation(1, "…")]
    public static (nint n, global::go.error err) ˢI0(params global::System.Span<object> aʗp)
    {
        aʗp[0] = ˢLiterals.ˢ0;
        return global::go.fmt_package.Println(aʗp);
    }
```

After:

```csharp

{
    file static class ˢLiterals
    {
        internal static readonly object ˢ0 = (global::go.@string)"orig len:"u8;
        …
    }

    file static class ˢInterceptors
    {
```

The other seven interceptor files have the same shape. The interceptor `data` argument encodes the
*intercepted* call's location in user code, so moving the interceptor file's own lines does not change it.

### B. Two statements on one line: TypeGenerator's MethodSet

**Cause.** `MethodSet.cs:363` builds a bound case as `$"{bind} return {boundDelegate}(…)"`, a declaration and a
`return` joined by a space. `:140` writes it as one line. **Fix:** join with `"\r\n"` plus the 20-column indent
that `:140` uses.

`core/internal/abi/…/go.internal.abi_package.ChanType.MethodSet.g.cs`, before:

```csharp

                    if (!bound)
                        return (global::System.Func<…>)(global::go.@internal.abi_package.Kind);
                    {
                        global::go.ж<…ChanType> ᴛp = (global::go.ж<…ChanType>)receiver!; return (global::System.Func<…ΔKind>)(() => …Kind(ᴛp));
```

After:

```csharp

                        global::go.ж<…ChanType> ᴛp = (global::go.ж<…ChanType>)receiver!;
```

All 205 MethodSet files have this shape, 1,739 lines in total. The value-receiver form at `:396` writes a
one-line braced block, `{ T ᴛc = v; return …; }`, which the formatter leaves alone.

The same class has a second writer. `StructTypeTemplate.cs:2489` and `:2491` write a constructor's
`if (x.Source is not null) this.x = x;` and `if (x != nil) this.x = x;` as one line (239 lines in 128 files),
where coding-style rule 1 puts the embedded statement on its own indented line. `dotnet format` makes that split.
**Fix:** a `"\r\n"` and four more columns before `this.`.

### D and E. Whitespace-only lines, trailing whitespace and blank runs: the raw-string templates

**Cause.** These come from C# raw-string literals. A raw string strips only the closing delimiter's indentation
from each line, so a template line that looks blank but is indented further than the closing `"""` keeps the
difference as trailing spaces. A line that holds only interpolations which render empty becomes a
whitespace-only line, or a second blank line. Fragment properties that end in `"\r\n" + indent` do the same.

| template line | effect |
|---|---|
| `StructTypeTemplate.cs:151`, `:153` and the lines around them in `TemplateBody` (`:131`–`:171`) | 8-space lines between members |
| `StructTypeTemplate.cs:144`, a line of four interpolations (`ValueCloneImplementation`, `GoZeroConstructionHook`, `TypeOpsSourceMembers`, `FieldBoxTableMembers`) | a whitespace-only line, or a blank run, when all four are empty |
| `NumericTypeTemplate.cs:28`, `:32`, `:34` and the operator ladder below them | 8-space lines between operators (InheritedType) |
| `InterfaceImplTemplate.cs:314`, `:316`, `:318` | 8-space lines between the interface `==`/`!=` operators (Implement, 4 files) |
| `ImplicitConvTemplate.cs:41`, `}    ` | four spaces after a closing brace (all 21 files) |
| `MethodDeclarationSyntaxExtensions.cs:206`, `GetWhereConstraints` | a line break plus an indent with no `where` clause after it, when every type parameter's constraint list is empty (Recv, 1 file) |
| `PartialStubGenerator.cs:149`, a line holding only the using-statement interpolation, written after the namespace | a blank run when there are no usings (4 files) |

### F. No final newline: PartialStub and InterfaceType

**Cause.** A raw string drops the line break before its closing `"""`. The PartialStub template
(`PartialStubGenerator.cs:141`–`:157`) ends at `}`, and so does InterfaceTypeTemplate's `AssertSourceOverloadClass`
(`InterfaceTypeTemplate.cs:87`–`:100`), which `:84` appends after the base footer. The base footer itself
(`TemplateBase.cs:113`–`:117`) ends in `PackageFooter ?? ""`, which leaves a final newline only when the footer is
empty. Every one of the 221 PartialStub files, and every interface file that carries assertion overloads (71),
ends `}` with no line break. **Fix:** §4's helper adds the one final newline. The template fix is a trailing
empty line before each closing `"""`.

### G. Mixed line endings on Linux: StructType and InterfaceType

**Cause.** `StringBuilder.AppendLine` writes `Environment.NewLine`. `StructTypeTemplate.cs` calls it 19 times
(the constructors block at `:2163`–`:2195`, the `ref var` receiver forwarders at `:1263`–`:1268`, and
`:2234`–`:2486`). `InterfaceTypeTemplate.cs:118`–`:120` calls it 3 times. go2cs-gen has no other `AppendLine` and
no `Environment.NewLine`. Everything else in go2cs-gen writes `"\r\n"` explicitly (26 files). On Windows the
result is consistent CRLF. On Linux, 696 struct files and 2 interface files mix LF into CRLF text, and the same
input produces different generated bytes on the two hosts. Sample: `dlogPerM.g.cs` above, where the
constructors block (`public dlogPerM(NilType _)` through the parameterless constructor's `}`) is the only LF
run in the file. **Fix:** replace each `AppendLine(x)` with `Append(x).Append("\r\n")`, or a local
`AppendCrlf` helper. §4's helper also normalizes the endings, but the writers should not depend on it.

## 4. Fix shape and its cost

Two shapes were weighed for the whitespace classes (D–G). Classes A–C need writer changes under either shape:
a line pass cannot re-indent a block or split a line safely.

| shape | covers | cost on runtime's compile (this box) | verdict |
|---|---|---|---|
| Roslyn `NormalizeWhitespace` on each generated `SourceText` | all classes, in principle | parse 0.38 s + normalize 2.34 s = 2.72 s | **rejected on output, not cost.** It is not the project style: it deletes every blank line, misplaces switch-section blocks (§1), and would trade these defects for new ones in all 2,578 files |
| one text helper at the `AddSource` seam: CRLF only, trailing whitespace trimmed, blank runs collapsed to one, leading and trailing blank lines dropped, exactly one final newline | D, E, F, G | 0.054 s | **recommended** |

Cost readings are from `docs/phase4/data/gen-format-scout/gencost/`: each file's existing text, mean of three
warm in-process runs after one cold run, on this box (linux cloud container, 4 cores), at `33589333b2`. Runtime's
generated files number 996 (4.2 M chars). Over the whole 2,578-file corpus the figures are parse 0.95 s,
normalize 5.18 s and the line pass 0.16 s. For scale, the BOARD's 2026-10-19 reading puts TypeGenerator at 296.4 s
of runtime's compile (linux, `821741f7b0`). That is a different tree and run, so the comparison only shows that
the helper's cost is negligible.

**The helper.** Add one `AddGeneratedSource(this GeneratorExecutionContext context, string hintName, string text)`
in `Common.cs`. The 28 `AddSource` call sites in 15 generator files route through it. A line pass can change
behavior only where a line break falls inside a string literal, which needs a verbatim (`@"`) or raw (`"""`)
literal in the generated text. None of the 2,578 files contains either. The helper leaves a file unchanged when
its text contains either opener, and the guard (§5) names that file, so the shortcut can never change behavior
silently. Keeping the helper text-only keeps it free of a parse. A token-aware version would cost about the parse
figure above.

**The writer fixes** are the structural edits in §3: A (`LiteralInterceptorGenerator.cs:527`–`:591`), B
(`MethodSet.cs:140`, `:363`; `StructTypeTemplate.cs:2489`, `:2491`), C (`TemplateBase.cs:38`–`:40`, `StructTypeTemplate.cs:755`), Recv's empty `where`
line (`MethodDeclarationSyntaxExtensions.cs:206`), and G's 22 `AppendLine` calls. F's and ImplicitConv's
template ends can ride along, or be left to the helper.

## 5. Proof and guard

**Behavior must be unchanged; only whitespace and line breaks may move.** The proof, per seat:

1. **IL identical.** Build the reflect closure and the behavioral sample before and after the change, then run
   `src/tools/ildiff <base> <seat> --roots <base src>;<seat src>`. It must read `differing=0`. One caveat to check,
   not assume: a generated call to a `[CallerLineNumber]` parameter would embed the moved line number as an IL
   constant. golib's only such parameters are on the goroutine launchers, which no generated file in the sample
   calls, and `ildiff --show` would name any method this affects.
2. **GenTests pass.** 9 GenTests files pin text that contains `\r\n`, and 586 assertions use `Contains(`. A pin
   that spans moved whitespace changes with the output. Each changed pin is listed in the seat's record.
3. **CNR and the behavioral suite read NO REGRESSION.** The converter and the goldens are untouched (generated
   files are not checked in), so this only confirms nothing broke at compile time.
4. **The scout instrument reads clean.** Re-running `collect.sh` reads 0 on arms (a) and (c) for every
   generator. Arm (b) keeps its documented noise.

**The guard: a new GenTests class, `GeneratedFormatTests`.** It runs every generator over the GenTests fixtures
that already exercise it, then checks each output file. A file passes when:

- arm (c)'s checks read 0, ported from `genfmt` into a GenTests helper of about 150 lines that needs only
  `Microsoft.CodeAnalysis.CSharp`, which GenTests already references;
- there is no LF without a CR, no trailing whitespace, no blank run, and exactly one final newline;
- the file is a fixed point of the §4 helper.

Red first: at `33589333b2` the guard must fail, naming the LiteralInterceptor, MethodSet, PartialStub and
ImplicitConv outputs. An exact `dotnet format` fixed point inside GenTests would need
`Microsoft.CodeAnalysis.CSharp.Workspaces` as a new test dependency. That is an option, not the recommendation:
arm (c) plus the line facts covered every class this census found.

## 6. Recommendation and size

**Two seats, generator-only.** Neither touches the converter, golib, the corpus or any golden.

| seat | content | closes | gates |
|---|---|---|---|
| 1 — structural | the guard's layout half, red first; writer fixes A, B, C and Recv's `where` line | the owner's brace defect, 333 files with two statements on a line, 849 files with two attribute lists on a line | GenTests, `ildiff` `differing=0`, CNR, the scout's arm (c) at 0 for depth, body and attributes |
| 2 — whitespace | the guard's whitespace half, red first; `AddGeneratedSource` at the 28 sites; the 22 `AppendLine` calls | D, E, F, G: 862 + 633 + 292 + 698 files | GenTests, `ildiff` `differing=0`, CNR, `dotnet format --verify-no-changes` returning 0 over a fresh `collect.sh` corpus |

Seat 1 goes first because it carries the visible defect. The seats share no lines (seat 1 edits writer bodies,
seat 2 edits `Common.cs`, the `AddSource` call lines and the `AppendLine` calls). One lane can run them back to
back, with seat 2 on top of seat 1. Each is about a day of lane time. The `ildiff` builds, the reflect closure
twice, dominate.

## 7. One call for the owner

Class C's fix changes visible output shape: **each attribute list on its own line** (recommended), against
**`[A][B]` on one line**, which is what `dotnet format` makes of a member's lists. Both are fixed points of the
formatter. Seat 1 takes the recommended shape unless the owner rules otherwise.

A separate, smaller question for COORD: `src/.editorconfig` sets no `end_of_line` for `*.cs`. That is why arm
(a) cannot see class G, and why `dotnet format` on Linux writes LF into the lines it fixes in CRLF files (seen in
this scout's own formatted copy). Adding `end_of_line = crlf` under `[*.cs]` matches what `.gitattributes`
already materializes, but it reaches every hand-authored file, so it is outside this plan.
