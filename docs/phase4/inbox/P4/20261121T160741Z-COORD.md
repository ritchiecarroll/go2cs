## G -> COORD, for P4: the M:N twin fact sheet, read at the item 13 merge 2cd6fa59c5 (verbatim)

OPT-IN (exact names)
- Build: GoTwinsFor=<project names, ';'-separated>, an MSBuild global property matched on MSBuildProjectName; it sets
  GoTwins=true in those projects only (a global GoTwins would reach every referenced package). GoTwins=true in a
  project file does the same for that project. An Exe built with twins starts at go.GoTwinEntry (main's twin).
- Run: GO2CS_MN=1 turns the scheduler on; it is OFF by default. GO2CS_MN_READING=1 prints one READING line at exit.
- Not for the doc: GoTwinsArm and the arm switches it admits (12.1: "the docs never mention it"); the other
  GO2CS_MN_* variables are prototype tuning knobs.

WHAT GETS TWINNED (a project built with twins)
- Every public member of its CONVERTED code (functions, methods, promoted forwarders, interface members) gets one
  <name>ꞏtwin returning GoTask, GoTask<T> or GoTask<(T1, ...)>: a state machine where it can park, else a forwarder
  that calls the plain member and returns a completed task. [GoParkForwarder] marks only a member that CANNOT park.
- Twin parameters are Go-shaped: a *T receiver takes ж<T>, string takes @string, ...T takes slice<T>.
- Every public interface gets a hidden Iꞏtwin : I. Unexported members are twinned only where the park analysis needs.
- Excluded: generics (E1: a generic function, a method of a generic type, a member of a generic interface).

COSTS (all Windows x64; no other platform read). A project built WITHOUT twins: unchanged.
- Build (MnHttpClosure, 186 projects, 184 libraries twinned, SDK 10.0.400, 12 cores): go.*.dll +0.51% vs no
  forwarders; build wall 1.016x. Forwarders are 70% of the members, real twins 28%, E1 2%.
- Native AOT size (prototype sheet, 2026-11-12): +185,856 bytes on the widest program (+0.09%).
- Per operation, JIT / Native AOT (same sheet): a non-parking twin call 1.9-2.2 / 2.1-2.3 ns scheduler off,
  4.0-9.3 / 7.8-8.2 ns on; one park step 625-711 / 764-805 ns. Sheet: src/tools/mnspike2/TwinRefs/FREEZE-SHEET.md.
- Threads (state the L-min cost beside any figure): the closure, 8 goroutines, GO2CS_MN=1: peak carriers 22-24,
  peak OS threads 38-40. An opted-in program holds its carrier on any plain call, incl. Mutex.Lock and time.Sleep.

SHIPPING LIMITS (.5)
- The stdlib ships WITHOUT twins (L-min): a stdlib call from an opted-in program stays plain and holds its carrier.
- Hand-owned members (R5) get no twin or forwarder yet, incl. 127 public Go functions whose bodies are hand-written
  (15 stdlib packages, mostly atomics). They move with row 7, the stdlib-twins arm.
- A call to a variadic interface member stays plain. Generics: E1 above; lifting is owed and additive.
- One package identity has one variant: a package that shipped twins keeps them. A twin member never disappears and
  changes shape only where its plain member does; E only gets shorter.
- The fallback warning (a function or go statement that cannot be made async) has no code minted at this tree.

DIAGNOSTICS, as a user reads them (rows in docs/DiagnosticCodes.md)
- GO2CS0016: a GoFrame (a converted function's defer list) is copied, stored or captured. Not twin-specific; not
  configurable. In converter output report it; in hand code keep the frame local and pass it only by ref.
- GO2CS0017: a public member of a twinned package got no twin, no forwarder and no E1 exclusion; the build stops,
  since adding one later changes the surface. Report it as a go2cs issue, with the message.
- GO2CS0018: a partial-set property (GoTwinsIface, GoTwinsIfaceAll, GoTwinsGo, GoTwinsRefuse) with twins on.
  Remove it.

FUTURE DEFAULT: ruled for .5 only: scheduler off, twins opt-in. Twinned stdlib = row 7 (owed). A default-on
scheduler or default-on twins: NOT DESIGNED.
