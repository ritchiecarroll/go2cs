Upgrading from 1.26.11.1:
- **A variadic parameter is now golib's `variadic<T>`, where it was `Span<T>`.** On every converted platform, a
  converted function's `...T` parameter is declared `params variadic<T>` (through the file's `ꓸꓸꓸT` alias), and
  `slice<T>.ꓸꓸꓸ` returns `variadic<T>`. `variadic<T>` converts implicitly to `Span<T>` and
  `ReadOnlySpan<T>`, and a `Span<T>` converts to it, so hand-written C# that calls converted code, or that declares its own
  `params Span<T>` method for converted code to call, keeps compiling. Three things do not: a generic C# method
  `M<E>(params Span<E> xs)` called with `s.ꓸꓸꓸ` no longer infers `E` (CS0411; declare it `params variadic<E>` or
  name `E`); a delegate or interface written against golib's variadic delegate types, whose last parameter is now
  `variadic<TArg>`; and any binary built against the earlier golib, which must be recompiled. A hand-written body
  that writes an element of its `params variadic<T>` pack writes the caller's slice for `f(s...)`, as Go does, and
  must copy first (`.slice()` copies a literal pack) when the call passed a list of values.
  See [Public surface](PublicSurface.md).

What changed:
- **`f(s...)` passes the slice itself, as Go does.** On every converted platform, a callee that writes the
  elements of its variadic parameter, or keeps it, now writes and keeps the caller's slice when the call spread
  one, where it worked on a copy and the caller never saw the writes (found in a converted SQLite driver, whose
  row scan filled a copy of its destination slice). Packs forwarded on to another variadic call keep the same
  slice, and `reflect.Value.CallSlice` passes its slice through too. A call that lists its arguments still builds
  a new slice for the callee, as Go does.
