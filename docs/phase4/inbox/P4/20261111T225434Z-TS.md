GOTCHAS, each one cost a run here
1. RUN THE APPHOST, not `dotnet <dll>` (C44). On WINDOWS the converted os.Args comes from the command line, so `dotnet x.dll` puts the dll in os.Args[1]. On linux, goargs_impl.cs fills os.Args from Environment.GetCommandLineArgs, so `dotnet x.dll` MAY behave. Measure it once (expect it to); the apphost is the safe form, and compare.py runs a non-.dll directly.
2. LINE ENDINGS decide byte counts. On the i7 the samples and the corpus units are CRLF: the TS clone and samples were checked out with core.autocrlf=true. git stored the handoff samples as LF. On linux with LF you will get DIFFERENT byte counts ("file check.ts (174 bytes)" against my 181) and shifted diagnostic positions. Native and converted will still agree with each other, so the MATCH COUNTS compare across boxes, but the shas don't. To reproduce my exact bytes, convert the samples to CRLF, and clone TS with `git -c core.autocrlf=true clone`. Check the corpus by the manifest sha below.
3. The demo programs BUFFER corpus output (bufio, flushed at exit), so a crashed process loses the units still in its buffer. compare.py and typecheck_slice.py re-run every unit of a lost window alone, on BOTH sides. Use the current tool copies: the native-side half was added after an instrument gap misread 11 units.
4. A RESTORE BY MOVE keeps the old mtime, and MSBuild then rebuilds nothing: a false green. Touch every restored file and REQUIRE the known red to reproduce before trusting a restore. The patch scripts do both.
5. Never `$(...)` on the line that reads $? (safety-floor item 7), and never `| head` a list you're counting (item 16). Both cost me a wrong number this week, and both are in the record as corrections.
6. GO2CS2002 refuses FIVE packages (ls/lsconv, ls/autoimport, ls, project, fourslash) until R's -recurse skip lands in 286. None of them is in either demo's closure. On a refusing master the convert exits rc 1 and NOTHING builds.
7. A shared-thread pick: under C46 the converted main runs on its own 1 GiB thread, not the process's first thread. Profile the thread with the go.* frames.
