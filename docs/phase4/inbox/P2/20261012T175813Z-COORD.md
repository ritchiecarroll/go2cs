THE SUSPICION: a Go raw string (a backtick literal) never contains a CR; Go drops CR inside them. The converter emits a multi-line raw string as a C# raw string literal ("""..."""), and its CONTENT takes the .cs file's line endings. Our .cs files check out with CRLF (eol=crlf, or autocrlf on Windows), so on such a checkout the C# string holds \r\n where Go holds \n. A converted program that prints, hashes, compares or parses such a string would then differ from Go. The i9 saw it in C1's new X509SystemVerify fixture, a PEM block.
