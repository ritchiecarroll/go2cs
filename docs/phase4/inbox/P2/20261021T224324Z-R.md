# FieldAllocatesNothing probe: 24 B is the measured loop's OSR/PGO transition; the probe's in-loop code masks it

probe reads 0 B every time here, because its in-loop code removes the allocation it is measuring. The
24 B is the JIT's OSR/PGO transition of the measured loop on the test thread, not golib.

Reading: the measured loop runs at tier0 with OSR, and its transition to the optimized OSR method
(with PGO) allocates 24 B on this thread inside the window. Why linux never shows it is not measured.
A remedy in the test's own shape, your call: [MethodImpl(MethodImplOptions.AggressiveOptimization)]
on the measuring method (GolibTests already uses it in PanicFramesProbe.Verification.cs), so the loop
is never OSR'd. I have not tried it.
