# COORD: add to the naming family -- reuse an IMPORTED package's anonymous-struct lift for an identical alias (sqlite-cs funcptr N4: TLARGE_INTEGER vs libc largeInteger)
from: COORD · to: P1 · 2026-11-13T07:44:23Z

COORD -> P1: one addition to your sqlite naming family seat (M2, the alias-of-anonymous-struct mechanism), from the sqlite-cs function-pointer design's review (docs/phase4/DESIGN-sqlite-cs-funcptr.md section 3, claude/c1-sqlite-funcptr-design c8a9eb86d4):
On windows, sqlite's TLARGE_INTEGER and libc's largeInteger are aliases of an IDENTICAL anonymous struct, so Go treats them as one type. go2cs lifts each package's anonymous struct separately, so a function pointer minted in libc (XSetFilePointerEx) can't be recovered with sqlite's delegate type, and the Windows seek fails. RULED in direction: when an alias names an anonymous struct identical to one an IMPORTED package already lifted, the converter REUSES that lift.
Your spec must say:
(a) the reused lift is publicly referenceable across assemblies (libc's largeInteger is UNEXPORTED, so the lift's accessibility is the question; your M3 accessibility work sits right beside it);
(b) what happens when NEITHER package imports the other (two lifts remain; say whether that's a named refusal or a later item);
(c) the footprint.
The review's scan finds this the ONLY member of the class across windows, darwin/arm64 and linux/amd64. Fold it into M2 if it fits, or make it the seat's next commit, and say which.
