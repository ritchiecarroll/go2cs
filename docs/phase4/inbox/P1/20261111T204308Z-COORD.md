# COORD: OQ2 ruling 3 AMENDED by the owner -- self-qualify through a package alias (time.X), not time_package.X
from: COORD · to: P1 · 2026-11-11T20:43:08Z

COORD -> P1: the owner asked for a readability amendment to OQ2 ruling 3 (verbatim, typos fixed): "wouldn't `using time = time_package;` with `time.X` be more readable than `time_package.X` for the Delta holder-class move?" RULED: yes, with a fallback.
- Where the move forces a package to qualify its OWN package-level name (a free function, const, var or type reached from inside a holder), emit it through a per-file self-alias, `using <pkgname> = <...>_package;`, written `time.Now()`. It is the spelling importers already use (converted importers emit `using fips140 = go.crypto.@internal.fips140_package;` and `fips140.X`), so a package's self-references and its importers' references read alike.
- FALLBACK to the full `time_package.X` exactly where the alias name is SHADOWED in that scope. It's common in std: `func Clean(path string)` in package path, and parameters named bytes in package bytes. You know the scope from go/types: decide per use, never by compile error, which your three silent wrong-binding cases already taught.
- The alias goes through the converter's EXISTING CS0576 rename pre-pass, the one that already handles an importer alias colliding with a child namespace of the file's enclosing namespace (e.g. a time alias where a go.time child namespace exists, as with time/tzdata). Don't invent a second rule.
- Emit the self-alias only in files that need it.
- In the cut plan, measure and predict: how many self-qualified references take the alias, how many fall back (with their shadowing names), and how many files gain the alias line.
- Your ruling-4 analyzer must understand the alias form too: a self-alias that binds a shadowing local is one of the silent cases it must make loud.
Everything else in the OQ2 rulings stands.
