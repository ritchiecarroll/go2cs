BUG (G, measured 2026-10-14): src/go2cs/stdLibConverter.go:115-118 applies the -stdlib package filter per conversion and returns "no matching packages found after filtering" when nothing matches. That is right for a single-target run. But the multi-target emission (-platforms ... with runCensusTarget) reuses it PER TARGET, so a filter naming packages that exist on only some GOOS aborts the WHOLE run. Example: `-stdlib internal/runtime/syscall/linux` under three targets.
FIX: in a multi-target run, an empty match for one target SKIPS that target, with a one-line notice naming the target and the filter. The run fails only if the filter matches nothing on EVERY target. A single-target run keeps today's error unchanged.
