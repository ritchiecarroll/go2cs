1. THE EMISSION (measured: the converter at fb885891b, over a 30-line Go repro of the test's parse). It is NOT
Reinterpret<>:
  copy(((ж<array<byte>>)(uintptr)(@unsafe.Pointer.FromPinnedBox(Ꮡdirent))).slice(), data);
`Dirent`'s `Name [1024]int8` is a managed array<sbyte>, so the box has no pinnable storage. The (uintptr) operator
hands out the box's ORDER TOKEN, and the (ж<array<byte>>) operator mints a NativeBox over it. The first
dereference hits arm 2a: "dereference of a managed pointer with no address". Go prints `7 32 3 abc` and
`7 32 3 97 1048` for the write-through and the read; C# panics.

3. WHY IT IS NOT A ONE-LINE golib FIX (read against .claude/rules/golib-gen.md):
- slice<T> has two backings, a managed T[] or a native base. A Go-layout byte view over Dirent spans TWO managed
  objects (the box's scalars and Name's sbyte[]), so no slice<byte> can alias it.
- "A box cannot OBSERVE a write performed through a ref it has already handed out": a golib hook at the operator
  runs when the view is TAKEN, not when copy() STORES. A view minted over a Go-layout native snapshot would read
  right and drop every write silently. That is option (B) below, refused.

4. OPTIONS
- (A) RECOMMENDED: the non-escaping copy through a Go-layout image, converter + golib.
  - Converter: recognize a reinterpret-to-scalar-array view `(*[N]E)(unsafe.Pointer(P))`, optionally sliced
    [lo:hi], used DIRECTLY as an argument of `copy` (dst or src), where P's pointee is a reference-bearing struct.
    Emit golib's copy-through instead of the token view.
  - golib: two public entry points beside NativeStructMarshal's existing private Go-layout encode/decode (the same
    GoFieldOffsets pass the libc funnel uses).
    - CopyIntoGoImage(box, lo, hi, src): encode the struct into a zeroed Go-size scratch buffer, copy src into
      [lo,hi), DECODE back into the box, and return n.
    - CopyFromGoImage(dst, box, lo, hi): encode, then copy out.
  - Exact Go semantics for the statement: copy's count, a partial final record (the test's own comment: "cap(buf)
    < Sizeof(Dirent)"), and padding bytes zero.
  - A struct holding a pointer/string/slice/map/chan/func/interface field is REFUSED BY NAME, as the funnel refuses
    it: an identity problem, not a layout one.
  - An ESCAPING view (`b := (*[N]byte)(unsafe.Pointer(&s))`) keeps today's arm-2a refusal by name. That is a
    stated limit, with no corpus member.
  - It allocates nothing on the GC heap per call (a stackalloc'd scratch up to a cap, a pooled buffer above it).
- (B) a golib-only snapshot view at the (ж<array<byte>>) operator. REFUSED by me: reads right, drops writes
  silently.
- (C) a third slice<T> backing (an element-ref view) so a byte slice can alias split storage. Fully general, but
  it puts a branch on slice<byte>'s hottest paths for one corpus member. Not proposed.
- (D) inline fixed arrays in structs, so Dirent becomes reference-free. A layout-model change with a corpus-wide
  footprint. Not this item.
