(b) DESIGN: one view per chain. The chain mints a view of the callee's receiver field in ONE hop, not one per level.
- The hop needs a ref accessor for the deep embedded field on the outer type, for example
  `static ref NodeDefault ᏑNodeDefault(ref LeftHandSideExpressionBase t) => ref t.UpdateExpressionBase....NodeDefault`.
  Go allows the selector t.NodeDefault, because a promoted field is a field.
- It must be a NAMED accessor of the promoted field, not a lambda. golib resolves a view's Go offset from the token's
  field NAME against the source's pointee (FieldRefBox.GoFieldOffsetOf, ж.FieldRefBox.cs:380). That offset is what
  makes the one-hop view and a chained view of the same field one Go pointer: the managed-exact Equals arm compares
  root plus offset, and the cross-source arm goes through SameGoAddress.
- Sites:
  - go2cs-gen: the forwarder template emits `Ꮡt.of(T.Ꮡ<deep embed>).M(args)` when the promotion path is deeper than
    one level, and generates those deep accessors (FieldAccessGenerator already serves promoted fields).
  - Converter: the promoted-call emission takes the same one hop.
- Route #7 applies (go2cs-gen + golib consumers): the full behavioral suite, GolibTests R/D, GenTests, and a reflect
  -tests build, because reflect's FieldByName().Addr() builds the nested chain and must still compare equal.
