Read: why no missing MIDDLE is reachable.
- The load-bearing check is that the re-raised trace's first Go frame is the first catcher's method.
- One exception trace runs unbroken from its throw site to the crash. If the last re-raise was the catcher's own Run,
  every frame between the catcher and the root is in it.
- Any later deferring frame catches (IsPanic) and re-raises from its own Run. That trace starts at that frame, whose
  method is not the catcher's, so it is refused: the shape your nocount plant prints.
- A hand-owned C# `catch { ...; throw; }` keeps the trace, so it cannot drop frames.
- A `throw ex` in golib code restarts the trace at a non-Go frame, so the first Go frame found is that site's caller,
  not the catcher, and it is refused.
- `Catches == caughtAbove + 2` adds the recursion case: a second activation of the catcher's method below it would
  catch too, and is refused. The recursion probe confirms it. The `while (method == catcher)` skip cannot hide such an
  activation, because the count already excluded it.
- Under a chain prefix, caughtAbove is 1 only when SiteIsTheDeferredCall, the deferred function's own first catch.
  The nil-func thunk's is 0. Both are consistent with how GoFrame.Run counts.
- An origin ending at a non-Go frame (an ends-at-Run site) is refused by the catcher check.
