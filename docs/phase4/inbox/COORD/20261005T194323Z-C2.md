GO-CMP NEW CLASSES ROOTED (std-only probes, converted at the local union 2d75610b7a, linux). NEW-1 is TWO mechanisms; NEW-2 is a design question.
NEW-1a, reflect Call cannot marshal a NAMED func into its unnamed func type (cmp's AssignA row).
  - Probe: `type AssignA func() int` with `Equal(y func() int)`.
    - AssignableTo(In(0), In(1)) reads true, as Go.
    - m.Func.Call(...) panics "reflect: Call using main.AssignA as type func() int"; Go calls it.
  - Root: value_impl.cs marshalCallArg -> marshalIntoSlot has no route from the named func's own delegate type to the unnamed one's, though the signatures are identical.
  - Fix size: one golib arm re-binding the delegate (CreateDelegate over Target/Method), plus reflect canaries. Small.
NEW-1b, a func signature's CHANNEL DIRECTION is lost in reflect (cmp's AssignD row). Go | converted:
    func value param       <-chan bool                          | chan bool
    named func type F      In <-chan bool, chan<- int; Out <-chan string | chan bool, chan int; chan string
    func literal param     chan<- int                           | chan int
    method param (AssignD) <-chan bool                          | chan bool, so AssignableTo false and Equal is never called
    struct field / conversion  <-chan bool                      | <-chan bool (stamped, correct)
  - Root: direction rides only as the /*<-*/ comment on parameters and results; the synthesized func descriptors never see it. The field arm is stamped, the signature arm is not.
  - It is visible in %T and String() of any func type with a directional channel (time.After's type prints `func(time.Duration) chan time.Time`), and in AssignableTo/ConvertibleTo between func types.
  - Fix size: LARGER. A sibling stamp per directional parameter/result (the GoChanDir family), read by func-descriptor synthesis. It needs a census of std signatures first, and of any banked row printing such a %T.
NEW-2, POINTER-KEYED MAP REPORT ORDER (cmp's MapKeyPointer and LargeMapKey).
  - Root: ж.PointerTokens.cs IdentityToken mints a box's token on its FIRST Pointer() request (Interlocked increment), not at allocation.
  - cmp's SortKeys orders pointers by x.Pointer() < y.Pointer(), so the order is whatever SortKeys asked first. Go's matches allocation order.
  - Go's spec does not guarantee that order, but cmp's goldens depend on it.
  - A fix means a sequence number at every box allocation. That is a per-box byte and time cost corpus-wide, which the doctrine names as a cost class. DESIGN ASK, no seat proposed.
