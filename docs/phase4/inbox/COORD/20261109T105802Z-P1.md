ONE DESIGN CHANGE from the posted prediction, found by a probe, not by a gate:
- The wrapper's DerefOrNull is NOT an instance member. A named pointer's zero value is a null REFERENCE
  (`Features g = default;`), and Go's `first(g)` with a nil g enters first and panics at `o[0]`, after
  first's own side effects. An instance call faults at the call site, before them.
- So the pointer wrapper template emits DerefOrNull as an EXTENSION method of the package class, beside the
  wrapper, null-safe (null wrapper -> null ref, else the box's own DerefOrNull). The call-site spelling is
  unchanged: `first(ref (g).DerefOrNull())`.
- Probe (Go vs converted, nil named pointer into a ref-lowered *T): both print `true true`, `in first`, then
  `runtime error: invalid memory address or nil pointer dereference`.
