1. MUST-FIX, box-health.ps1:83. An EMPTY `-Compare` is a silent pass. `if ($Compare)` is false for '', so the
   script prints the line and exits 0 without comparing.
   Scenario: a driver keeps the before-line in a variable and the before-read failed or the variable is
   misspelled: `box-health.ps1 -Compare $before` with $before empty or $null exits 0, "nothing to report". This
   is the rc-2 case in its most likely form: the refusal exists for a wrong line and not for a missing one.
   Minimal fix: decide on `$PSBoundParameters.ContainsKey('Compare')`; an empty or whitespace value prints
   REFUSE and exits 2. One self-test line.
2. MUST-FIX, :21 and :23. A FAILED event-log read is read as "no events". Both Get-WinEvent calls carry
   `-ErrorAction SilentlyContinue`, needed because an empty result is itself an error, but it also swallows
   access denied, an unavailable log service and a bad provider. The field becomes `none`, and Test-Newer
   (:40) returns false for an after-value of `none`.
   Scenario: the after-read cannot read the System log (the box is in exactly the state the tripwire is for);
   newestWhea and lastCrash read `none`; with boot unchanged the script says "nothing happened", rc 0.
   Minimal fix: catch the error; treat only the no-matching-events error id as `none`, and print any other as
   `unread`; in -Compare, `unread` on either side exits 2 naming the field.
3. SHOULD-FIX, :32. The parse accepts any non-space text as a field (`\S+`), so a line with the right words
   and wrong values is not refused. Scenario: a before-line whose newestWhea is some other token, for example
   `unread` after fix 2 or a hand-edited `n/a`: every real stamp compares ordinally LOWER than a letter (:42),
   so no later WHEA event ever trips. Minimal fix: each of the three fields must be `none` or match
   `^\d{4}-\d\d-\d\dT\d\d:\d\d:\d\dZ(/\d+)?$` (boot: the stamp only), else return $null, which is rc 2.
4. SHOULD-FIX, :42, the clock. "Newer" is decided on wall-clock text at one-second resolution.
   Scenarios: (a) the clock is stepped back between reads (time sync after a bad RTC read, plausible on a box
   with hardware faults): a new corrected-error event carries an older stamp and is missed, with no reboot to
   catch it; (b) a second WHEA event in the same second as the newest one read before is missed.
   Minimal fix: carry the event's RecordId in the field and compare it as a number; it rises with each event
   whatever the clock says. State the one limit: a cleared log restarts it.
5. NIT, :18. ToString with a custom format uses the current culture's calendar and time separator. Two reads
   under different cultures (a scheduled task as another user) give different text for one instant; today
   that trips on boot, the safe direction. Pass InvariantCulture and it cannot happen.
6. NIT, :50. Win32_OperatingSystem.LastBootUpTime is derived from uptime and can move by a second after a
   time adjustment: a false "reboot", the safe direction. Name it in the header so a lane does not chase it.

What is sound: an event ageing out never trips; a new event during a wrap trips; rc 2 on the old monitor
