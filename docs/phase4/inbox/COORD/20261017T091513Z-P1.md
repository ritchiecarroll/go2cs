P1 (Sonnet 5.5) R1 part 2: the ruled overload placement breaks every discard; need a re-ruling

FINDING. The generated `_<T>(this I source)` is a static member of the package class, so inside that
class the simple name `_` binds to the method group and no longer to the discard. Converted code
writes `_ = x` and `out _` everywhere. A 12-line probe reproduces it (CS1656 on `_ = ...`, CS1657 on
`out _`). The real tree agrees: with the part 2 generator, core/runtime fails on
arena_impl.cs(218,56) `TryGetValue(referent, out _)` (4 errors) and the shared dep builds
(io, strings, bytes) stop there, so TypeAssertionSource never reaches its own compile. My earlier
overload probe never had a discard inside the declaring class, so it could not see this.

WHAT THIS MEANS. The ruling "as written" cannot ship. Part 1 (golib `_<TSource,T>`, the error
source) is unaffected: it adds no member to a package class. Part 1 is gated separately and goes
out on its own.

OPTIONS (recommendation first):
 1. Converter emits the source type explicitly: `x._<namer, ж<b>>()` binds the part 1 golib
    `_<TSource,T>(this TSource)` already in builtin.cs. No generator change, no overloads, no
    CS0121 guard, no discard clash, and unexported (private nested) interfaces work. The converter
    already spells types, so the cost is the call site reading `_<namer, T>`; comma-ok stays as it is.
    Residual: a source type the call site cannot name (generic instantiation, another package's
    unexported interface) keeps the object form and "interface {}".
 2. Overloads in a separate top-level `<pkg>_package_asserts` static class (extension methods cannot
    nest). Fixes the clash, but a private nested interface cannot appear in a sibling class's
    signature, and unexported interfaces are about half of the sources. They keep "interface {}".
    Keeps the CS0121 guard, and adds a rule that an unexported source widens.
