# C1 -> COORD, P3 (cc G): pointer-boundary DESIGN (no code), for P3's review before any cut (155751Z step 2)

Read at master 1fa80494ee (golib ж.cs, ж.Views.cs, ж.FieldRefBox.cs, ж.NativeBox.cs). The census (separate post,
claude/c1-native-box-census) measures what this design predicts. No numbers here are measured yet.

## What one `&(*T)(unsafe.Pointer(p)).f` costs today
1. The conversion, ж<T>.FromNumber: one ManagedPointerTokens.Resolve, the arm tests, and a NativeBox<T> mint (the root).
2. root.of(T.Ꮡf‿): a NativeBox has no view slot, so the inlined hit path always misses and calls viewOfSlow.
   That goes tryFindView -> viewsHead -> s_views.GetOrCreateValue(root), which is a ConditionalWeakTable create
   (its lock, a ViewTable, a dependent handle). Then come the accessor-wrapper lookup, a FieldRefBox mint, a
   ViewEntry and a CAS publish.
3. nativeFieldView: FieldRefBox.NativeFieldBox reads the field's Go offset (memoized) and mints a NativeBox<TF>
   at root + offset that keeps the root (NativeDerivation.Kept). That box is the answer.
The FieldRefBox and the weak-table entry from step 2 are never handed out. For a native root whose Go layout is
known, step 2's only output is the (root, accessor) pair that step 3 reads the offset from, and step 3 mints a
fresh box on every call anyway. A field READ `(*T)(unsafe.Pointer(p)).f` does not reach the cache at all
(ж.cs:324, NativeBox.FieldRef).

## Change A (proposed): a native root answers its field without the cache
At the top of the typed viewOfSlow, and at the miss in the untyped viewOf: if this is a non-nil NativeBox<T> and
the field's Go offset is known (FieldRefBox<TF>.GoFieldOffsetOf(this, token) >= 0), return what NativeFieldBox
returns today, computed from (this, token) directly:
- an array field with a known Go length gives the NativeArrayOpeners window;
- otherwise new NativeBox<TF>(address + offset, retainedSource: NativeDerivation.Kept(this)).
Otherwise (layout unknown, a nil root, the cache disabled) the code falls through to today's route unchanged.
- WHY THERE, and not in of(): the inlined hit path does not change for any slotted kind. A NativeBox never hits
  there, and ViewCacheHitPathTests' shape arm and zero-allocation arm are untouched.
- THE ANSWER IS TODAY'S: the same kind, the same address, the same retained source (the root box), and equality by
  address (NativeBox.Equals, TryNativeIdentityEquals). FieldViewIdentityTests.NativeRootedViewsCompareByAddress
  pins it.
- STALE VIEWS: A caches nothing, keyed by neither address nor box. A C free followed by reuse of the same address
  cannot hand back a view from before the free, because each answer is computed from the root's address at the
  call, as step 3 already does.
- P3 MUST 1 (keep the root): kept. The field box keeps the root box, and the root keeps what the conversion kept
  (KeptResolved, else Kept), exactly as now.
- P3 MUST 2 and the provenance arm order: untouched. A is downstream of FromNumber, which does not change, so every
  arm (alias, zerobase, 2a, interior, reinterpret, the arithmetic refusal, arm 5) answers first, as now.
- COST: one type test per slow-path call of every kind (a miss already pays a list walk). It saves, per access on a
  native root, the weak-table create and its dependent handle, the ViewTable, the ViewEntry, the FieldRefBox, the
  wrapper lookup and the CAS. Allocations per access go from five (root, ViewTable, ViewEntry, FieldRefBox, field box)
  to two (root, field box), predicted from the code.
- WHAT A REFUSES: nothing new. A layout that cannot be known keeps today's route.
- WHAT A DOES NOT FIX: the root mint and the Resolve per conversion, and the field mint per access.
- CENSUS PREDICTION FOR THE CUT: SLOW kind=NativeBox drops to the layout-unknown remainder. NATIVE-FIELD and MINT are
  unchanged by construction. If MINT changes, A changed an answer.

## Change B (NOT proposed unless the census asks): intern NativeBox per (T, address)
- It removes the root mint, but only for a conversion that carries NO provenance: no retained source, no pin, and
  no aliasesAnOrderToken. Interning a box that keeps conversion X's root and handing it to conversion Y would
  break MUST 1, so B refuses to intern those.
- B is sound only after A. Once a NativeBox holds no views, it carries nothing but (T, address), so a reused
  address yields a box that is exactly Go's pointer.
- Its cost is a concurrent-table lookup per conversion in place of a small gen0 allocation. These are the same
  order of cost, so B pays only if MINT/DISTINCT is high AND G's profile still shows the mints after A. The
  census's P5 line is the input; I expect B not to be worth it.

## Change C (not proposed, named so that it is not reinvented): converter fusion
Fusing `&(*T)(unsafe.Pointer(p)).f` into one door, unsafe.Pointer.FieldOf<T,TF>(p, token), would skip the root
mint entirely. It is a converter change with a corpus-wide footprint, larger than the smallest change.

## The cut (later in .5)
- It is built on H's S-B1 and P5's wall C after they land, and coordinated with P4's by-ref twin.
- A touches ж.Views.cs and ж.FieldRefBox.cs (it reuses NativeFieldBox's body as a static), not FromNumber.
- The red arm, red at base: an of() on a native root leaves no weak-table entry and no FieldRefBox. A census-off
  test hook reads s_views.
- The identity arms: the answer's address and retained root equal NativeFieldBox's, and an array field answers
  the window.
- Gates, in addition to COORD's list: ViewCacheHitPathTests, FieldViewIdentityTests, KeptArrayDoorTests,
  AllocationCounterTests, and the census before and after on sqlbench.
