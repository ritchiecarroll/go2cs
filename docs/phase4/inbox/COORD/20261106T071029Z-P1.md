Sketch:
- Where: assembly attributes in generated files, golib-defined: [assembly: GoExtensionHostList] (a sentinel,
  "this list is complete") and one [assembly: GoExtensionHost(typeof(X))] per host (AllowMultiple). A host is a
  top-level non-generic static class declaring an extension method. Nothing enters the emitted .cs.
- Two writers, because a generator never sees a sibling's output: (1) a new ExtensionHostListGenerator over the
  converter and hand-owned sources writes the sentinel and their hosts; (2) GeneratedSource.AddGeneratedSource, the
  one door every generator file passes, parses each generated file and appends a line per host in it
  ({pkg}_package_asserts, the ᴛxpkg siblings, any future template). Over-listing is harmless.
- How golib finds it: TypeDef walk where raw metadata exists (JIT/R2R, unchanged); else the assembly's own
  GoExtensionHost attributes if the sentinel is present; else GetTypes (today). JIT never reads the list.
- No generator: no sentinel, so GetTypes for that assembly, as today. An OLD generator falls back the same way;
  the unsafe case is a new generator under-listing, which the guard below catches.
- -tests whitebox bridges: the test host is a converted project with go2cs-gen, so its writer 1 lists its bridge
  classes. L2 still reads every assembly. L3's receiver-assembly scope against bridges stays OPEN, untouched.
- OPEN, order: the list's order is not GetTypes order. Order shows only through GetExtensionMethod's MinBy tie
  between same-named, equal-precedence receivers, which one Go package cannot have. Proposed: the guard asserts
  equal method SETS plus no such tie per assembly, rather than equal order.
Files: ExtensionHostListGenerator.cs (new), GeneratedSource.cs, golib GoExtensionHostAttribute.cs (new) and the
registry's fallback, GenTests ExtensionHostListTests.cs (new), GolibTests list-vs-TypeDef guard. No converter,
emission or hand-owned change.
Guards: GenTests (converter host, _package_asserts, ᴛxpkg sibling, nested/generic not listed, sentinel with zero
hosts); GolibTests: for every loaded assembly with the sentinel, listed hosts yield the TypeDef walk's methods,
made to fail once by dropping a host; the AOT probe; route #7 item 4: the full behavioral suite (identical by
construction under the JIT; the AOT probe is the arm that reads the list).

PREDICTION:
- AOT first structural assert (the probe): 255 -> 110-150 ms (GetTypes 75 + first touch of 6,359 non-hosts ~63
  removed; attribute reads +3-15 over 56 assemblies).
- BoGo probe launch (JIT/R2R): 836 ms unchanged within 3%; JIT first assert 117 ms unchanged within 3%.
- Emitted .cs and CNR byte-identical; GenTests +5, the rest unchanged; build time per assembly under +3%.
- Falsifiers: AOT first assert above 170 ms; any assert result unlike Go; any CNR drift.
- Inferred only: PerfTlsHandshake's 516 ms AOT warm-up -250 to -290 ms (its ILC needs ~23 GB: the i9's arm).
Not in L2: L3 (receiver types in the list: GetParameters, 72 ms AOT / 48 JIT, the part that would move BoGo).
