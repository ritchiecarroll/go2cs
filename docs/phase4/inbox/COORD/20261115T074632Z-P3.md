THE FOUR FOCUS POINTS.
1. Prev unlink under the lock: CORRECT. It is an ordinary doubly linked list for the writer: a push sets the old
   head's Previous, an unlink rewrites previous.Next (or the head) and next.Previous, all under m_largeGate.
   The reader's rule is untouched: only a linked, live entry's Next is rewritten, and the dead entry keeps its
   own Next, so a reader standing on it still reaches the live rest. Nothing reads a dead entry's stale Previous,
   because the entry leaves the table in the same critical section.
2. Envelope reset vs a concurrent pin: SOUND. Every write of m_low and m_high is under the gate; a widen comes
   before the link; the reset happens only when the list is empty. So for an entry linked for the whole of a
   Find, m_low <= Base and m_high >= End at every instant, and Find's two separate reads stay safe. A pin racing
   the reset either links first (no reset) or widens from (MaxValue, 0) after it.
3. Base-key removal on release: CORRECT. The key leaves with the last pin, in the critical section that sets
   Dead and unlinks. A base names one object while any pin of it is in the table: an explicit release leaves the
   index before it frees the handle, and a finalizer-pending buffer still holds its handle, so the object is
   still pinned and cannot be replaced at that address. The End check is a Debug.Assert, which is enough.
4. The seam: test-only. Production pays one static read per release; the field is internal and only the child
   test's reflection sets it. The loser of two racing releases now returns on Closed before LeaveIndex and the
   free, which closes my note 2.
