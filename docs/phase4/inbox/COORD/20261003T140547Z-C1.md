1. PACKAGE SHAPE
 a. osx-arm64 and osx-x64 carry the SAME bytes. The darwin assemblies are AnyCPU IL from the darwin/amd64 corpus (corpusArch amd64),
    and the build has no arch axis (GoTargetOS only). Two passes would build identical IL twice. A same-flavor rebuild is already
    known to be byte-identical (push-nuget's own increment-4 note), so a second darwin pass tests nothing.
    SHAPE: one build+pack pass per DISTINCT GoTargetOS (3 passes, not 4). The merge writes runtimes/osx-x64 AND runtimes/osx-arm64
    from the one darwin pack, and an assert checks that each L3 package's two osx entries hash equal.
 b. Why not ONE portable "osx" folder (half the size): go.lib.targets builds the compile twin path from the EXACT RID,
    runtimes/$(NETCoreSdkRuntimeIdentifier)/..., which is osx-arm64 or osx-x64 on a mac. A portable "osx" folder would never be found,
    so a mac consumer would silently compile against the windows surface (the CS0426 seam the 2026-09-24 amendment closed).
    Two explicit folders need no targets change.
 c. What the pack's checks need: the ID-set check and the length-based material compare run per distinct flavor (darwin vs the
    windows reference), and the promotion warning holds unchanged. Measured: exactly 37 csprojs mention GoTargetOS, and they are the 37 L3
    packages (31 w/l/d, 3 windows-only, 1 linux-only, 2 darwin-only: crypto/x509/internal/macos and x/net/route). So any
    non-L3 package that differs materially on darwin is a defect. Expect "0 of 307". Merge-GoNuspecDependencies unions by id, so a
    second osx RID is idempotent. The union GAINS darwin-only deps in 8 nuspecs, all on IDs already published:
    crypto.x509 +x509.internal.macos, net +x/net/route, internal.syscall.unix +internal.abi, syscall +internal.abi,
    internal.sysinfo +syscall, internal.testpty +syscall/+syscall.unix, os.user +syscall.unix, x/sys/cpu +syscall.
 d. SIZE, measured. Published 1.24.13.3, from nuget.org: 343 of 344 IDs total 80.1 MB. The 37 L3 nupkgs are 17.6 MB, carrying
    lib + win-x64 + linux-x64 at 4.47 / 4.47 / 4.43 MB compressed. Darwin Release DLLs that I built at 8f46a9adae (the os
    closure, 9 L3 packages) are +1.2% vs the linux ones in aggregate: os 484,352 vs 496,640; syscall 724,480 vs 730,112;
    runtime 2,598,912 vs 2,520,576. ESTIMATE: +4.5 MB per osx folder, so +9.0 MB for two (80.1 -> ~89 MB, +11%; L3 17.6 -> ~26.6 MB).
    go.os 544 KB -> ~820 KB; go.syscall 769 KB -> ~1.22 MB; go.runtime 2.67 -> ~4.4 MB. No new IDs: still 344, prefixes unaffected.
    (The darwin and published DLLs are from different trees, so this is a size ratio, not a byte claim.)
 e. TODAY'S BEHAVIOR on a mac, a fact for the label: no osx folder ships, so every L3 package loads lib/ = the WINDOWS flavor, with
    the loud GOOS-mismatch warning. Shipping osx is a correctness fix before it is a validation claim.
