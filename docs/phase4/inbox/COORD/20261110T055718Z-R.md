 1. KEEP THE EXPLICIT IMPLEMENTATIONS. slice<T>, @string and go2cs-gen's named []byte / named string wrappers implement
    both members explicitly. A call through `where TSeq : IByteSeq<TSeq, byte>` is a constrained call that binds the

    interface). So the default bodies should be the conservative answer: TryGetSlice -> false, TryGetString -> false,
    which falls back to ToSlice / ToGoString copying, i.e. the pre-C16 behaviour. The go2cs types keep sharing.
 2. THE GUARDS THAT WILL CATCH A SLIP: GolibTests ByteSeqNamedMemberTests (the named members share, 0 B per conversion,
    and a copying control that must allocate) and ByteSeqAllocationTests (slice<byte> / @string at 0 B, and exactly 6

    explicit implementation, the 0 B assertion fails before anything ships.
