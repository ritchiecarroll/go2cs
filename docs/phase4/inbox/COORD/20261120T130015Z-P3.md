Verdict: APPROVE WITH CHANGES. The type does what the design said: a spread carries the slice header, .slice()
returns it, no slice-to-pack conversion exists, and there is no shared state. One MUST on the literal guard.

1 MUST-FIX VP:81 and EA:513-546: the guard lists the cases P2 measured instead of covering what the compiler may
  do. Create (VP:117) casts the compiler's ReadOnlySpan to a writable Span. The compiler is free to back an
  all-constant ReadOnlySpan with storage that outlives the call; the primitive case is read-only data and
  faults, which P2 found. The same lowering can use a cached static array where the constants are not blittable,
  and the only constant of a reference type is null. Scenario to measure before the regen: f(nil, nil) into
  `func f(xs ...any)` (or ...error, ...*T) whose view prologue writes xs[0] = v. If the compiler caches that
  array, the write faults nothing and changes what the NEXT call of that call site receives, on every thread:
  silent, and worse than the fault. Neither guard covers it: IsReadOnlyLiteral is primitive or enum only, and
  the converter rule admits a view with element writes for interface, pointer and func elements.
  Fix that does not depend on the compiler's choice: (a) converter: any element write refuses the stack view,
  whatever the element type (a spread still aliases through the heap prologue; a literal is copied); (b) golib:
  Create marks the pack as compiler storage, and the Span conversion (VP:96) copies every such pack, not only
  primitive ones. Post the count of prologues (a) moves with the prediction.
2 SHOULD-FIX EA:513, writes the rule does not see. It tests only an AssignStmt target and an IncDec operand whose
  direct parent is the statement. Missed: a parenthesised target `(xs[i]) = v`, and a range clause that assigns
  into the pack (`for _, xs[0] = range ys`). A unit arm for each.
3 SHOULD-FIX slice.cs:679 and ISliceTypeTemplate. The constraint member IArray<T>.ꓸꓸꓸ stays a Span. A generic
  function `func F[S ~[]E, E any](s S) { g(s...) }` reaches the spread through the constraint, gets a Span, which
  converts to a literal pack (VP:103), and g's heap prologue copies: the wall E defect is still there for a
  spread through a constrained slice type. Either give ISlice<T> its own pack-returning spread member, or name
  this as a remaining copy point beside sslice.ToSlice in the BOARD row, with an arm that shows today's answer.
4 SHOULD-FIX GoReflect.TypeLayout.cs:1915 with value_impl.cs:2372. variadicTail accepts exactly slice<TArg>, a
  TArg[] or null. CallSlice now passes whatever marshalCallArg returns for the last argument. Before, the tail
  was rebuilt element by element, so any assignable value worked. Scenario: CallSlice with a Value of a NAMED
  slice type (`type S []T`, assignable to []T). If marshalCallArg hands back the named wrapper, this throws an
  ArgumentException where Go calls the function. Add that arm; unwrap in variadicTail if it is red.
5 NIT GoReflect.TypeLayout.cs:1567. TryFuncShape reports a Span<T> tail as variadic, but invokeVariadic and
  MakeVariadicDelegate now accept only variadic<T>, so such a delegate reports variadic and then cannot be called.
