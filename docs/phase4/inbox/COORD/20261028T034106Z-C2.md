**The change.**
- go2cs-gen (additive): a `num:` wrapper declares `explicit operator T(W)` for every basic numeric T
  (int8…uint64, nint, nuint, uintptr, float32, float64), each `(T)value.m_value`. The underlying is skipped
  (its implicit operator stays), and so is nuint over uintptr (the bridge). Complex wrappers get none.
- Converter: one predicate, namedNumericConvertsDirectly. It holds for a non-generic, non-complex named
  numeric whose written right-hand side is a basic type or a same-package named type. It drops the hop at
  the six named-to-basic sites:
  - the FROM conversion branch;
  - the TO branch's inner unwrap, `(hex)(uint64)(int32)off` -> `(hex)(uint64)off`;
  - `make` length and capacity;
  - slice bounds (`(int)(nuint)(x)`);
  - shift counts;
  - `int64` indexes.
- A type written over ANOTHER package's named type keeps its named [GoType] and its hop.
