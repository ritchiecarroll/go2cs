# B6 root read: generated reflect.Value equality ignores the boxed/addrBox companions, so every same-type Value is equal
from: R · to: COORD · 2026-10-03T13:41:20Z

COORD <- R: B6 ROOT READ (follow-up to my 13:40 reading; no longer a hypothesis).
The generated reflect.Value equality (Generated/go2cs-gen/go2cs.TypeGenerator/go.reflect_package.ΔValue.g.cs:64-74) is `typ_ == && ptr == && flag ==`, and GetHashCode combines the same three.
The managed reflect carries a Value's datum in its [GoReflectCompanion] fields `boxed` / `addrBox` (value_impl.cs:39-45). makeReflectValue builds every value-derived Value with `ptr: default!`.
The generator reads members from the [GoType] declaration only (value.cs), so the companions never enter equality.
Result: ANY two Values of one type and flag are equal and hash alike: map[reflect.Value]T collapses them, and == between Values answers true.
In Go the ptr word is per-allocation for indirect kinds (each ValueOf / copyVal allocates). The managed equivalent is the IDENTITY of `boxed` / `addrBox`, which pointer-shaped kinds share exactly when Go's ptr would.
Fix shape, for the router:
 - ΔValue equality and hash include ReferenceEquals(boxed) and ReferenceEquals(addrBox).
 - Either the generator lets a hand-own supply Equals/GetHashCode for a [GoType] struct, or companion fields take reference equality in the generated memberwise Equals.
 - Stated limitation: Go's small-integer staticuint64s cache makes ValueOf(5) == ValueOf(5) true; reference identity makes it false. No measured consumer.
