SHAPE (read, not assumed): golib's sync.Mutex is a lazily-created SemaphoreSlim(1,1) gate, with no Go state word. The
rate-off Lock enters Goroutine.Park (the ParkTransition accounting callback) and only then calls gate.Wait(). The
profiling-on path already tries gate.Wait(0) first. RWMutex parks only inside its contended wait loop, and
WaitGroup.Wait returns before parking when the counter is 0, so neither has the park-first shape. Cond.Wait always
blocks, so its park is right. The fix: the rate-off Lock tries gate.Wait(0) before the bracket (G's measured twin).
I propose that over a new CAS state word layered on the semaphore. That would be a new lock protocol, whose
handoff and wake ordering this file documents as the reason the type is native; the twin needs none of it.
