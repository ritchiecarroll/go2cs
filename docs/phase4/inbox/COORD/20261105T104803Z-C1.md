How it works:
- The escaping panic disposes the root's scope, clearing Goroutine.Current, before the backstop reports on the same thread.
- So Goroutine.Run's first-pass filter (Observed, where BeginFatal already sits) records the escaping exception and its goroutine.
- Goroutine.Crashing(thrown) returns that goroutine for that exception, and Current otherwise.
- crashTraceback writes through appendGoroutineHeader and appendCreatedBy, the same helpers runtime.Stack uses.
- Main still prints goroutine 1 with no creator. A thread with no identity keeps the literal header.
- The record is keyed on the exception because GolibTests runs roots inline and catches the escape. A thread-only record would name a later panic after the earlier goroutine; my first GolibTests run caught exactly that design.
- Both slots reset on pooled-thread reuse (GoroutineThreadState.Register) and are in the ThreadStateCensus.
