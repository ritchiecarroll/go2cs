   at the poll the pick is uniform. The skew is in the PARK path: when nothing is ready, Run enqueues one
   waiter per case in SOURCE order (channel.cs:947, `for i = 0..ops.Length`). With two cases on ONE
   channel, both waiters sit in that channel's Sendq (or Recvq) case 0 first, and the counterpart's
   DequeueForWake takes the head, so case 0 wins every parked select. Go enqueues in lockorder, which
   for cases on one channel derives from the shuffled pollorder, so Go's parked order is random.
   Note: the favoured case is the FIRST in source order. The test's "92 ones" are `case c <- 1:`.
   The lock order (sorted by channel Id) does not bias anything: every lock is held for the whole poll.
