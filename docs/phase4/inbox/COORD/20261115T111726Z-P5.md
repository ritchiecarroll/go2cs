BOX KIND DESIGN BLOCK (your 09:54Z item 2), before any cut. Sized again at the end. Census: posted 11:13Z.

THE CLASS. `(*[N]E)(unsafe.Pointer(&x.f))` where x's converted struct holds a reference, so x has no address.
Today: refused by name. In every census closure the field f is ONE NUMBER and the view fits inside it
(N x size(E) <= size(f)): a port as two bytes, an address word as four.

WHAT THE BOX IS. golib already answers, for every pointer box, "your pointee's storage as bytes": the
non-generic IReinterpretSource (PointeeSize, PointeeContainsReferences, RawSlot, recomputed from the live box on
each access, so the collector may move the struct between two reads). PointerExtensions.Reinterpret reads one
value through it. The new kind is the same read for N elements:

  internal sealed class ReinterpretedArrayBox<E> : ж<array<E>>
      holds     the FIELD's own box (the `x.Ꮡf` the converter already passes) and N
      made      only when the field's type holds no reference, E holds none, and N x size(E) <= size(field).
                Anything else is refused by name at the conversion, in true words (see CROSSING below).
      element i ref to byte i x size(E) of the field's RawSlot, read as E. Index checked against N, Go's panic.
      Value     refused by name (no array<E> exists), the words NativeArrayBox uses.
      nil, ==   the field box's own identity: two views of one field are equal, a view is never nil.

READ AND WRITE. p[i] reads the field's bytes at that moment; a store writes them. No copy exists to lose a write.

ALIASING WITH THE FIELD'S OWN ACCESSES. `x.f = v` and `p[i]` name the same storage through the same box, so each
sees the other at once, in both directions, as in Go. Byte order is the host's, as Go's is. No state is added
that a race could tear.

CROSSING INTO THE NEXT FIELD. A view longer than its field (N x size(E) > size(f)) is REFUSED BY NAME at the
conversion: "the view is N x size bytes and the field holds M; the struct holds references, so the fields after
it have no address to read". That is the held-extent rule with the extent equal to the field. Over a
reference-free struct the same view is legal today (V2 reads the following fields inside the root's extent);
that difference is stated in the reference page. Census: 0 sites cross.

A FIELD THAT IS NOT A NUMBER. A struct field with no reference in it (two uint16) is served the same way: its
RawSlot is contiguous. A field whose converted form holds a reference (an array, a GUID with an array in it) is
REFUSED BY NAME: its bytes are not contiguous. 1 census site (the Bluetooth GUID). Door C's layout copy.

PER-KIND ARMS (golib ElementRef has three; this adds the third):
  NativeArrayBox<E>            native address + i x size             unchanged
  INativeWordArray<E>          word i                                unchanged
  ReinterpretedArrayBox<E>     RawSlot + i x size                    NEW, ahead of the `Value[i]` fallback
  whole load / store (part C)  Load copies N through the element; Store writes N through it        NEW arm
  slice(), range by value      range over the pointer takes the element per round; an open slice `p[:]` is
                               refused by name (a slice header needs storage it can name; 0 census sites)
  no generic virtual method anywhere (GenericVirtualMethodGuardTests stays green by construction).
