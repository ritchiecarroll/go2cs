1. PAIRING (required). §3.B.1 pushes entries only for panic sequences, and §3.B.4 pairs each GoFrame.Run frame with the next entry. That is positional, but a Run frame is on the stack whenever ANY deferred sequence runs, including a normal return. Reachable shape: a panic's deferred call invokes a helper that defers, and the helper's deferred call calls Callers. The stack is Callers, helper.func1, Run (normal), helper, func1, Run (panic), TestX. The normal Run takes the panic's entry, and the splice lands one sequence too high. Fix: push one entry for EVERY Run activation in its m_count > 0 branch, holding `owned` (this frame's own panic, or null), not `handling ?? outer`. That branch already saves and restores GoFuncRoot.HandledPanicValue, so the no-panic path already pays a thread-static read and write there. The record's "none on the no-panic path" then becomes "one push and pop per deferring return, beside the existing save/restore". A Run with m_count == 0 runs no user code, so it can never sit under a Callers and needs no entry.
   Also: when a deferred call's panic REPLACES the handled one inside one Run (the AbortedPanic shape), that Run's entry must be updated to the new panic, so later defers in the same sequence splice the panic Go would show.

2. OWNER FRAME, CHECKED. "The panic's SiteTrace Go-source frames up to (not including) the frame that owns the sequence": take the trace from the exception object as caught by the owning frame (StackTrace(ex, true)). It spans exactly the throw site to the catching frame, so the owner is its LAST Go frame. Drop that frame, and ASSERT that its MethodBase equals the next live Go frame of the walk. On a mismatch, splice nothing and answer today's stack. A missing splice is a known divergence; a wrong one is a silent lie. For a re-panic, the raised exception's own trace (throw site to Run's inner catch) gives func1 between the two gopanics, which is what DoublePanic wants. So SiteTrace = the raised exception's own trace, never the inherited PanicTrace, as §3.B.2 says.

3. ROUTE THROUGH M3's WALK (order dependency: B lands on M3). M3 (claude/p2-stack-roots, local, pushing after its readings) reshapes captureCallers' loop. Each frame that will be reported passes skip, then the capacity check, then is stored. It also adds internRootFrame(function, file, line), which interns a record no live call site backs, and it appends runtime.goexit after the loop. The spliced frames must go through the SAME skip and capacity path: Go's skip counts gopanic, and a full buffer ends the walk from the top. The spliced frames should be interned with internRootFrame, so every walk answers one PC per Go call site. Go has one call site per spliced frame per GOOS (gopanic always reports panic.go:792). If B ever models sigpanic's two paths (signal_unix.go 915 and 925), add the line to internRootFrame's key; today the key is the function. Spell the file GOROOT-relative ("runtime/panic.go"), as the other stdlib records are. M3 also changes §2's "got" column: testCallersEqual stops losing the test function, so read R's red arms on the M3 base.

4. NAMES AND IDENTITY. Match Run frames by MethodBase identity (cached handle), never by name. Agree with NoInlining on GoFrame.Run, and put it in the same seat. runtime.gopanic is also a real converted method. If a live gopanic frame is ever walked (Go code calling it directly), it interns a second record for the function with a different Entry. That is harmless to the six rows, but name it rather than fold it.

COVERAGE: yes for Panic, DoublePanic, NilPointer, DivZero and DeferNilFunc, given the kinds in §3.B.3 and changes 1 and 2. For WithLoop, agree on the residual. The converter's one-bit hint is Go's open-coding rule (no defer in a loop, at most 8 defers, returns times defers at most 15), not only "in a loop"; state that rule if the hint is ever cut. NOT COVERED, and fine to leave: CPU-profile stacks sampled inside a deferred call. The sampler walks threads through EventPipe, not captureCallers, so it will not show gopanic. The heap and block recorders do go through callers() and will show it, as Go's do.
