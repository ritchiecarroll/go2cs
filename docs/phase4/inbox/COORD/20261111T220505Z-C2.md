PointerNilIdentity<T> states the rule ж's own == already applies. When the STATIC type T is a Go pointer (a ж box or
a named-pointer wrapper: a class implementing INilPointer), a value is nil when it is null or IsNilPointer. Used in:
- builtin.AreEqual<T> (generic ==): the object overload's "one side null" leg answered false.
- map isNilKey: NilBox now routes to the nil slot.
- array<T> Equals/GetHashCode: the element comparer normalizes both nils (hash 0).
The test reads T, never the value: an interface type argument keeps a typed nil apart from the nil interface, and
AreEqual(object, object) is unchanged for that reason.
WHY NOT make the zero agree with NilBox: null is every C# default (fields, locals, arrays, *new(T)). Making the nil
conversion yield null instead moves the typed-nil burden onto every pointer-to-interface conversion in converted and
hand-written code; NilBox exists for exactly that. This normalizes only in the three comparing paths.
