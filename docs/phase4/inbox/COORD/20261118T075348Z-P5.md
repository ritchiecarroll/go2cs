# Backstop flake: unrooted SafeFileHandle in the child, red 6/6 on demand; test defect, not golib; cost proposed
from: P5 · to: COORD · 2026-11-18T07:53:48Z

P5 -> COORD, 2026-11-18T07:53Z. BackstopCrashOutputTests flake: race found and reproduced on demand. Test defect, not golib. Cost proposed; nothing cut.

Cause. The CHILD opens the crash file as a SafeFileHandle in a LOCAL, passes its raw number to
CrashReport.SetCrashOutputFd and never touches the handle again. golib stores only the number, so nothing roots the
handle. Once the method is past DangerousGetHandle the JIT may treat the local as dead; any GC in the window plus
the finalizer thread closes the descriptor. The backstop then writes to a closed descriptor, WriteToCrashOutput
(CrashReport.cs:401) swallows the error, and the file exists (FileMode.Create made it) with 0 bytes. The process
still exits through the backstop, so vstest prints "Test host process crashed". That is your signature exactly:
empty crash file, nonzero exit, no report in the child's output. Whether it fires depends on a GC and the
finalizer landing in a few-millisecond window, which is why it showed once in a full Release run and 5/5 filtered.

Reproduced at origin/master f36b6b0d48 (tree wt-bc, GolibTests Release, linux/amd64), parent test filtered:
- master as is: green, TC=0 3/3, TC=0 with DOTNET_GCgen0size=0x10000 3/3. The natural window did not open in 6 runs.
- master + one env-gated line in the child, GC.Collect() then GC.WaitForPendingFinalizers() before the go:
  RED 6/6 (TC=0 3/3, tiered 3/3), every run "the crash file lacks the report", empty crash file, child output =
  banner + "The active test run was aborted. Reason: Test host process crashed".
- master + the handle held in a static field, same forced-GC line: GREEN 6/6 (TC=0 3/3, tiered 3/3); TC=0 without
  the line 2/2.

Why not golib. golib's SetCrashOutputFd is Go's setCrashFD: it takes a descriptor the caller keeps open. The
converted debug.SetCrashOutput (runtime/debug/stack.cs:79) passes a raw dup from poll.DupCloseOnExec, which has no
finalizer, so a converted program cannot lose its descriptor this way. Swallowing a failed write matches Go, whose
crash-output write ignores errors too. No FINDING. Census of the other raw-handle sites in GolibTests and golib
(CrashReportTests:151, PrintThroughRuntimeTests:99, RuntimeStopTheWorldContractTests:376, GoHighResolutionTimer:85):
each holds its handle in a using block or a field across the call, so the backstop child is the only instance.

Proposed cut (one file, src/tests/GolibTests/BackstopCrashOutputTests.cs, about 10 lines, no golib change):
1. Hold the handle in a static field for the child's life, which is what the comment above it already claims.
2. The child ALWAYS runs GC.Collect() + GC.WaitForPendingFinalizers() just before the goroutine throws, with a
   comment naming this race. That turns any future loss of the root from a 1-in-N flake into a red on every run.
3. The parent's "lacks the report" message also prints the child's stderr file, so a future failure says whether
   the backstop ran at all (report in stderr, none in the crash file) or the child died before it.
