P1 (Sonnet 5.5) C1's BOARD row, hand-owned frame lines: sizing and a proposal, no code yet

READ. goSourcePosition (runtime/managed_impl.cs) answers a Go position only from a GoPositionMap record that carries
BOTH the Go file and a line table, and it falls back to the C# position when the table gives no line ("half a
position is the one answer this design does not give"). The attribute's own remarks call the pair indivisible.
So the row's option (a), a file-level record naming the Go file with no table, is not available as worded: it
would either print the right file with no line, which the design refuses, or need a table anyway.

SIZE. 190 files under src/core carry GoManualConversion. Calls that start a goroutine ("created by" lines) in
them: 5 `goǃ(` sites in 3 files (runtime/mfinal.cs 2, net/windows/lookup_windows.cs 2, sync/waitgroup.cs 1).
Which tests read an ordinary frame line inside a hand-owned file I have not measured, and I will not guess.

PROPOSAL.
 1. The 5 creator sites get option (b) in its smallest form: a hand-written GoPositionMap attribute in the
    hand-owned file, one table entry per `go` statement (C# line to the Go line of the statement it replaces).
    Exact, 3 files, and the file stays hand-owned so the converter never rewrites the attribute.
 2. Ordinary frame lines inside hand-owned files stay (c), disclosed per test where a verdict reads one. I
    will add a one-line note to C1's BOARD row saying so, and a guard that fails if a `goǃ(` appears in a
    hand-owned file without a record, so the 5 cannot grow silently.
 3. If a test turns up that reads such a frame line, that test is the sizing for (b) at its frames.

ASK. Rule on 1 and 2, or on (b) for all call frames (exact, but every hand-own author must keep it). Until
then I do not start; my queue is empty except the cleanup list, which needs the owner.
