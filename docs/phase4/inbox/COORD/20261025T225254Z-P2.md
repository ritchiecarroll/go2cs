ONE ROOT, confirmed host-neutrally (two scratch GolibTests probes with fake libc functions, never
committed): on darwin's libc funnel (GoLibcCall.Call -> NativeStructMarshal.CallLibc) an argument
whose pointee IS or HOLDS a non-nil Go pointer reaches libc as the raw order token. That is the
2026-09-27 ruling's option (b) working as designed: nil pointer fields encode as 0, anything else
keeps the token so libc answers EFAULT. Its remarks already name "Msghdr/Iovec as hand-own mirrors"
as the follow-up. The two symptoms differ only in WHO dereferences the token:
- writev (zsyscall_darwin_amd64.cs:1906, reached from internal/poll via linkname): &iovecs[0] is a
  token (Iovec.Base is a ж<byte>; probe: 0x80000002_00000000). MarshalledSizeOf(Iovec) is 16, but the
  Base fields are non-nil, so the token stays and the KERNEL's copyin refuses it: EFAULT, "bad
  address", nothing written, the client reads "". Behind it: the marshaller copies ONE box per token,
  so even a marshalled iovec would carry element 0 of 10. Linux hit the same seam on 2026-09-02 and
  fixed it with syscall.GoWritevNative (blittable NativeIovec, each Base pinned) plus a whole-file
  hand-own of internal/poll's fd_writev_unix.go. darwin has neither; NativeIovec is already declared
  in syscall/darwin/sockaddr_darwin_impl.cs for sendmsg/recvmsg.
- readdir_r (Getdirentries, syscall_darwin.cs:279): the entry crosses as a correct 1048-byte native
  copy, but the result slot is ж<ж<Dirent>>, a pointer pointee the marshaller cannot classify, so
  libc gets the raw token. libSystem's readdir_r stores *result = entry IN USERSPACE: a store to a
  non-canonical address, a GP fault, delivered as SIGBUS (inferred; no mac trace read). Behind it:
  entryp is never decoded back, and copy(buf, unsafe.Slice((*byte)(unsafe.Pointer(&entry)), reclen))
  panics today ("dereference of a managed pointer with no address ... arm 2a", probe-confirmed).
