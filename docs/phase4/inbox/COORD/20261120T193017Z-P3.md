1. SHOULD-FIX, DESIGN-mn-pin.md:311-313 against GoScheduler.cs:266. The text says the Enqueue gate's cost is "a cost to read in M1". M1 as defined (:155) is the UNLOCKED cost, base against pin build, with no pinned goroutine alive, so s_blocked is 0 and the gate is never taken: M1 cannot read it. The case that pays is the common use of LockOSThread: one goroutine locked for the program's life and parked on a channel most of the time (a UI or GL thread). While it is parked, s_blocked is at least 1, so every Enqueue with no idle carrier takes s_carriersLock (:383), and under saturation no carrier is idle, so that is every Enqueue, from every carrier, on one lock. Minimal fix to the plan: a run in M1 or M7 with one pinned goroutine parked for the whole run and all P busy, reading the unbuffered ping-pong's cost against the same run with no pinned goroutine, with a stop line (1.25x is the band the design uses elsewhere). If it misses, the cheap cure is to keep the unblocked count where Enqueue can read it without the lock and call EnsureCarrier only when it is under s_procs; with K pinned parked and P busy it reads P and the lock is skipped.
