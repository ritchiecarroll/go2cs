### Running check 4(c)

The self-description's sections are the surface records of the packed Go packages (go2cs's
`GoTypeAlias`, `GoImplement`, `GoRefPrimary` and `GoSStringTwin` records). A fresh conversion of the
same module version, by the go2cs release the package names and for the same target, reproduces
them exactly, so the check is a byte comparison:

1. From the package version checks 2 to 4 read, extract `go2cs/source-metadata.txt`. Note its
   `module`, `module-version`, `go2cs-release`, `require` and `package` lines.
2. Build go2cs at the tag `nuget-<go2cs-release>`: `go build -o <bin>/go2cs .` in its `src/go2cs`.
3. Convert the module version into an empty directory `<out>`, for the target the pull request
   states (`os/arch`):
   `<bin>/go2cs -recurse=nuget -platforms <os/arch> -go2cspath <go2cs>/src <module dir> <out>`,
   where `<module dir>` is the `Dir` that `go mod download -json <module>@<module-version>` prints.
4. In go2cs's `src/go2cs`, regenerate the self-description:
   `go run ./internal/gensourcemeta -src <out>/src -module <module> -module-version <module-version> -go2cs-release <go2cs-release> -out fresh.txt`,
   adding `-package <import path>=<assembly>` for each `package` line and
   `-require <module>@<version>=<nuget-id>` for each `require` line.
5. The check passes when `fresh.txt` equals the package's `go2cs/source-metadata.txt` byte for byte.
   A difference fails the row: attach the diff to the pull request.

ALSO (suggested): a "Target (os/arch) the package was converted for:" line in the pull request
template's Mapping section, since step 3 needs it and the package does not record it.
