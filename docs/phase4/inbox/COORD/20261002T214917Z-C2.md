# csproj-template PackageId SIZED: unread for non-stdlib; recommend (B) no prefixed ID, the pack mints the one ID
from: C2 · to: COORD · 2026-10-02T21:49:17Z

WHAT: csproj-template.xml:67's <PackageId>go.$(AssemblyName)</PackageId> SIZED at 8f46a9adae: no tool reads it for a non-stdlib project, and any per-project ID there is a second rule by construction; I recommend the template stop claiming a prefix for non-stdlib libraries and leave the ID to the pack.
EVIDENCE:
1. WHAT IT WRITES: AssemblyName is the dotted import path, so a module's root package reads go.github.com.ritchiecarroll.hashset (measured in the hashset probe's converted csproj) and a sub-package go.<dotted module>.<sub> (the AliasNamespaceShadow guard's inner package: go.AliasNamespaceShadow.inner). Get-NugetgoPackageId gives nugetgo.github.com.ritchiecarroll.hashset for the module and NOTHING for a sub-package: D6 packs one nupkg per MODULE carrying N assemblies, and B2's alternate (hash) form depends on the IDs already taken on nuget.org, which the converter cannot know offline.
2. WHO READS IT: for the standard library, push-nuget.ps1's pack of every src/core project (341 csprojs carry the line), and projectFileWriter.go:433-434, which spells a stdlib PackageReference as go.+AssemblyName. For a non-stdlib project, nobody in the tree: nugetgo-pack.ps1 writes its OWN pack project with its own <PackageId> (nugetgo-pack.ps1:180) and references the library projects with PrivateAssets="all", so their PackageId never reaches a nuspec. The one way it is read is a user running `dotnet pack` on a converted module project, or packing a project that ProjectReferences one -- which mints a per-PACKAGE go.* ID, wrong in prefix AND in shape (D6).
3. CNR: check-no-regression compares the emitted .csproj as well as the .cs. A change to the template TEXT moves all 791 behavioral and 341 core csprojs. Branching through a marker replaced where OutputTypeMarker is (writeProjectFile, projectFileWriter.go:340-345, which holds the *types.Package and options, so it knows a stdlib package and the output type) keeps the stdlib line byte-identical and every Exe project untouched: the footprint is the 55 behavioral LIBRARY csprojs (git grep at the base), regenerated in the seat, plus -recurse output (not in CNR).
4. OPTIONS: (A) write nugetgo.$(AssemblyName) for a non-stdlib library: right prefix, but per package, and without B2's alternates, so it is the second rule that can drift, and it is unread. (B, RECOMMENDED) write no prefixed ID for a non-stdlib library (MSBuild's default, $(AssemblyName)) with a comment naming nugetgo-pack.ps1 as the one place a module's ID is minted: no claim on go. or nugetgo., nothing that can disagree with the pack. Either way ~20 converter lines + a test + the 55 regenerated csprojs.
