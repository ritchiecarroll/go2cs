# C2: B2 DESIGN BLOCK (before any cut): decode a VALUE at T's Go layout into a fresh managed T; prerequisite is a dims stamp on [0][N] fields; three questions

The target: `*(*T)(p)` read as a VALUE, where T is a Go struct kept out of inline arrays (array<T> fields) and p is a
NativeBox. Today that read is B0' (managed source) or P5's B2 (C memory). The motive is TBF_ctx in modernc libc. My
09:43Z note also named 2 musl log tables and an 8 KiB netlink buffer: same shape, unmeasured.
WHY IT IS SOUND: Go's `x := *(*T)(p)` is a COPY, so a decode into a fresh T is exact for reads. Nothing can alias the
result, so a decode never has to write back.
G1, PREREQUISITE (converter): make T's Go layout KNOWABLE.
- GoFieldOffsets(T) needs every array field's dims. A field's dims come from the zero instance's initializer
  (`= new(18)`). A `[0][1042]` field's zero instance is an EMPTY outer array, with no element to measure, so 1042 is
  lost and TBF_ctx's layout is "unproven".
- Fix: stamp `[GoArrayDims(0, 1042)]` on a field whose outer length is 0 and whose element is an array (the existing
  attribute; FieldStampedDims already reads it).
- Consequence: TBF_ctx becomes PROVEN mismatched, so the existing layout floor names it before B0' does. Both are
  named; B0' stays for other unproven shapes.
G2 (golib): `GoValueCodec<T>.Decode(byte* address) : T`, walking GoFields at their Go offsets:
- reference-free scalar or value struct: an unaligned read;
- array<E> with dims [N, ...]: a fresh array<E>(N), filled element by element at E's Go stride (recursive);
- nested struct: recursive;
- any OTHER reference kind (pointer, string, slice, map, chan, func, interface, unsafe.Pointer): refused by name.
  Those bytes are a native-origin contract (an address), which is P5's B2, not this.
G3 (where reads reach it), two options; I recommend D2:
- D1 (golib only): ValueAddress decodes. Not possible: Value returns `ref T`, and a ref to a fresh copy would silently
  swallow writes.
- D2 (converter + golib): an RVALUE dereference of a pointer to a kept-out, array-holding struct emits `p.GoValue()` in
  place of `~p`. GoValue on a NativeBox decodes (G2); on every other box it returns the value as today.
  - The converter already decides "kept out", so the trigger is a fact it holds, not a new analysis.
  - Writes and field updates keep today's emission and stay refused by name, unless they reach a field at its Go
    offset (FieldRef), which works now.
  - This covers TBF's literal site AND a pointer stored first and dereferenced later.
FOOTPRINT, predicted by census (go/types, std, 4 targets):
- `*(*T)(unsafe.Pointer(x))` whole reads of a struct whose only references are arrays: linux/amd64 0, darwin/amd64 0,
  linux/arm64 0, windows/amd64 1 (SID_IDENTIFIER_AUTHORITY, a 6-byte struct that is inline-admitted, so not kept out;
  native source).
- [0][N] fields in std: 0 (the W15 census), so G1 moves no std bytes.
- D2's general rvalue `*p` over kept-out array-holding structs is NOT yet censused; that is Q2.
ARMS, red first: (1) the held-back TBF value read prints what Go prints (go2cs = go on linux); (2) a write through the
same pointer is still refused by name; (3) a T with a string field is refused by the decode by name; (4) G1's stamp
makes ClrLayoutMismatch(TBF_ctx) non-null; (5) C memory decodes as well (see Q1).
