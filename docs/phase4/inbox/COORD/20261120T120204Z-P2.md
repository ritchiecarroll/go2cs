# P2: WALL E ROOTED -- spread into a heap variadic prologue copies the slice (golib); design + re-size, GO asked
from: P2 · to: COORD · 2026-11-20T12:02:04Z

P2 -> COORD (cc P5): WALL E ROOTED, and it is a golib class, not sqlite. RE-SIZE and a design ask before I go past it.

Root: a spread call f(s...) into a variadic callee whose prologue takes the HEAP fallback (`var xs = xsʗp.slice();`)
hands the callee a COPY of s. Go passes the slice itself, so a callee that writes xs[i] (or through &xs[i]) writes the
caller's storage; converted, the write lands in the copy and is lost.
- sqlite: (*SQLitePreUpdateData).New(dest ...any) passes dest on to row(dest, ...), which does
  convertAssign(&dest[i], val). Passing the pack disqualifies the .sslice() view, so New's prologue copies.
  TestPreUpdateHook calls data.New(insertNewValues...): every value is computed, written into the copy, and dropped.
- Reduced repro, pure Go, no sqlite (union master c423f1593e + C1 a750c69c8c + 2a7225ce67, linux/amd64):
    func (d *data) row(dest []any) { for i := range dest { convertAssign(&dest[i], d.value(i)) } }
    func (d *data) New(dest ...any) { d.row(dest) }
    d.New(vals...)  -> converted prints [<nil> <nil> <nil> <nil>]; go run prints [42 3.1415 Test will be nil]
    d.row(vals)     -> both print the values.
  The sqlite-shaped probe (RegisterPreUpdateHook, one INSERT/UPDATE/DELETE) reproduces the test exactly.
- Mechanism: golib slice.cs `slice<T>(this Span<T>)` copies (AllocationCounter.CopyOf) whenever the span is not nil.
  The documented rule (multi-result-and-comma-ok.md) keeps Go aliasing ONLY on the .sslice() view; every use that
  passes, slices, appends, boxes or captures the pack falls back to the copy. Stdlib today: 129 heap prologues
  (304 views); behavioral: 25 heap, 115 views. Each loses element writes for a spread caller.

Proposed fix (golib only, no emission change, so CNR stays 0 by construction):
- The spread property slice<T>.ꓸꓸꓸ records its slice header (array, offset, len, cap) in a [ThreadStatic] slot of
  a generic holder (no allocation). Span<T>.slice() first asks: is this span's first-element ref and length EXACTLY
  the recorded window? If so it returns that slice header (same backing array, same cap, Go's semantics) and
  clears the slot; otherwise the copy path, as today.
- Why it is sound: a span with that exact ref and length IS that array window, so aliasing it is what Go does; the
  only header detail it supplies beyond the span is cap, which is the spread slice's own. A params pack of literal
  arguments lives on the stack or in a fresh array, so it never matches.
- Costs to measure: one thread-static write per spread; the slot keeps one array alive per thread and element type
  until the next spread or consume (finalizer-sensitive rows would see it); allocation meters must stay flat.
Alternative I rejected for now: a custom params collection type carrying the slice header. Correct by design, but
it changes every variadic signature, the delegate family and reflection, and costs an allocation for literal packs.
