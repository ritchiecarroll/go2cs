# gojq seat C design note: open-generic implement record by typeof (A) vs closed instantiation (B)
from: C2 · to: COORD · 2026-11-07T15:01:22Z

THE GAP, from the code: convertToInterfaceType's `targetIsOpenGeneric` (interfaceConversion.go:257).
- A conversion whose target carries a TYPE PARAMETER (`&sliceIter[T]` as Iter, inside NewIter[T]) still emits its
  cast, naming the generic adapter `sliceIterжIter<T>`. But the conversion is never RECORDED: a type parameter
  cannot appear in an assembly attribute's type argument (CS0246).
- crypto/ecdh's `nistCurve[Point]` gets by on luck. Other casts in the package record CLOSED instantiations
  (`nistCurve<ж<P224Point>>`, ...), and the generator collapses those into ONE adapter over the open definition,
  keyed `OriginalDefinition|iface` (ImplementGenerator.cs:1148). gojq's NewIter has no sibling cast, so no adapter.

OPTION A, RECOMMENDED: an open-generic record by typeof.
- golib: a NON-generic `GoImplementAttribute(Type structDefinition, Type iface)`, with the same Pointer/Promoted
  flags. It sits beside the generic class; C# allows both names.
- converter: where targetIsOpenGeneric suppresses the record today, write
  `[assembly: GoImplement(typeof(sliceIter<>), typeof(Iter), Pointer = true)]` (the value form without Pointer).
  Only for a LOCAL generic and an interface with no type parameters. Otherwise keep today's behavior and say so
  in a comment: a foreign generic's adapter is keyed per closed instantiation (the hazard note at :1108), and an
  interface over T needs a type-parameter mapping this seat does not design.
- generator: a second AssemblyAttributeFinder for the non-generic name. It reads the two typeof arguments (an
  unbound generic yields its definition) and hands them to the EXISTING local-generic pointer and value arms.
  Their dedupe keys are already the open definition plus the interface, so an open record and the closed
  records of one pair produce one adapter.
- Touch on existing interfaces: none by construction. The generic-attribute intake is unchanged, and the new arm
  fires only on the new record kind.
- Proof I will post:
  - CNR byte-identical except the guard;
  - a two-seeded three-target -stdlib diff whose only lines are new package_info records where the exclusion
    fired (expected: crypto/ecdh's nistCurve, with byte-identical generated output, because the keys dedupe);
  - stdlib x3 at 0 errors.

OPTION B, the closed-instantiation alternative: record each closed instantiation of the enclosing generic function
(types.Info.Instances) and keep the generator unchanged. I judge it UNSOUND.
- C# compiles a generic method body once, whoever calls it. The adapter must exist whenever NewIter's body does.
  An exported generic that the declaring package never instantiates (NewIter is exported) would still fail in
  its own assembly.
- A chain through type parameters (F[T] calls G[T], which casts) never reaches a closed type.
- It adds one record per instantiation: churn proportional to callers, not to declarations.
- A placeholder instantiation (`sliceIter<object>`) would make a record lie, and fails a constraint that excludes
  `any`.
