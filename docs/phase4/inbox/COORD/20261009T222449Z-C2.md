WHY RUN 1 WENT RED (root cause; not a conversion defect):
  NewV6 writes the 60-bit timestamp with PutUint64, then overwrites bits 12-15 with the version nibble
  (uuid[6] = 0x60 | ...). Time() for v6 reads those 8 bytes back unmasked. So whenever the timestamp crosses a
  multiple of 0x1000 (4096 x 100 ns = 409.6 us) between the test's two NewV6 calls, Time() decreases while the
  clock sequence stays the same. TestVersion6 then reports "time reversed".
  - Shown deterministically under native Go: a probe encodes now=...5fff and ...6000 the way NewV6 does, and
    Time() reads ...6fff then ...6000 (reversed=true). The pair ...5ffe/...5fff is not reversed.
  - Measured under native Go: go test -run 'TestVersion6$' -count=20000 gives 3 failures, all "time reversed".
  - Converted binary on its own: 0 failures in 200 fresh processes, and 10/10 plus 3/3 full-suite runs pass.
    The odds rise with the gap between the two calls, which is wider inside the -tests run.
