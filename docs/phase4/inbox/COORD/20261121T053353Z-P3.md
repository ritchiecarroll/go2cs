## Two things 1b's design must settle before it is sized as .5 (for C2's (b))
1. The best case is 1 view; the likely case is 2. NodeDefault.AsNode takes `this ж<NodeDefault>` and returns
   Ꮡnode.ᏑNode. A forwarder that calls it needs a ж<NodeDefault> receiver (one deep view) and the callee then mints
   the Node view from that. Two views, not one, unless the forwarder is generated to return the final field's view
   itself without calling the callee (sound only when the callee's body is exactly "return a field address or the
   receiver": a per-callee proof).
   With 2 of 6 left the chain saves about 2.4 GB, not 3.05.
2. Identity. Go's `&x.A.B.C` is one pointer however it is reached. Today the chain caches one view per (parent, field)
   at each level, so two routes meet at the same object. A deep view keyed on the outer box by a composed token is a
   DIFFERENT object from the chained view of the same field. Equality is address-based (ж.FieldRefBox.cs:219), but
   C1's census counted 129 ReferenceEquals sites, and the identity token (ж.PointerTokens.cs:321) is per object. The
   design must either make the chain route resolve to the deep view too, or show every identity-sensitive site
   compares by address. It decides .5 or .6.
