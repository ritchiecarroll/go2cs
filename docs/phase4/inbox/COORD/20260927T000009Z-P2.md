P2 CLASS M sizing: memory-profile records. Nothing is cut yet. Asking for a ruling on the shape, the order, and one cost question (section 5).

Sources read at origin/master 7433c7ac38, plus the Go 1.24.13 tests. Rows are from the linux runtime/pprof readings at 00ca353c89 (cloud box P2). This is a desk sizing: no instrument has been run for it yet.

1. What fails today, and why
All five rows fail for one reason: the heap profile has NO records ("heap profile: 0: 0 [0: 1]"). Nothing ever calls mProf_Malloc, because allocation never passes through Go's mallocgc on this host. The managed bucket store (I2, fecae49a35, on master) already holds memRecords, and the converted readers (MemProfile, the writers, mProf_NextCycle/Flush) are there unchanged. What is missing is (a) allocation events, (b) free events, and (c) cycle publication.

2. Honest versus structural
The question was about allocation sampling without a GC hook. The host does not need a GC hook for the allocations Go code makes explicitly, because the converter already routes each one through a golib constructor I read at master:
- &T{} and new(T): Ꮡ(value) and @new<T>().
- Escaping locals: heap(...).
- make([]T, n) and slice literals: the slice(length, capacity) constructor, and array.slice().
- make(map): map constructors; growth happens in the map's own setter.
So a golib hook at those sites sees every explicit Go allocation, with its Go type and element count. Go's own sampling rule applies as written: MemProfileRate is read per allocation, a per-thread nextSample is drawn exponentially with mean MemProfileRate, the size is roundupsize(GoSizeOf(T) x n), GoSizeOf is golib's existing Go-layout size (what unsafe.Sizeof uses), and the stack comes from the hand-owned callers(). At MemProfileRate=1 that is exact per allocation site, which is what the tests assert (32: 1024 for 32 Obj32, 1: 2097152 for make([]byte, 2<<20)).
Frees are honest the same way. Each SAMPLED object gets a weak reference. runtime.GC() (hand-owned in managed_impl.cs, a full blocking collection) sweeps the dead ones into mProf_Free and then runs mProf_NextCycle and mProf_Flush, which is Go's mgc order. inuse is then "as of the last GC", as it is in Go.
Structural:
- (s1) Go's inliner. TestGenericsInlineLocations asserts that location 0 holds three inlined functions. The CLR's frames carry no Go inline tree, so that one assertion stays red even when the sample string matches. It is the same family as TestCPUProfileInlining, except Go skips that test and fails this one. It is a disclosure candidate.
- (s2) Escape analysis and implicit allocations. The host heap-boxes locals that Go keeps on the stack (address-taken, not escaping), and it does not see Go's implicit allocations: interface boxing of values, closure contexts, string concatenation and conversions, and runtime-internal allocations. So the profile is the Go-visible explicit allocations on the managed heap, not Go's byte-for-byte heap. None of the five rows depends on that difference; a general heap profile does. It is a disclosure line.
- (s3) Other .NET sources are not used. EventPipe's allocation events sample at a fixed mean (AllocationTick about every 100 KB; not re-measured here) with CLR object sizes, so they cannot honour MemProfileRate=1 or Go sizes.

3. Proposed pieces, each red first
- M1 allocation records. A golib hook at the constructors above, with Go's rate and nextSample rule, Go size classes, and callers() into mProf_Malloc. MemProfileRate must be readable from golib on every allocation, as Go's mallocgc reads it. The tests assign runtime.MemProfileRate directly, so the runtime field is backed by golib storage: the var is hand-owned as a ref property. The converter's manual-conversion path for a var still has to be confirmed, and if it does not exist that is part of this seat's size.
- M2 frees and cycles. Weak references for sampled objects, swept in runtime.GC(), followed by Go's flush order. A per-collection sentinel covers GCs no one asked for, as BoringCaches already does.
- M3 stack roots. Go's profile stacks end in testing.tRunner and runtime.goexit. The hand-owned testing presents neither: master has no tRunner, and callers() adds no goexit root. /debug=1's regex wants exactly 4 PCs (allocatePersistent1K, TestMemoryProfiler, tRunner, goexit), and the generics tests want "testing.tRunner;..." first. goexit in callers() changes the absolute depth of runtime.Callers for everyone. That is Go's own shape, but it needs the runtime row and the Caller/Stack filter read before and after.
- M4 generic shape names. pprof uses the symbol name, so it wants genericAllocFunc[go.shape.uint32] and nonRecursiveGenericAllocFunction[go.shape.struct { runtime/pprof.buf [128]uint8 },go.shape.struct {}]. That name has to be derived from the instantiated method's generic arguments. The CLR shares code for reference-type arguments, which lines up with Go's pointer shapes; I will check that claim before relying on it.
- Map growth, for TestHeapRuntimeFrames: the map records Go's table allocations at Go's growth points, and the golib frames are already not Go frames, so no runtime frame shows.

5. The ruling I need: cost
Go samples by default (MemProfileRate = 512 KiB), so Go parity means the hook runs in every converted program. Each allocation then pays a static read, a thread-static decrement and a per-type size read; a stack walk happens only on a sample. That has not been measured. Options:
- (a) Always on, as Go is. The Performance suite measures it before M1 is claimed, and the result goes in M1's post.
- (b) Opt-in, like the CPU sampler: off unless the program opts in, and runtime/pprof's test project opts in. This avoids any cost for everyone else, but a default program's heap profile stays empty, which is not Go's default.
I recommend (a) with the measurement as M1's gate, falling back to (b) if the cost is visible.
