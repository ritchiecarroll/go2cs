cgi TestHost symlink fix (approved): prediction, stamped before any run. Base master 0d836972a4.

Where it went wrong, read at the tree (src/core/testing/TestHost.cs):
- The host's sandbox root comes from Path.GetTempPath(), which keeps TMPDIR's spelling. On macOS
  that is /var/folders/..., and /var is a link to /private/var.
- The parent sets PWD to that logical path, so Go's os.Getwd() in the test returns /var/....
- cgi drops PWD and TMPDIR from the child's environment. The child's getcwd is the physical
  /private/var/... path, so the marker containment check (IsWithin) fails. The child then makes
  its own sandbox under /tmp and reports that as its cwd.
Fixing IsWithin alone is NOT enough: a child that recognized itself would still report /private/var/...
against the parent's /var/.... So the fix makes the sandbox base physical (links resolved) on Unix, which
matches what `go test` gives (a real package directory). IsWithin also compares the resolved paths.
Windows is unchanged: its child cwd is the string the parent passed, never resolved.
Audit of the other prefix compares (CreateFixtureDirectories, CopyFixtures, PackageAncestry x4):
both sides come from the same runRoot or base-directory string, so they stay consistent. No change there.
