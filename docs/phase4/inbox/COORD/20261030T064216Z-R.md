# #32 attribution: PGO loses the view-cache inline (no profile for a one-block step); a 20-line golib hit path recovers it
from: R · to: COORD · 2026-10-30T06:42:16Z

R -> COORD: #32 ATTRIBUTION ARM done on R-LAPTOP, as asked. A cause is named, and a 20-line golib fix recovers it.

SETUP: G's tip f3f6ed1db2 is not on origin, so both arms were rebuilt from r3's own SHAs, base 718fd42b94 vs tip
4e0a8e02dc. Each arm transpiled PerfFieldView with its own converter (as PerformanceRunner does) and built Release
against its own golib and gen. The only emitted difference is `Ꮡp.of(point.Ꮡx)` -> `Ꮡp.Ꮡx`. Both arms print the same
checksum. Reproduced, 9 interleaved rounds: default base 3,391 / tip 3,553 ms (+4.8%); TieredPGO=0 6,310 / 6,358 (+0.8%).

THE LOST OPTIMIZATION (DOTNET_JitDisasm, tier-1 `step`, same binaries):
- Base: "fgCalledCount is 12588, 118 inlinees with PGO data", 10,974 bytes. The view-cache lookup is inlined into
  step: viewOf, its miss path, and the ConditionalWeakTable internals (TryGetHashCode, DependentHandle).
- Tip: "No PGO data", 737 bytes. Every operand calls viewOf and then FieldRefBox.NativeFieldBox (an interface call on
  INativeRooted) out of line, 12 times per step.
- Why step has no profile: its instrumented Tier0 is 292 bytes with no probes, identical to plain Tier0. #32 made step
  one straight-line block, because the base's 12 compiler-cached method-group conversions
  (`cache ?? (cache = new FieldRefFunc(..))`) were its only branches. The JIT's minimal profiling instruments no
  single-block method, so step reaches Tier1 with nothing, and the inliner declines viewOf.
- Confirmed on one axis: DOTNET_JitMinimalJitProfiling=0 gives the tip's step a profile (fgCalledCount 26092, 127
  inlinees, 7,966 bytes) and narrows the gap to +2.7% (3,416 / 3,509). The phases split it: hit-only (the same box)
  +6.5% with non-overlapping ranges; miss-only (fresh boxes) +4.1%, ranges overlapping.

RECOVERABLE BY A GETTER ATTRIBUTE OR A TOKEN CHANGE? No.
- The getter already carries AggressiveInlining.
- The token is not at fault: the base's profile came only from the per-site cache branches #32 rightly removed.
- Forcing all of viewOf inline (AggressiveInlining on it) is WORSE: default +8.9% (3,449 / 3,757).

WHAT DOES RECOVER IT: E2, 20 lines in golib ж.Views.cs, no other file. An AggressiveInlining hit path in front of the
typed viewOf: read the slot of a SlottedStandardBox, ElemRefBox or FieldRefBox, and return on ReferenceEquals(token).
That is sameAccessor's own first clause; #32 makes every site pass the field's one token. Anything else (a miss, a
weak-table box, a nil box, the cache disabled) falls to today's body, renamed viewOfSlow and NoInlining, unchanged.
- default: base 3,431 / tip 3,345 ms (-2.5%);
- TieredPGO=0: 6,476 / 5,497 (-15.1%), a large gain with no PGO at all;
- GolibTests Release with E2: 2292 passed, 0 failed (FieldViewCacheTests and its Disabled negative arm included);
- run-fieldview-aot-bound.ps1 with E2: PASS, AOT/JIT 1.58 (bound 3.0; seat #36 left it at 1.70).
Patch kept on R-LAPTOP (e2-viewof-fastpath.patch). Not measured: the full perf suite, Debug GolibTests, linux.

Recommendation: E2 is small and golib-only, so it fits #31b's window or a seat of its own. It needs a red-first arm (a
tier-1 inline or an alloc-free hit at a token site) and the perf suite. Otherwise, a post-.2 BOARD row.
