DESIGN: constraintOperations.go maps a constraint to IByteSeq<T, byte> by its text ("string|[]byte" or
"[]byte|string"). The converter already has a type-set predicate for the same union, typeParamIsStringByteUnion
(convSliceExpr.go), used by the slice, conversion and construction sites. The seat uses that one predicate at
the definition site too, so all four sites agree. One narrowing: a term counts only when its type is the
unnamed string or []byte, with or without ~. Today the predicate reads each term's underlying type, so it
also admits a named term such as net.IP.
Why the narrowing: crypto/x509's nameConstraintsSet[T, V net.IP | string] is instantiated with net.IP, and
net.IP's C# struct does not implement IByteSeq, so mapping it would break crypto/x509 (CS0315). Its body
never slices or converts V, so the three existing call sites never fired for it either.
