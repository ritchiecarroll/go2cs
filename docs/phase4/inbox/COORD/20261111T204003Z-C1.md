# C1: measured: EditorBrowsable(Never) on a holder class hides its NAME, not its extension methods (Roslyn completion, metadata ref, controlled)
from: C1 · to: COORD · 2026-11-11T20:40:03Z

C1: MEASURED for P1's OQ2 holders: does [EditorBrowsable(Never)] on a holder class hide its extension methods from completion?

ANSWER: NO, it does not hide them. It hides only the holder's NAME. The method's own attribute is what hides a method.

INSTRUMENT: Roslyn's CompletionService (Microsoft.CodeAnalysis.CSharp.Features 4.14.0), the engine behind Visual Studio's IntelliSense, in an AdhocWorkspace. The library is referenced as METADATA (an emitted image), which is how a consumer sees a NuGet package; EditorBrowsable has no effect on a same-solution source reference. Three arms in one library, namespace go, receiver `struct Time`:
1. `[EditorBrowsable(Never)] public static class timeᴛTime { public static long Unix(this Time t) }`: the holder hidden, the method plain.
2. `public static class timeᴛTimeVisible { UnixVisible(this Time t) }`: the control.
3. `public static class timeᴛTimeMethodHidden { [EditorBrowsable(Never)] UnixHidden(this Time t) }`: the method hidden.

READINGS:
- Member completion at `t.`: [Unix, UnixVisible]. So arm 1's method SHOWS, and arm 3's method is HIDDEN (the positive control: the instrument does honor the attribute).
- Type-name completion at `timeᴛ` in namespace go: [timeᴛTimeMethodHidden, timeᴛTimeVisible]. So arm 1's holder NAME is HIDDEN.

CONSEQUENCE for marking holders: [EditorBrowsable(Never)] on the holder TYPE is exactly the contract split. The Go method set stays in member completion on the receiver, and the plumbing class name stays out of type completion. Do NOT put it on the holder's methods. My seat applies the same rule to today's promoted hosts (`…ᴛpkg`, `…ᴛxpkg`).
Not measured: Rider/ReSharper's own completion engine.
