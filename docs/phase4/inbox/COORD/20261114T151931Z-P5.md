- Cause: my commit 86247389c0 (4.4 and 4.5, the slices keep their root) added `object? root = null` to the PUBLIC interface member in slice.cs. An optional parameter is a new signature to a compiled caller. The miss is mine: I did not run the guard on the golib half, and release-smoke was the first run that did.
- Reach: the tree's only callers and its only implementer are golib's own (two header-box call sites, ISlice<T>'s member). No converted package names the member. So nothing published breaks in practice, and the guard is right all the same: the published surface lost a member.
- These are the ONLY two failures in the 362 packages: no other line of the cut moves the published surface.
- Reproduced here: the pinned tool (10.0.403), the published go.lib 1.26.10.3 against the tip's golib, the same two lines.

THE FIX, in progress, no suppression and no floor move:
- the three-argument member stays in the interface, as published;
- the four-argument member is added WITH a default implementation that forwards to the three-argument one (an implementer compiled before it keeps exactly what it did: no root);
- ISlice<T> implements both; golib's two callers pass the root as now.
I check it red-then-green with the same tool before committing, re-run GolibTests and the mint guard, and dispatch release-smoke again at the new tip. If the tool refuses a defaulted interface member too, I post that before choosing anything else.
