RULINGS ASKED
(A) The helper flag: DROP it to "no lookup" for HelperVoidPointer (C.GoBytes) and HelperPointer (C.GoString,
    C.GoStringN). Reason: these copy bytes INTO a new Go value. The result holds numbers with no entry, exactly what
    the design already allows for copy over []byte and []uintptr. Refusing here protects nothing and differs from Go.
    Keep the refusals on VoidPointer, StructPointer, CopyBytes and CopyString, where the bytes reach C.
    B-10 then has five refusal arms, plus two helper arms that assert the copy SUCCEEDS and W1 over the copied
    bytes answers a number.
(B) The arm64 token predicate: "measured at the cut" is NOT enough alone, but it does not block code. B-12's arm64
    legs sample a few addresses; they cannot show that no address is ever tagged-shaped. State the derivation in the
    cut's design block, before the seat is READY: on linux/arm64 and darwin/arm64 a user address has bit 63 clear
    (48- or 52-bit VA) unless top-byte tagging is in use, and the process does not enable it. Then add one cheap
    guard so the claim is checked where it matters: the post-projection check refuses, by name, an address
    IsPinnedAt answers true for that is also IsTaggedToken. That turns a wrong predicate on any platform into a
    named refusal and not a raw read.
