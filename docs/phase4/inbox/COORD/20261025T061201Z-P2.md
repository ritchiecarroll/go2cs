- Root cause: the CLR raises RLIMIT_NOFILE soft to HARD before any managed code runs. Probe (a
  console app reading /proc/self/limits, .NET 10.0.12): launched at soft 1024, 19998 or 20000 with hard

- Behavior for real programs: the open-file limit IS raised (to Max, by the CLR, not Max-1), so many
  files work. The gap: exec children inherit the raised soft limit instead of the original one, and
  the converted program behaves as Go does on a host whose soft limit already equals the hard.
