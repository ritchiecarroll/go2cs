(d) THE SHARED PREDICATE
The bare-literal predicate the string slot uses today is two checks in consider() (hoistedLiteralOperations.go):
`!stringLiteralNeedsByteArray(lit.Value)` for an interpreted literal (convBasicLit.go; a raw-byte escape such as
"\xff" is not valid UTF-8 and has no C# literal form) and `plainLiteralForm(lit)` (a multi-line raw literal keeps
.Raw(), which strips the checkout's CRs). The cut names them as ONE function, `hasBareCSharpForm(lit)`, and both
the string-slot arm and the new any-slot arm call it, so the any slot cannot admit a literal the string slot
refuses. Consequence: nothing `u8` cannot encode ever reaches the generator from the converter (Go rejects a lone
surrogate escape; byte-escaped surrogates are raw-byte and refused). The generator still refuses a lone UTF-16
surrogate with GO2CS0005, for hand edits.

The guard, so the census cannot go stale: the generator, for every bare string literal argument in converted code,
reads the invocation's method group (SemanticModel.GetMemberGroup). If another member of the same arity takes object
(or a params object span) at that position while the bound member does not, it reports GO2CS0005 "overload drift:
binds {bound}, while {other} takes the any slot". So a later overload added beside a converted callee (a golib or
hand-owned convenience overload, the class G named) is a build error, never a silent rebind. If the cut's own
corpus run reports any site there, I disclose that class by name before proceeding.
  Red arm: GenTests, a callee pair F(object) + F(@string) called as F("x") -> GO2CS0005 drift; F(object) alone ->
  intercepted, no diagnostic.

ROSLYN FLOOR
  - Floor: compiler 4.14 (the probe's version; GetInterceptableLocation is absent in 4.10, and RSEXPERIMENTAL002
    in 4.11 and 4.12, per the proposal).
  - The SDK route forces it. A converted project targets net10.0, which needs the .NET 10 SDK. Here, SDK 10.0.112
    builds with its own Roslyn 5.0 ($(CompilerApiVersion) = roslyn5.0, read with msbuild -getProperty), and its
    minimumMSBuildVersion file says 17.14.0, so a Visual Studio host is VS 17.14 or later.
  - Not proven, and not relied on: that VS 17.14's own compiler is 4.14 or later, and that nobody pins an older
    Microsoft.Net.Compilers.Toolset.
  - So go.lib.targets gets an ERROR: a target before CoreCompile fails with a GO2CS code from the registry when
    $(CompilerApiVersion) parses below roslyn4.14. The SDK sets that property from the compiler in use: from
    Roslyn's Microsoft.Managed.Core.CurrentVersions.targets, or, in older compilers, from the RoslynTasksAssembly
    identity (Microsoft.PackageDependencyResolution.targets _ResolveCompilerVersion).
  - Second hole, found while reading: CS8032/CS8034/CS8784/CS8785 are errors only inside the repo
    (src/Directory.Build.props). A converted project OUTSIDE the repo loads go2cs-gen through go.lib.targets'
    consumers with them as warnings. The cut appends the same four codes to WarningsAsErrors in go.lib.targets,
    so a go2cs-gen that fails to load is an error for every consumer, not only in-repo.
  - Red arm: build one behavioral fixture with -p:CompilerApiVersion=roslyn4.13, a global property the SDK target
    does not overwrite. Expect the floor error by its code; with roslyn4.14 and roslyn5.0, expect a clean build.
