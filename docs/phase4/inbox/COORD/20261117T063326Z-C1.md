## What Go does (measured here, go1.26.11)
A module with good/ (tested) and bad/ (no tests, does not compile):
- `go test ./...`: `FAIL example.com/m/bad [build failed]`, `ok example.com/m/good`, exit 1.
- `go test ./good`: ok, exit 0.
So `go test ./...` builds EVERY package in the pattern, tested or not, gives each its own verdict, runs the rest, and
exits nonzero. -tests -recurse is the `./...` form.

## Recommendation: (a)
Skip refused packages under -tests too. In phase B, a tested package that is refused, or whose test closure reaches a
refused package, is named with its reason and gets no test project. The rest convert and run, and the run exits nonzero.
- Fidelity: it is `go test ./...` package for package. A refused package plays Go's "[build failed]".
- (b) alone does not fix the case: a refused package INSIDE one tested closure would still end the run for every
  tested package. That includes a refused package that has tests of its own, since its closure is in the union. So (b)
  needs (a) anyway.
- (b) would also stop converting the module's untested packages (cmd/ mains, ls/lsconv-like packages), so phase A would
  no longer convert what plain -recurse converts, and `go test ./...` does build those.
- Size: (a) is about 60 converter lines; (b) on top of it is a second closure model for phase A.

## The design
1. moduleConverter.go:600: skipRefusedPackages is true under -tests as well. convertAll already records the refusal,
   writes no project, and goes on (d2657df2f5).
2. ConvertModule's refusal-only error becomes typed, so runModuleTests can tell "refused" from a real phase-A error.
   A real error still stops before phase B; a refusal does not.
3. addTestOnlyPackages already walks each tested package's test variants (`p [p.test]`, `p_test [p.test]`). It also
   records, per tested package, the import paths those variants reach. That closure covers production imports and
   test-only imports alike.
4. Phase B, per target, before any conversion:
   - refused itself: `-tests P: not converted: the package was refused (CODE)`;
   - closure reaches a refused package: `-tests P: not converted: its test closure imports the refused package R`
     (the first such R in sort order);
   - otherwise unchanged.
   The first two join `failed` and `unvalidated`, so a compare run's MODULE.md names them with that reason.
   Today, phase B on a refused package with tests would hit the gate with the flag off and log.Fatalf mid-phase-B.
   Step 4 is what prevents that.
5. Exit: nonzero when anything was refused, as `go test ./...` exits 1 on a package that fails to build. The
   refused packages are named by the existing summary (reportRefusedPackages) and by the phase-B lines above.
6. Docs: recurseRefusal.go's header comment; CommandLine.md's -recurse row, which today says "-tests -recurse" stops at
   a refusal; and DRAFT-news-1-26-10-4.md's "-recurse converts the rest" paragraph, which gets one sentence giving -tests'
   scope.
Out of scope, unchanged: a package that FAILS to load or panics. -tests already goes on past it in phase A, and its
importers fail at build.
