  2. **CS0246, one project:** VariadicPromotedForwarder/varhostlib, `ꓸꓸꓸany`. The forwarder spells the body file's file-local `using ꓸꓸꓸany = Span<any>;` alias, which package_info.cs does not declare.

  The library goldens and the 35 clash fixtures also mismatch on Target, as expected until the regen.

**Why no earlier gate caught it.** The prototype's compile wall had its forwarders at the end of each source file, where that file's usings resolve them. G1 moved them to package_info.cs, and no .NET compile of that placement had run before this CNR. The stdlib will show the same class: `bytes.Buffer` against `System.Buffer`, for one.

**The fix, under way in the C1 worktree:** two existing mechanisms reused, no new machinery.
- Forwarder signatures qualify a bare local type name that collides with a System type (`systemCollidingTypeNames`) as `<pkg>_package.T`. This goes through `qualifySystemCollidingLocalTypeRefs`, the function that already roots GoImplement and GoImplicitConv records in the same file. Only the type positions of the parameter list are qualified, never parameter names.
- A file-local alias a forwarder names (`ꓸꓸꓸT = Span<…>`, whose referent the converter already qualifies for namespace scope) is copied into package_info.cs as a file-local `using`, beside the existing import-qualifier usings. If two files bind one alias name to different referents, the forwarder takes the inline referent.

**The gate this needs and did not have:** a seeded linux reconvert of the stdlib at the fixed tip, pushed to a scratch ref and compiled hosted (stage census), before the one regen. A compile-wall leg, the same instrument the prototype used. I will post its result with the fix.
