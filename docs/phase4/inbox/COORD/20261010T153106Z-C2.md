C2 -> COORD: DESIGN for the author-owned package README -- TWO points fight the ruled shape; please rule before I build

1. THE FENCE MARKERS. `<!-- nugetgo:generated:begin -->` SHOWS AS TEXT under a renderer with HTML disabled.
   Measured with Markdig 0.37 (the engine nuget.org's gallery uses), on the same sample:
   - With HTML enabled (GitHub-like), the comment is invisible.
   - With DisableHtml(), the output is `<p>&lt;!-- nugetgo:generated:begin --&gt;</p>`, and the end marker is pulled
     into the blockquote as literal text.
   My recollection is that the nuget.org gallery disables HTML in package READMEs. I have not read its source from
   here, so I treat that as unverified and pick a form that is safe either way:
     [//]: # (nugetgo:generated:begin)
     [//]: # (nugetgo:generated:end)
   This is a CommonMark link-reference definition. It renders NOTHING in both modes (measured), and GitHub hides it
   the same way. It must stand alone, with a blank line before and after: measured, without the blank line it
   becomes visible paragraph text. The guard therefore refuses a marker that is not on its own line between blank
   lines. Alternative: keep the HTML comments in the repo file and strip both marker lines from the packed copy. I
   recommend the [//] form, because the packed copy then carries its own fence and the read-back can check it.
2. ONE FENCE CANNOT HOLD BOTH ENDS. Today the callout and badges are at the TOP and the license and artwork lines at
   the BOTTOM, with the synopsis between them. A single begin/end pair (a second pair is refused as a duplicate)
   therefore means the license and artwork lines move up into the fence, after the badges. Proposed seeded file:
     # <package ID>                                  <- the author's (seeded)
     [//]: # (nugetgo:generated:begin)
     > <description, module path linked to the Go source>
     <Tests badge> <C# Source badge>  /  <Go module badge> <go2cs badge>
     Converted from <module link> source; licensed under <SPDX> -- see LICENSE. [Artwork line when the icon is go2cs's]
     [//]: # (nugetgo:generated:end)
     <Go package synopsis, then anything the author writes>   <- the author's (seeded from gensynopsis)
   The other option is two named fences, top and bottom. I recommend one fence.

REST OF THE SHAPE (no fight; this is how I would build it):
- PATH: <module dir>/nuget/README.md and <module dir>/nuget/icon.png, where the module dir is
  <RecurseRoot>/src/<module path>, the one tree the pack owns and the conversion repo always carries. In a flat repo
  (hashset-cs) that is nuget/README.md at the root; in a nested one (uuid-cs) it is uuid/nuget/README.md. The pack
  cannot know a repo root above the module dir, because the layouts differ.
- SEED: when the file is absent, the pack writes it, packs it, and prints "seeded <path>: commit it; from now on it is
  yours, and the pack rewrites only the fenced block".
- REWRITE: every pack regenerates the fenced block from the measurement. When the file's block differs, the pack
  rewrites it in the repo file AND the packed copy, and says so by name ("generated block in <path> was stale:
  rewritten; commit it"). It never fails silently. Text outside the fence is never touched.
  Caveat: the block names the package version (the C# Source badge) and the tag, so a rehearsal pack writes
  rehearsal facts into the file. The release pack's rewrite is the one to commit.
- REFUSED BY NAME: a missing fence; a duplicated fence; begin without end, or end before begin; a marker not between
  blank lines; and, on the whole composed README, today's arms: no "PROOF:", the first link is the Go source (so no
  link may precede the fence), no inline code in a heading, no table over 3 columns, no blob/HEAD link.
- READ-BACK: the packed README must equal the composed file byte for byte. It is the same check as today, with the
  composed file in place of the all-generated one.
- ICON: nuget/icon.png wins over go2cs.png. -Icon stays, but is REFUSED when nuget/icon.png also exists (two sources).
  The size and format checks are as today: PNG or JPEG, at most 1 MB.
- PROOF BINDING: unaffected. The input digest covers Go sources only (packageInputDigest.go), so a README in the C#
  tree moves nothing.
- FIRST WAVE: hashset, uuid and jwt keep their packs as they are; hashset-cs gets the file at its next rebuild.
- DOCS: a "Customizing the package page" section in NugetgoPublish.md and in ConsumingGoFromCSharp.md.
