WHAT GC DOES, read so far (cmd/compile/internal/walk, go1.26.10):
  order.go expr1: every call, and every call-like builtin (len, cap, copy, append, make, new, min, max,
  real, imag, complex, recover, string<->[]byte conversions), plus receives and &&/||, is evaluated by
  o.call and then COPIED to a temporary (copyExpr) in a statement ahead of the containing statement, in
  source order. Plain reads (names, field selects, slice/array index, derefs, arithmetic) stay in the
  expression and run when it executes, which is after every hoisted call in the statement.
  walk.go walkCall1 then moves any argument that mayCall (it also counts index, deref and ., which can
  panic) into a temporary before the call.
  So gc's unit is the STATEMENT, not the operand list. That extends COORD's list: a plain read anywhere
  earlier in a statement against a call later in it, including an assignment's LHS index or deref
  (`a[i] = f()`, `p.x = f()`) and a compound op (`x += f()`, where C# reads x first).

CENSUS DESIGN: a go/types tool over the Go sources the corpus is converted from (std production + std
tests, per target) and over the behavioral corpus. A site is a statement where a plain read of variable
V comes before, in C#'s left-to-right order, a call that could write V. Tiers:
  T1 DEFINITE: the call writes V's storage visibly in the statement (&V or a pointer-receiver method of
     V in its arguments or receiver; a captured closure called by name that assigns V; a same-package
     function called by name that assigns global V directly).
  T2 POSSIBLE: V address-taken elsewhere in the function, captured by a closure, or a package-level var,
     with any call that could reach it.
  T3 HEAP: the read goes through a pointer, a slice/map element, or a deref (any call might write it).
  The existing spills (multi-value return, send, select, value-receiver args) are counted as handled.

PREDICTIONS (ranges, because nothing like this has been counted before):
  P1 T1 is small: std production 20-80 sites, std tests 10-60, behavioral 5-20 (the latter includes the
     guards built for return/send/receiver order). Call args and binary operands are most of T1; LHS
     index/deref second; composite literals rare.
  P2 T2 is two orders of magnitude larger: thousands in std, mostly globals read beside calls into
     other packages, which cannot write them. So the tool splits same-package or dynamic callee from
     cross-package callee.
  P3 T3 is the largest tier (tens of thousands) and is not a useful fix target alone.
  P4 Among T1, "real risk" (a read whose value demonstrably changes and is used) is at most half; many
     write an unrelated field of V (the access-path rule, as returnOperandOrder does).
  P5 H's two repros classify as T1 (arg &p) and T1 (captured closure called by name).
  P6 Fix-option cost: hoisting the CALLS (gc's own rewrite) touches only T1 sites if it is gated like the
     return spill, at roughly 1 to 3 extra lines per site. Hoisting the plain reads after the calls
     instead needs the same predicate, but reads worse (a read moved away from where Go wrote it).
