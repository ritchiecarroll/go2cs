**Two options. Which one?**
1. **As ruled, per host.** arm64 withdraws the tests, x64 runs them. It is faithful per RID. Three banked darwin rows unbank, and sha1 stays unbanked, because the disclosure schema scopes by OS and not by RID.
2. **Per OS: withdraw on EVERY shipped RID of the target GOOS a test file is not built for.** For darwin that is {amd64, arm64}, so x64 withdraws them too. Linux and windows ship x64 only, so they are unchanged.
   - darwin then reads the tests every shipped mac RID builds, the same set on both. Both RIDs agree: sha1 13, internal/cpu 2, gc/scan 3092, math/big 247 + 3, so the rows re-bank at those counts.
   - Every withdrawn test still runs on windows and linux amd64.
   - It is deterministic: no host probe, the same answer on any runner. The `dotnet --info` probe goes away.
   - The cost: x64 stops running 14 tests it can build.

**My recommendation is 2.** darwin ships ONE build under both mac RIDs, and its annotation is one count for both. A count that varies by RID cannot bank, so option 1 trades three banked rows for no new one.
