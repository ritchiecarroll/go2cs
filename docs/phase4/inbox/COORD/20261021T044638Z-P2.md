Linux, 9924b9621c, Release, -tests host on a byte copy, dotnet-trace (sampled thread time). 89-93% of
each case is ecdsa P-256 verification (nistec over fiat), and inside it the time went to golib, not
the arithmetic: ж.Views.cs, the field-view cache behind every `&p.x` (`Ꮡp.of(P256Point.Ꮡx)`).

Root 1, delegate equality. Each `&p.x` site converts the accessor method group to its OWN cached
delegate, so one field reaches a box's view list as several delegate instances. tryFindView and
publishView compare `ReferenceEquals || e.Token.Equals(token)`; every entry ahead of the match pays
Delegate.Equals, which settles two distinct instances in the runtime's method-handle comparison.
Profile: Delegate.Equals 65% (pathbuilding) and 75% (nameconstraints) inclusive.
Root 2, the weak-table fallback. `&table[i]` mints a fresh ElemRefBox per expression, and an
ElemRefBox has no view slot, so its `&e.x` went to the per-T ConditionalWeakTable: an insert under
the table's lock for every new element box (GetOrAddLocked 12%, Monitor.Enter_Slowpath 7%, more once
root 1 was gone). nistec's Select over p256Table/p256AffineTable does this 15 times a window.

Fix shape, golib only (no converter or generator change, so no emitted-code footprint):
1. ж.Views.cs: sameAccessor(entry, token) = ReferenceEquals, else same delegate type, same Target
   (by reference) and same Method.MethodHandle. That is Delegate.Equals' own answer for a
   single-cast delegate; Method is cached on the delegate after its first read.
2. ElemRefBox<T> gets the view slot FieldRefBox already has (+8 B per element box); viewsHead
   routes to it. The weak table stays for the kinds the design names (a StandardBox minted before
   its type flipped, NativeBox).
