## Design (answers COORD 014015Z's five and P3 014126Z's three)
Mechanism: BoringCaches' sentinel PATTERN with one change, as P3 point 1 says. BoringCaches re-registers ONE sentinel,
which is promoted into gen2 and fires once per gen2. Here each firing allocates a FRESH sentinel, so it is in gen0 and
the next collection of any generation condemns it: one firing per CLR collection. Code: PoolCleanupCadence, a private
class beside the registerPoolCleanup shim in runtime/managed_impl.cs; the shim arms it once after registering.
1. Thread: the CLR finalizer thread. It takes s_gcCycleLock with Monitor.TryEnter and skips if busy, so it never
   overlaps gcCycleLocked and never waits (a waiting finalizer would deadlock runtime.GC(), which holds the lock
   across its finalizer drains).
2. Double aging: runtime.GC() runs the cleanup once, then collects twice. Both collections' sentinels are finalized by
   its own drains (WaitForPendingFinalizers, then GcPauseRecorder.Drain) while it holds the lock, so they skip. Plus
   s_servedThrough (the s_clearedThrough pattern, keyed on CollectionCount(0)), set by gcCycleLocked after its second
   collect, so a late firing for a served collection does not age again. Control showed that second guard is NOT
   load-bearing today (removing it alone reds nothing; the drains already cover it); kept and commented as such.
   GOGC=off with no memory limit: no aging except runtime.GC() (gcTrigger.test()'s condition), which sync's TestPool needs.
3. Workstation concurrent and server GC: every CLR collection collects gen0, and there is one finalizer thread in every
   mode, so one firing per collection, the count CollectionCount(0) reports. A firing that lands while the finalizer
   thread is busy folds into the next.
4. Cost per collection: one small allocation, and one poolCleanup: lock allPoolsMu, walk oldPools then allPools.
   Bound O(pools that held a shard array in the last two cycles). No per-shard or per-item work: aging swaps whole
   shard arrays (P3 point 2 said pools times shards; it is pools only).
5. pool.cs header (27-33) and the poolCleanup comment, and gcCycleLocked's comment, change in the same commit.
Diff: managed_impl.cs +121/-2, pool.cs +9/-9, new GolibTests/PoolCleanupCadenceTests.cs.
