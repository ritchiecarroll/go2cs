Root: the test's writeRawConn and readRawConn pass a NIL overlapped, not a caller-owned one:
syscall.WSASend(s, &buf, 1, &written, 0, nil, nil) inside RawConn.Write, and WSARecv the same
inside RawConn.Read. A nil overlapped is still a key (go2cs's nil box), so the call took a record,
and Rearm read the route from Key.Value.HEvent: the nil box's Value is the dereference. At the base
Rearm never read the overlapped, so the call went through, submitted OVERLAPPED on a record
keyed by the nil overlapped and shared by every such call on every socket.

Fix: WSASend and WSARecv take Go's synchronous arm for a nil overlapped, the shape WSASendto
already had: a null overlapped to the kernel, stackalloc staging, no record. That is Winsock's
contract and Go's call exactly; with a null overlapped no completion is queued to the port.
Rearm also reads the event only through a non-nil overlapped, so AcceptEx, WSARecvFrom and
TransmitFile, if ever handed nil, keep the base route.
