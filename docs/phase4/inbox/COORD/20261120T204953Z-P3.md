P3 review: C1's CompareAndSwapPointer seat, claude/c1-atomic-casp-address 8c80148c92 (one commit on master 1fa80494ee; doc_impl.cs and one GolibTests file). Read-only.

Verdict: APPROVE WITH CHANGES. One MUST-FIX (a nil addr), two SHOULD, one NIT. The loop itself is right.

The loop, read for ABA and livelock (sync/atomic/doc_impl.cs:106-118). It reads the slot, compares addresses, and exchanges against the very reference it read.
- A racing store of ANOTHER object over the SAME address fails the exchange; the loop reads again, the address still matches, and the second exchange succeeds. Correct, and it is the case the reference compare alone would lose.
- The classic ABA (the same object back in the slot) succeeds, as Go's value compare does. Nothing here makes it worse than Go.
- A retry happens only when another thread changed the slot between the read and the exchange, so each retry is someone else's progress: lock-free, no livelock. A mismatch returns false on a value the slot did hold.
- `expected` is taken once, and unsafe.Pointer's number is fixed at construction (it is a StandardBox of uintptr), so the comparison has no side effect and pins nothing.
Nil against casPointerLatched (internal/runtime/atomic/atomic_impl.cs:322): the same addressOf, so a null slot, a nil-marked Pointer and address 0 are one value. The second bug (a never-stored slot) is fixed by reading the structural slot, as the latched one does. One thing the latched one does and this does not:

1. MUST-FIX, doc_impl.cs:106. The old code took `ref addr.Value`, which panics when addr itself is nil. The new code takes `ref addr.ValueSlot`, which has no nil test (ж.StandardBox.cs:132), and a nil `*unsafe.Pointer` is the shared `ж<unsafe.Pointer>.NilBox` (ж.cs:1088, the implicit conversion from nil returns it). Scenario: `atomic.CompareAndSwapPointer(nil, nil, p)`. Go panics with a nil pointer dereference. Here the slot of the process-wide NilBox reads null, old is nil, the exchange succeeds, the call returns true, and every nil `*unsafe.Pointer` in the process now holds p in its slot. casPointerLatched avoids this by reading through `~ptr` first, which tests IsNilPointer (ж.cs:1035). Minimal fix: the same test before the slot is taken (`if (addr.IsNilPointer)` raise the nil dereference). Red first: an arm that calls with a nil addr, expects the panic, and asserts NilBox's slot is still null.

2. SHOULD-FIX, the tests. All five arms build their pointers from numbers. The real callers pass pointers minted from Go variables, which carry a referent, and for those unsafe.Pointer's own equality is not the raw number: Equals compares IdentityOf the referents (unsafe.cs:380-414). I could not construct a pair where the two disagree, and the comments there say they must not, but this seat makes `.Value` a second definition of pointer equality beside Equals, as casPointerLatched already does. Add two arms that hold them together: two mints of `unsafe.Pointer(&x)` from one variable swap and mints from two variables do not, once for a reference-free pointee and once for a struct that holds a reference (a token-numbered pointer).

3. SHOULD-FIX, the sibling. atomic.Pointer[T].CompareAndSwap (sync/atomic/type.cs:183) still compares references, and it is the one converted programs use most. It is on the identity list of the Change B read. Name its seat in this one's record so the list is not read as closed by this commit.

4. NIT. internal/runtime/atomic guards its pointer store and CAS with a latch (atomic_impl.cs:315, :324), and sync/atomic uses Interlocked. One slot reached through both packages is not atomic across them. That predates this seat and no caller is known to do it; a comment at either site is enough.
