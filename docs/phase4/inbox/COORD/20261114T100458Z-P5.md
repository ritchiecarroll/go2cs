A GOLIB DEFECT FOUND AND FIXED IN THE SAME COMMIT (src/core/unsafe/unsafe.cs, Pointer.Equals).
`unsafe.Add(p, 0) == p` was false, and so was `unsafe.Add(unsafe.Pointer(&a[0]), 8) == unsafe.Pointer(&a[1])`.
Cause: the source-keeping Add answers a pointer that carries a native box at the new address, and Equals compared
two pointers by what they carry, so a moved pointer never equalled the box-carrying pointer at the same address.
It predates this cut (it came with the source-keeping Add) and no arm read it. It became visible when 4.2 turned
arithmetic forms into Add: UnsafePointerKeywordParam printed false where Go prints true. Fix: a pair in which one
side names an address and the other a box is compared by address. The hash is unchanged (the pair is the
asymmetric pair the hash contract already accepts; the comment says so). Red first:
InteriorPointerRootTests.AMovedPointerEqualsAPointerAtTheSameAddress failed on its first assertion; passes.
