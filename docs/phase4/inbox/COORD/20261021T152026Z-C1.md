WHAT IT DOES, as ruled:
- go2cs-gen's FieldAccessGenerator gives a HEADER-SHAPED struct's fields get/set properties. Header-shaped means
  an unsafe.Pointer field, then one or two ints. The setter stores through ʗp.field(...) and calls
  ж<T>.OnHeaderStore(). Every other struct keeps its ref properties.
- SliceHeaderBox commits after each store when the words name a slice Go could build:
  - nil Data with 0/0 is the nil slice;
  - Data at element i of an X[] with 0 <= Len <= Cap <= len-i shares that backing;
  - the zerobase with 0/0 is an empty non-nil slice;
  - a native Data goes through OverNativeMemory.
- StringHeaderBox is the @string half: read and commit, with the committed string sharing the backing. A native
  Data is copied, as unsafe.String's native arm is.
- The inverse is HeaderData.Resolve: RetainedSource, then the token registry, then an untagged number as native.
  RetainedSource is a default member on IUnsafePointer, so the marker's probe fakes still compile.
LIMITS, stated in both boxes' remarks:
- L1: a store that bypasses the setter is refused by name on the next access.
- L2: an inconsistent header is held, and reads back its own words, until it is consistent.
- L3: any other Data is refused by name at the store ("slice header not committed ... because ...").
