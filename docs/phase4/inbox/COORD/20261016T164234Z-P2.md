DESIGN, G's rule, wired as: windows syscalln calls NativeStructMarshal under a new DEEP policy instead of refusing (a token CALL TARGET stays refused). Three points where I read G's text one way:
(1) A pointer field whose pointee converts to a REAL pinned address (blittable, e.g. WSABuf.Buf = &b[0]) passes THAT address, not a copy. Reason: Go hands the callee the real buffer; a copy of `&b[0]` would carry ONE byte where the callee reads Len, and overlapped I/O (WSARecv) writes the buffer AFTER the call returns, into a freed copy. Only a TOKEN pointee (reference-bearing) is copied recursively, identity-mapped per call, decoded back, freed.
(2) A token that resolves to an ELEMENT box (SetEntriesInAcl's &entries[0], count 3) marshals the contiguous RUN from that element to the end of its backing, because the callee reads count entries; an alias to another index of the same backing maps into the same run.
(3) An OUT word: a pointer that was nil before the call and is non-zero after it (newAcl) decodes as a native-address box (NativeBox<T>, the kernel-returned kind), so the caller's LocalFree and the next call get the real address. A word the callee left as our buffer decodes the copy back; a word it replaced decodes as a native box.
RETAINED pointers: syscalln sees only the target address, not a proc name, so a by-name refusal can only key on (*Proc).Call/(*LazyProc).Call names. None of the 19 retains a COPIED pointee (overlapped buffers are pinned pass-through under (1)). I propose stating the precondition in the class remarks and refusing by name only through a short Proc-name list, empty today. Say if G wants otherwise.
