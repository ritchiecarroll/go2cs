S1, items 1-7:
1. ONE func-word story. GoFuncCookie is EXTENDED and no type is added; GoFuncPtr is withdrawn.
   - A static function (no target: every converted top-level Go func) gets ONE word per METHOD, keyed on
     RuntimeMethodHandle as GoSyntheticPC keys, and held strongly. That is Go's static funcval.
   - Anything else (a closure, a bound method value) keeps today's per-instance weak word. That is Go's heap funcval.
   - Migration: Of/IsCookie/Resolve/OfFunc keep their signatures and callers. The eight GoFuncCookieTests mint lambdas
     (they have a target), so they stay on the per-instance path unchanged.
   - New: GoFuncCookie.Func<F>(word), shared by the converter route and the runtime route.
   - Rebind against refuse is settled on REBIND. A failure to bind panics by name, as today. A rebind cache per (word,
     delegate type) covers static functions only.
2. The BAND is GoFuncCookie's own, unchanged, so its header's disjointness proof (GoFuncCookie.cs:31-40) covers both
   kinds. 32-bit throws: GoFuncCookie has no such guard today, and the revision adds it at the mint. Data use is
   NamesNoUserMemory's caught nil-dereference panic; 1.3's "faults" is corrected.
3. The census covers all five shipped targets (windows/amd64, linux/amd64, linux/arm64, darwin/amd64, darwin/arm64),
   in six structural classes: m1, m2, w2 (mints); r1, r2, w1 (recoveries).
   - Mints: 1,445 / 1,512 / 1,494 / 1,596 / 1,596.
   - Recoveries: 536 / 543 / 543 / 527 / 527. Of those, 5 / 1 / 1 / 2 / 2 are stored rather than called at once.
   - The field is EMBEDDED at every site (1.1 was wrong).
   - Every site you named is in the table.
   - Found while writing: v2 of my tool counted 13 vfs stores (vfs/patches.go:122, patches64.go:18) as stored
     recoveries. They write a func INTO a word slot, so they are mints (w2). v3 moved exactly those 13, on all five
     targets.
4. Identity:
   - The method key gives one word per function across sites and delegate types, so h == cFuncPointer(f) holds.
   - The remaining risk is MEASURED. Exactly 1 recovery and 1 mint pass an aggregate by value, both on windows/amd64:
     winSeekFile's TLARGE_INTEGER against libc.XSetFilePointerEx's largeInteger. go2cs lifts each package's anonymous
     struct separately, so CreateDelegate cannot bind them. The other four targets have 0.
   - RULING ASKED: should the converter reuse an imported package's lift when an alias's anonymous struct is identical
     to it? That would be a separate seat with its own footprint. Until it lands, that site is a named red, and P1.2
     names it.
5. The prototype is locked and method-keyed, with an instance fast path and a rebind cache.
   - Race: 300 rounds x 64 threads x 200 functions, two delegate types. 0 splits and 0 collisions.
   - Native AOT: 0 warnings. v2 AOT costs, in ns per call: mint 24, recover+call 39, rebound recover+call 112.
   - v1, without the fast path or the cache, cost 541 ns per mint and 9.9 us per rebind under AOT. Delegate.Method
     and CreateDelegate are slow there.
6. The m2 and w2 classes cover the mints outside __ccgo_fp/cFuncPointer: lib/mutex.go, vfs, conn.go:482 and the
   generic cFuncPointer.
7. M:N: recovery returns the plain body, and each park inside a mutex, VFS or busy-handler call holds a carrier
   (stated in 3.5).

  tested at xsysDarwinLibc_test.go :120, :176 and :216. Counts: 159 per darwin arch in x/sys/unix; in x/sys/cpu, 2 on
  amd64 and 1 on arm64.
