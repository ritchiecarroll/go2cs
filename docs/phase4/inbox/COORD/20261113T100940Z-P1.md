P1 naming seat: N4 spec (M5, the seat's next commit) -- reuse an imported package's anonymous-struct lift

Repro (red, no unsafe needed): ImportedAnonStructLiftReuse. lib has `type largeInteger = struct{ QuadPart int64 }`
and exported `func SetFilePointerEx(distance largeInteger, moved *largeInteger) int64`; main declares
`type TLARGE_INTEGER = struct{ QuadPart int64 }`, passes its values to lib, and holds lib's func in a
`func(TLARGE_INTEGER, *TLARGE_INTEGER) int64` variable. Go prints "21 40 / 6 10 / struct { QuadPart int64 }".
Converted with the seat converter, both packages lift their own struct and the build fails: CS1503 twice
(TLARGE_INTEGERᴛ1 is not largeIntegerᴛ1) and CS0123 (the delegate does not bind). The same mismatch is what
breaks winSeekFile's delegate recovery.
Mechanism: when this package lifts an anonymous struct, and a package it imports directly published a
GoDynamicTypeLift for an IDENTICAL struct whose lift is public, it lifts nothing. The alias becomes
`global using TLARGE_INTEGER = <that package's namespace>.lib_package.largeIntegerᴛ1;`, a bare use is spelled
with that name, and its own GoTypeAlias record names the reused lift, so its importers get the same type.
- Identity is checked with types.Identical on the imported package's struct, not only by the signature text:
  two structs with an unexported field have the same text but are different Go types; they keep two lifts.
- The importer already loads every imported package's GoDynamicTypeLift records (importedDynamicTypeNames);
  today only anonymous interfaces read them. If two imports qualify, the lexically smallest import path wins.
(a) Accessibility. The reused lift is already public whenever another package can reach a value of it: the
  publicization pre-pass makes an exported func's parameter and result types public (collectPublicizedTypes,
  types.Func arm), and the repro's lib emits `public partial struct largeIntegerᴛ1 {}` although largeInteger
  is unexported. libc's XSetFilePointerEx is exported, so its largeInteger lift is public the same way. If the
  imported lift is internal, M5 does not reuse it; reading that needs Q's accessibility record from its
  package_info.cs, which the importer parses already.
(b) Neither package imports the other: two lifts remain. That is a later item, not a refusal written now.
  The failure stays loud: a third package that mixes the two values fails to compile (inferred from the
  repro's CS1503), and a func word recovered across them is refused by name at run time (design P1.2).
(c) Footprint. A go/types scan of std (package-level declarations on both sides, every import edge) finds 0
  identical pairs on windows/amd64, linux/amd64, darwin/amd64 and linux/arm64; a planted two-package control
  finds its pair. Predictions: std footprint 0 lines on all four targets; CNR 0 moved goldens; the new program
  is the only new golden. Most likely miss: a struct spelled inside a function body, which the scan does not
  read on the importing side; the two-seeded footprint is what measures it.
