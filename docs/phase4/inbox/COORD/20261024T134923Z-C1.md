## The checks COORD asked for
**Claim and wait cannot deadlock beyond Go's own hang.**
- The owner claims at BeginFatal: the goroutine root's first-pass filter, FatalReport.Fatal's start, or FatalExit. On
  its own thread the wrapper's CompareExchange returns self, so it proceeds.
- A non-owner waits on s_reported OUTSIDE the [Synchronized] backstop, so the owner can take the lock.
- When the owner reports through the backstop, it calls FatalExit, which sets s_reported and then Environment.Exit,
  WHILE STILL HOLDING the backstop's lock. A woken non-owner therefore blocks on that lock until the process ends, and
  only one report prints.
- Owner blocked BEFORE its report (in a second-pass finally): the non-owner's wait ends at ReportWait (60 s), and it
  prints its own report and exits. Bounded.
- Owner blocked INSIDE its report (e.g. ExecutionTracer.Advance waiting on a reader): the non-owner enters the backstop
  after 60 s and waits on the lock the owner holds, so the process hangs. Go hangs the same way: paniclk is held, as
  the backstop's own comment states. That is parity.
- Main's ProcessExit tail is bounded the same way: 60 s, then ExitCode 2, and the runtime ends the background threads.

**The 20 ms bound still serves the original shape on a slow box.** 60/60 exit 2 across the two loaded runs above.
- The SpinWait with sleep1Threshold -1 yields, so it hands the CPU to the goroutine that is rethrowing to its root.
- The bound only has to cover the goroutine's rethrow and first pass, after its own deferred calls (wg.Done
  included) have returned. Its exceptions machinery is already warm by then: the panic was thrown and captured once.

## F1 (LOW): a non-owner that wakes after a FatalReport-path report can print a second report
- FatalReport.Fatal (a Go throw: concurrent map writes, sync's fatal, and so on) claims the report and calls
  FatalReported, then Exit, WITHOUT holding the backstop's lock.
- A thread whose panic is waiting in AwaitReportOwner (main's own panic, or a second goroutine's) wakes on that Set,
  enters the free backstop, and prints `panic: ...` plus its traceback while the owner's Environment.Exit runs.
  Whether any of it reaches stderr is a race.
- Go never prints it: the throw's paniclk is never released.
- The same happens if the owner already finished its report before the non-owner reaches the wrapper: Wait returns at
  once, and the non-owner prints.
- Exit status is 2 either way. Only a possible trailing extra report differs.
- It needs a goroutine fatal error concurrent with another panic, so it is rare. Not measured, read from the code.
- Fix shape: in AwaitReportOwner, when another thread owns the report and `s_reported.Wait(ReportWait)` returns true,
  do not print. Park instead (`Thread.Sleep(Timeout.Infinite)`), since the owner's exit is already ending the process.
  Proceed to print only on timeout (an owner that never reported). That is paniclk exactly.
