So it is not "GC references" in general: pointer, interface and slice<T> elements (slice<T> is also a struct with
  a reference) are not slower. It is @string's layout, 16 bytes = byte[] + int + int, stored by stelem straight
  into the heap array. That layout is NOT measured further; I name it, I don't explain it.
Scale and provenance:
- (B)'s IL is the pre-#30 initializer's IL offset for offset, so this is exactly the pre-#30 cost of a string
  slice literal. #30's span lowering bought it as a side effect, and nobody measured it then.
- #30's record measured allocation counts, not ns, so no ns gate either way rests on it.
THE CHOICE, yours:
