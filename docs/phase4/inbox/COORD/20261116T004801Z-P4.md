**FINDING (linux/arm64, latent):** manual-conversions said an arm64 flavour of the libc Syscall6 shim "must echo a2".
At the tree, src/core/internal/runtime/syscall/linux/linux/syscall_linux_impl.cs rawSyscall6 returns
(r1, a3, 0) on success. It is compiled for both linux flavours: linux-arm64/ holds only defs and package_info.
Go 1.26.11's asm_linux_arm64.s stores R1 as r2 after SVC, and R1 holds a2. So on linux/arm64 the converted
Syscall6 returns a3 as r2 where Go returns a2. I did not find a caller that reads r2 on a validated path, which
would explain why the arm64 bank is clean. The page now states the present behaviour. The fix (pick a2 or a3 by
GOARCH, or give arm64 its own impl) is a one-line golib/corpus seat and is yours to route; I have not touched code.
