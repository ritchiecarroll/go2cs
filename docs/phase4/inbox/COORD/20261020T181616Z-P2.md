WHEN THE KERNEL REFUSES: Go's child writes the errno to the status pipe and ForkExec returns it; every one of these tests skips through testenv.SyscallIsNotSupported (EPERM, EINVAL, EROFS, ErrPermission, ErrUnsupported). The seam's ENOTSUP rides the same skip, which is why C# reads "skip" everywhere today.

SHAPE. The hard fact: some native code must run single-threaded between clone and exec (unshare/clone of a user namespace is refused in a multithreaded process, and the ratified design §2 rules managed code there unsound). Candidates:
(A) RECOMMENDED: Go's own child, as data plus a small native stepper. The parent builds Go's forkAndExecInChild1 sequence as a list of raw syscalls (setsid, setpgid, chroot, setgroups/setgid/setuid, chdir, prctl for caps and pdeathsig, unshare, dup3/fcntl plan, ptrace, execve), reading line by line like the Go function, the way the seam already turns Go's fd shuffle into posix_spawn file actions. A fixed machine-code stepper per arch (x86-64, arm64; about 100-150 bytes each, carried as data, mapped executable) does the clone/clone3 itself, and in the child only walks the list; on a failed step it writes the errno to Go's status pipe and exits, exactly Go's protocol. The parent half is Go's forkExec (status pipe, uid/gid map writes before releasing the child), which the converter already emits (exec_unix.cs.auto beside the hand-own). Covers every refused field plus UseCgroupFD (clone3) and PidFD (CLONE_PIDFD) the Go way. Used only when a refused field is set; posix_spawn stays the default, so banked rows do not move. Where executable memory is denied the seam keeps today's ENOTSUP.
(B) Host tools (unshare(1)/setpriv(1) exec chain): pid survives the exec chain, but a refusal arrives as the tool's exit status after the child started, not as an errno from StartProcess, so on a host that refuses, C# would FAIL where Go skips. Rejected.
(C) A C shim built at compile time, or a Go helper binary: the design's §2(b) toolchain ruling, and a Go helper cannot unshare a user namespace either (its runtime is multithreaded). Rejected.
Measurable here: this host runs all of it, so the seat can be red-first on TestCloneNEWUSERAndRemap and TestSetFallbackRoots. Darwin's Credential/Ptrace refusals are out of this seat.
