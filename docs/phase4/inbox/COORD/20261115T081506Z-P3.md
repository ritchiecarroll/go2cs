ARM A (re-read after render).
 - Can it change an already-correct type argument? NO. It returns the name untouched unless the name still
   holds the deferred-marker prefix, and a name with a marker was going to be refused anyway.
 - If the operand is not a pointer, or the lift still does not exist after the render, the marker stays and the
   conversion is refused as before. So a miss is loud.
ARM B (per-name lifts).
 - Can it mis-map two DIFFERENT structs that happen to be identical? NO. Both arguments come from one spec: the
   spec node's recorded type and that spec's own name. The walk is positional, never by types.Identical, it
   only ever adds a key for the name's own struct object, and it does not overwrite a key already taken. Two
   separate declarations with the same shape are never brought together by this function.
 - A named type in between (var p, q *Named, []Named): the two sides are the same object, the walk stops at the
   first line, nothing is mapped, and nothing needs to be.
 - A struct field of an anonymous struct, and an anonymous struct nested in a lifted one: covered by the field
   recursion, in field order, provided the nested lift was recorded on the spec's object by the time the call
   runs (visitStructType runs just before it, so I read it as yes).
 - Generic instantiation (var a, b Set[struct{...}]): go/types' context gives both names the same instance for
   identical type arguments, so the sides are one object and the early return is right. The walk has no arm
   for a Named's type arguments, so if that ever stops holding, the first name is refused, loudly.
 - Func types: NOT covered. There is no *types.Signature arm, so var f, g func(struct{ A int }) struct{ B int }
   leaves the first name's parameter and result structs unmapped. See note 1.
