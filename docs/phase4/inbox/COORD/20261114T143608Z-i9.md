1. IS THE LIMIT HARD? Yes, twice over.
- aot/ILCompiler.Compiler/Compiler/ObjectWriter/StringTableBuilder.cs:16: the table is one `MemoryStream`.
  CreateIndex (:156-168) appends each name as UTF-8 plus a NUL. A MemoryStream cannot pass int.MaxValue bytes;
  that is the "Stream was too long". The only saving is suffix sharing (:43-69).
- Behind it is the format. CoffObjectWriter.cs:966-967 writes a name's offset as a uint32, and :1043-1054 writes
  the table size as a uint32. So 4 GiB is the COFF ceiling even if the stream were replaced. :481 and :505 also
  keep every file offset in a `uint`, unchecked, so section data plus relocations must stay under 4 GiB too.

2. WHAT FILLS IT. Every symbol of every emitted node, by its full mangled name.
- ObjectWriter.cs:414-419 defines a symbol for each node's definitions; CoffObjectWriter.cs:218-246 turns every
  defined and undefined symbol into an EXTERNAL record, and :552-559 reserves every one of those names.
- Common/Compiler/NativeAotNameMangler.cs:169-329: a type's name is its assembly name plus its full name, and a
  generic instantiation spells out every argument's full name, recursively (:288-304). A method's name is its
  owner's name plus its own, plus its instantiation (:334-355, :438-459). There is NO length cap: the SHA-256
  shortening at :92-115 applies only to the compilation-unit prefix and to literals.
- Our assembly names are long (the import path), so one mention of a converted type costs roughly 100-150 bytes
  and a generic over two of them several hundred. That is an estimate, not a measurement.

3. IS THERE A SWITCH? No.
- aot/ILCompiler/ILCompilerRootCommand.cs lists every option (:19-183). None shortens, hashes or omits symbol
  names, and none skips the string table. --map (:81) and --mstat (:83) are opt-in dumps; the targets pass them
  only on IlcGenerateMapFile / IlcGenerateMstatFile (:248-249), so map generation was not in the failed run.
- Splitting exists only as --multifile (:67; IlcMultiModule, targets :243). It needs the framework compiled as
  separate objects too (BuildFrameworkNativeObjects.proj) and is not a supported publish mode. Last resort.
- -g is passed when NativeDebugSymbols is true (targets :246). It adds CodeView sections, not symbol names, so
  dropping it would cut memory and object size but not the string table.
- Method body folding is already `generic` by default (targets :227-228). `all` skips more nodes
  (ObjectWriter.cs:388-393), which removes their names. A small lever.

4. WHAT CONTROLS THE VOLUME: the rooting. checkdemo.csproj:61-63 sets PublishTrimmed with TrimMode=partial
   ("unless set"). The targets turn that into one --root per non-trimmable assembly (:205, :292) plus
   --defaultrooting (:297). UsageBasedMetadataManager.cs:326-353 then roots EVERY type of each such assembly.
   So all of golib, the converted stdlib and the converted TypeScript packages compile whole, used or not.

5. LINUX DOES NOT ESCAPE IT. ElfObjectWriter.cs:1177 derives its string table from the same StringTableBuilder
   (:744), and :256-310 names every defined symbol just as COFF does. ELF64 lifts the 4 GiB file offsets, not
   the 2 GiB stream. So I am NOT asking for a WSL SDK now.

6. FIXED LATER? No. On dotnet/runtime main the builder moved to Common/Compiler/ObjectWriter and went UTF-8
   (last change f540517cb0, 2026-09-02) and still holds `MemoryStream _stream` (:17). CoffObjectWriter there
   still has `uint dataOffset` (:387), and the mangler still has no cap. Two issue searches returned nothing;
   that is not an exhaustive search.
