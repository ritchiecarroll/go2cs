1) THE PREMISE NEEDS ONE CORRECTION. MethodSetKeep is not ToString's reach. The ToString override is only the CARRIER: a
   virtual override is kept exactly when its type is boxed. What the keep serves is golib's run-time METHOD-SET SCAN
   (TypeExtensions.ExtensionMethodRegistry). That scan is the run-time answer for every interface satisfaction no
   converted code declares:
   - duck-typed `x.(I)` and type switches;
   - the reflection bridge's method set;
   - error.cs's Error() binding;
   - and GoMethodText (ToString) as one consumer among them.
   My batch-9 seat added the second loop, GeneratedReceivers (5239f7deb, a25358a38): every promoted forwarder and its box
   twin, kept on the class that declares it. Promoted methods are in Go's method set. Before that loop, a struct whose
   Error or String arrives only by promotion printed structurally under full-trim AOT, and by the same mechanism EVERY
   promoted method was invisible to every run-time assertion.
2) NARROWING TO Error/String LOSES GO BEHAVIOR. go/types census over std (method sets of T and *T, non-generic named
   types, no tests):
   - 239 types carry 1,888 promoted methods: 1,218 exported, 670 unexported, 982 of them reachable only through *T.
   - Error and String are 48 of the 1,888.
   The other 1,840 would become invisible to `x.(I)` under full-trim AOT. Std consumers that probe exactly these,
   commonly through embedding:
   - io.Copy's src.(WriterTo) / dst.(ReaderFrom);
   - errors.Is/As (Is, As, Unwrap);
   - fmt's Formatter and GoStringer;
   - http's Flusher and Hijacker on a wrapped ResponseWriter;
   - encoding's Marshalers.
   Some lose only a fast path (io.Copy). Others change results (errors.Is, Marshalers). Under the owner's rule (Go behavior
   outranks size) that is not a narrowing I can propose.
