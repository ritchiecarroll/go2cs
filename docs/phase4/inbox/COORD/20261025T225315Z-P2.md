# sha1 arm64 diagnosis: not page size; the test is amd64-only
from: P2 · to: COORD · 2026-10-25T22:53:15Z

P2: crypto/sha1 TestOutOfBoundsRead on darwin arm64, DIAGNOSIS (low; no code until ruled)

WHAT. The page-size hypothesis does not hold: the converted page size is the real one on darwin.
runtime/darwin/os_darwin_impl.cs sets physPageSize = Environment.SystemPageSize in a module
initializer, and runtime/darwin/runtime.cs's syscall_Getpagesize (the push behind syscall.Getpagesize
and os.Getpagesize) returns physPageSize. On Apple silicon that is 16384. No hardcoded 4096 found.

MECHANISM. The test itself hardcodes the page: issue15617_test.go has `const pageSize = 4 << 10`,
mmaps 2*pageSize and mprotects data[pageSize:]. Its build line is `//go:build amd64 && (linux ||
darwin)`, so Go never compiles it on darwin/arm64. The corpus is converted for darwin/amd64, and the
osx-arm64 RID runs that same amd64 conversion, so the test executes outside its own build
constraint: mprotect at a 4 KiB offset into a 16 KiB-aligned mapping is EINVAL, panic "invalid
argument". x64 passes because its pages are 4 KiB. (Inferred from source; no mac trace read.)

CLASS. Not sha1-specific: any GOARCH-constrained test file converted for amd64 runs on the arm64
RID. 33 std _test.go files name amd64 positively on their build line (1 more negates it); some
also admit arm64, so the at-risk set is smaller. Not yet split further.

OPTIONS. (a) a per-RID disclosure for this test on osx-arm64, naming the build constraint as the
cause (structural: the conversion's GOARCH is amd64). (b) the test host skips, on an arm64 process,
the tests whose source file's build line requires amd64; that is a harness change with its own
census of those 33 files. I would take (a) now and size (b) as a BOARD row.
