CENSUS: which records are keyed by a C# position
- GoBoundedGoroutine(file, line, column): 215 records in 54 info files (32 package_info, 17
  package_test_info, 5 package_info_internal_test). ONE LINE PER go STATEMENT, apart from the file's
  other records, so two seats' edits merge conflict-free into a stale record. THIS IS THE SILENT CLASS.
- GoPositionMap, its C#-line fields: table (514,569 mapped lines in 4,290 records), calls (1,996
  groups), thunks (1,442 line:column entries). One record per .cs file, so two seats that both shift
  a file both re-encode the SAME line and conflict loudly. Silent only when one seat shifts and the
  other edits without shifting (the merged map is then the shifter's, still right for lines).
- Not C#-keyed: funcLits and methodValues (Go line space; a hop moves them, a merge cannot);
  GoStackRoot (hand-written golib method attribute, 1 use); GoImplement, GoFieldAccess, GoTypeAlias
  and the rest (type or name keyed).

starts with a separator line). The tables have no exact oracle without re-running the converter.

THE RESIDUAL in the bounded check: under a shift, 3 to 6 records still land on a goǃ, a NEIGHBOUR's
(consecutive go statements). A cross-check through the file's own position map cannot fix it: 12
shifted records land on a goǃ whose line maps to a Go `go` line, and 5 correct records do NOT map to a
`go` line (4 one-line Go funcs `{ go t.loop() }` in GoStmtReceiverBoxGroup; pprof_test.cs 2581 maps to
the enclosing func literal at Go 2066). GO2CS0010 at build has the same blind spot: a record on a
neighbour's goǃ intercepts the wrong statement, silently.

PROPOSAL (two parts; A alone is worth having):
A. repoguard TestLineKeyedRecordsLandOnTheirCode, plain go test, file reads only (no build, no
   transpile, GOROOT not needed). For every package/test info file:
   1. each GoBoundedGoroutine: its file exists beside the info file and (line, column) begins goǃ;
   2. each GoPositionMap: the table decodes (no corrupt byte, C# lines strictly increasing), no mapped
      line past the end of the file, every calls key is a table line, every thunk column follows "=>".
   Zero false positives at both trees (measured above). It names the info file, the record and what
   sits at the position. Cost: the python census reads all of it in 1.4 s here (1.2 + 0.2).
B. Close the residual at the record: GoBoundedGoroutine gains its goǃ ORDINAL in the file (the n-th
   goǃ in reading order), and the guard checks that (line, column) is the n-th. A shift onto a neighbour
   then fails, and an unrelated edit elsewhere in the file does not (no false red on a merge that did
   not move the call). Footprint: the golib attribute (a 4th parameter), the converter's record writer
   (goroutineStackRecords.go), the 215 records, and the generator (which can ignore it, or refuse a
   mismatch as GO2CS0010). R owns that record; B is R's call or a seat after batch 182 lands.
Not proposed: a digest of the .cs in each record. It is exact, but it reds every merge that touches
the file, moved or not, and on GoPositionMap it would rewrite 4,290 records.

Proving it, at build: A is made to fail first by inserting one line above a recorded goǃ and one
above a thunk in a scratch copy of the tree (it must name both), then restored byte-identical.
