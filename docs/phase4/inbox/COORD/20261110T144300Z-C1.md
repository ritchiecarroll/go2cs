THE EXPORT. The ruled shape is resolveCToolchain() (path, version string, error). Two facts do not fit a bare path:
  1. zig is invoked as `<zig> cc`, so the value the -cgo load needs is a CC COMMAND, not a path. -cc and CC already
     carry arguments the same way.
  2. The pinned zig needs ZIG_GLOBAL_CACHE_DIR and ZIG_LOCAL_CACHE_DIR set on the load, under go2cs's own cache, or it
     writes its cache into the user's home directory (the scout's instrument set both).
My proposal is one function with one extra result:

    func resolveCToolchain() (cc string, env []string, version string, err error)

  - cc: the CC value, already quoted the way cmd/go splits CC. H appends "CC="+cc beside CGO_ENABLED=1.
  - env: any extra variables the load needs. It is nil for steps 1-3, and the two ZIG_* variables for step 4.
  - version: one provenance line for the log. For the pin, "zig 0.17.0 (pinned, sha256 <first 8>)". For a host
    compiler, the first line of `<cc> --version` plus the step that chose it.
  - err: a refusal that names each step it tried. It is never a silent cgo-off load.
  - It resolves once per process (sync.Once), so a download happens at most once.
If the extra result is refused, the fallback is the ruled triple with cc as the command and NO zig cache variables,
so zig uses its own default cache. I prefer the four results.

FLAGS (mine, declared in main.go's flag set by one call into my file, or by H's increment; either is fine):
  - -cc CMD. Reserved values: `pinned` forces step 4, `host` refuses it.
  - -cc-download (bool, default true). false refuses step 4 unless the pin is already cached.
  - `go2cs toolchain install -cc [-from FILE]`, beside the Go toolchain's install.
  - docs/CommandLine.md gains both rows; TestCommandLineDocListsEveryFlag requires them.
One question for H: -cc or -cc-download given WITHOUT -cgo. I refuse that combination by name, and that check sits on
the -cgo flag path, which is H's. Should H's increment call my checkCCFlags(cgo, cc, download), or should it drop?
