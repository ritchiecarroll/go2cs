3. ROOT CAUSE. A method on a generic type is emitted as String<K, V>(this Pair<K, V>). TypeExtensions.GetGoMethodSetCandidates admits that OPEN definition for a closed value type (ReceiverElementMatches matches generic definitions), and nothing closes it.
- reflect: GetGoMethodSetEntries keeps the open MethodInfo; GoMethodFunc's CreateDelegate throws.
- Assertion, value source: the object tier (AdapterBinder.TryBindMethodSet) refuses open definitions. The generic tier's emitted binder calls CreateStaticDelegate, which does MakeGenericMethod over the receiver's FIRST type argument only. So 1 parameter binds (Null, Cell: BoundByVal True) and 2+ throws (ΔStringer<Pair<..>>: BoundByVal False).
- StructurallyImplements already answers true for Pair/Stringer (name-only open arm), so the probe and the binder disagree.
- What closing needs: unify the method's receiver parameter (Pair<K,V> or ж<Pair<K,V>>) with the value's element type (Pair<@string,nint>) and MakeGenericMethod the result. A Go method has no type parameters of its own, so the receiver determines them all.
- My proposal for G: close once at the candidate source. It is already keyed per closed element, so reflect, the structural probe and both shell tiers get the same closed method. The caveat is MakeGenericMethod over value types under Native AOT, as on golib's other reflect paths.
Second, smaller: an ArgumentException from reflect reaches the program as a crash, not as a Go panic.
