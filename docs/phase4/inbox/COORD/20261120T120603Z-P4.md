# P4 -> COORD: (jj) design -- one lift per anonymous type per package

Design post for (jj), before any code, as asked. Nothing is cut yet; this is the plan and its footprint class.

## The defect, measured

One package, one Go type, two C# lifts. Repro (a library package, landed converter, CS1503 x1):

    func With(n int) interface{ Option; Other } { ... }   // lifted With_R0
    type Holder struct{ V interface{ Option; Other } }      // lifted AGAIN as Holder_V
    func Mk() Holder { return Holder{V: With(1)} }         // CS1503: With_R0 -> Holder_V

The producer already dedups by signature (visitInterfaceType and its twin in visitStructType: lookupDynamicTypeName, then
reuse when admissible). Two things stop it here:

1. Admissibility asks only whether the NEW site needs a public type (`v.inFunction || !liftNameNeedsPublicType(name)`),
   never whether the EXISTING lift is public. An exported field needs public, so it refuses the reuse even though
   With_R0 is public, and mints Holder_V. The disjunct that used to admit a public existing lift was removed because it
   judged publicness from the name and could not see localTypeAccess's explicit `internal` on a function-local lift.
2. The registry is filled during concurrent file visits. registerDynamicTypeName keeps the lexically smallest name, but
   a reuse decision is taken at visit time against whatever is registered then, so when the two sites sit in different
   files the outcome depends on visit order. The same-file case above is deterministic; the cross-file case is not.

## The design

A. The registry records how each lift was actually DECLARED: its name, and whether its declaration is public (the
   accessibility the converter writes, including the explicit `internal` of a function-local lift), not a guess from
   the name. Admissibility becomes: reuse when the site does not need public, or the existing lift's declaration is
   public. This restores the removed disjunct on a sound basis.

B. Which name wins, decided before emission so file order cannot change it: a pre-pass over the package's files (the
   same walk that already collects names for the collision analysis) gathers every package-level anonymous
   interface/struct site by signature, with the name each would mint and whether it needs public. Per signature:
   - the winner is the lexically smallest minted name among package-level sites (the rule registerDynamicTypeName
     already applies, so where today's emission is deterministic it keeps the same name);
   - the winner is declared public if ANY site needs public;
   - only the winner's site emits the declaration; every other site references it.
   Function-local lifts stay out of the pre-pass: they keep their explicit internal declaration and reuse a
   package-level lift only under the rule in A.

C. Publication is unchanged in shape: one GoDynamicTypeLift record per signature, now always naming the winner, so the
   importer side ((ii)'s importedInterfaceLift) sees one lift per type.

## Footprint class

A converter emission change: a lift that is a duplicate today stops being declared and its sites take the winner's name,
and a winner can widen from internal to public. The stdlib footprint is NOT predicted yet. Before the cut I will run a
census over the seeded -stdlib emission at master: per package, signatures with more than one package-level lift, and
for each the names and accessibilities. That census is the basis for the posted prediction (files and lines per target,
the four targets), which goes out before the three-target A/B. If the census finds zero duplicates in std, the
prediction is 0 files and the behavioral guard carries the whole proof.

Guard: a behavioral test with the shape above in a library sub-package plus the cross-file variant (the two sites in
two files), output-compared through a main package.

## Open questions for COORD

1. Winner rule: keep "lexically smallest", or prefer the first site in file-then-position order (more readable: the
   lift is named for where the type first appears)? I recommend lexically smallest, because it matches today's
   registry and so moves the fewest names.
2. Scope: struct lifts share the code path (visitStructType's twin block). I plan to fix both in one seat, since the
   admissibility rule and the registry are shared. Say if you want the struct half split out.
