CAUSE, read at ff19c516af. A TS *Type is &data.Type promoted through embedded structs, so a FieldRefBox chain. A probe of my repro's view reads the trace's T list hop by hop: Type, TypeBase, ConstrainedType, StructuredType, ObjectType, then StandardBox<TypeReference> as the root; every hop's token is exact.
An UNEQUAL == is the costly case (an equal one is the same cached view, and the existing ReferenceEquals line answers it). At every hop, FieldRefBox.Equals runs the native arm, which walks to the root through interface tests. SameSource then calls the sources' Equals, one hop down, so the walk recurses. Finally SameGoAddress walks the chain again: OrderTokenIsExact makes one GoFieldOffsetOf weak-table lookup per hop, then AllocationIdOf. The cost is quadratic in depth.

(3) DESIGN. FieldRefBox only; operator== and C49's one-nil rule are untouched, since a field view is never nil.
- One cached byte per view, computed once from the view's immutable source and accessor:
  - MANAGED-EXACT means every hop down to the root is a field view with an exact Go offset (a reinterpret hop counts as 0), and the root is a non-nil StandardBox that does not name the zerobase and is not a NilArrayBox.
  The same byte caches IsNativeRooted and OrderTokenIsExact.
- Equals, after ReferenceEquals, when this view is MANAGED-EXACT:
  - other is a MANAGED-EXACT field view: equal exactly when PointerOrderToken matches (cached: root id<<32 plus the Go offset) AND ReferentObject is the same object (the root itself, so a wrap of the 29-bit id cannot alias).
  - other is any other kind: false, which is what today's native arm and kind test already answer.
  - anything else: today's arms, unchanged. They are now linear in depth, because they read the two cached facts.
- Equivalence for MANAGED-EXACT pairs, arm by arm:
  native arm: both addresses are 0; distinct roots: StandardBox equality is pure identity; token, name and reinterpret arms: same root and same Go offset; SameGoAddress: the same predicate.
- The one intended difference: two distinct roots whose ids collide after a wrap now compare unequal, as in Go.
- Zerobase roots stay on the slow path on purpose: distinct zero-size boxes are Equal while their ids differ. Layout: the byte goes in ж<T>'s existing padding, beside m_isNull. I'll measure the box size before and after; the prediction is +0 B.
- GetHashCode is unchanged. Out of scope, named: ElemRefBox roots (&arr[i].f) and native roots keep the slow path, linear now.
