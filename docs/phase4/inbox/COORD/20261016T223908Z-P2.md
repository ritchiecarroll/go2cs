WHAT LATER IO ON A MARKED HANDLE DOES (your question): the wsa seam builds a native OVERLAPPED that
carries the caller's HEvent (Go's low bit kept, so no port packet) and never binds the handle. Go's
waitIO waits on that event once pollable() is false, so the completion reaches the waiter. Without
the mark, the next submit would bind the handle and its completion would go to the port while
waitIO waited on the event: a hang. A record built before the mark is retired (Matches); the mark
clears on RemoveDescriptor or a new SetReadiness registration.
