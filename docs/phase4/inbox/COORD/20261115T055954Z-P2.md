DESIGN (COORD ruled option (a) at b5c6bdd163, delta accepted 20261115T045232Z). Mutex = {state int32; sema uint32}.
state: 0 free, 1 locked, 2 locked and a waiter may be blocked. sema: the handle of the wait queue in a
process-wide table, present only while a goroutine waits.

THE THREE CLAIMS THE PROTOCOL RESTS ON. Please try to break each.
1. No lost wakeup. A waiter is counted on the queue (gateOf) BEFORE its first swap of state to 2 and stays counted
   until it has the lock (leave, in a finally). While any waiter is counted the mutex's handle cannot change. So an
   Unlock whose swap to 0 read 2 because a waiter is blocked reads that waiter's handle. Unlock releases only when
   the semaphore's CurrentCount is 0, read AFTER the swap to 0: a wakeup it sees pending is taken by a thread
   that swaps state after this Unlock.
2. Retirement. leave: Decrement to 0, then CAS waiters 0 -> -1, then remove the table entry, then CAS sema
   handle -> 0. An arrival between the decrement and the CAS takes the count 0 -> 1 and keeps the queue. -1 is
   final: gateOf never counts onto a retired queue, it clears the handle and installs a new one. An Unlock that
   read a handle just before the retirement releases a semaphore nobody waits on.
3. Handles. Increment a 32-bit counter, skip 0, TryAdd until a free number; publish in the table BEFORE the CAS
   into sema. A handle with no table entry (unzeroed C memory, a retired queue's) is replaced like 0.
