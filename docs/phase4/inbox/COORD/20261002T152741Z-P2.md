DESIGN, by your five questions:
(1) WRITER: one `.editorconfig` beside the package's csproj(s), written by the same per-package pass that writes
  package_info.cs (packageInfoWriter.go), so -stdlib, single-package and -recurse outputs all get it. First line is a marker
  (`# go2cs: generated per-file warning entries -- do not edit`). An existing .editorconfig WITHOUT the marker is a user's: never
  overwritten; the converter prints a warning naming the entries it would have written. With the marker and no facts left, the
  file is DELETED (no stale file). No root = true; sections in the leading-slash form, one code per line.
  -tests: the production csproj and the .tests.csproj share the folder, so they share the file. Ownership is split by name:
  -stdlib rewrites only sections for non-_test files, -tests only `_test.cs` sections, so neither run erases the other's.
(2) PER TARGET: each target derives its own facts. The multi-platform merge already COMPOSES the project file from every
  target (mergeCompanionArtifacts / platformProject.go), and the .editorconfig takes the same route: a file the layout puts in
  <goos>/ gets `[/<goos>/file.cs]` from that target's facts; a FLAT file gets the UNION over targets (one emission, so one
  section; it can be inert on a flavour where the fact does not hold, which is the cost of a shared file). Single-target runs
  write flat paths.
(3) FACTS AND GUARD. Facts come from the converter's own bookkeeping, not a list:
  CS0219: count the references the converter actually RENDERS for each local; a local declared with a constant (or default!)
    initializer and zero rendered references is the fact. That one rule covers both of P1's shapes (Sizeof/Offsetof operands
    folded to literals, and bufio's local const whose `maxInt/2` folded), and it excludes heap-boxed locals (`ref var e`).
  CS0649: a package var with no initializer, not boxed, with no write, no address-take and no pointer-receiver call in the
    files selected for THAT target; plus a blank `var _ T` with no initializer.
  CS0675: an operand of `|` (or `|=`) that is a conversion of a signed operand to a wider unsigned type.
  GUARD (a script, linux and windows flavours): build A with the entries -> any CS0219/CS0649/CS0675 = a warning with no
