THE RULE THIS CHOOSES (for B): a type is a converted Go type iff ALL of:
 (1) it is a struct or interface (not a delegate; plain [GoType] is never on a class, the 28 [GoType] classes are pointer-defined `[GoType("ж<...>")]`, which is C);
 (2) it is declared directly inside a `*_package` class;
 (3) it is in a converted FILE: not *_impl.cs, not a [module: GoManualConversion] file, not Generated output;
 (4) it is in a converted PROJECT: the hand-owned packages are the trap. core/testing has 9 hand-written files with neither marker, and unsafe's Pointer sits beside its package class. I propose a csproj property the converter's template already owns (e.g. GoConvertedProject=true), which the generators read through AnalyzerConfigOptions; hand-owned csprojs do not set it;
 (5) its name does not end in the converter-reserved carrier suffix ᴅ;
 and, for the DEFINING part (IsGoTypeDefinition, today "carries [GoType]"): the part not in package_info.cs's TypeAccessibility section.
 Hand-written files keep the attribute as their opt-in, as the plan says.
