## m_publishedArrayBacking: PROVEN for every T that exists, not at the type level; B therefore excludes the class
- The only write is ж.cs:509, under lock(this) at :472. Its three callers:
  - arrayView (:453) and ReadBoxSlotPublished (:991) both evaluate `ref Value` / `ref ValueSlot` BEFORE the call.
  - pinnedArrayData is reached only from `operator uintptr` and `operator void*`. Both return early for a box with
    NativeAddress != 0 (:1407, :1510).
- On a NativeBox, Value runs ValueAddress(). There the NAMED-ARRAY FLOOR (ж.NativeBox.cs:154-155,
  `s_isNamedArrayShaped && address != null`) throws before the lock. (The reader corrected my hypothesis: it is
  not s_isReference.)
- The floor flag equals the publish flag plus `IsReferenceOrContainsReferences<T>`. Every value-type IArray that
  exists today holds a reference: go2cs-gen's holder wrapper, and the array-view wrapper. So the proof holds over
  today's types only.
- A future reference-free value-type IArray (not a slice, not array<>) would pass the floor and reach the write on a
  native box. So B excludes every T whose s_publishArrayBacking is true. The cost is zero, and it turns the proof
  into a type-level one.

## Existing bug found by the census (not B's; for the BOARD)
- sync/atomic/doc_impl.cs CompareAndSwapPointer, managed arm: `Interlocked.CompareExchange(ref addr.Value, @new,
  old) == old`.
- The exchange compares by REFERENCE, while `==` on unsafe.Pointer compares by value.
- So with the slot holding p1, and old being p2 (another object over the same address): nothing is swapped, p1 comes
  back, and p1 == p2 is true. The call reports swapped=true without swapping.

  the slot is unchanged.
