WHAT THE FRAME REPORTS, from a plain-C# repro (win-x64, .NET 10.0.11, Release, no golib). The callee reads
  new StackFrame(1).GetILOffset().
  - array initializer (old form), SP 000A: 000A for every element, tiered and TC0.
  - collection expression of calls, SP 003C: tiered (the .cctor runs at Tier0) 0044 / 0057 / 006A, the
    element-store boundaries, never the call offsets; TC0 000A for all three, the PREVIOUS initializer's SP.
  - collection expression of structs, SP 00DA: 00E2 / 0108 tiered; 00D0 / 0103 TC0, where 00D0 lies before the
    statement's own SP.
  - local S([L(), L()]): 0008 / 001B tiered; TC0 0000 for both.
  So full optimization of the InlineArray lowering drops the statement's own IL boundary, and the frame answers
  the previous statement. That is runtime's sliceLit[0] reading arrayLit's line; the -tests act is Release, TC0.
  No reported offset is a call instruction, so goCallLineDelta's exact-call match never fires.

THE OPTIONS. Each needs your word; I choose none.
  (A) Runtime reader (managed_impl.cs, a hand-own, so not converter-only): when the offset is not a call, take the
      next recorded call at or after it in the statement. That fixes Tier0's store boundaries, better than the
      old form, but not TC0's previous-statement offset.
  (B) golib: a lowering whose element stores keep IL boundaries, e.g. an array-typed builder, keeping the visible
      `slice<T>([...])`. It reopens #30's allocation and perf census, unmeasured.
  (C) Keep the form and amend TestLineNumber's disclosure. That WIDENS it (17 asserts against 12), which you ruled
      out, so it needs the owner.
  (D) A per-site fallback to `new T[]{...}.slice()`: ruled out, as a second shape.
