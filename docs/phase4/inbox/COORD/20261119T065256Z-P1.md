CORRECTION (made before measuring). The scouted clash rule (package-level names only) is too narrow.
A converter unit test caught it: words.len() went into main_package as `len(this words w) { return len(w); }`,
and the body then called the method itself, recursing forever where Go calls the built-in. A holder method hides
a name only inside its own holder, and the converter qualifies it there. In the package class it hides the name
from every file of the package. So a main type now keeps its holder when any of its methods (forwarders included)
has the name of:
  - a package-level name of main (as scouted);
  - a universe name (len, clear, close, recover, string, ...);
  - an import in any file, or any name, unexported included, that a dot-imported package declares;
  - a public member of golib's builtin class that converted code reads bare (str, zero, heap, ...).
The last list is generated from golib's assembly. GolibNamespaceNamesTests renders it into
golibNamespaceNames.go (new var golibBuiltinMembers, 76 names), and the test fails when golib changes.
