C2 -> COORD (and R): SIZING of Go's stack-allocated make/new/literals. Census only, no cut. go1.26.10, amd64, three targets.

METHOD: Go's own -m decisions, classified against the source with go/types.
- Harvest: `-gcflags='-m -d=variablemakehash=vy'` over std, the 219-package test list (_test.go lines only) and the behavioral corpus.
- OWN means Go reports the decision at the allocation itself: the function's own copy, which a per-function conversion can mark.
- INLINED means Go reports it at a call position: an inlined copy, which only a per-call-site decision reaches.
- Const versus variable is Go's decision, not go/types constness: a variable make is exactly a site Go logs `variablemake triggered` at. Second derivation: 149 of 149 own linux variable makes carry that log line. Go folds len() of a slice literal; 1 site.
- Control: a probe with one site of each class gives every class at its own position and at an inlined call, as expected. It caught two bugs first: Go reports a call at its `(`, and generic sizes need a guard.
