# F2 sized: go-cmp cyclic = golib CreatorFrame (386 s -> 20 s floor); fix A small

F2 SIZED (go-cmp v0.7.0, TestDiff/Transformer/CyclicString + CyclicComplex). Reading only, no fix. Master 20279db5f6,
windows, Release with DOTNET_TieredCompilation=0 (the configuration of record) unless noted.

REPRODUCED: both pass at 381-386 s wall (parallel subtests; C2 read 269 s on linux). Go: 0.30 s and 0.21 s.

WHAT THE TEST DOES: go-cmp's recChecker only panics "recursive set of Transformers detected" once the path reaches
65,536 steps (1<<16). So each subtest recurses 65,536 Go levels deep (several deferring Go frames per level), then
panics through all of them. Every cost that grows with stack depth is multiplied here.

HOT PATH (dotnet-stack samples, then EventPipe CPU sampling; analyzer in scratch gocmp/ntagg):
1. golib Goroutine.CreatorFrame (golib/runtime/Goroutine.cs:1113), at EVERY `go` statement: 86% of on-CPU samples.
   It builds `new StackTrace(false).GetFrames()`, resolving a MethodBase for every frame of the full stack, to keep
   the first frame above golib's launch machinery (2-3 frames up). go-cmp's callTRFunc runs `go detectRaces(...)`
   whenever its dynChecker fires, on the 65,536-deep stack.
   MEASURED A/B, local experiment only (golib patched in a scratch worktree, host re-published, tree restored clean):
     base 386 s | frame-at-a-time walk (new StackFrame(n) until outside golib) 70 s | capture stubbed 20 s.
   The walk still spends 40% in CreatorFrame: each StackFrame(n) is a full native stack walk. O(1) is needed.
2. Residual at the stub floor (20 s for both = 67x Go). Fixed: host startup 1.4 s, a trivial TestDiff subtest 2.4 s.
   CyclicString alone 8.7 s, i.e. ~6.3 s of work vs Go 0.30 s (~20x), spread over per-step costs:
   - panic unwind: a deferring frame is emitted `catch (when IsPanic) { Capture } finally { Run }` and Run re-raises,
     so the panic is caught and re-thrown at EVERY deferring level. Probe (scratch deeppanic: 65,536 deferring
     levels, panic at the bottom): C# 285 ms vs Go 9.5 ms (30x), ~4.3 us per level, roughly linear in depth.
     The normal return of the same recursion: 80 ms vs 6.3 ms (13x).
   - thread-per-goroutine creation (Thread.StartCore + StartWithCreator ~13% of the stub trace), reflect.Call /
     MethodBaseInvoker, StandardBox struct copies (BulkMoveWithWriteBarrier under compareSlice's withIndexes), and
     GC stack-scan of very deep stacks. EventPipe overweights deep phases, so these shares are indicative only.

FIX SKETCH AND EFFORT:
A. golib, small, ~1 day with gates. Make the creator capture O(1) per `go` site: the `goǃ` rungs take
   [CallerFilePath] / [CallerLineNumber] / [CallerMemberName] optional parameters (filled by the C# compiler, so
   converted code recompiles unchanged: no converter or corpus change). A static cache keyed by (file, line)
   resolves (MethodBase, IL offset) once with the existing identity walk. Every later `go` from that site is a
   dictionary lookup. Expected near the measured 20 s floor: 386 s -> ~20 s for the pair, CyclicString ~9 s with
   startup. That fits go-cmp's default 2m -test-timeout, so it ships without the 10m override.
   Fallback if caller info is rejected: the frame-at-a-time walk, measured 70 s, a 10-line change.
B. Converter, medium (emission change, corpus-wide goldens): emit a deferring frame's catch only when a deferred
   call can recover. Go's recover only works called DIRECTLY by the deferred function, so a defer of a known
   function or literal whose body has no recover() cannot recover. compareAny's defers (curPath.pop, PopStep)
   qualify. The panic then crosses those frames in ONE .NET dispatch instead of a catch + re-throw per frame.
   Bounded by the unwind share, ~1-2 s of the residual here.
C. Getting within 10x of Go (~3 s) for THIS adversarial test needs A + B plus per-step work: reflect.Call cost,
   value-struct copies, thread-per-goroutine. No single fix gets there; several medium golib projects. Realistic
   after A (+B): ~15-20x Go on this test. Ordinary go-cmp use (shallow paths) is not dominated by any of these.

CLASSIFICATION: golib, not the converter and not the reflect bridge (reflect.Call is ~5%). B alone is a converter
emission change. The Go 1.26 hop does not touch it: Goroutine.CreatorFrame and GoFrame are hand-written golib,
version-independent, so A can land before or after the hop.

RECOMMENDATION: A, as a small golib seat, before go-cmp ships (it removes the 10m timeout need). B and C go to the
BOARD as performance findings, not blockers.
