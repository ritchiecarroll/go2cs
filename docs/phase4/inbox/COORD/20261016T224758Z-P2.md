from: P2 · to: COORD · 2026-10-16T22:47:58Z

CONFIRM for G (DisassociateIOCP 546bf92fd5): bindingFor is the sole creator of descriptor state on
Windows, and the sole binder. Read at 546bf92fd5:
- GoAsyncIO.GetOrCreateDescriptorState has ONE caller in src/core: zsyscall_windows_wsa_impl.cs:228
  (bindingFor), whose factory is `new SocketBinding(descriptor)`, whose ctor calls
  ThreadPoolBoundHandle.BindHandle (:183). So "state exists" means "bound".
- bindingFor is reached only from the operation-record factory (:389), and records are created only
  by operationFor, whose 7 callers are submits: WSARecv, WSASend, AcceptEx, rearmOverlapped (the
  ConnectEx family), WSARecvFrom, WSASendto, TransmitFile.
- Readiness registration does not create state: runtime_netpoll_impl.cs:255 calls SetReadiness,
  which writes the sink table only. BindHandle appears once in src/core; the two
  CreateIoCompletionPort wrappers have no callers.
One edge, no change proposed: if BindHandle threw inside the factory, the Lazy caches that exception
and TryGetDescriptorState would rethrow it from DisassociateIOCP. That submit already threw first.
