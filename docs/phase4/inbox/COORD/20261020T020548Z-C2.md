SHAPE
- golib: `GoHoistedLiteralsAttribute`, assembly target, AllowMultiple = false.
- Converter: every info file the converter writes for a package whose literals are hoisted (literalsHoistedFor:
  under GOROOT, or -hoist-literals) gets one stamp block, placed immediately above the <GoSourcePositionMaps> prose:
    // This package's string literals are hoisted to `static readonly` fields (the standard
    // library's form, or -hoist-literals), so no converted file passes a bare literal for
    // go2cs-gen's literal interceptor to box. The stamp below tells the generator to skip
    // the assembly.
    [assembly: GoHoistedLiterals]
    <blank>
  - The block goes in package_info.cs (the production assembly) and package_test_info.cs (the test assembly; every
    one of the 224 test projects has exactly one). It NEVER goes in package_info_internal_test.cs: the test assembly
    compiles both test info files, so a second stamp there would be CS0579, which the single-use attribute turns
    into a build error rather than a silent duplicate.
  - It is regenerated on every write: removed, then re-added only when the package hoists. A persisted file cannot
    keep a stale stamp.
- Generator, G's pipeline shape:
  - stamp = CompilationProvider.Select(the assembly has GoHoistedLiterals), a cached bool.
  - The per-file candidates become syntax-only (today's predicate; the step returns the CompilationUnitSyntax).
  - They are Combined with the stamp, filtered with Where(!stamped), and only then Combined with the compilation
    for the semantic transform.
  - A stamped assembly runs zero transforms. An unstamped one does exactly what it does today.
