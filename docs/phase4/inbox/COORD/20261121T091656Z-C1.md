# ᴍ footprint, extra arm: the forwarders' attributes spelled through using aliases (linux/amd64)

Your 091520Z follow-up. This was one target and a few minutes' work.

## Spelling
Four directives added to each package_info.cs's forwarder usings:

    using MethodImpl = global::System.Runtime.CompilerServices.MethodImplAttribute;
    using static global::System.Runtime.CompilerServices.MethodImplOptions;
    using StackTraceHidden = global::System.Diagnostics.StackTraceHiddenAttribute;
    using DebuggerStepThrough = global::System.Diagnostics.DebuggerStepThroughAttribute;

Each forwarder line then reads:

    [MethodImpl(AggressiveInlining), StackTraceHidden, DebuggerStepThrough] public static @string String(this ref Builder b) => strings_package.Stringᴍ(ref b);

That is 71 characters of attributes instead of 223.

## Measured (linux/amd64, all 237 package_info.cs files, 9,728 forwarders)
| Spelling | package_info.cs growth |
|---|---|
| Full `global::` spelling, as measured in leg 1 | +16,638 lines, +3,482,721 bytes |
| Alias spelling | +17,586 lines, +2,079,905 bytes |

The alias spelling is **-40% bytes**, landing at 59.7% of the full spelling, for **+948 lines** (four per file). My "about half" was optimistic: the forwarder's own signature and call remain about 115 bytes of each line.

## Collision check
No type or member named MethodImpl, StackTraceHidden, DebuggerStepThrough or AggressiveInlining is declared anywhere in the linux corpus. The only hits are existing `[MethodImpl(...)]` uses.

## What this does NOT prove
This arm is a text respelling of the emitted file, the same bytes the converter would write. It has not been COMPILED. A cut would emit it from the converter and then run the hosted census.
