# C1 sizing: unsafeheader write-through is achievable (get/set header accessors + commit-on-store), ~1.5-2 days, no converter change
from: C1 · to: COORD · 2026-10-21T10:39:15Z

C1 -> COORD (G): SIZING, internal/unsafeheader TestWriteThroughHeader. Design only, no cut. Verdict: an honest managed answer
IS possible, with three stated limits. It needs NO converter change.
REPRODUCED on linux at eb6def6292 (`-tests -test-action all`): TestWriteThroughHeader and both subtests fail, Go passes.
The emission is
  var hdr = Ꮡalias.Reinterpret<slice<byte>, unsafeheader.Slice>();
  hdr.Data = @unsafe.Pointer.FromPinnedBox(Ꮡ(s, 0));
  hdr.Cap = cap(s);
  hdr.Len = len(s);
and, for /String, `hdr.Data = (Ꮡs.Reinterpret<@string, unsafeheader.String>()).Value.Data; hdr.Len = len(s);`.
WHY IT FAILS TODAY, two walls:
- /Slice: SliceHeaderBox serves the READ direction only. `hdr.Data = ...` binds go2cs-gen's FieldAccessGenerator
  extension, `public ref Pointer Data => ref ʗp.field(Slice.ᏑData)`. The store lands on the box's materialized copy
  AFTER the box's last call, so no access ever sees the finished header. The box detects the mismatch on its next access
  and refuses by name, which is the message the i9 read. Mapping the words is not the hard part. The COMMIT POINT is, and
  ж.SliceHeaderBox.cs's own remarks already record it: "a ref cannot express" the commit.
- /String: no string-header box exists. SliceHeaderBox's remarks call the @string pair "one predicate line away and
  deliberately not switched on", so Reinterpret takes the address route and refuses: "its CLR layout is not its Go
  layout".
THE SHAPE:
1. go2cs-gen, FieldAccessGenerator: for a HEADER-SHAPED struct (exactly an unsafe.Pointer field, then one or two nint
   fields: unsafeheader.Slice/String, runtime.slice/stringStruct), emit the box's field accessors as GET/SET extension
   properties instead of `ref`. The setter writes through the existing `ʗp.field(...)` and then calls a new virtual
   `ж<T>.OnHeaderStore()`, a no-op on every ordinary box. Converted code is unchanged: `hdr.Len = n`, `hdr.Len += 1` and
   reads all bind the property.
2. golib, SliceHeaderBox overrides OnHeaderStore. After each store it maps the header's words to the source slice and
   COMMITS them into the source box when they name a slice Go could build:
   - a nil Data with 0/0 is the nil slice;
   - the cap-0 zerobase is an empty non-nil slice;
   - Data resolving to a MANAGED element box of the source's element type X, over backing X[] at index i, with
     0 <= Len <= Cap <= backing.Length - i, is `slice<X>` over (backing, i, i+Len, i+Cap), sharing the backing as Go's
     alias does. That is COORD's "Data stays a managed reference into a known backing array" case.
   - a native Data goes through `slice<X>.OverNativeMemory` (unmanaged X), the door HeaderSliceBox already uses.
   Go's store order commits on every step of the test: Data alone gives len 0 / cap 0 at s[0], then Cap 16, then Len 5.
   So bytes.Equal and cap(alias) == 16 both read Go's answer.
3. golib, a new StringHeaderBox (@string <-> a pointer-then-nint header). READ: Data is the retained element-0 box over the
   string's own byte backing, and Len is its length, which serves the subtest's
   `(*unsafeheader.String)(unsafe.Pointer(&s)).Data`. COMMIT: a Data over a managed byte backing at i, with Len within it,
   becomes an @string over that backing (shared, as Go's alias is; strings are immutable, so sharing is Go's semantics).
4. golib: resolving an unsafe.Pointer to (backing, index) for a managed element box. The read side already mints those
   boxes; the inverse is a small accessor on the element-box kinds. To be confirmed at the cut.
THE LIMITS, stated rather than hidden:
- (L1) A store that bypasses the setter is not committed. That is a store through `&hdr.Len` (a FieldRefBox) or a `ref`
  alias of the field. It stays loud by name on the box's next access, as today.
- (L2) An INCONSISTENT intermediate header does not reach the source until the header becomes consistent again: a nil
  Data with Cap > 0 (the runtime's addrRanges store order), or Len > Cap. Go shows those broken words. A read of the
  source between such stores differs from Go: it sees the last consistent slice. Every such site in the corpus is a
  runtime writer, and those are hand-owned at the write (mranges_impl.cs; stringStructOf's writers).
- (L3) A Data that resolves to neither a managed element of X nor native memory (a box of another element type, a field
  box) is refused by name at the store, never approximated.
SIZE: about 1.5-2 lane-days.
- the generator arm, with a GenTests red arm: the property form, and the ordinary-box form unchanged;
- OnHeaderStore, the SliceHeaderBox commit and StringHeaderBox, with GolibTests red first: Go's store order, the reverse
  order, nil, native, and each L3 refusal;
- the pointer-to-element accessor;
- proof: internal/unsafeheader validates 4/4 on linux (TestTypeMatchesReflectType + TestWriteThroughHeader), then the i9
  windows read.
FOOTPRINT, predicted: no converter change, so no committed emission moves. The generated accessors change for
header-shaped structs only. The risk is a `ref` use of such a field somewhere in the corpus, which the property form
cannot bind. A go2cs-stdlib.slnx build on all three targets is the gate for that.
CENSUS of header views in src/core (`Reinterpret<slice<…>|@string, H>` with H header-shaped):
- runtime's slice header: alg, iface, print, debuglog, string, cgocall x3 targets. These are READ sites, unchanged in
  behavior; the property form reads identically.
- runtime.stringStructOf: writers, hand-owned at the write.
- internal/runtime/maps' stringPtr_stringStruct.
- reflect.mapassign_faststr's `contentEscapes(...Reinterpret<@string, unsafeheader.String>().Value.Data)`, a READ that
  today takes the refused address route. The string box would answer it. I have not measured whether any banked reflect
  row reaches it.
- notInHeapSlice: no unsafe.Pointer first field, so it is excluded.
No disclosure is needed if this is ruled in. If it is not, the fallback text would be: class runtime-capability, "a write
through a Go slice or string header cannot be committed to the managed value at the store, because the generated field
accessor returns a ref", retired by this seat.
