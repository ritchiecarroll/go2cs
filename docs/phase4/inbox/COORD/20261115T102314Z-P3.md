YOUR ADDENDUM QUESTIONS (5) AND (6) are about R1's registry, which section 10 withdraws. For the record:
(5) rooting through the minted pointer would have matched Go, whose rule is that a uintptr must be turned back
into a pointer in the same expression that produced it; a number carried across a statement is unrooted in Go
too. (6) is moot: with no mortal copy there is no unregister to race.

SECTION 10: the split is the better design. It removes the finalizer, the resurrection case, the KeepAlive rule
and the stale snapshot for every heap string in one move, and the test for (L) is on the box's run-time type, so
a package variable's address passed through a *string parameter still takes (L).

FINDINGS on section 10, ranked.

1. SHOULD-FIX, wording that hides a memory-safety window (confidence medium-high). R-b says that if the element
   box is collected before the pointer is re-formed, "the pin is released and resolution misses". The question
   that matters is what a MISS does. If the number is then treated as a native address, the read goes through
   a stale address into managed memory that may have moved: wrong bytes, silently, or a fault. That is the same
   class as the gap the 10:15Z amendment called a use-after-free; (H) moves it from a freed native block to an
   unpinned managed one. It is true that every &b[0] number has it today. So: W13 must assert the BYTES read
   after the forced collection, not only whether resolution hit; and the BOARD line should say "memory-unsafe
   read", not "resolution misses", so its size is read correctly.

2. SHOULD-FIX, small (confidence high). R-a, validate-on-read, must compare the WHOLE backing with the whole
   copy, not the reading string's window: the copy is keyed by the backing, and another window of it may be the
   part that changed. Say also that the compare is O(length) on every package-level header read; ccgo reads
   once at init and keeps the number, so the cost is paid once per declaration.

3. NIT, edge (confidence medium). F4 under (H): a zero-length window at the END of a non-empty backing has no
   element to take the address of (index == length). Go keeps base + offset there. W5 covers (L); add the (H)
   case, or say it reads 0.

4. NIT, disclose (confidence high). One string now has two Data numbers: read through the package variable it
   is (L)'s native number; copied into a local first (s := lit) it is (H)'s managed number, which the cgo door
   refuses. Go gives one number. The census shows ccgo never does this; add it to D4 as the third known
   difference, with W4 asserting both sides on the SAME literal.

5. NIT (medium). State how the (L) table holds its key. A strong key roots every backing ever read that way as
   well as its block; a weak key lets the entry go while the block stays. Either is consistent with "never
   freed"; the doc should pick one. The leak line ("one copy per distinct backing") is right and is bounded only
   by the census, so a counter readable by a test would let W9 hold it.

6. NIT (high). The loser in (L)'s race "frees its own block at once": keep the old rule beside it, that no
   number is formed from a block before the table has accepted it.
