HARNESS (P5's GeneratorDriver; scratch only, nothing committed):
- Both arms call the REAL LiteralInterceptorGenerator.Transform by reflection, and count and time each run per file.
  - faw: ForAttributeWithMetadataName("go.GoInterceptLiteralsAttribute"), keyed on the package-class partial.
  - csp: today's CreateSyntaxProvider over each compilation unit.

G's pass line (an unedited file costs about the control's) is NOT met.
- Why: the attribute index narrows WHICH nodes match, exactly as the syntax pre-check would. A transform that
  receives a SemanticModel still re-runs for every matched node on every compilation change; only the downstream
  output is cached.
- The probe also shows what any per-file isolation would have to give up: an edit in another file can change what an
  unedited file's call binds, for example an overload that captures a literal. GO2CS0006 must see that. A transform
  cached per tree could not.

WHERE ONE SITE'S TIME GOES (COORD's item 2). Measured on AnyBoxedUntypedConst: one file, 57 candidate calls, fresh
compilations, medians of 15.
- The first semantic query of a method body binds that body: GetOperation 0.35 ms per call, GetSymbolInfo 0.35,
  GetMemberGroup 0.39. That is about a whole-file GetDiagnostics (0.45).
- After the bind, everything is small:
  - the member-group bind for the drift guard: 0.027 ms per call;
  - the accessibility check: 0.034;
  - GetInterceptableLocation: 0.003, with no bind at all.
- The real Transform: 28 ms on a fresh model and 9 ms on a warm one. Binding is about 2/3 of the cost, and the
  generator's own work about 1/3.
- So the cost is the BIND, which any semantic transform pays. No cheaper API call removes it.

THE FALLBACK, per G: -hoist-literals as the opt-out, plus the disclosure with the per-site number. Measured number for
the post: about 0.06-0.3 ms per site, in EVERY file with sites, on EVERY edit, plus the driver. For example, 3,000
sites cost about 0.2-0.9 s per keystroke. The doc keeps it abstract: the cost grows with a project's any-slot literal
sites, and -hoist-literals is the opt-out for a large project that is IDE-heavy or performance-critical.

TWO THINGS FOR A RULING before I cut:
1. COORD's syntax-only pre-check (item 1, superseded by G's message). It does not fix the per-site cost. It does
   remove the cost of finding nothing, which is P6: fmt 32 ms and net/http 572 ms, files with no site. I recommend
   it in this seat anyway. Yes or no?
2. The only shape I can see that WOULD isolate: the generator does no binding at all.
   - The converter, which knows each callee, would stamp what the interceptor needs: the callee's C# signature and
     each slot.
   - The generator would then use only GetInterceptableLocation, which needs no bind (3 us per call).
   - The drift guard (GO2CS0006) would move to the build-time analyzer.
   The cost is converter machinery, and a generator that trusts stamps rather than binding. I do NOT recommend it
   without G. I am naming it so the choice is explicit.
Absent a ruling, the default is the fallback: disclosure in strings.md, plus the pre-check if (1) is yes. Then
re-measure and post the head.
