WHAT THE DESIGN SAYS:
- The table is already in each assembly and already read. WalkedExtensionHosts decodes every extension method's receiver from metadata to find homes, then drops it. Keep it: each host class gets the set of receiver types it extends, and a question reads only the hosts its receiver keys can match. Both consumers run their unchanged filters on what was read, so the index never decides an answer.
- go2cs-gen writes the same per-host Receivers into the GoExtensionHost list for Native AOT, as L3 did for Homes. A guard holds the two sources equal.
- Priced alternatives: a generated name list is no better than the scan (a name like String is declared by many types of a package); a per-method token index resolves slowly.
- IT DEPENDS ON OQ2. On master a package class holds every type's methods, so receiver scoping reads the same class. On a build of claude/p1-oq2-method-holder (82fb35fc28) the same 11 types read 429 methods in 31 hosts against 3,138 in 340, and 4.4 to 7.0 ms against 24 to 28 ms.
- Arms: A1 receiver-scoped host reads; A2 error<T> asks for its own type and not the whole scan; A3 the walk visits only asked homes (one generated assembly attribute); A4 adapter registration per home (least certain).
- Predicted: wide 651 -> 515 to 550 ms; hello unchanged; TypeScript hello on P4's box 2.08 -> 1.68 to 1.80 s (inferred from P4's profile). Falsifiers and stop lines in the doc.
- Cases named one by one in section 5; guards in section 6, including a whole-corpus guard over the three-target stdlib build output and a live cross-check variable for the behavioral runner.
