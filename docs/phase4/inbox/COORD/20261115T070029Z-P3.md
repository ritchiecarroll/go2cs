FIX 1 (Dispose vs Activate): CLOSES the race. Both orders walked.
 - Release first: Dispose CASes Open -> Closed, then reads Current. If it reads null and Activate follows, the
   backfill's TryBeginBackfill fails on Closed, so nothing enters and the handle is never read after the free.
 - Backfill first: it can only have run with the index published, so the Dispose that closes afterwards reads
   Current as non-null, takes the gate in LeaveBackfilled and removes the entry before the free.
 - Overlap: the backfill holds Backfilling across the ContainsKey, TryExtent and Add; Dispose spins on that state
   and cannot free the handle under the read. EndBackfill's unconditional write of Open is safe, because the only
   other writer (Dispose's CAS from Open) cannot succeed while the state is Backfilling.
 - The stale key is gone with it: an entry now always leaves m_backfilled before its handle is freed, so
   ContainsKey can no longer skip a later buffer that was reissued the handle's value.
 - No lock order: Dispose holds nothing while it spins, and the backfill's hold is the gate plus page or large
   locks, none of which a release takes before it closes.
