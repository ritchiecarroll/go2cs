## Shape
T.Deadline() = min(TestHost.PackageDeadlineUtc, now + (TestDeadline - charged)), read from the watchdog's own clock
(the top-level test's m_clockRoot: m_runningSince and m_chargedTicks under m_clockLock). That is the instant
WaitBounded abandons the test if its clock keeps running. Two choices to rule on:
- A testing.RunTests list runs inside its caller, and the watchdog bounds the CALLER, so a listed test reports the
  caller's clock (NestedRoot carries it). Its own clock root is never watched.
- With no package deadline (-timeout 0) and a per-test deadline set, Deadline reports ok=true with the per-test one.
  Go reports ok=false there, but the per-test bound still ends the test. The sweep never passes 0.
Read BEFORE t.Parallel(), it is start + D, while the watchdog restarts the clock at resume. That errs EARLY, never late.

## Which rows can move
A row moves only when its effective package budget is LONGER than its per-test deadline. The package deadline counts
from host start, and a test starts later, so a row whose budget is less than or equal to its per-test deadline reports
exactly what it reports today.
- Local default (10m / 15m): only rows in $longTimeouts with a per-test deadline under their budget. Among the
  t.Deadline rows: net (120m/15m), net/http (60m/15m), runtime (120m/60m). crypto/tls moves through testenv only.
  internal/poll (30m/30m) does NOT move locally.
- Hosted sweep-shard (45m): every row above whose per-test deadline is under 45m, which is all of them except
  crypto/dsa, go/parser and sync/atomic. None of those three calls t.Deadline.
