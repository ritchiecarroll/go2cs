PICK: sync.RWMutex is the last sync lock that is neither Go's layout nor Go's code. Today it is hand-owned
(rwmutex.cs): one managed reference, RWState, a monitor plus four counters. Measured the same way:
  row                          Go 1.26.11       master          floor in C#
  RLock + RUnlock              14.8 to 15.8 ns  64.7 ns         15.4 ns (two atomic adds)
  Lock + Unlock                22 to 30 ns      65.6 ns         -

  first use of a new RWMutex   0 B              about 120 B with its box (RWState + gate about 96 B, inferred)
It also differs from Go in behaviour, not only in cost:
  1. A COPY shares the state. Write-lock an RWMutex, copy it, unlock the original: the copy's TryLock() is
     true here (measured) and false in Go, where the copy is a separate locked RWMutex.
  2. It cannot sit in C memory: a struct holding it is refused by the native box, the shape W9 cured for
     Mutex (inferred; the cut shows it red first).
  3. reflect sees one opaque handle where Go sees five fields, so DeepEqual of a held lock and a free one
     reads equal.
