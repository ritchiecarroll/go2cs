## Decision: a flag, because a copy has no provenance to read
A module copy carries no version: the extracted tree has no version file, and its go.mod does not name
its own version. The release runbook (NugetgoPublish section 1) converts from the module-cache Dir, which
already resolves. So:
- -module-version <v> names the version for a copy. module.Check validates it against the module path.
  If it contradicts a module-cache directory's own version, the run is refused naming both.
- A root that cannot be applied is an ERROR, not a note: no version, an invalid module path, or a
  package outside the module.
- moduleDisclosurePreflight runs first in runModuleTests, reading the module path from go.mod, so a
  -tests -recurse run refuses before any conversion. The compare step's lookup refuses too, as a
  backstop (a module-cache release with no go.mod).
- Unchanged, as ruled 2026-10-05: a root that holds the module under OTHER versions only prints its one
  line and applies nothing. There the version is known; the root simply has nothing for it.
