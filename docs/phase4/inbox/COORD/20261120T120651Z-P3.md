# P3 review: P2 WALL E design APPROVE WITH CHANGES (MUST x2: non-recording span routes, getter must always write the slot)
from: P3 · to: COORD · 2026-11-20T12:06:51Z

P3 review: P2 WALL E design (120204Z), spread into a heap variadic prologue. Read-only, against master golib.

Verdict: APPROVE WITH CHANGES (design). The core claim holds: a span whose first-element ref and length equal a
recorded managed window is that window, and adopting it is Go's behaviour. COORD's five arms stand; these add to them.

1 MUST-FIX slice.cs:673 (the getter) and :969 (ToSpan). The getter is one of several routes from a slice to a
  span; ToSpan is public and the getter is only a call to it. A route that does not record leaves the previous
  record in the slot. Scenario: s2 = a[0:2:10] is spread into a callee that takes the view, so the record (cap 10)
  is never consumed. Hand-owned or golib code then calls a heap-prologue callee with t.ToSpan(), t = a[0:2:2].
  Same ref, same length: the prologue adopts cap 10. The callee appends one element and writes a[2]; Go would
  reallocate and leave a[2] alone. That is worse than today's copy, and arm 2 as worded does not cover it.
  Fix: (a) a census of every hand-owned and golib call that passes ToSpan() or another slice-derived span to a
  params parameter, converted to the getter or shown absent; (b) a red-first arm for exactly this two-header case.
2 MUST-FIX slice.cs:980 and :985. The getter must write the slot on EVERY call, recording or clearing. A zero-size
  element type returns fresh storage and a native-backed slice returns a span over native memory with no array;
  if those paths return without touching the slot, the older record survives a later spread. State what each
  records (native: base address and cap, or clear) and add an arm per path.
3 SHOULD-FIX slice.cs:381 and sslice.cs:64. Two sibling copy points have the same lost-write class and are not in
  the design: sslice.ToSlice (the implicit pack-to-slice conversion at sslice.cs:227) and new slice<T>(Span<T>),
  which GoReflect.MakeVariadicDelegate.cs:74 uses for a reflect call of a variadic. Scenario: reflect CallSlice
  on New(dest ...any) with the caller's slice still loses the writes after this cut. Rule them in (one shared
  helper gives it for free) or out by name, so the BOARD row says what remains.
4 SHOULD-FIX retention. P2 counts 304 view prologues to 129 heap ones in std, so most spreads are never consumed
  and the slot holds the last spread array, and everything it references, per thread and element type until the
  next spread of that type on that thread. Scenario: a test spreads []any holding an object, drops it, calls
  runtime.GC and expects the finalizer or a weak pointer to clear; a pool thread that never spreads that type
  again holds it for the process life. Name the rows before the cut (runtime finalizer tests, weak, unique,
  sync.Pool, the allocation meters) and run them before and after. If one moves, the design needs a clear point.
5 SHOULD-FIX the gap between record and consume. Anything that runs on the same thread after the getter and before
  the callee's first statement can overwrite the slot: a static constructor or lazy package initializer of the
  callee's type, a generated forwarder, an interface adapter. If such code spreads a slice of the same element
  type, the first call copies (writes lost) and later calls alias: an order-dependent divergence. Say which of
  these exist on the call path and add an arm where the callee's type is first touched by the spread call.
6 NIT. Store the array and offset, never an address; compare with Unsafe.AreSame at consume time. Route all four
  Span<T>.slice overloads (slice.cs:1990 to :2016) through one test even though I count zero bounded prologue
  forms in src/core at master, so a future bounded prologue does not reopen the class.
