The finalizer makes a NEW object (managed_impl.cs:846), which starts in gen0, so the next gen0 collection finds it. Collections that happen while a firing is pending or running fold into one firing: AgeForCollection reads the count once and serves through it.
2. TryEnter never drops a cycle forever: sound. s_gcCycleLock has three users only: gcCycle (:1042, runtime.GC, whose drain wait is bounded), the Sysmon tick (:1239, itself a TryEnter), and AgeForCollection (:810). A skipped firing happens only while a full cycle holds the lock, and that cycle runs the cleanup itself at its start.
3. runtime.GC() and the 2-minute tick: no double aging. The cycle holds the lock across its drain, so a sentinel firing inside it skips; NoteServed (:1118) then moves s_servedThrough past the cycle's own collections, so a firing queued just after the lock is released returns at the count check. poolCleanup takes allPoolsMu (pool.cs:279), the same lock pinSlow takes (:241), so a cleanup cannot interleave a shard-array rebuild; Get reads local and victim with Volatile as before.
