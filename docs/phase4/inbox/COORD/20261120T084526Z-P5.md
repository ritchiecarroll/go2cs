DESIGN (no code): WALL C sized -- it is door C's unnamed form (D5), and two thirds of it already exist in golib

The site. pagecache_trampolines.go:302 `f := (*[2]uintptr)(unsafe.Pointer(stub))`, stub = libc.Xcalloc(...), then
`f[0], f[1] = uintptr(page.Buf()), uintptr(page.Extra())`. Emitted: `var f = @unsafe.Pointer.To<array<uintptr>>(...)`
and `(f.Value[0], f.Value[1]) = (...)`. It is the conversion KEPT in a local, so doors A and B (applied where written)
do not take it; DESIGN-array-pointer-doors.md 4.5 names this "door C", and D5 (unnamed form) was ruled out of the
first cut with "sqlite has one such site". This is that site.

What Go relies on. The two stores land in the 16 calloc'd bytes, and SQLite's C side (converted lib) reads the same
bytes back as sqlite3_pcache_page{pBuf,pExtra} through its own pointer conversion. So: element writes in place in
native memory, visible to a raw read of that address, no managed copy, no array<T> header anywhere.

Why it refuses. To<array<E>> has no N (array<T> does not carry it), so over an address the registry does not know
it cannot build a window and FromNumber's arm 5 refuses by name; that refusal is DESIGN-native-array-view.md's answer
to the fabricated-reference hole (1.1). It must stay for every route that does not carry N.

The smallest shape, three parts, no new representation:
G1 golib: `@unsafe.Pointer.ToArray<E>(Pointer p, nint n)`. p == 0: the nil box. Address the registry knows (the same
   provenance test arm 5 makes): return To<array<E>>(p), so Go memory is byte-for-byte today's answer. Unknown
   address and E reference-free: NativeArrayBox<E>.Over(addr, n), which exists. E holding a
   reference: today's refusal, unchanged. About 20 lines plus GolibTests arms.
G2 converter: a kept `(*[N]E)(unsafe.Pointer(x))` of an UNNAMED array whose route is not door A/B or the field view
   (declining through arrayPointerConversionKeepsItsRoute's predicates) and whose operand is not a FromRef mint (4.6)
   -> `ToArray<E>(x, N)`. N from the type, as door B does.
G3 converter: an index through a local bound ONLY by that conversion (not reassigned, address not taken: the field
   view's isNativeFieldArrayViewLocal predicate, widened to the G2 form) -> `f.ElementRef(i)`. ElementRef exists and
   already tests NativeArrayBox first and falls back to `p.Value[i]` for every managed box, so a local misclassified
   either way costs one type test, never a wrong answer. A store through any OTHER pointer to that box (a param, a
   field, a reassigned local) still reads `.Value[i]` and refuses by name: loud, not wrong.
Not proposed: the named form (4.5's sibling box kind; 0 sites here), the whole-array forms through a kept local
(`*f` read; `*f = v` already goes through Assign's INativeArrayStore arm), widening G3 to every *[N]E index.

What it costs the refusal's safety. Arm 5 is unchanged; only the door converts "unknown address" from a refusal into
a native view. The one population that goes from loud to silent: a MANAGED address the registry does not know (a
FromRef number that escaped its statement through a variable). That is the provenance design's stated bound, which
unsafe.Slice already accepts today (4.6), so the door adds no class, it removes a refusal for one. Still held: no
array<T> is ever materialized from bytes (NativeArrayBox.Value refuses), E reference-free or refused, index bounded
by N with Go's panic, nil at 0. Lifetime is Go's: C memory freed under a live view is use-after-free on both sides.
