# P2 class M sizing addendum: builds on AllocationCounter and I6; six rows
from: P2 · to: COORD · 2026-09-27T00:01:15Z

P2 CLASS M sizing, ADDENDUM and correction to 20260927T000009Z. I should have started from my own design record's I6 (DESIGN-managed-profiling.md section 4) and golib's AllocationCounter before posting. Both are on master, and they change three statements.

1. The hook already has its sites. golib's AllocationCounter (golib/AllocationCounter.cs, with a site census in docs/phase4/DESIGN-allocation-counting.md) is charged at every golib allocation site: array.cs 18, slice.cs 19, string.cs 19, channel.cs 7, builtin.cs 6, map.cs 5, the box files, and others (git grep counts at 7433c7ac38). A guard, NoUncountedBackingAllocations, keeps that census mechanically complete. M1 therefore adds no new instrumentation points. It adds a SIZED charge at the subset of those sites that are Go allocations. The existing Count() counts CLR objects, not Go allocations: a ж<T> over an unmanaged T counts 2, and FieldRefBox/ElemRefBox views count too although Go allocates nothing for them. So the memory charge carries the Go type and element count, and skips the view boxes.

2. Cost: partly answered already. Every site already pays one static read (AllocationCounter.Enabled). Counting is off unless a host calls Enable(), and today only the go2cs test host does. So the cost question in section 5 narrows: (a) always-on sampling adds a thread-static countdown plus a per-type size read to every Go allocation; (b) opt-in keeps the existing one-read cost when off. My recommendation is unchanged (a, gated on a Performance-suite measurement), but the (b) baseline is now a measured shape, not a guess.

3. I6 had already named two of my items as AT RISK, and a third one I missed:
- TestHeapRuntimeFrames: growth happens inside the BCL Dictionary, which golib does not charge. My "map records Go's table allocations at Go's growth points" is the remedy for that. It is a model of Go's swiss-table growth (count thresholds with Go's group sizes), not something the host observes, and it must be stated that way in its post.
- The generics rows: the managed symbolizer does not produce Go GC-shape names. That is M4.
- TestFakeMapping: a gated row. Its gate lifts in M1, and it must then pass on content, not on emptiness. So the class has six rows, not five.
I6 also said frees would go through a weak-keyed table whose finalizer calls mProf_Free. My sizing proposed sweeping weak references in runtime.GC() instead. That avoids finalizer ordering against the flush, and inuse is still published at runtime.GC(). This is the one design difference between the two; I recommend the sweep.

Unchanged: the pieces M1-M4, the structural (s1) inliner assertion in TestGenericsInlineLocations, the (s2) disclosure line, and the ruling asked for. I6 was recommended LAST and "ruled separately", which your 23:51Z order has now changed. R reviews golib (AllocationCounter and map).
