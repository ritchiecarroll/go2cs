What: reflect Value.Call, and reflect.MakeFunc, of a VARIADIC func or method value under Native AOT (census rows 1, 2 and 30). Both closed a generic trampoline over the delegate's own signature with MakeGenericMethod. For a value-type signature AOT has no code for that, so it threw NotSupportedException ("callVariadicFunc1<string,string,string> is missing native code").

Mechanism: one compiled registry, fed by the generator.
- golib GoReflect.VariadicRegistry.cs: RegisterVariadicFunc/RegisterVariadicAction, one overload per family arity, record the call and make trampolines of one Actionꓸꓸꓸ/Funcꓸꓸꓸ instantiation. buildVariadicInvoker and BuildVariadicMakeFactory use a registered pair first. MakeGenericMethod remains the route for an unregistered signature: always under the JIT, and under AOT for shared reference-type code.
- go2cs-gen emits the registrations at the two places a variadic value can reach reflect from:
  - the escape registry's module initializer, for every variadic func type a package converts to an interface or reaches through a converted value. It is spelled from Invoke, so the natural type of a method group or lambda registers too. A func boxed by golib's typed-nil carrier, f.OrTypedNilFunc(), also registers (4bec0321ef).
  - each variadic IGoMethodSet arm, which registers its unbound and bound signatures before handing out a delegate.
- Why one mechanism and not two: registering at arm creation alone covers only method values. The measured varfunc probe shows func values need the module-initializer path, so both emitters write the same golib call.
