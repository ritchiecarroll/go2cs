## The five assembly functions (asm_bsd_arm64.s): route 2
- **The shape:** each is a pure jump to syscall's exported twin. For example `TEXT ·Syscall9(SB),NOSPLIT,$0-104` is
  followed by `JMP syscall·Syscall9(SB)`. The same holds for Syscall, Syscall6, RawSyscall and RawSyscall6.
- **The file is selected:**
  - Its constraint is `(darwin || freebsd || netbsd || openbsd) && gc`.
  - Route 2 picks it with go/build's MatchFile under the target platform (asmTrampolines.go selectedAsmSources).
  - asmJumpRE accepts arm64's `B` and `JMP` (asmTrampolines.go:74).
- **The signatures are identical:**
  - x/sys declares `Syscall9(num, a1, ..., a9 uintptr) (r1, r2 uintptr, err syscall.Errno)` in syscall_darwin_arm64.go.
  - std declares `Syscall9(num, a1, ..., a9 uintptr) (r1, r2 uintptr, err Errno)` in syscall_darwin_arm64.go:64.
  - The other four come from syscall_unix_gc.go against std's syscall_darwin.go.
  - All five targets are exported, so no asmJumpForwardTargets row is needed.
- **The targets have bodies:** in the darwin flavour, the hand-owned src/core/syscall/darwin/syscall_darwin_impl.cs
  implements all five as public partials, at :74, :78, **:82 (Syscall9)**, :86 and :90.
  - Each makes a libc call through GoLibcCall under the low-32-bits == -1 failure rule.
  - osx-arm64 uses the darwin flavour, which is emitted from darwin/amd64. The arm64 Syscall9 declaration has the same
    types, so the forwarder binds.
- **Reach:** no x/sys code calls these five on darwin. In the darwin and arm64 files I counted 0 call sites for each.
  Only user code calling `unix.Syscall9` and its siblings reaches them.

## The seven libSystem linknames: forwarded, by a path my S21 route list left out
- **The path:** `syscall_syscall`, `_syscall6`, `_syscall6X`, `_syscall9`, `_rawSyscall`, `_rawSyscall6` and
  `_syscallPtr` are linkname PULLS into syscall's unexported family.
  - They are not route 2 or route 3. funcLinknameForward answers them through **xsysDarwinLibcTwins**
    (visitFuncDecl.go:2713-2736), scoped to x/sys package paths.
  - Five map to the exported twins above.
  - `syscall6X` and `syscallPtr` map to `GoSyscall6X` and `GoSyscallPtr`, the public doors in syscall_darwin_impl.cs
    :121 and :125 that keep those two failure rules (all 64 bits, and NULL).
  - **Correction to my S21 scout:** its four-route list omitted this linkname-forward path. These seven belong there,
    not in route 2 or route 3.
- **The libc addresses they are called with:**
  - `libc_*_trampoline_addr` is filled by DATA words in zsyscall_darwin_arm64.s; I counted 158 in the v0.42.0 Go file.
  - Those resolve through `asmTrampolineAddrIndex` (cgoDynamicImports.go:395) to the `//go:cgo_import_dynamic`
    symbol, the same shape as zsyscall_darwin_amd64.s.
- **Reach:** this is what x/sys actually uses on darwin/arm64. I counted 95 syscall_syscall, 35 syscall_syscall6,
  27 syscall_rawSyscall, and 1 each of rawSyscall6, syscall9 and syscallPtr.
  - gojq's path (go-isatty, then unix.IoctlGetTermios, then ioctlPtr, then syscall_syscall) is the one the xsys twin
    forward was cut for.
  - Its comment records the README walkthrough app dying in fatih/color's initializer on both mac legs before it.

## Stated gaps, none of them a stub
- **r2 is always 0** on the darwin family. syscall_darwin_impl.cs:36-38 states it as a known gap: a managed indirect
  call cannot observe the second register. Code reading r2 from Syscall9 or its siblings gets 0.
- **Not measured here:** an osx-arm64 run of a program calling `unix.Syscall9` directly. The forwarder's shape is
  unit-tested for arm64's `B`, but no darwin/arm64 conversion of x/sys was run on this box.
