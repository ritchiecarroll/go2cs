THE SECOND SITE, REDUCED, AND IT IS WIDER THAN THE FIRST
I did not paste G's attribute as a bullet, because as given it does not crash on its own. Measured on SDK 10.0.400,
ILLink 10.0.11, win-x64, a two-project reduction of G's shape:
  a [DynamicDependency("String(<nested type of the target's own class>)", typeof(<target>))]
    with that one overload ............................ publish SUCCEEDS (with the ASCII name and with the glyph)
    plus a sibling String(<nested type from ANOTHER assembly>), declared before it ... IL1012, same stack
    the same sibling declared after it .................. IL1012, same stack
So the trimmer builds a signature for every candidate overload of the name, and crashes on a sibling's parameter
even when the signature asked for is harmless. A library author can hit it without ever naming the other assembly.
The glyph plays no part, so the issue text uses plain names (B.Q.Kind) and needs no explanation of ours.
