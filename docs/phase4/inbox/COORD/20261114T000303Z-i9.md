# TS AOT sizing: checkdemo FAILS on the i9 at ILC's object writer (COFF string table > 2 GiB), not RAM; peak 56.5 GB private
from: i9 · to: COORD · 2026-11-14T00:03:03Z

RESULT: the converted TypeScript checkdemo does NOT build under Native AOT on the i9, and RAM is NOT what stops it.
ILC compiled the whole closure, then failed writing the object file:
`System.IO.IOException: Stream was too long` at `ILCompiler.ObjectWriter.StringTableBuilder.CreateIndex`
(from `CoffObjectWriter.CoffSymbol.Write` <- `CoffObjectWriter.EmitObjectFile`). The COFF symbol string table outgrew
a MemoryStream (int.MaxValue, ~2 GiB). That is a size ceiling in ILC's Windows object writer, not a memory fault.

THE FIVE READINGS (checkdemo, P4's B4 subject; win-x64, Release, PublishAot, default ISA, no ILC property):
- Box total RAM: 63.7 GB (i9-13900K). Only 29.9 GB was AVAILABLE at the start: ~27 GB is held outside every
  process (not in any working set or private commit; standby ~22 GB). I did not chase it; it is the owner's box.
- ILC peak, by PID 19232 (process counters, every 5 s): private 56.48 GB, working set 51.96 GB (PeakWorkingSet64).
  Shape: ~22-24 GB private from 15:20 to 17:48, then the object writer climbed 23 -> 56.5 GB in the last ~3 min.
  Free physical memory reached 105 MB, so ILC paged at the end.
- ILC wall: 2 h 57 m (15:04:16 -> 18:01:10), under the owner's 4-CPU affinity (0xF; -m:4 does not bound ILC).
  Whole publish: 11,479 s, including the RID-specific rebuild of the closure (~14 min before ILC started).
- Pass/fail: FAIL (MSB3073, ilc rc != 0; the stack above).
- Binary size: none.
- WHEA 319 -> 319, no reset.

SO, FOR B4: P4's 15 GB cloud box ran out of memory at ~722 s. The i9 got through the whole compile on ~24 GB, then hit
the writer's ceiling at 56.5 GB. A bigger box alone does not produce an image. Candidate levers, all unmeasured:
- shrink the closure (partial trim keeps golib and every referenced core package rooted; ilc.rsp has 372 -r refs);
- shorter mangled symbol names;
- the linux ELF writer, which may have a different limit (P4's run never reached writing).
