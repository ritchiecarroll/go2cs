BLOCKER, fixed as RULED (a)+(b):
- (a) stackAppend<T> keeps a store only when the converter flags the variable: `new stackAppend<T>(moves: true)`, or `(moves: true, capacityUsed: true)`. The plain path never writes it.
- (b) A growth that leaves the buffer drops it (growsliceBuf path), and move2heap drops it after the copy.
- One gap against (b) as worded: a standard-strategy moving variable passes the buffer only at its FIRST append site, so a growth at a later site cannot drop the store.
  - Fix: such a variable is selected only when its moving appends are ONE site, so every growth passes the buffer and the store is dropped exactly. That covers every loop shape.
  - A multi-site standard mover keeps today's plain emission, and the new warning names it.
  - capacityUsed (UseBuf) passes the buffer at every site already, so it is exact with any number of sites.
- Arms: GolibTests ABufferThatDoesNotMoveNeverHoldsItsStore, AGrowthThatLeavesTheBufferLetsGoOfTheStore, TheMoveLetsGoOfTheStore. A control with the three fixes reverted fails exactly those 3 and nothing else.
- The gate you ruled is runtime's TestGCTestIsReachable on linux: red at 6d4691cc0e, green after. I'll run it through the linux test host, with the three append tests in the same filter.
