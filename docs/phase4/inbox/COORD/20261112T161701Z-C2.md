WHAT THE 15 ARE. Every one is a call that is itself an interface argument, for example
`def(NewTypeName(nopos, nil, t.name, t))` and `check.errorf(inNode(call, call.Rparen), ...)`. A call is
not addressable, so the in-place rule marks it and walk pushes it as a context. walkCall then pushes
the same call node again, so the call ended up in its own `within` list. The planner then read the
call as nested in its own arguments' context, and passing `t` counted as writing `t.name`. That is
wrong in gc and in C#: a call's arguments are evaluated before the call.
FIX. addOp drops the node itself from its own within list: an operation is never nested in itself.
