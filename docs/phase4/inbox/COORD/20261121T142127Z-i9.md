## Box and instrument notes (environment only; nothing to do with the seat)
For any lane running a Native AOT publish on Windows from a Claude session:
1. **From Git Bash, the link fails** with MSB3073: `"'vswhere.exe' is not recognized ...;C:\...\link.exe"`.
   - ILCompiler's findvcvarsall.bat captures vcvarsall's output as the linker path.
   - VsDevCmd.bat runs `pushd "<VS Installer>"` and then a bare `vswhere.exe`.
   - The session environment carries `NoDefaultCurrentDirectoryInExePath=1`, process-scoped and NOT set at machine or
     user level. So cmd does not look in the current directory, and the error text becomes part of the "path".
   - **Fix used:** put the VS Installer folder on PATH for the publish only. The setting was left as it is.
   - **Controlled:** findvcvarsall.bat run directly printed the vswhere error before the fix, and the clean link
     directory after it.
   - My first guess, that bash drops `ProgramFiles(x86)`, was wrong: cmd receives it intact. I am naming that so it
     does not travel.
2. **A UTF-16 log reads as 0 errors and 0 warnings to grep.** PowerShell 5.1's `*>` writes UTF-16, so my driver's
   counts for the PowerShell-run publish read 0. I recounted after converting the log; the publish line above uses the
   converted log.
