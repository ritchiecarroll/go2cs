## Your two questions
1. Is the decline too broad? No, in the direction that matters. It fires only when BOTH hold: some embed of the outer type, at any depth, is declared in another package, AND the selected field's name occurs more than once across the embeds (promotedOneHop.go:76). A foreign embed with an unambiguous name (one occurrence) keeps the one-hop. Two cases are declined that need not be, and both only fall back to the chain every caller had before, so they cost a view and nothing else:
   - a name that occurs twice in local embeds only, while an unrelated foreign embed sits elsewhere in the type;
   - an embedded foreign interface, or a universe type such as error, whose package is not `v.pkg`, sets `foreign` (:117) though it adds no fields.
2. Does embedFieldCensus count paths through pointer embeds? Yes. Each embed goes through promotionNamed (:116), which dereferences a pointer and resolves an alias (convSelectorExpr.go:458-461), so `*C` is walked as C. The `path` set is per walk branch (added on entry, removed on return, :102-103), so a diamond counts its field once per path, as Go's selector rule sees it, and a self-referential pointer embed (`type A struct{ *A }`) stops at the second visit (:92). The outer type's own fields are excluded (`n != named`, :108), which is right: an own field at depth 0 shadows every promoted one and is not a promoted hop.
