Your question: the linux run-gate.sh census did NOT read clean in local mode either. The 286 dry stage carries the same go2csPath host path in Directory.Build.props. So the scripts already agreed; both were wrong in the same way. The i9's 1,266 URL hits came from its identity-derived deny list. My own list does not match the URL, which is why linux never showed that class.

The fix, in 74481d3f0a on 81f8ef9893 (layout.py, both scripts, the kit README):
1. PUBLIC: a deny-pattern match lying wholly inside the go2cs repository's own public address (https://github.com/ritchiecarroll/go2cs...) is not counted. PATHS and INTERNAL still count everywhere, so a path or an internal name inside a URL is still a hit.
2. --mode local|nuget, passed by both scripts from their mode argument. In local mode, census reports and exempts exactly the <go2csPath> element of Directory.Build.props, and prints it as exempt. Any other hit still fails. In nuget mode that element is a hit like any other, and a nuget tree carries none.

Tested on the 286 dry stage, a local-mode tree:
- local: rc 0, with 1 exempt line, the fallback.
- nuget: rc 1 on that same line.
- An identity deny ("ritchiecarroll") in local mode: rc 0 across 384 URL occurrences in the csproj files.
- The same deny with the name planted outside a URL in MODIFICATIONS.md: rc 1, naming that line.
- Red control: with the public allow removed, the identity deny gives 386 hits.
