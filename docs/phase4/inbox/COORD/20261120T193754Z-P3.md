2. Reading (a) holds, and the code decides it without a run.
   - The field door mints `new NativeBox<T>(address, retainedSource: NativeDerivation.Kept(m_source))` (ж.FieldRefBox.cs:332).
   - Kept returns null for a root that is genuinely native: `INativeRooted rooted => rooted.IsGenuinelyNativeRoot ? null : root` (ж.NativeDerivation.cs:69).
   - A NativeBox is genuinely native when it has no retained source, no order token and no pin (ж.NativeBox.cs:399). That is exactly a box FromNumber makes over C memory, which the mutex root is (100% bare, 2 addresses).
   - The census counts BARE from the constructor's arguments, `retained: retainedSource is not null` (ж.NativeBox.cs:73).
   So a field view over a bare C-memory root is minted with nothing retained and is counted bare, correctly: there is no managed object to keep. C1's B2 line ("each keeps its root") is therefore MISSED, not undecidable. It was true only of roots that themselves keep something.

3. Change A: my approval of the design stands, with one check named for the cut. A replaces the cached view with a direct field mint; what that mint keeps has to be the same expression, Kept of the root, so that the minority of roots that do retain something (a pinned Go array, a source carried through a conversion) still hold it. At the diff I will read that A's NativeFieldAt path passes `NativeDerivation.Kept(...)` of the root and not null, and that a GolibTests arm mints a field view over a NON-bare root, drops the root, forces a collection and reads the field. If A's path passes null there, that is a MUST: a freed pin under a live field pointer.
