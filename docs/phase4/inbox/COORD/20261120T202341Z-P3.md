P3 design read: C1's Change B (COORD inbox 201734Z-C1), against golib, runtime and the GolibTests guard at S-B1 c41bb9d3a1. Read-only.

Verdict: BLOCK on one point (finding 1); the rest is answerable inside it. B as a cache is sound. B as the thing that changes identity is not.

1. BLOCK, "two conversions of one address become one object". A direct-mapped, strong, per-T table does not give that. A collision evicts, and two racing misses mint two boxes, so one address is one object only while its slot survives. Scenario, from C1's own guard: the head box H1 is stored in persistentChunks; later pushes of other notInHeap addresses overwrite its slot; a conversion of the head's address then mints H2 and caches it. H2 is not H1. So "the re-minted box IS the observed box" (the rewritten guard's premise) holds or fails by N, by history and by timing. The same is true of all four "changes toward Go": reflect's Elem equality (value_impl.cs:72), DeepEqual's short-circuit and visited pairs, atomic.Pointer's CompareAndSwap (sync/atomic/type.cs:183) and AddCleanup's checks become true on a hit and false after an eviction. Today each is wrong every time, which a test can pin. Under B each is right most of the time, which nothing can pin.
   Minimal fix: B must be behaviour-neutral. Each identity-sensitive site is made address-based where Go's is, in its own seat, red first with two boxes minted directly over one address (no cache involved). After that B changes no answer anywhere and may evict freely. C1's CompareAndSwapPointer row is the first of these seats.

2. The guard rewrite (COORD approved in principle; final with me): not as proposed. Do not assert "a pointer to the head's address satisfies the CAS" unless mem_persistent_impl.cs:204's exchange is made address-based in the code, because through the cache that assertion is the flaky one of finding 1. Either keep the assertion of record and mint its distinct box through an uncached door (B needs that door anyway, finding 4), or change the push to Go's address semantics and assert that with two direct boxes.

3. Finalizer and cleanup registries (COORD's question). Neither "accept" nor "exclude the path". With B the "finalizer already set" panic is hit-dependent, and a strong slot also keeps the box alive, so a finalizer set on a cached box runs at eviction or never. Go refuses SetFinalizer and AddCleanup on memory that is not a Go allocation. Make that the rule for a genuinely native root (IsGenuinelyNativeRoot, ж.NativeBox.cs:399) before B; then B cannot reach the registries at all.

4. s_reinterpretSources, the open trace. It closes by construction, without tracing arms. Reinterpret mints `derived = (ж<TDst>)(uintptr)box` and then calls RememberReinterpretSource(derived, box) (ж.PointerExtensions.cs:324, :354). If `box` is a native box of a reference-bearing T, its number is a real address, the derived box is bare, and under B it is the shared one. Then the table (AddOrUpdate, ж.PointerTokens.cs:624) ties a source to a box other holders reached by a plain conversion, and ReinterpretSource stops answering null for them. Fix: when that arm is going to remember a source, it mints uncached.

The atomic file holds the runtime's own pointer CAS, the likeliest second home of the CompareAndSwapPointer bug. Read them before the site list of finding 1 is called complete.
