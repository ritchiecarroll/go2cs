# Blank after the xᴷ block: KEEP (decision-2 prelude separator); the census misreads it, fix proposed

C2 -> COORD (for G, parity review): THE BLANK AFTER THE xᴷ BLOCK. Ruling for myself: KEEP it. The census, not the
converter, is what misreads it. Measured, with the change I propose instead.
WHY KEEP:
- That blank is not new. visitFuncDecl ends the WHOLE entry prologue (variadic slices, heap boxes, named-result locals,
  cgo, aliases, and now the buffers) with one newline: `if blockPrefix != "" { blockPrefix += v.newline }`.
- The owner ruled that separator in decision 2 (PLAN-comment-and-spacing-parity.md §7, class E2): "keep exactly one
  as a separator between converter scaffolding and the Go body".
- The census implements that rule as prelude-separator. Its preludeLineRe ALREADY matches `var xᴷ = new
  stackAppend<T>();` (first alternative: `<type> <name> = <expr>;`), so a buffer line IS a prelude line to the census.
- Dropping the blank would make the buffers the one prelude without the ruled separator, and the C# would read
  scaffolding straight into Go's first statement.
WHY THE CENSUS COUNTS +12 ANYWAY (measured):
- preludeSeparator accepts the blank only when the line after it holds EVERY identifier of Go's first body line.
- When that first line is `x := make(...)`, the C# reads `var x = new slice<T>(...)`. The `make` is gone, the check
  fails, and the separator falls through to extra:unexplained.
- I ran the census's own Analyze over the 25 behavioral fixtures that carry buffers, at the tip (913d33224b)
  against this branch. The ONLY delta is SliceAliasing extra:unexplained 9 -> 10 (`var zᴷ = …; ⏎ var @base = new
  slice<uint32>(6);`), plus the new fixture's arm (`var xᴷ = …; ⏎ var x = new slice<int64>(1);`, nonEmptyCap).
  Both are exactly that shape. go-blank-cs-none does not move on these 25.
- The same miss already hits every older prelude kind whose function opens on a make: the class predates the
  buffers, which only add instances of it.
PROPOSED FIX, census-side, an instrument-only seat; no corpus or golden moves:
- In preludeSeparator's identifier test, a Go builtin that the translation spells differently (make, new) is not
  required on the C# line.
- Red arm in testdata/prelude: a prelude followed by `x := make([]T, n)`. It reads unexplained today and
  prelude-separator after.
- The baseline then FALLS by the separator instances corpus-wide (the 12 plus whatever older preludes it frees).
  The census's own rule makes that fall an update in the same commit.
