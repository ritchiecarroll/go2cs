THE THREE CLAIMS: I could not break any of them.
1. No lost wakeup: HOLDS. A blocked waiter is counted before its swap to 2, so sema names its queue before any
   Unlock can read 2 from it; the only writers of sema (gateOf L148, L158, leave L176) each need that queue retired or
   absent from the table. When Unlock skips because CurrentCount >= 1, whoever takes that permit swaps state after
   the Unlock's swap: it gets the lock and leaves 2, or leaves 2 for a newer holder. Induction closes.
2. Retirement: HOLDS. Walked the three orders of Decrement / CAS 0->-1 against an arrival's CAS 0->1; exactly one

FINDINGS, ranked.

1. SHOULD-FIX before seating (confidence medium; I cannot run the corpus). The old Mutex held a SemaphoreSlim
   REFERENCE, created on the first Lock, so every struct copy made after first use shared one gate and still
   excluded. The new one is two words: a copy is a separate lock. Go never copies a used mutex, but emitted C#
   can (a copy-box Ꮡ(value), a by-value capture, a value hop in an embed chain). Review #1 finding 1 on C2's
   range (scanAddressedGlobals misses a package-level var, which may alias a Ꮡ(value) copy) is one producer.
   Failure: two goroutines Lock two copies of one Go mutex, both win CAS 0->1, the guarded data races silently;
   or Lock lands on one copy and Unlock on another and the process dies with "sync: unlock of unlocked mutex".
   Ask: do not count the 26 Mutex arms as coverage for this. The full sweep and behavioral suite P2 already
   owes are the gate, and any new "unlock of unlocked mutex" there is this finding, not a flake.

2. SHOULD-FIX, cost (confidence medium-high that the cost exists, unknown size). mutex.cs:152-158 and 175: every
   contention EPISODE now allocates a WaitQueue (a SemaphoreSlim) and a dictionary node, takes the process-wide
   table's bucket lock twice, and increments one shared counter; master allocated once per mutex for life.
   Lock goes to gateOf on the first failed CAS, with no spin on state first. Scenario: two threads, short
   critical sections, collide thousands of times a second: each collision builds and retires a queue; every
   mutex in the process shares s_lastQueue's cache line and the table. Ask: the owed cost arms must include
   CONTENDED pairs (2, 4, 16 threads; one mutex and many) against master, with B/op. If red: spin a few rounds
   on state before gateOf, as Go's lockSlow does, or retire lazily.

3. NIT, disclose (confidence medium it exists, low it bites). Unlock L368 and L373 read m.sema AFTER the swap to
   0. Go's Unlock touches nothing after release when no goroutine waits. Here 2 stays behind after any waiter
   took the lock, so the read happens with nobody waiting; with a profile rate on and any stamped waiter
   anywhere, L368 reads it on every Unlock. In C memory: T1 swaps 0; T2 locks, drops the last reference,
   unlocks, frees; T1 reads freed bytes. Usual result is a garbage handle and at worst a spare Release on
   another queue; if the page was unmapped it is an access violation. Add it to the header's residuals.

4. NIT, wording (high). The header says a handle "with no queue" is replaced like 0. A stale or unzeroed handle
   that names another mutex's LIVE queue is joined instead (L135), which is the copy residual's lost wakeup
   between two unrelated mutexes. With the counter wrapping, the stale handle in a copied-while-waited mutex
   becomes live again after 2^32 episodes. Unzeroed STATE (any value but 0, 1, 2) blocks Lock forever. Go also
   requires zero bytes, so say "zeroed memory" rather than "recycled C memory that was not zeroed".

5. NIT, comment (high). "Unlock keeps at most one": two Unlock tails can both read CurrentCount 0 and both Release. Harmless.

6. NIT, M:N (high). gate.Wait() blocks the OS thread; Unlock, non-blocking in Go, takes the semaphore's monitor;
   gateOf and leave take dictionary bucket locks; WaitStamps takes lock(this). All short except Wait. Whatever
   park replaces Wait must keep "a wakeup is pending" readable, or Unlock's CurrentCount rule has no equivalent.

7. NIT (medium). Go 1.26 fields are {_ noCopy; mu isync.Mutex}; reflect sees state and sema here. Same eight bytes.
