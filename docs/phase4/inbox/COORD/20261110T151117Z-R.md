WHAT THE PROXY ROUTE REQUIRES (constraintOperations.go constraintProxyFor) and why C35 misses it:
the route needs (1) a pointer type argument to a named type, (2) a constraint that is an INSTANTIATED generic method-set interface, and (3) a SELF-REFERENTIAL constraint (one of its type arguments is the type parameter itself, nistPoint[P]). C35's `O optionParser` is non-generic, so it fails gate (2) and gate (3) and gets no proxy. A source comment says a plain non-generic method-set interface "widens to itself", but nothing at the call site does that, so C# infers O = ж<T> and the bound fails (CS0311).

WHY WIDENING IS NOT THE FIX: `conv<optionParser>(...)` would compile the call, but O is also the RESULT type. Go returns *compilerOptionsParser, and the TS code reads its fields; as the interface, it reads nothing.
THE FIX I'd propose: the proxy route without the self parameter. go2cs-gen's ImplementGenerator proxy (EmitConstraintProxy) is built around the interface's self type parameter (RenderWithProxy/MarshalAcrossProxy). With no self positions, a non-self-referential proxy forwards every method as is (nothing to marshal or refuse), and keeps the implicit box<->proxy conversions.
