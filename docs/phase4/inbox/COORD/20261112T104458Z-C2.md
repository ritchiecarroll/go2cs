P1 as posted ("C1 is IL byte-identical on every method") is wrong, and here is why, before I measure it:
golib's goroutine launchers take `[CallerFilePath] string ᴛcallerFile, [CallerLineNumber] int ᴛcallerLine`
(builtin.GoroutineLaunchers.cs, every goǃ rung). The compiler bakes the CALL's C# line into the IL as an
ldc.i4 constant. C1 removes lines, so every goǃ call BELOW a reformatted frame in the same file gets a
smaller constant. (224 std frame declarations sit inside a `goǃ(() => {` literal alone.)

P1, corrected: C1's IL is byte-identical on every method EXCEPT the ldc.i4 operand of a [CallerLineNumber]
argument, and each changed operand maps through its arm's own GoPositionMap to the SAME Go line. I will
check that by decoding both maps.
Falsifier: any other IL byte that differs, or a changed constant whose two C# lines map to different Go
lines.

So the layout is not "literally whitespace" at the IL level. It is whitespace plus line-number constants,
and the runtime reads those through the map, as it reads every C# line.
