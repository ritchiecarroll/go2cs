# SIZING: narrow arithmetic -- 9 consumer classes wrong (value+type), 345 GOROOT sites at risk; source-side pre-pass proposed
from: C2 · to: COORD · 2026-09-27T20:12:31Z

SIZING: narrow-integer arithmetic (int8 / uint8 / int16 / uint16, unnamed) reaching a non-wrap-invariant consumer. Read-only on master 4fb6e460c6; no cut. All runs are local and unofficial, linux flavour; Go is the oracle.

MECHANISM: C# promotes sub-int arithmetic to int32, so `a + a` (int8 100) is 200, where Go wraps to -56 at int8 width. Deferring the wrap is exact only while the consumer is same-width + - * & | ^ &^ << or unary - ^, or a typed destination that casts. Everything else sees the unwrapped value.

PROBES, per consumer class, Go vs C#:
- Interface sinks: fmt argument, any var/param/variadic/return, []any / map / struct-field element, chan send, any(x). Go prints `-56 int8`; C# prints `200 int32` (value AND type). Seven classes, all wrong.
- A named empty interface (`type I interface{}`) is a COMPILE error: CS0029/CS1503 on `int`.
- Generic inference: gen(a+a) instantiates T=int32. Wrong.
- Widening conversion: int(u+u) 400 (Go 144), int64 / float64(a+a) 200 (Go -56), int(c-'0') -1 (Go 255). Wrong.
- Index: s[u+u] PANICS index 400 where Go reads index 144. Slice bounds: the same unnarrowed `(int)(u + u)`.
- Switch tag: `switch u + u` takes default where Go takes case 144.
- Shift count: 1<<(u+u-140) is 0 (Go 16).
- Typed destinations after an intermediate overflow: (a+a)/2 is 100 (Go -28); %7 4 (Go 0); >>1 100 (Go -28); (a+a)<0 false (Go true). narrowArithmeticCastTypeFor accepts only a bare Binary/UnaryExpr, so a PARENTHESIZED operand is skipped. That is why even the existing comparison arm misses `(a+a) < 0`.
- Correct today: typed assign / return / param, direct compare, append's element, << as a value, and every NAMED narrow type (its wrapper operators cast).

CENSUS (go/types, GOROOT 1.24.13, windows+linux+darwin, prod + tests; classified by consumer; controlled 27/27 on the probe): 1687 non-constant narrow arithmetic expressions.
- Safe or handled: typed-assign 495, arith-invariant 367, direct compare 237, conversion-narrow 92, typed return 46, typed arg 27.
- AT RISK, 345 (327 prod): widening conversion 175, index 84, shift count 34, divrem operand 15, slice bound 12, paren compare 9, iface arg 7, switch tag 5, SHR operand 4.
- UNMEASURED: builtin arg 43 (append is fine; min/max/copy not probed), typed composite 35.
A site diverges only when the operation actually overflows at runtime. That is common by design in hashing, checksum and codec code, and cannot be counted statically.

PROPOSED SHAPE, source-side: a per-file pre-pass (like markUntypedConstContexts) marks every non-constant narrow arithmetic expression whose consumer, seen through parens, is NOT wrap-invariant. convBinaryExpr / convUnaryExpr then emit its own `(int8)(…)`. It is one decision in one place, and it covers every sink class, including ones not enumerated here.
The existing destination casts already skip a whole-expression cast (wholeExprIsCastOfType), so a typed destination's text does not change: the cast just comes from the source. Predicted churn is the at-risk sites only.
The sink-side alternative is nine separate arms (conversion, index, slice, switch, shift count, divrem / SHR / compare operand, interface target, generic inference), each one a place to miss.
COST: a cast appears where Go semantics needs one, e.g. `fmt.Println((int8)(a + a))`, `s[(uint8)(u + u)]`, `int((uint8)(c - '0'))`. It reads as Go's own width.
ASK: rule the shape. The cut would carry a red-first behavioral arm per class, the paren fix, the named-empty-interface arm, and a two-seeded three-target footprint predicted at the at-risk sites only.
