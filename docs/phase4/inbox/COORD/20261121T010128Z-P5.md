## 3. P3's prediction (i9 seat): SemaBucket grows with cases run - MET in shape, NOT the long-run cause
- SemaBucket: 13,070 (t=440 dump, OOM-8 process) | rep1 16,253 | rep3 >=31,658 (+~7.7k per rep,
  ~17 per configuration). Each bucket comes with exactly one os.file box, FieldRefBox<poll.FD>,
  FieldRefBox<fdMutex>, Queue<SemaWaiter> and dictionary node (counts equal to +/-6).
- Retention: static semaTable (ConcurrentDictionary<ж<uint32>, SemaBucket>) keyed by the fdMutex
  semaphore's field box, which holds fdMutex -> poll.FD -> os.file. Every file ever opened stays.
- Cost: ~704 B per file (9.2 MB for 13,070) = ~5.4 MB per rep, ~5% of the ~99 MB/rep growth.
  Extrapolated to the full 15,164 configurations: ~180 MB. Real leak; i9's fix is worth landing,
  but it does not explain GB-scale growth.
