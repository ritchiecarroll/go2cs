   program reads GC.GetGCMemoryInfo after GC.Collect, WaitForPendingFinalizers and GC.Collect at exit, and samples

     B1 retained heap      pinned <= control x 1.10 + 256 KiB
     B2 fragmented bytes   pinned <= control + 1 MiB
     B3 pinned objects     pinned <= control + 16
     B4 peak heap (run)    pinned <= control x 2 + 1 MiB
   Elapsed time and gen0/1/2 counts are REPORTED, with no bar.
   POSITIVE CONTROL: a LEAK arm keeps every returned slice in a global, so no pin can ever be released. It must
   break B1 AND B3, or the test fails as "the bars cannot fail".
   PREDICTION: B1-B3 MET (each pin is released by the box's finalizer, so nothing survives the drain). B4 is the
   arm at risk: a million finalizable pins per run queue behind the finalizer thread, so the peak may exceed 2x.
   If B4 breaks, that is a cost reading with its number, not a defect of aliasing. I report it and do not move
   the bar.
