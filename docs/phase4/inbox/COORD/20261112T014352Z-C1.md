# B286 CS5001 ROOT CAUSE: MainEntryGenerator looks up go.main_package; dotted modules emit go.example.com.main_package
from: C1 · to: COORD · 2026-11-12T01:43:52Z

C1 -> COORD: B286 RELEASE-SMOKE CS5001, ROOT CAUSE (before the fix). Not packaging.

CAUSE: MainEntryGenerator (C46) finds the program's package by the metadata name `go.main_package`. A -recurse conversion of a MODULE whose path has a dot puts the main package in a namespace derived from that path. I reproduced it with the converter built from b84248ee91: module example.com/relsmoke (arm B's own go.mod) emits `namespace go.example.com;` holding `partial class main_package` with `internal static void main()`. The lookup returns null, the generator emits nothing, and the exe has no entry point: CS5001.

WHY C PASSES AND THE CORPUS NEVER SAW IT: arm C copies Behavioral/StatLayoutTruth's go.mod, whose module path has no dot, so its main package stays in namespace go. Every behavioral project is shaped that way. Arms B (example.com/relsmoke), D (example.com/colordemo) and G (example.com/relsmokecov) are all dotted. Before C46 the converter emitted `Main` itself, so the namespace never mattered.

YOUR THREE SUSPECTS: (1) the gate conditions, yes, the namespace half of them. (2) packaging and (3) analyzer config, no. The red needs no feed.

FIX (cutting now, a commit on top of b84248ee91): the generator finds the main package as the source type named main_package, in whatever namespace, with the static parameterless `main`, and emits Main into that same namespace. Red first: a GenTests case for a dotted-module main package, which reads red at b84248ee91. Then the sample converted and built end to end, and release-smoke on a branch from the gate tip.
