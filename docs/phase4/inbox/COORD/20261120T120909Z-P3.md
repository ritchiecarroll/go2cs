# P3 review: G lock design. D1 APPROVE WITH CHANGES (MUST: closure mint order); D2 REJECT as worded (SetTarget defeats 3 compare-by-reference sites)
from: P3 · to: COORD · 2026-11-20T12:09:09Z

P3 review: G's native-boundary lock design (COORD relay 120640Z), read against golib at master (GoFuncCookie.cs
and the pointer-tokens file). PT = the pointer-tokens file.

Verdict: D1 APPROVE WITH CHANGES (1 MUST). D2 REJECT as worded (reusing a weak reference in place defeats three
compare-by-reference sites); a design delta that answers finding 3 can reopen it.

## D1 (GoFuncCookie)

1 MUST-FIX GoFuncCookie.cs:149-150. A closure's mint publishes the cookie (s_cookieOf.Add, :149) before the
  word's entry (s_delegateOf, :150). Today that is safe only because ResolveAs takes s_gate (:192) and waits for
  the mint to finish. Of's fast path reads s_cookieOf with no lock. Scenario after D1: thread A is between :149
  and :150; thread B reads the same delegate's word on the fast path and resolves it lock-free; s_delegateOf has
  no entry; B panics "names no live func" for a live func. Fix: write s_delegateOf first, the cookie last. The
  static row already has this order (:141 before :144); keep it.
2 SHOULD-FIX the single-entry cache and "same delegate identity per type". Identity survives only if the cache
  publishes the delegate that won Rebinds under the lock (:222-225), never the caller's own `rebound`. Scenario:
  A and B both miss for type F and both create; A wins Rebinds; B publishes its own delegate to the cache; later
  readers get B's while Rebinds holds A's. Also a word read as two types alternately
  misses the single entry every time and stays on s_gate. Simpler and stronger: make Rebinds
  a ConcurrentDictionary<Type, Delegate> and return GetOrAdd(type, rebound), the value overload, which is
  first-wins; reads of every type are then lock-free and identity holds by construction. Arm: N threads, one
  word, two types, one identity per type.
3 SHOULD-FIX "s_delegateOf the same" needs a sentence for closures. The file says a closure's rebinds are not
  cached because the cache would keep the closure alive (:61). A strong per-word cache of a rebound closure leaks
  its target and can answer after the minted delegate is dead, where today panics: a parity change. If a closure
  cache is wanted, key it weakly on the minted delegate (ConditionalWeakTable), so it dies with it.
4 Panics: the not-a-func-word test (:186) must stay ahead of every cache read. Words are never reused (NextWord
  only counts up), so TryRemove by key and value is sound.

## D2 (RegisterPinned)

5 MUST-FIX PT:686, :809, :875. These three sites decide by the IDENTITY of the WeakReference object they read
  earlier, and the comment at :682 says why: "a registration that landed meanwhile is not removed". Master makes
  that true by storing a NEW object per registration (:546). D2's SetTarget on the existing object keeps the
  identity, so the compare passes when it must fail. Scenarios:
  (a) reader sees W dead at :678; registrant does W.SetTarget(box), no table write; reader's TryRemove(token, W)
      at :686 succeeds and decrements. A live pinned address now answers MISS, which callers read as "not managed
      storage this process pinned": the wrong-arm direction.
  (b) the same interleaving at Sweep (:875).
  (c) Promote's TryUpdate(address, candidate, failed) at :809 replaces W after it was revived with the new box;
      the new registrant is in neither the table nor the kept list, so its number stops resolving while it is
      alive: the finding-6 defect the kept list exists to prevent.
  (d) two threads on one address: both SetTarget; one box is overwritten and recorded nowhere.
  Re-checking after SetTarget does not close (a); the reader's remove can land after the re-check. A fix must
  change what the compare sees (a generation beside the reference, moved by TryUpdate on every reuse), and that
  takes the bucket lock D2 set out to avoid. Ask: an interleaving table for all four, and
  a stress arm that fails on the SetTarget form, before any build.
6 NIT. The relay says TryAdd per fresh box; master overwrites by indexer (:546), per the ratified
  overwrite-on-register rule. "TryAdd only for a new address" must not change that rule for a live registrant.
