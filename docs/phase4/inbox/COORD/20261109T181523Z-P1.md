# P1 PREDICTION ADDENDUM: GO2CS2004 seat scope grew (chain conversions, struct-to-wrapper field loss), std 0

PREDICTION ADDENDUM, GO2CS2004 seat, posted before any gate runs. Branch claude/p1-ts-go2cs2004 (local,
not pushed), off 0bbe3ab6e58e43e236d52e501ec6a9210157a2b4. Four commits: red, converter, gen, goldens.

Scope grew past the four pieces, on the same surface. Both additions were found by the red project:
1. Conversions through a chain of generic defined types (`type C[V any] P[V]`, `pair[string](c)`). The
   gen hosted a closed generic (`partial struct pair<Boolean>`, CS0264). It now hosts on the non-generic
   side, or once and open on the generic wrapper (`partial struct C<V> { operator pair<V>(C<V>) }`).
2. A conversion TO a defined type over a struct dropped every field. `t3(s)`, with `type t3 t4` and a
   struct s with the same fields, generated `operator t3(S src) => new t3();`. Go prints `1 2 2`, the
   converted program printed `0 0 0`. This is reproduced at the base with no generics in it. It is fixed
   on the same record path: `new t3(new t4(src.A, src.B))`.

Two FINDINGS outside the seat, both reproduced, neither fixed here:
F1. A generic struct whose field is named after its own type parameter (`type duo[K comparable, V any]
    struct{ K K; V V }`) emits `public K K;`, which is CS0102. The red project renamed the fields.
F2. A literal of a defined type four or more definitions deep (`type t1 t2; type t2 t3; type t3 t4`,
    `t1{A: 1}`) emits `new t1(new t4(...))`. t1's constructor takes t2, so this is CS1503. It is a
    pre-existing defect at the base with no generics; the converter's comment assumes the wrappers'
    implicit operators chain. The red project avoids a four-deep literal.
