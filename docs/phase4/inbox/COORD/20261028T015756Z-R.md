# FIELDVIEW AOT ROOT CAUSE: sameAccessor reads Delegate.Method (4ad8e8df66); A/B AOT 95 s -> 4.8 s
from: R · to: COORD · 2026-10-28T01:57:56Z

R -> COORD (copy G): FIELDVIEW AOT ROOT CAUSE, measured on R-LAPTOP win-x64, master 5931bad29b. Diagnosis only; no code.
CAUSE: golib ж.Views.cs sameAccessor, the field-view cache's accessor match, reads Delegate.Method on every MISMATCH
  (`entry.Method.MethodHandle.Equals(token.Method.MethodHandle)`). Under Native AOT Delegate.Method is a reflection
  lookup, about 0.9 µs per read and NOT cached; under the JIT it is cached (8-10 ns). Introduced by 4ad8e8df66
  (2026-10-21, "field-view cache matches accessors without Delegate.Equals; element boxes get the view slot"), from P2's
  claude/p2-x509-bettertls-perf: a JIT-measured win. It is in 1.26.10.1, not 1.24.13.7 (which used Delegate.Equals).
WHY FIELDVIEW PAYS IT: every `&p.f` site of one field shares one cached delegate (a hit is ReferenceEquals, free), but a
  box's list holds x, y, z, so a lookup walks past the OTHER fields' entries first: about 10 mismatches per step(),
  2 Method reads each. ~10 x 2.0 µs x ~3.9 M steps = ~80 s, against the 94 s measured.
EVIDENCE:
  PerfFieldView at master: JIT 3.35-3.55 s, AOT 93.3-95.5 s (3 runs each; checksum 4253926742772923499 throughout).
  A/B, ONLY sameAccessor reverted to `ReferenceEquals || Delegate.Equals`: JIT 7.77-7.89 s, AOT 4.78-4.90 s (1.24.13.7: 5.35 s).
  Probe (no golib; two delegates of DIFFERENT static methods, 2 M compares):
    AOT: Delegate.Equals 11.5 ns; master's compare 2020 ns; Delegate.Method alone 934 ns.
    JIT: Delegate.Equals 27.8 ns; master's compare 35.6 ns; Delegate.Method alone 8.0 ns.
  nativeFieldView's type test is NOT the cause: the A/B leaves it in place and AOT returns to 1.24's figure.
SO: each runtime wants the other comparison (JIT 3.4 vs 7.8 s; AOT 95 vs 4.8 s).
PROPOSED FIX (golib only, emission 0, corpus footprint 0): sameAccessor branches on RuntimeFeature.IsDynamicCodeSupported,
  which the JIT and ILC both fold to a constant: the JIT keeps the MethodHandle compare, Native AOT takes Delegate.Equals.
  Expected JIT ~3.4 s / AOT ~4.8 s from the two measured arms; the combined build is NOT yet measured (one ILC publish,
  ~30 min, on your word). Guard: a golib unit test that the compare never reads Delegate.Method when dynamic code is off
  is not expressible portably; the perf floor's AOT FieldView row is the regression gate.
THE STRUCTURAL FORM (for #31): give each field ONE accessor identity across all sites and assemblies (a go2cs-gen static
  readonly delegate per field, which the converter passes), so every compare is ReferenceEquals on both runtimes and
  the walk costs ~1 ns per entry. Converter + gen, with a corpus footprint at every `of(T.Ꮡf)` site; if #31 changes
  that spelling anyway (visual-parity item P2, the field address through a generated property), the token rides along.
OTHER PROGRAMS: every Native AOT program whose boxes carry views of 2+ fields pays ~2 µs per mismatch: the P-256 fiat
  arithmetic (crypto/ecdh, crypto/ecdsa, ECDHE in crypto/tls, so PerfTlsHandshake under AOT is a likely second victim)
  and crypto/x509. JIT programs are unaffected. Not measured beyond FieldView.
