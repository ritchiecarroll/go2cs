Bench: src/tests/Performance/LiteralSiteBench on claude/r-seat52-literal-classes (base 893d48976f).
- Hand-written C#, against golib and converted strings. Not a Perf* program, so the runner skips it.
- One source; the form is a compile-time constant. Each run warms up for 600 ms and then times a 400 ms window.
  Bytes come from GC.GetAllocatedBytesForCurrentThread.
- In situ: every kernel walks 16 run-time-built lines with idx = (idx + f(literal result)) & 15. The literal's
  length, byte, or HasPrefix/map result decides the next index.
- Kernels:
  C1 HasPrefix(line, "//go:build").
  C2 StringMatch's kindName, called from the loop.
  C3 counts["build"]++.
  C4 a heap-element store of T{Name: "name"}.
  C5 s := "line", then a use.
  C6 sink(object), where plain is the real go2cs-gen interceptor.
  control: lines[idx] == "package main"u8.
Forms, each its own binary:
- F1 HOISTED; F5 the same source in a second copy, built separately.
- F2 PLAIN on master golib.
- F3 PLAIN on golib with "D6 reconstructed" (scratch tree, never committed). The patch is 26/-3 lines in
  StringLiteralCache.cs:
  - Get reads a static readonly, direct-mapped 4,096-slot primary table indexed by the same Fibonacci hash.
  - On a miss it falls to master's Slow, i.e. the growable table as overflow.
  - Insert claims the primary slot under the lock, or overflows when it is taken.
  I don't know whether G's D6 probed within the primary table. Mine is direct-mapped.
- F4: C1's call intercepted by a hand-written interceptor with an @string parameter. It runs in F2's binary.
  Proved live: an inverting copy changed the checksum, 600 -> 1672.
- Extra arm, outside G's readout: F1u8 on C4. This is what -hoist-literals really emits for a composite element:
  the literal inline as a u8 span. G's F1 is a field there, which today's stdlib does not emit.

Prediction per class, JIT default and AOT alike. Verdicts are read against the F5/F1 A/A band.
  C1: F2/F1 above the band (hoisting FASTER). F3/F1 above the band but below F2/F1. F4/F2 >= 1, as G predicts:
      the call site still converts.
  C2: F2/F1 above the band. F3/F1 above, but closer.
  C3: F2/F1 and F3/F1 INSIDE NOISE. The map operation, about 60 ns, dominates.
  C4: F2/F1 above the band. F3 between. F1u8/F2 far above 1, at 32 B/eval; every other arm is 0 B.
  C5: F2/F1 above the band. The hoisted load is loop-invariant, so F1 pays almost nothing.
  C6: F2/F1 and F3/F1 INSIDE NOISE. Both forms load one pre-boxed static, and D6 does not touch this path.
  control: every ratio INSIDE NOISE.
  AOT: the same verdicts, with F2/F1 at least as large as on JIT.
Bytes: 0 per evaluation in every arm except F1u8. A plain arm that allocates means a cache miss after warm-up.
Falsifiers:
  - control outside the band: the instrument is broken, and every verdict is void.
  - C1, C2, C4 or C5 INSIDE NOISE on either runtime: in situ, hoisting is not measurably faster for that class.
  - F3/F1 inside the band where F2/F1 is outside: D6 closes the gap for that class.
