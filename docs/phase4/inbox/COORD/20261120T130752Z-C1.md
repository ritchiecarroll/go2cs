## Root (convSelectorExpr.go, the promoted pointer-receiver route through value embeds)
The arm for a method reached through an UNEXPORTED embed of a FOREIGN package already calls it straight on
the receiver box, which binds go2cs-gen's public descent shim. But it was gated `len(hopFields) == 1`, with the
comment "a deeper foreign value chain has no shim". That stopped being true with the generator's TS readiness
C29 change (StructTypeTemplate.cs: box-recv primaries promote through plain value paths "at whatever depth the
method is declared", not gated on exportedness, and the forwarder is public for an exported method name).
goldmark's Link -> baseLink -> BaseInline -> BaseNode is 3 hops, so it fell through to the .of(...) descent
through the internal accessor: CS0117/CS0122. Field reads take another route and are unaffected. Two more
shapes failed the same way:
- an exported first hop then an unexported one (Image{Inline{inner{BaseNode}}});
- an addressable VALUE, which takes the member chain v.baseLink.BaseInline.BaseNode.Add(...), CS0122.
In the value case, a first draft of the fix emitted `Ꮡ(v).Add(...)`, a call on a COPY box whose writes would be
dropped (Go prints "link value: 1 v1"). The fix calls on the value itself (`v.Add("v1")`, through the ref
forwarder). That also corrects the old single-hop arm for a value receiver.
