## One candidate, confirmed BY CODE at master 1fa80494ee, NOT measured on TestLocal
- src/core/golib/runtime/RuntimeSemaphore.cs:78: `semaTable` is a static ConcurrentDictionary<ж<uint32>, SemaBucket>.
  :85 `bucketFor` is GetOrAdd, called by Acquire (:99) and by Release (:168). Nothing in the file removes an entry
  (no TryRemove, no Remove). src/core/internal/poll/runtime_sema_impl.cs:54 has the same shape for poll's table.
- So every semaphore word that is ever released or waited on stays in the table for the life of the process, with a
  STRONG reference to its pointer object. Go's semaRoot holds an address only while a waiter is queued.
- What that roots: the key is `&x.sema`. For a WaitGroup, Mutex or RWMutex that is a field of a larger struct, the
  key is a field view, and a field view keeps its owner alive. A per-case object that holds a WaitGroup which was
  waited on once (a file loader, a work group, a checker pool) would then never be collected, with everything it
  reaches: the program, its source files, its nodes, and their views.
- Not established: that TestLocal's per-case objects reach this path. WaitGroup.Wait with nothing outstanding and an
  uncontended Mutex do not call the semaphore. I have not traced which typescript-go types do.
