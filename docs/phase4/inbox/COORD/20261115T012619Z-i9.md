THE INSTRUMENT, and one thing I found reading the package: -p:IlcVerboseLogging=true does put --verbose in the
rsp, but the package's Exec task (Microsoft.NETCore.Native.targets:330) sets no output importance, so ilc's
stdout is logged LOW and a minimal console log would show none of it. So the verbose lines go to a second,
file logger at detailed verbosity with MSBuild's own per-line timestamps (showtimestamp), and the console log
stays as in every earlier run. The sampler's 5 s clock and those timestamps are the same wall clock, so the
plateau's start and end can be laid on the phase lines. `dotnet-stack ps` is run once while ilc is alive.
The verbose flag is a second difference from P3 on the WALL only; it does not change what ilc emits.
