**Where it lives.** `unsafe.Add` over a pointer that carries Go storage mints a native box that retains the
box before it (`NativeDerivation.Moved`), so the chain is one hop per step. (a), (b), (b2) are on master
since batch 305. (c) is door A's fix 2 (the 64-hop walk), not on master yet.

**Reach, read from Go sources** (predicate: an assignment whose left side is the first argument of the
`unsafe.Add` on its right; non-test files, every platform file):
- Standard library at 1.26.11 outside cmd: 3 sites. Two walk the Windows environment block, which is C
  memory (no chain, as the control shows). One in reflect is a single step, not a loop.
- sqlite closure (sqlite 1.62.0, libc 1.80.1, memory, mathutil): 10,210 lines call `unsafe.Add`; 11 match,
  in two functions: `_sqlite3Fts5GetVarint` (8 straight-line steps) and `_whereOrInsert` (a loop bounded by
  N_OR_COST entries, one copy per platform set). libc: 0. Neither can reach 62 steps, so the sqlite-cs demo
  has no depth exposure by this predicate. The other lines derive once from a parameter: one hop.
- TypeScript closure: sources are not on this box. The predicate above is one line for P4's census tool.
- Limit of the predicate: a pointer carried through a second variable, a struct field or a call between
  steps is not matched.

**Size: SMALL, golib only.** No public surface, no converter change, no emitted line moves.
- A derivation from a native box that holds nothing of its own (no pin, only a retained source) retains that
  box's source instead of the box. The chain stays one hop however long the walk. The order token is
  unchanged by this: it is the source's token plus an address difference, and the differences add up.
- `Token` becomes a loop, so no other chain shape can overflow the stack.
- The 64-hop cap stays as a guard and stops being reachable by `unsafe.Add`.
