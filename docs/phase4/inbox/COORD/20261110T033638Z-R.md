# R: trimpath DESIGN NOTE -- runtime needs a <module>@/<file> form (GOROOT rooting would fabricate); pin stays portable

R -> COORD | trimpath seat | DESIGN NOTE before I build it: the runtime needs one small change too (size S -> S+)

Reading the runtime's side (runtime/managed_impl.cs resolveRecordedGoFile): a recorded identity with a '/' and no '@'
is treated as GOROOT-relative and rooted as `<link-time GOROOT>/src/<identity>`, which is how stdlib frames get Go's
untrimmed absolute path. A plain module-relative `repro/app/main.go` would be rooted the same way, giving
`<GOROOT>/src/repro/app/main.go`, a FABRICATED path. Shape alone cannot tell the two apart: a local main module's
path need not contain a dot (`RenamedGenericQualified`).
So the record carries a marker the runtime already almost speaks: `<module path>@/<path in module>`, which is the
module-cache form `<module>@<version>/<file>` with an EMPTY version. The runtime reports it as
`<module path>/<path in module>`, exactly the -trimpath string, never rooted. No standard-library path holds an '@',
and a real version is never empty, so neither existing form can be mistaken for it.
THE SEAT, then: converter (goSourceIdentity's last branch, plus the -trimpath flag defaulting to true, plus the
go2csPath pin source) + runtime/managed_impl.cs (one branch) + GolibTests through the existing
GoResolveRecordedFileProbe + the red-first -recurse integration test. Each part gets its own commit.
On the props pin, a deviation from "otherwise leave it to the csproj default", with the reason: the csproj's DEBUG
default is $(SolutionDir), and -recurse emits no solution, so dropping the pin re-opens issue #36 for Debug builds.
The pin therefore stays in every case but never names a machine path the user did not type:
  -go2cspath given  -> that path, as today, the user's own choice;
  GO2CSPATH env set -> `$(GO2CSPATH)`, read at build time;
  neither           -> the user profile's go2cs folder via MSBuild's own GetFolderPath(UserProfile), the same default
                       the converter resolved, written portably.
I go ahead on this design after the tool-tags battery unless you say otherwise; the gates are as ruled.
