## How a bodyless function in a module outside GOROOT converts today

Four routes, in this order; anything left over is a throwing stub.
1. **Build tags first.** A `-recurse` conversion adds `safe,purego,noasm` (defaultModuleBuildTags,
   commandLineOptions.go:313), so a library's own pure-Go fallback behind `!purego` or `!noasm` is selected
   instead of its assembly. `-stdlib` and `-tests` use `purego,math_big_pure_go`. An explicit `-tags` replaces
   all of these.
2. **Pure-JMP trampolines** (asmTrampolines.go) become forwarders when the signatures are identical, or layout-
   identical with a bridge. x/sys/unix's Syscall family, its NoError raw-syscall blocks and gettimeofday are
   covered this way.
3. **Managed bodies by name** (asmForwardBodies.go) forward to golib: today only x/sys/cpu's cpuid and xgetbv go to
   GoCpu. A listed function whose signature differs refuses its package (GO2CS2011).
4. **Everything else** converts to a bodyless partial. go2cs-gen's stub throws "<name>: no implementation reached
   this compilation (assembly, cgo, or a linkname whose push did not arrive)". The conversion names each such
   stub with the warning GO2CS2012 (reportAsmStub).
So s21asmfuncinmodule's crash is route 4 working as designed: a user's own `.s` body (`add`), no fallback, the
GO2CS2012 warning at conversion and the throw at the call. Nothing short of a C# body or a pure-Go build tag can
give it a body.

## (b) The design options

1. **Select the purego/noasm variant automatically.**
   - Already shipped (route 1). It covers every library that gates its assembly on a tag: compress, x/crypto, cpuid.
   - It cannot cover a file gated on the architecture alone (xxh3, libc's Y_), a user's own `.s` (the repro), or a
     function whose only body is machine code (x/sys/cpu cpuid).
2. **A forwarding table.** Shipped for golib bodies (route 3) and pure JMPs (route 2). Two extensions are sized
   against this census:
   - **2a, same-package sibling rows.** A row names a Go function of the same package with a types.Identical
     signature, and the stub forwards to it. xxh3 needs exactly two: accumNEON -> accumScalar and
     accumBlockNEON -> accumBlockScalar. `ptr` is an alias of unsafe.Pointer (utils.go:26), so the signatures are
     identical, and the scalar code is xxh3's own answer for the same input.
     - Size: one row kind beside asmForwardBodies (emit the existing linkname-forwarder shape to a local target),
       the GO2CS2011 signature refusal reused, a behavioral or GolibTests arm hashing 241+ bytes, and an arm64 leg.
     - About half a lane-day.
     - It cannot cover any function whose fallback is not a same-signature Go sibling.
   - **2b, an ABI0 call-wrapper recognizer.** It would take a TEXT block that only moves arguments, CALLs one Go
     function of the same package and moves the result back, with types.Identical signatures, as a forwarder,
     exactly as route 2 takes a JMP.
     - It would cover libc's 1879 on linux/amd64, and their arm64 twins (a different instruction set: a second
       parser arm).
     - Size: about one to two lane-days, mostly the per-arch block parser and its refusals.
     - It cannot cover real machine code.
     - Today it buys nothing measured: no Go code calls those 1879.
3. **A loud refusal at conversion time, instead of the run-time throw.**
   - GO2CS2012 already names every stub at conversion, as a warning.
   - Turning it into a refusal would refuse sqlite on linux (1879 inert stubs), xxh3 on amd64 (6 unreachable) and the
     atlas set without tags: refusals of code that never runs.
   - A refusal gated on reach needs whole-program analysis at conversion time. Rapid type analysis from `main` and
     every init (G's R5 tool) is the converter's own x/tools, but it exists only for an application conversion; a
     library pack (nugetgo) has no main. RTA is also conservative over address-taken functions:
     runtime_getAuxv reads "reachable" through `reflect.Value.Call`. Such a gate would false-positive.
   - Size: about 1.5 lane-days for an application-only "reached stubs" report. What it cannot cover: libraries,
     reflection, function values.

## (c) Recommendation, and whether the docs are accurate

**Recommendation:**
- Take **2a now**, as its own small seat: xxh3's two arm64 NEON stubs forward to xxh3's own scalar functions.
  - It is the one LIVE break in this census.
  - It is exact, two rows, and covers linux-arm64 and osx-arm64 for anything in the TS closure that hashes more than
    240 bytes.
  - Its arm needs an arm64 leg (a hosted linux-arm64 golib-tests or behavioral run), which this box cannot give.

- **Defer 2b** until a consumer reaches a libc `Y_`. The static census says nothing calls one today.
- **Do not turn GO2CS2012 into a refusal.** If anything, add the application-only reach report (option 3's
  analysis) as a warning tier that lists the stubs RTA reaches, with its conservative edges named. Your call; I would
  not schedule it ahead of 2a.
