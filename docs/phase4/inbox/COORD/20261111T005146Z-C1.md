YOUR FIVE POINTS
  (1) The download-on-first-use step picks the pinned toolchain BY HOST OS. defaultCCToolchain(goos) gives
      llvm-mingw on windows and zig on linux and darwin.
      - The provisioner is now generic (ccZigProvision.go becomes ccPinnedToolchain.go). The spec carries a name, a
        release, an archive pin, the compiler under the install (zig, or bin/x86_64-w64-mingw32-clang.exe), the CC
        arguments (" cc" for zig, none for llvm-mingw), and the sources (zig: mirrors then ziglang.org; llvm-mingw:
        its GitHub release alone).
      - zig's cache variables are set for zig only.
      - llvm-mingw 20261020 ucrt-x86_64, sha256 fd5462b7..., 190,612,575 bytes, is pinned for windows-amd64 ONLY.
        windows-arm64 therefore has no default pin and refuses by name, as any platform with no pin does.
  (2) No publisher signature: llvm-mingw is pinned by the GitHub asset digest ALONE.
      - genzigpins becomes genccpins and holds it as constants, since there is no index. The generated file and
        DotnetTool.md both say "digest alone".
      - A new test (TestTheLLVMMingwPinIsTheInstruments) reads the converter-cgo pin table in os-matrix.yml and fails
        if the generator and the instrument disagree.
  (3) The zip goes through archive/zip, with no xz check. The xz pre-check stays for zig's .tar.xz on linux.
  (4) `-cc pinned` means the per-OS pin. The explicit choices are `-cc pinned:zig` and `-cc pinned:llvm-mingw`, so zig
      stays reachable on windows. Any other `pinned:` name refuses, naming the two.
      - I chose that spelling over a bare `-cc zig`, which reads as a command (and a real zig on PATH needs `zig cc`).
        H, say if you want another.
      - The CLI gains `go2cs toolchain install -cc [-pin zig|llvm-mingw] [-from FILE]`.
  (5) The APSL paragraph is unchanged, plus one line: "On Windows the default is llvm-mingw, which go2cs likewise
      downloads from its publisher and does not redistribute." DotnetTool.md also gains the per-OS table (with the
      why), sources and integrity per toolchain, and the cache table.
      - The CommandLine.md -cc row, the flag's help, and a dated block in the design note record the ruling.
