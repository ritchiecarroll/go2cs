   @unsafe.Pointer.FromPinnedBox(Ꮡx.Ꮡf) (the field box of x's heap box) and a native slice over it with P5's anchor
   root. The exact door call is settled at the cut, from the doors' signatures, with no new golib member unless
   one is missing.
3. Heap box. x must live in a box: a local or a value receiver that is sliced is boxed by the converter's existing
   address-taken path (the same as `&x`). Go escape-analyses it to the heap here too.
4. Root and lifetime. FromPinnedBox pins the BOX (EnsureStableAddress stores a GCHandle in the box) and retains it.
   The slice's anchor retains the derivation (P5, NativeDerivation), so the box and its pin live as long as ANY
   slice of it does. The pin is released by the box's finalizer when nothing reaches the box. Rule: the pin's
   lifetime is the box's, never a statement's.
5. Writes alias. copy(g.Data4[:], b) writes through the native slice into the boxed struct's own bytes, so a read of
   g.Data4[i] afterwards sees it, as in Go. RED asserts exactly that for go-winio's four shapes: copy into, copy
   from, [:2] and [2:].
6. Cost. One pinned box per sliced variable, pinned while it lives. A GC-pressure arm: a loop slicing N boxed GUIDs,
