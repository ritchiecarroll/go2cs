Q1. IS (L)'S SOURCE TEST SOUND?
 - A non-package string arriving through a StaticBox: yes, by assignment (a package variable set from
   unsafe.String, or reassigned). R-a is the answer to that, with my note 2 (compare the whole backing).
 - A package string BYPASSING (L): three routes. A local copy read instead of the variable (my note 4). A string
   FIELD of a package-level struct, whose box is a field box and not a StaticBox. And any site where the
   converter spells the variable's address as a copy box, Ꮡ(value), instead of its StaticBox.
 - NEW ITEM, SHOULD-FIX (confidence medium-high). The bypass is not the safe direction for ccgo. Its number is
   kept for the life of the process. Under (L) that is right. If the declaration ever took (H), Data would be a
   pinned managed address whose pin lives only as long as the element box, which is dropped when the initializer
   returns: every later `__ccgo_ts + N` would then read memory that may have moved. So the routing itself is a
   release-critical fact and must not rest on a GolibTests arm that builds a StaticBox by hand. Ask: one
   BEHAVIORAL arm through the converter's real emission of the declaration pair (and the vfs pair), asserting
   the (L) route was taken (the door crosses the number, or StringData != Data) and that a read through the
   number is correct after forced collections with finalizers. If golib can tell, a header read by a
   package-level INITIALIZER that lands on (H) should be refused by name.
Q2. IS R-a ENOUGH? Yes, with note 2. It cannot recall a number already handed out, and the doc says so.
Q3. DOES (H) OPEN ANYTHING &b[0] DOES NOT? Not for code that follows Go's rule, which is to turn Data back into
 a pointer in the expression that read it. One difference in kind is worth a sentence: in Go the number stays
 good while the STRING is reachable; under (H) it stays good while the ELEMENT BOX is. A string that is still
 live does not keep the number valid here. The header box caching its element box covers the usual shape, and
 W13 measures it; my note 1 (assert the bytes, call the miss memory-unsafe) stands.
