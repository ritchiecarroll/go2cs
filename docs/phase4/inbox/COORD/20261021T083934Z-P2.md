While waiting on the A/B ruling I prototyped the nested fix on the same uncommitted RAM-disk tree
(base eb6def6292). It is neither A nor B as posted, so here is its shape for the ruling.

N1, reflect only (deepequal_impl.cs). After the scalar-slice test, the Slice and Array arms try a
per-element-type comparer for a sequence whose element is a RAW slice<E> or array<E> of the same
scalar kinds (bitwise kinds, or float/complex/string by their own ==). It reads both sides through
IArray<slice<E>>.ToSpan() with no Index, no ElemRefBox and no boxing. Per inner pair it follows
Go's slice order: nil-ness, length, same initial entry (&x[0] == &y[0], so a shared []float64{NaN}
stays equal to itself), then content. Inner pairs are not marked visited: a scalar element cannot
lead back to the pair, and a re-encounter only skips a comparison that already returned true.
Anything else (deeper nesting, defined element types, structs) keeps the Index walk.
The two scalar comparers fold into one generic over a static-abstract span-equality struct.

N2, golib + abi, for [][6]byte only. TypeOf of a slice whose element is an array read element 0
boxed and built a fresh [6] (64 B), then rendered the descriptor key (32 B).
- IGoReflectSequence gains ReflectFirstArrayLength(): element 0's length read in place when the
  element type is a one-dimension array<E> (every array<E> has one layout, so it is read as an
  array<byte> via Unsafe.As; never boxed), else -1.
- SliceElemArrayDims uses it and shares one dims array per length, as recorded dims are already
  shared.
- abi.TypeOf interns a slice whose dims are one long on (type, length), the dictionary the
  one-dimension array fix already uses.
