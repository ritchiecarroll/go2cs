S1, FUNCTION POINTERS AS NUMBERS
- Census (lib, the sqlite package, libc):
  - 1,360 __ccgo_fp mints of 989 functions, ALL package-level. Not one is a closure, method value or func variable, so no number can go stale.
  - 46 Go-side cFuncPointer mints.
  - 509 recoveries, all ccgo's &struct{ f uintptr }{x} form, unnamed func types, called at once. Your count was 503.
  - 16 comparisons against a mint (busy.go: h == cFuncPointer(busyHandler)), so a function's number must be stable.
  - SQLITE_TRANSIENT is ^uintptr(0).
- Registry GoFuncPtr.Of / Get<F> in golib. Prototype: 0 failed under JIT and AOT, and AOT publishes with 0 warnings.
  - One number per function.
  - Numbers are 0xFFFF_F000_0000_0000 + 16i: kernel half, never 0 or all ones, and data use faults.
  - Recovery returns the MINTED INSTANCE: identity holds for N3's twins.
  - 0 is nil. An unknown number and a signature mismatch (a C cast) each fail loudly, by name.
- MEASURED TRAP: Delegate.GetHashCode is the TYPE's hash for a static method, so one table scans a whole signature's bucket (75 ns to 13 us with 300 functions).
  - Two tables (reference identity, then Delegate.Equals) plus C# 11's per-site cache of method-group delegates bring a mint to about 50 ns.
  - Call sites keep reading __ccgo_fp(F).
- The converter recognizes three shapes BY STRUCTURE: the ccgo mint body, the Go-side mint, and the recovery. Anything else through unsafe.Pointer is a convert-time warning.

S21, ASSEMBLY IN THIRD-PARTY MODULES
- go2cs already converts modules under safe,purego,noasm. Under those tags all of x/crypto's and klauspost/compress's assembly goes (amd64 63 to 2; arm64 50 to 4), leaving x/sys/cpu.
- sqlite closure, per target:
  - linux: x/sys/unix syscall entry points only. libc's 1,879 asm functions are ABI0 entry points for compiled C with no Go caller, so their stubs never run.
  - windows/amd64 and darwin/amd64: x/sys/cpu cpuid/xgetbv, from its init. libc's pthread.go imports x/sys/cpu everywhere but linux, which is why the wall is on windows and darwin.
  - darwin/arm64: no asm. Its sysctl path is the LINKNAME syscall_syscall6, a linknameForwardTargets entry.
- RECOMMEND a signature-checked converter table forwarding to golib (cpuid via X86Base; xgetbv synthesised from Avx/Avx512 IsSupported) or to std syscall (x/sys/unix's asm is JMP syscall-Syscall).
  - Unlisted asm keeps the stub, and the converter warns by name.
  - REJECTED: a nugetgo companion (one per x/sys version) and per-consumer hand-owned files.
