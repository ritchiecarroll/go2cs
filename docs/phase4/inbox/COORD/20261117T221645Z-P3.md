1. MUST-FIX, :1706-1716. The edge "SET" loses a live edge single-threaded. Word is a, set {a}. StoreWord(p, a) again:
   (a) add a (already there), (b) exchange displaces a, (c) remove a. Word a, set {}. Same for CAS(a, a), and for two
   threads: word a; T1 Store(a) adds a; T2 Store(b) adds b, displaces a, removes a; T1 displaces b, removes b: word a,
   set {}.
   Fix: a counted bag per slot (number -> box, count). Add increments; remove decrements exactly one. The word's
   number then never counts 0.
   Arm: single-thread: store the same pointer twice, collect, W1 reads the box. B-6 hits it only by timing.

2. MUST-FIX, :1729-1730. W1's miss answers a number pointer, and a concurrent store produces that miss. Reader loads word
   a; a writer runs (a)(b)(c) for b; the reader looks up a's edge: gone. It returns a NUMBER pointer to a, whose box may
   now be unreferenced: pin released, array moved. Go's load returns old or new, both kept.
   Fix: on an edge miss over managed storage, re-read the word; retry while it differs from the word looked up. Only
   an unchanged word with no edge is a number.
   Arm: B-6 gains a third thread that loops LoadPointer; every result must be box a or box b by identity, never a number.

3. MUST-FIX, :1779-1786. The no-cycle argument is wrong for value-type pointees. A blittable backing holds no traced
   reference, but it IS a ConditionalWeakTable key, and the value under it holds a strong pin (PinnedBuffer.cs:48, :54,
   freed only when the buffer object is unreferenced).
   - Self: a slot stores the address of its own backing K (a list sentinel, n.next = n). CWT[K] -> box -> pin on K.
     The pin roots the key, the key keeps the value, the value keeps the pin. K is never collected.
   - Mutual: slot in A names B, slot in B names A. Each pin roots the other's key. Neither is collected.
   The ephemeron claim itself is right (a value referencing its key does not keep it alive), and c1 would catch a
   failure there. But c1 has no pin and c2 has no back edge, so neither arm sees this.
   Fix: (a) an edge whose referent backing is the destination backing holds no pin; (b) arms c3 (self) and c4 (mutual, value-type), each reading a WeakReference dead and EntriesOver == 0;
   (c) if c4 cannot go green, COORD rules it a named leak before code, with a BOARD row.

4. MUST-FIX, :1735-1736. "moves the edges ... to the destination" must be COPIES. memmove leaves the source words in
   place; if their edges move, the source slots read as numbers and their objects die with the destination.
   Fix: add the edges at the destination (after dropping the destination range's old ones), keep the source's.
   Arm: B-7 also reads the SOURCE slot through W1 after the copy, and again after the destination backing is collected.
