# Seat #41 ROOT CAUSE: unused imported aliases are emitted, so package_info.cs carries the TARGET's alias set

C2 -> COORD. Cut from 03d19d9279 as claude/c2-seat41-host-golden (local). Root cause and prediction, posted before the
stdlib runs.

**Red, reproduced.** The committed FieldAccessReinterpret, built for linux (-p:GoTargetOS=linux), fails with:
- package_info.cs(14,50): error CS0426: The type name 'ΔHandle' does not exist in the type 'syscall_package'
- package_info.cs(16,52): error CS0305: Using the generic type 'syscall_package.ΔSockaddr<ΔTTarget>' requires 1
  type arguments

**It is TARGET-dependent, not host-dependent.** On linux, converting with `-platforms windows/amd64` reproduces the
committed main.cs exactly. package_info.cs differs only by its BOM and the hand-added [GoTestMatchingConsoleOutput].
The host enters only because the harness converts for its own GOOS.

**Root cause.** The converter reads each imported package's package_info.cs for the target GOOS
(platformPackageInfoPath), which is correct. It then emits a `global using` for EVERY alias parsed there, whether or not
the Go source names it. Only DERIVED aliases (a dependency with no package_info.cs) are gated on use
(usedDerivedTypeAliases). syscall's windows alias set holds Handle and a non-generic Sockaddr, and the linux set does
not. FieldAccessReinterpret names neither: it uses syscall.RawSockaddrInet4.

**Fix (prototyped, not committed).** Gate every imported alias on use, the rule derived aliases already follow: a
`global using` is emitted only when an emitted reference resolves through it. A reference that resolves through an
alias depends only on the Go source, which compiles on every target, so the emission no longer varies with it.
Measured with the prototype:
- FieldAccessReinterpret and OsGetpagesize: package_info.cs and the program .cs are byte-identical on linux, windows
  and darwin.
- Behavioral census (master 03d19d9279 against the prototype, every package in place): 166 projects, 167 files,
  all package_info.cs, +0 -640, every one an unused `global using`. By package: reflect 279, time 115, os 114,
  runtime 34, CrossPkgLib 34, net 23, syscall 17, json 10, and 8 more across exec, xml, x509 and big. No
  main.cs and no .cs.target moves.

**PREDICTION for the stdlib (two-seeded, all three targets), stated before measuring:**
1. Deletions only, and only `global using` lines in package_info.cs; no other file kind moves.
2. Some per-GOOS (L3) package_info.cs copies may become identical across targets. If the converter then routes a copy
   flat, files MOVE between folders rather than only shrink. I will report that as its own count if it happens.
3. The risk, named: hand-owned files compile against their package's global usings, but the converter never sees
   their references. 35 code references in 29 hand files name an alias (syscallꓸHandle 13, abiꓸKind 9, and others).
   Where no converted file in the same package names that alias, the stdlib compile arm goes red with CS0246.
   If that happens, the fix grows one rule: a reference in a hand-owned file of the package also counts as a use.
4. The behavioral Compile phase stays green on linux for all 166 moved projects; I run it over them.
