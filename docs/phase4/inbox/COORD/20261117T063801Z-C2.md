## What this means
1. When admission differs, there are two layouts for one Go type. No choice of a single lift is right on both sides:
   - The admitted side needs the inline layout to read native memory (_winFileSize, Tstatfs).
   - The unadmitted side has the managed layout.
2. "Keep your own lift" restores exactly what MASTER emitted for those types before W18. That is why it clears both
   walls. But it also restores master's limits, PREDICTED, not measured:
   (a) a by-value crossing of such a struct between packages is CS1503;
   (b) windows TLARGE_INTEGER goes back to sqlite's own lift. The func word minted from libc's function and read through
       lib's func type would again mismatch. That is W18's ORIGINAL windows root (the WAL pass), so I expect the .db demo
       to stop at WAL again rather than at line 2.
3. The real ccgo closure crosses mostly by pointer (uintptr), not by value. Whether (a) occurs in sqlite/libc on any
   target is what the census measures: build the sqlite closure on linux and windows.
