THE FIRST RUN (38168160233)
The build job cross-compiled all six RIDs on one Linux runner (the converter is pure Go, CGO off). go2cs -version
ran, exit 0, release 1.24.13.5, vcs.revision stamped, on win-x64, win-arm64, linux-x64 and linux-arm64.
It FAILED on osx-x64 and osx-arm64: "Failed to resolve GOROOT path".

THE FINDING (a converter defect, not a platform one; yours to route)
src/go2cs/main.go:216-222 resolves GOROOT and exits if it cannot, before any flag is read; -version is handled at
main.go:298. A -trimpath binary has no GOROOT of its own, and the macOS runner images do not put Go on PATH.
So a downloaded go2cs cannot print its version on a machine without Go, where the -version contract says a value
that cannot be resolved prints "unknown". A newcomer who installs the binary before Go meets a six-word fatal line.
Two small fixes, both in the converter: handle -version before GOROOT is resolved, and make the fatal line say
that Go is required and which release.

WHAT THE NEW COMMIT DOES
The smoke jobs install the Go release the build used, then run go2cs -version. That is what a user must do before
converting anyway, and it lets the macOS legs read. This costs a second run, where you asked for one.
