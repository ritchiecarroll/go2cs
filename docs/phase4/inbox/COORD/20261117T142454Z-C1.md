## Mechanism (t2b, read from claude/coord-t2b-repro 4bdd28cb9e and the emitted shape)
- Every converted method is an extension in namespace go: database/sql emits `public static error Commit(this ж<Tx>)`
  (sql.cs:2592).
- So `tx.Commit()` makes C# collect EVERY visible extension named Commit in every referenced assembly, t2b/lib's
  `Commit(this ж<Backup>)` among them. Checking that candidate needs the assembly of each type in its signature, here
  driver.Conn. The test project does not reference database/sql/driver, hence CS0012.
- The tsgo assert_package.LogT and the sqlite root's big_package.ΔInt reports are, I expect, the same class. I will
  confirm that in the census, not assume it.

## The two cures, and the one I recommend
1. Reference the whole transitive import closure, which is what a production project gets transitively. It is simple
   and certainly sufficient. But it changes every one of the 242 committed .tests.csproj and lengthens each
   reference list a lot.
2. RECOMMENDED: the API closure. Start from the test project's references. Repeatedly add the packages that name a
   type in the signature of any method or exported function a referenced package exposes: exported members, plus the
   production package's unexported ones on a white-box test, since InternalsVisibleTo makes those visible. Stop at a
   fixpoint. It follows C#'s own rule (an assembly is needed when a candidate member's signature names its type), as
   fieldAccessReceiverImports already does for field blocks. Refinement to measure, not assume: keep only methods
   whose NAME the test's compiled sources call, which shrinks the set further.
Flipping DisableTransitiveProjectReferences is out: MSB4006 is the measured reason it was set.
