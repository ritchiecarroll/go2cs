Findings
1. MUST-FIX (arm). Section 3/4, "p is not a NativeBox: p.Value". One native receiver takes that arm: `&l.next` where
   the field has no known Go offset. `of` keeps a FieldRefBox there (ж.cs:276, "a root whose field offset cannot be
   known keeps its view"), so LoadPointer reads `.Value` on a view whose source is native. I read that this reaches the
   floor through the source's NativeBox<T>.Value and is refused, but 1a needed RequireGoFieldOffset for exactly this
   receiver on the word doors, and no 1c arm names it. Scenario if the read is wrong: a load returns the CLR slot of a
   struct in C memory, a store writes a managed reference into C memory. Fix: an E-2 row (native receiver, accessor
   with no Go offset, `of`, then LoadPointer and StorePointer: both refused by name, all bytes unwritten), and one
   sentence in section 3 saying which refusal it is. If the row shows no refusal, the door tests
   INativeRooted.IsNativeRooted and refuses itself.
2. SHOULD-FIX. Section 1, the ref-lowered parameter exclusion. `func set(pp **C.struct_e, v *C.struct_e) { *pp = v }`
   called as `set(&l.next, v)` with l in C memory is ordinary Go and is the out-parameter idiom inside Go code. The call
   site builds a C# ref from the native box, so it hits the floor. That is loud and acceptable for 1c, but it is not
   in "Not in 1c". Name it there, and make control (e) run the call over a native receiver and assert the floor's
   text (stop line 6 then has an arm).
3. SHOULD-FIX. Same for the tuple target over a native slot (`*pp, n = v, 1`): name it and assert the floor's text
   once, in E-2 or E-3.
4. SHOULD-FIX. E-1 lacks emission rows for the load in non-statement positions, where a converter path may spell the
   dereference itself: `&*pp`, `(*pp).family = 3`, `f(*pp)` to a callee whose `*C.T` parameter is ref-lowered, and
   `*pp` inside a closure. Each either takes the door or is a named exclusion.
5. SHOULD-FIX. One chained arm across the two seats: a C struct field of type `**C.T` (1a's accessor mints a
   NativeBox<ж<U>>), then `*e.pp` through the door. It proves the box 1a mints classifies as CMemory for 1c.
6. NIT. "Not in 1c": add a slice of `*C.T` over C memory (`unsafe.Slice(argv, n)`); it stays refused at the slice
   door because the element holds a reference.
7. NIT. Section 4 cites 1a's store "once SHOULD 1 is folded". State the order as a stop line: 1c's core is cut on the
   folded 1a, never on 01ecb22bb9.
