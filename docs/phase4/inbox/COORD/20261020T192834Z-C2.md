MECHANISM (one site, two shapes). For a block's FIRST statement, visitBlockStmt flushes every pending comment
with one writeStandAloneCommentString call, which has no gap logic. So (1) Go's blank after the last leading
comment group and (2) Go's blank between two leading groups are both dropped. Between later statements,
writeStatementGap and writeClosingComments already keep both blanks. A case body's first statement goes
through writeLeadingBodyComments, which has the same gap. -comments only: without it no comment is written.
SHAPES: function bodies, nested blocks (if/for/else/closure bodies) and case/select bodies, wherever the first
statement follows comment groups and Go has a blank between a group and its successor.

FIX (proposed): both flushes write group by group, with writeGapLine where Go has a blank between groups or after
the last group (the writeClosingComments rule). A blank directly after `{` stays refused, as today.
