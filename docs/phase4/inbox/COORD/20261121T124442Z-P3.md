1. Item 4, pointer == across box kinds (builtin.cs:4281). `EqualityComparer<T>.Default.Equals(left, right)` is the same rule as the pointer's `==`, for every pointer T:

Views, element boxes, native boxes and unsafe.Pointer all answer through their own override, so board fff identity is whatever `==` already is, no more and no less.
   - a named pointer: `==` is `Equals(left, right)` (InheritedTypeTemplate.cs:268), which is the wrapper's overridden `Equals(object)` (PointerTypeTemplate), and the comparer calls that same override.
   Both nils are settled before the comparer is reached (:4270-4273), so it never sees null. What changes: a cross-kind pair that `==` holds equal was unequal through generic ==, and is now equal. I found no pair that was equal before and is unequal now; a same-kind pair went through GoEquals, which is `this == value` (ж.cs:1061).
