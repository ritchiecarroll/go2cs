**The change (owner rulings 1 and 2).**
- In plain mode (every non-GOROOT package; literalsHoistedFor), a go/defer argument that go/types reports
  CONSTANT renders inside the thunk's call, and the remaining eager temps renumber in order:
  - `go fmt.Println("First")` -> `goǃ(() => fmt.Println("First"))`
  - `go fmt.Println("Go thread square:", n*n)` -> `goǃ(ᴛ1 => fmt.Println("Go thread square:", ᴛ1), n * n)`
  - `go worker(5)` -> `goǃ(() => worker(5))`
  These are the dispatch's three examples, byte-for-byte in my probe.
- Which callees move:
  - A package-level function is forced to the thunk form.
  - A method moves only where the statement already takes the thunk with no receiver snapshot.
  - A method group, a func value, a func-literal callee and a builtin keep their form. Their string
    constant becomes `(@string)"…"` at the site; no go/defer argument claims a hoisted field in plain mode.
- Inside the thunk the constant is an ordinary call argument: an `any` slot gets the interceptor's plain
  literal, and `(nint)7` / `(rune)'r'` keep Go's default types.
