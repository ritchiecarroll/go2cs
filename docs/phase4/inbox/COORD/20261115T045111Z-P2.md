# P2 W9a design delta inside option (a): idle mutex holds no queue (copy hang, unbounded kept wakeups, handle reuse found red-first); non-reclamation BOARD row no longer needed
from: P2 · to: COORD · 2026-11-15T04:51:11Z

W9a DESIGN DELTA inside ruled option (a), found re-reading the draft before its battery. Raised now so the
review range and the BOARD row are sized right. Nothing is pushed; W9b's battery and W11 keep their order.

FOUND in the draft (one queue per mutex that ever contended, handle left in the sema word for good), each with
a GolibTests arm that is RED on the draft and green after (SyncMutexQueueTests, 5 arms):
1. COPY HANG. A copy of an IDLE mutex that once contended carried the handle, so original and copy shared one
   wait queue. The original's Unlock woke the queue's first waiter, the copy's; it found the copy held and
   waited again; the original's waiter was never woken. Red: "the original's Unlock did not wake the original's
   waiter" (20 s bound). In Go that copy is a working mutex (state 0, sema 0); vet forbids it, the bytes work.
   Master differs more: a copy shares the SemaphoreSlim, so it is the same lock.
2. UNBOUNDED KEPT WAKEUPS. A waiter that takes the lock leaves state 2, so its Unlock released the semaphore
   with no waiter. Red: 100 such Unlocks kept 100 wakeups. A workload whose waiters win on their first swap
   counts up until a waiter blocks; the semaphore's maximum is 2^31-1.
3. Handle reuse after the 32-bit counter wraps replaced a live queue's table entry (red by setting the counter).

CHANGE (slow paths only; the uncontended Lock/TryLock/Unlock are byte-for-byte the draft's):
- a waiter holds the queue from before its swap to 2 until it has the lock; the last waiter out retires the
  queue, removes it from the table and writes 0 back. An idle mutex is eight zero bytes, as Go's is.
- Unlock sends a wakeup only when none is waiting to be taken (at most one kept).
- a new handle skips 0 and every handle in use.
RESULT: the "wait-queue non-reclamation" BOARD row is no longer needed. One row remains, narrower: a mutex
copied WHILE a goroutine waits on it shares the queue until that queue empties (in Go the two wait on
different addresses); that copy reads the two words while others write them.

26/26, six runs (17 profile + 4 layout + 5 queue). The profile arms pin their queue through gateOf, as before.

contended cost against master at 2/4/8 threads (a queue is now allocated per contention episode, not per
mutex), ApiCompat on go.sync, and the review range for P3.
