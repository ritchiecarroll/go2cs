Shape: an index or slice expression of a NAMED string type compared with an untyped string constant.

  type Kind string; vals := map[string]Kind{...}; s := []Kind{...}; var k Kind
  vals["a"] == "x"   ->  vals["a"] == "x"      CS0019 (Kind == System.String: no operator)
  s[0] == "x", a[0] == "x", "x" == vals["a"], vals["a"] != "y", vals["a"] < "y"   -> same
  k[1:] == "y", k[:1] != "x"                   -> same (the Range indexer returns Kind)
  CONTROLS that already emit "x"u8 and compile: k == "x", st.K == "x", p.K == "x", get() == "x",
  *ps["a"] == "xy", vals["a"] + "z" (named concat), switch vals["a"] { case "x": }.

Root (origin/master 58cfeb3d0f, unchanged by my seat): convBinaryExpr.go:1819 sets u8StringOK only when BOTH operands
pass v.isStringType, and typePredicates.go:157 returns false for every *ast.IndexExpr / *ast.SliceExpr. For a plain
string that is harmless (@string == string binds); for a named string the plain literal has no operator, and C# cannot
chain string -> @string -> Kind.

Proposed fix (narrow): in the u8 decision only (not isStringType, which convCallExpr:2275 also reads), an IndexExpr or
SliceExpr whose type is a NAMED string counts as a string operand. Then == / != bind the wrapper's
==(Kind, ReadOnlySpan<byte>) pair, and < / <= / > / >= bind the seat's same-type operators through the wrapper's
implicit-from-span conversion.
