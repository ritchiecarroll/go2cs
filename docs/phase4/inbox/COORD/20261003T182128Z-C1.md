THE SHAPE, read at the source. x/sys/unix on darwin reaches libc in two halves, and BOTH are missing in a conversion today:
 (1) 7 bodyless PULLS in syscall_darwin_libSystem.go: `//go:linkname syscall_syscall syscall.syscall`, and likewise syscall6,
     syscall6X, syscall9, rawSyscall, rawSyscall6 and syscallPtr. Go authorizes them from runtime/sys_darwin.go
     ("golang.org/x/sys linknames syscall_syscall", with siblings), where runtime PUSHES the bodies. x/sys's Errno is
     `type Errno = syscall.Errno` (aliases.go:12), so every signature is types.Identical to its target.
 (2) 154 ADDRESS VARIABLES per arch (zsyscall_darwin_{amd64,arm64}.go): `var libc_ioctl_trampoline_addr uintptr`, each with
     `//go:cgo_import_dynamic libc_ioctl ioctl "/usr/lib/libSystem.B.dylib"` and set ONLY by assembly:
     `DATA ·libc_ioctl_trampoline_addr(SB)/8, $libc_ioctl_trampoline<>(SB)` over `TEXT libc_ioctl_trampoline<>: JMP libc_ioctl(SB)`.
     Converted, the variable is a plain field that stays 0.
WHAT ALREADY EXISTS (so most of this is binding, not building):
 - The darwin syscall flavor implements the whole keystone family (syscall_darwin_impl.cs: one GoLibcCall per call, Go's failure
   rule per variant). All 7 pull targets are `internal` partials, BUT each has a PUBLIC twin that is the same call under the same
   rule: Syscall, Syscall6, Syscall9, RawSyscall, RawSyscall6 (Int32MinusOne), and the increment-10(a) doors GoSyscall6X and
   GoSyscallPtr (internal/syscall/unix's net_darwin_impl.cs already routes its pulls through them).
 - The cgo pass (cgoDynamicImports.go) runs for EVERY converted package, third-party included, and binds a pragma to a bodyless
   `func <local>_trampoline()` (the stdlib's FuncPCABI0 shape). golib's GoCgoDynamicImports.Resolve(symbol, library) is public
   and applies the $INODE64 linker rule. GoLibcCall refuses a zero address by name (ArgumentException), so a half-fix fails
   loudly, never with a jump to 0.
THE FIX, two pieces, converter-side, no corpus hand-edits:
 P1 TWIN FORWARD (piece 1). A darwin row table mapping each pulled target to its public twin: syscall.syscall->Syscall,
    syscall6->Syscall6, syscall9->Syscall9, rawSyscall->RawSyscall, rawSyscall6->RawSyscall6, syscall6X->GoSyscall6X,
    syscallPtr->GoSyscallPtr. writeLinknameForwarder emits the forwarder against the twin's name when the signatures are
    types.Identical, the existing proof standard. Why a twin and not linknameForwardTargets' widening (the syscall.prlimit
    shape): widening would publicize the targets, which moves syscall_darwin.cs in the darwin corpus AND needs the hand-owned
    partials' modifiers changed (C# requires them to match). The twins make both unnecessary.
    About 40 converter lines + about 80 test lines (forward emitted on a darwin target; not on windows or linux, where no file
    carries the pulls; refused on a signature mismatch).
 P2 ADDRESS VARIABLES (piece 2). Extend the cgo pre-pass to bind `var <local>_trampoline_addr uintptr` to the pragma `<local>`.
    The proof is the package's own .s: a DATA line storing $<local>_trampoline<>(SB) into it, over a pure-JMP TEXT to <local>(SB).
    asmTrampolineIndex already scans those files, but today it only treats DATA/GLOBL as block boundaries; P2 adds the DATA
    parse. The var gets an initializer
    that resolves the dynamic symbol: the same value class-B gives a stdlib trampoline, since the trampoline's only instruction
    is that jump. Recommend a non-throwing golib twin (ResolveOrZero) so a symbol missing on an older macOS costs that one
    call a loud ArgumentException rather than killing the package's static init over 154 symbols.
    About 80 converter lines + about 10 golib lines (a GOLIB seat) + about 90 test lines.
