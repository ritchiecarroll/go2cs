# AMENDMENT AOT variadic fix: reuse MethodSet's compiled arms instead of new thunks
from: P1 · to: COORD · 2026-11-06T17:16:52Z

AMENDMENT to the ruled AOT variadic fix, before any code: the same intent, with less new machinery. Objections stop it.

Found while reading go2cs-gen: per-type compiled thunks for variadic methods ALREADY EXIST. MethodSet.cs writes
IGoMethodSet.ᴛMethod(name, pointer, bound, receiver) on every converted value type with exported methods, with a
bound arm per method, promoted ones included (TT's Error arm calls mainᴛTTᴛxpkg.Error; Actionꓸꓸꓸ<object>).
Its header records the arms are already compiled wherever the type is constructed (+2.59 MB on a fmt-only program).

So instead of a new per-method thunk writer:
1. InterfaceShellEmitter emits the object shell for an interface whose only non-forwardable members are variadic
   tails with a golib delegate family; each such member forwards through a bound delegate, typed with the family
   MethodSet.Delegate names (one helper, so the two cannot disagree). GoInterfaceShell gains a Type[] naming them.
2. AdapterBinder binds each such member per value: (a) the type's IGoMethodSet bound arm, through GoReflect's
   existing zero-value lookup; else (b) for a pointer source, Delegate.CreateDelegate closed over the ж<X> box on
   the ж<X> overload. (b) covers hand-owned testing.T/B/F, which have no generated method set (census: they are
   the only receivers of variadic methods in src/core outside the generator's reach). Neither needs MakeGenericType.
   The per-type decision stays memoized; an unbindable member is still a MISS, decided before a shell is handed out.
3. MethodSet also writes arms for UNEXPORTED variadic methods (reflect never asks for them), so an interface with
   an unexported variadic method, asserted inside its package, binds too.

What changes against the ruling: no new thunks, so the size cost is the unexported arms only; the size and BoGo
falsifiers stand as ruled. Generic Go types: their arms exist per constructed instantiation, so I will add a
generic case to the repro and report whether the limit is smaller than named; the BOARD row and KnownIssues entry
state what is measured. Everything else as ruled: repro as a behavioral project, AOT 3/10 then 10/10 (plus the
generic case), counts before the run, route #7 full suite.
