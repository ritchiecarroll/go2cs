# I1 sizing (no code): whole value S, element address M, slice L; 0 value for sqlite-cs; windows sockaddr group needs S+M, linux/darwin all three

I1 SIZING (no code): spell the three faces so a group is admitted whole. Census at the sockaddr fix (3c25375a04).

WHO NEEDS IT. Face-blocked types, by face (whole value / sliced / element's address), plus partner keep-outs:
  x/sys/windows        3 / 5 / 4, +1 partner
  x/sys/unix linux     8 / 5 / 1, +4 partners (amd64 and arm64 alike)
  x/sys/unix darwin    4 / 2 / 1, +2 partners
  libc, sqlite/lib     0 on all 4 targets (libc's 1-4 are caps; I1 does not touch caps)
  behavioral           FieldAccessReinterpret, GoImageCopyThroughView and PointerFieldSelectors (I0 record)
So I1 is worth NOTHING to sqlite-cs. Its value is Go layout for x/sys's native socket and setupapi calls:
getsockname, recvfrom and accept write a RawSockaddrAny the converted code then reads. Today that round trip
works only between managed boxes, as in std.

THE THREE FACES, sized:
1. WHOLE VALUE (copied, stored, compared, returned) -- SMALL, one seat.
   - Read: `x.f.ΔCopy()` exists (I0 boxing uses it).
   - Compare: through the copies, or a generated Equals.
   - Store `x.f = v`: one new go.arrays member (assign from array<T>/ReadOnlySpan, length fixed by the type).
   - Converter: the face rule drops the case, and the emission picks the member per context.
   - Subsumes I0's stated deviation (a copy between two admitted fields).
   - Gain ALONE: about 0 in x/sys, by my reading of the census lists (not measured). Every type it unblocks is in
     the RawSockaddrAny group or holds a member by value, and RawSockaddrUnix's &Path[0] keeps that group out.
2. ELEMENT'S ADDRESS (&x.f[i], and an address below an element) -- MEDIUM, one seat.
   - An alias box for an element of an inline array inside a box, on golib's existing alias-box pattern
     (FieldAliasBox, the element box `at` builds, GoReflect.InteriorAlias). It must hold the OWNING box alive and
     re-derive the element ref on each access; no pin.
   - Risk: the ж<T> surface; GolibTests at both configurations.
3. SLICED (x.f[:], x.f[i][:]) -- LARGE, one seat plus a perf gate.
   - The slice must alias the inline storage, which today's slice<T> backing cannot (a T[] or native memory). It
     needs a new backing kind, an object plus a byte offset, re-derived on each access.
   - That is the slice hot path: every index, append and copy goes through the backing switch. So it needs a
     Performance-suite A/B, not only GolibTests.
   - Check first whether P5's interior-pointer seat (batch 305) already gives that shape.

WHEN A GROUP IS ADMITTED WHOLE (the sockaddr group, by OS):
  windows   whole value (Inet4/6) + address (Unix)                     = 1 + 2, no slice
  linux     whole value + address (Unix) + slice (NFCLLCP, ALG, Inet4)  = all three
  darwin    whole value + address + slice                               = all three
  windows setupapi (DrvInfo*, DevInstallParams, win32finddata1) are all slice-blocked.

RECOMMENDATION. Do not schedule I1 for sqlite-cs; nothing there needs it. If x/sys native sockets are wanted:
  I1a whole value (S) + I1b element address (M) admits the windows sockaddr group;
  I1c slice (L) admits linux/darwin and setupapi.
Each is red-first with the census arm as its prediction instrument. The -stdlib footprint stays 0 by construction
(std never runs admission). The behavioral footprint is the three projects above, and every move there is
predictable from the I0 record.
