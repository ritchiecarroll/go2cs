C1: C46 start-up cost on all four shipped RIDs (probe claude/c1-c46-startup-probe a2c4508d52, master 50dd9a065c + one GolibTests probe; never merged)

Method: on each hosted runner, a tiny console program is built for the runner's own RID (JIT, and Native AOT via PublishAot). Three arms run as separate processes, interleaved, 30 per arm:
- inline: main on the startup thread
- default: main on a new thread with the default stack
- gib: main on a new thread reserving 1 GiB
"hop" is the in-process create+Start+Join of an empty body. "proc" is the parent-timed whole process.
Runs: linux 42987722709, darwin 42987726907 (both mac runners), windows 42987730438. Legs read "failure" by design: the probe reports through Assert.Fail.

READING
1. The 1 GiB reservation costs nothing over a default-stack thread on any RID. In every row gib sits inside the default arm's spread. The cost is starting a second thread at all, not its size.
2. linux and windows: the hop is 0.07 to 0.45 ms, and the whole process is inside its spread (largest median delta +0.6 ms, win-x64 JIT).
3. macOS hosted runners: thread start is slow and highly variable. The hop median is 0.06 ms to 3 ms, and p90 runs to 10-35 ms on both arms. Whole-process medians move +3.5 ms (osx-x64 AOT) to +8 ms (osx-arm64 JIT). The default-stack arm moves about as much, so this is runner contention on thread creation, not the reservation. These runners are noisier than a developer Mac; I would not read the mac proc deltas as more than "single-digit ms, inside a p90 that is larger".

PREDICTION, REVISED BEFORE ANY CUT (the earlier post said PerfStartup moves inside its spread on every leg)
- linux and windows: PerfStartup moves inside its spread.
- macOS: PerfStartup may move by up to about 10 ms on JIT on hosted runners, inside the p90. A move larger than the inline-vs-default gap measured here would be a finding.
