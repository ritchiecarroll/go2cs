## Recommendation: a rule in the oracle, not a per-module tag set
The oracle's go test drops math_big_pure_go unless the package under test is math/big; the conversion
keeps it everywhere.
- Fidelity argument. The tag selects math/big's arithmetic implementation and nothing else. With it,
  math/big uses the pure-Go `_g` bodies. Without it, math/big uses assembly. Both compute the same Words,
  and math/big's own tests compare the assembly against `_g`. For any package other than math/big,
  dropping the tag changes no file in the package under test or in its tests. So the oracle answers the
  same question the conversion answers. It also becomes plain Go as a user runs it. The conversion stays
  pure-Go math/big, because assembly cannot be converted.
- math/big's own row keeps the tag on both sides, because there the tag changes the test file set.
- Against a per-module list: it records a property of math/big against each module that happens to
  reach bigfft, needs an entry for every new such module, and fails silently when one is missing.

## Shape of the change
oracleTestArgs takes the tested package's import path (comparisonRecordPackage is already in scope at
the caller) and filters math_big_pure_go out of loaderBuildFlags' list, except for math/big. About 15
converter lines, all in the oracle's command line. TestOracleTestArgsCarryResolvedBuildTags is amended,
not loosened: oracle == loader byte for byte on the math/big arm; on any other row, the loader list
minus exactly math_big_pure_go.
