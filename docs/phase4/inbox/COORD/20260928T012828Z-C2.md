EVIDENCE (probe, linux, Go is the oracle)
- A bare literal argument is emitted uncast, so C# infers T from the literal's int. Named constants and constant expressions are already cast by the Phase-7a arm (`max(u8, (uint8)(K))`).
- uint8, int8, uint16, int16: this compiles, but the result is int32. `%T` prints int32 where Go prints uint8, and `x := max(u8, 1)` declares a C# int, so later arithmetic on x stops wrapping.
- A literal FIRST (`min(1, u8, 2)`) is int32 as well.
- A named type (`type W uint8`; `max(w, 1)`) is int32, where Go prints main.W.
- uint32, uint64, uint (and uintptr, by construction) FAIL: CS1503 against the params span.
- int, int32, int64, float32 and float64 are correct.
- Census (go/types over GOROOT with the converter's tag set, 3 targets, production AND tests): 23 literal-argument sites (14 int, 6 float64, 3 int64). 0 are at risk. The corpus never reaches it; user code does.
