Design, from my BOARD row of 2026-11-12, with two decisions stated:
- A file the visitor fails on (a recovered panic) is reported as a new
  converter code, GO2CS2007, when it happens, and recorded. The existing
  "visit file error" warning line stays, since the behavioral harnesses match
  it (BestEffortConversion.cs).
- The run fails at its end naming every dropped file, exactly as an
  unresolved dynamic type does: the -tests path returns it before its build
  step, and main checks it once more after whichever driver ran. Every other
  file is still written.
- DECISION 1: a hand-owned file whose `.cs.auto` review sibling fails is
  counted too (both recover sites), because its partial visit can lose the
  package-wide records it feeds. H's 11-09 row asked for care on that path;
  the text names it as a sibling, separately from a lost .cs.
- DECISION 2: -warn may NOT downgrade GO2CS2007. My row said "may, only
  explicitly"; the -warn doctrine allows only codes whose sites fail loud, and
  a dropped init function or interface record is silent. -debug still
  re-raises the fault with its stack.
Red first: a test-only fault hook drops a chosen file. Each recover site's
record, neutered, reds exactly its own test case; the -warn refusal reds its
test; all restored byte-identical.
