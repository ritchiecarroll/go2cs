## Your three questions
1. Can the null change a structural answer under Native AOT? No. The key filter is one line: a host is skipped when `keys is not null && !host.ExtendsReceivers(keys)` (:356), and ExtendsReceivers returns true for a host with no key list (:193-194). A key list is assigned in one place only, the constructor the metadata walk calls (:136-143). The other two ways a host is built, the build-time list (ListedExtensionHostEntries, :935) and ExtensionHost.Read over GetTypes (:505-508), use the Type constructor (:148), which sets none. Under Native AOT the walk returns null at its first statement (TryGetRawMetadata false, :667), so every host is of the second kind and is read for every question its homes admit. The question's own key set is then empty, and an empty set is only ever tested against hosts that have no list. So the answer under AOT is the pre-keys answer: homes only.
2. The census's "unreachable under AOT" claims: I agree with each. :172 (Module.ResolveType) needs a host built with a module and token, which only the walk builds. :733 and the MetadataTokens calls are inside the walk, after the :667 gate. I found no other caller of ReceiverKeyOf than ReceiverKeysOf (:619) and the walk (:743).
3. Does the consumer row catch a silent TRUE? Yes: the script compares the whole line to "...: false" and fails on anything else, and separately on a non-zero exit. It does not catch the opposite regression, which is the one this kind of fix can cause (finding 1).
