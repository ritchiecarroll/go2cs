# Docs: ConvertingAModule step 1 creates main.go as UTF-8 (PS 5.1 trap)
from: COORD · to: R · 2026-10-13T05:05:07Z

COORD -> R: a small docs fix from the owner's hand walkthrough of docs/ConvertingAModule.md on a clean Windows Sandbox (Windows PowerShell 5.1).
WHAT HAPPENED: step 1 says "Create `main.go`" and shows only the Go code. The owner made the file with `echo "Test" > main.go`, then pasted the code in with an editor. Windows PowerShell 5.1's `>` writes UTF-16, and the editor kept that encoding, so `go build ./...` failed with "read ...main.go: unexpected NUL in input". A new Windows user will hit exactly this.
THE FIX, on a new branch claude/r-docs-utf8-maingo from master:
1. Step 1 gains a ready-to-paste way to CREATE main.go with the shown content, in two blocks labelled by shell, following the page's own convention for genuinely shell-specific commands:
   - PowerShell, which must work on 5.1 as well as 7: a here-string piped to Set-Content -Encoding utf8. Go ignores a leading UTF-8 BOM, which 5.1's utf8 writes; verify that with go1.24.13 rather than trusting me.
   - bash/zsh: a quoted heredoc to main.go.
   - Keep the existing Go block for readers.
2. One short NOTE: Go source files must be UTF-8. In Windows PowerShell 5.1, `>` and `Out-File` write UTF-16. Include the one-line re-save that fixes a file already written that way:
   $t = Get-Content main.go -Raw; [IO.File]::WriteAllText("$PWD\main.go", $t, (New-Object Text.UTF8Encoding $false))
3. If the FAQ or a troubleshooting section exists, add the error text "unexpected NUL in input" there, pointing to this note.
4. Check README.md and the other user-facing walkthroughs (docs/, the Tour of go2cs) for the same "create a file" gap, and fix them the same way. List the pages you touched.
PROOF: run both PowerShell blocks on Windows PowerShell 5.1 AND pwsh 7, and the bash block on Linux. Then run `go build ./...` on each result. Report all three.
