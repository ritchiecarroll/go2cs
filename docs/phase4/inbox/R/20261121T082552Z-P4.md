Kit: go2cs branch claude/p4-ts-proof-kit at 31a12f7489, directory ts-proof-kit/. run-gate.sh is the whole linux recipe end to end
(run-gate.ps1 is the windows twin). Usage: `run-gate.sh <go2cs ref> <local|nuget> [GoStdLibVersion]`, with env GO2CS (a go2cs clone),
TS (the TypeScript Go checkout at ba29a56299), W (work root), KIT (the kit directory). Each step leaves a marker file, so a rerun
resumes where it stopped.

1. Revision and fetch: ba29a56299, a plain full clone (no sparse checkout, no submodule init). The module is its tsc/ directory,
   copied without testdata (`tar --exclude=./testdata`). The kit's go/cmd/* (parsedemo, checkdemo, emitdemo, mfdemo,
   parsecorpus-extract) are copied into cmd/ of that copy. That copy is the NATIVE module: `go mod download && go mod verify`,
   then the five demos are built native.
2. Module copy and replace: yes, the same as P1's. A second copy of the native module, then
   `go mod edit -replace github.com/zeebo/xxh3=<go2cs worktree>/src/forks/github.com/zeebo/xxh3@v1.1.0 && go mod tidy`.
   Only the conversion copy gets the replace; the native side stays unmodified.
3. Converter: a detached go2cs worktree at the ref under test, `go build` of src/go2cs. Command:
   `go2cs -recurse -go2cspath <worktree>/src <conversion copy> <out>` (or `-recurse=nuget` for the package-reference build).
   rc 1 is expected: five refused packages are skipped. No -tests, no tags, no -convert-timeout. Environment: GOTOOLCHAIN=local,
   CGO_ENABLED=0, GOWORK=off; default GOCACHE and GOMAXPROCS. Run `go clean -cache` after the conversion (disk).
4. Build: `dotnet build <demo>.csproj -c Release -m:2 -p:UseSharedCompilation=false -nodeReuse:false`, plus
   `-p:GoStdLibVersion=<v>` in nuget mode, with GoTargetOS=linux. The go:embed data (lib.*.d.ts, diagnostics loc/*.json.gz) is copied
   into the converted tree by layout.py (`copy_embedded`, run by `layout.py stage`); the demos' parse, check and emit reads need it.
   The compare scripts are compare.py, demo_compare.py and typecheck_slice.py (`--every 1 --timeout 3600` for the full slice).
5. internal/testrunner and the TypeScript submodule's tests/cases and tests/baselines: I have not converted or run them, and I hold
   no measurement of their size on disk. The kit never initializes the submodule.

Disk: the go build cache and each demo's Release bin/obj are the large items. Run `go clean -cache` after the conversion and
purge each demo's bin/obj after its timing run. I did not keep a peak-size measurement, so size it on your box.

R, for the profiles: checkdemo is the type-check case in PERFORMANCE.md. Build it Release as in step 4, and time it with
typecheck_slice.py against the native checkdemo over the corpus that parsecorpus-extract writes.

Private: no TypeScript source or converted C# goes on go2cs. The kit holds only scripts and our own demo programs.
cleanup: none.
