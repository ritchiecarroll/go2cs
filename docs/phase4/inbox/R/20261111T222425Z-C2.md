Key facts measured at 742a3dbb24: go.gen is PrivateAssets=all (projectFileWriter.go:403-411) and packed go.* deps are

RULE TO ENFORCE (Go's own, cmd/go/internal/load findInternal): an import of a path whose FINAL "internal" element
sits under root R is allowed only from R or below; vendor/ packages: root = parent of vendor/.

WHO CAN VIOLATE IT: not converted Go code. go/packages refuses `use of internal package ... not allowed` before go2cs
emits anything, so a converted file never crosses a root. Only HAND-WRITTEN C# can: a pure C# consumer of go.*
packages, or a hand-written file inside a converted project (a *_impl.cs companion, a GoManualConversion file, a
user's own partial).

MARKING (the ruled half):
- [assembly: GoInternalRoot("<root>")] on every internal/vendor package's package_info.cs. Root "" = the std root
  (std's internal/*, std's vendor/*), else the module path prefix.
- [EditorBrowsable(EditorBrowsableState.Never)] on that package's `<name>_package` class.
- Census at 742a3dbb24: 184 of 352 production projects (169 internal, 17 vendor, 2 both). Per-flavour
  package_info.cs files multiply that; to be counted per target before predicting lines.

CONSUMER'S GO PATH (the open decision; the analyzer needs it to answer "inside the root?"):
- Assemblies record no import path today; AssemblyName is lossy (internal.bytealg: '/' and '.' both map to '.').
- (a) compiler-visible MSBuild property: projectFileWriter writes <GoImportPath>path</GoImportPath>, and golib (both
  the in-tree csproj path and buildTransitive) declares <CompilerVisibleProperty Include="GoImportPath" />. The
  analyzer reads build_property.GoImportPath; empty = hand-written C#. Footprint: one line per converted csproj
  (behavioral csprojs too), no .cs change.
- (b) [assembly: GoImportPath("...")] in every package_info.cs. Footprint: every package_info.cs, std and behavioral.
- Recommend (a): no emitted .cs moves, so CNR goldens stay put; csproj lines only.

ANALYZER (a new GO2CS0xxx, registered in DiagnosticCodes.md; text: "<type> belongs to Go package <path>, internal
to <root>; it is not covered by any compatibility promise and this warning may become an error"):
- Fires on a symbol USE (type, member, or using alias) whose containing assembly carries GoInternalRoot(R), from a
  syntax tree that is NOT converter output, when the compilation's GoImportPath is empty or outside R.
- Converter output is skipped per tree (its Go source already passed Go's check), so the stdlib's own emission and
  every converted module stay silent by construction; the check costs only hand-written trees.
- CARRIER: converted projects get it through go2cs-gen (in-tree ProjectReference, and go.gen for packages). A pure
  C# consumer gets neither, because go.gen is PrivateAssets=all and go.* dependencies exclude Build,Analyzers. So
  go.lib's buildTransitive adds an <Analyzer> item for a small analyzer DLL packed in go.lib (not under analyzers/),
  conditioned off when the project already references go2cs-gen. Kept separate from go2cs-gen so no source
  generator runs over hand-written C#.

RED FIRST (each must fail before the analyzer exists, then pass):
1. in-root: a converted module with its own internal/ package and a hand-written file in the module root using
   it: no warning.
2. outside root: a hand-written file in a converted project of module A using std's go.internal.*: warning.
3. pure C#: a plain csproj referencing a go.* internal package and using a type: warning.
4. the stdlib's own hand-owned files (e.g. os using internal/poll): none. Measured over the whole stdlib build:
   warning count 0.
Negative control: the same as 3, using only a public package: none.

UNLIST (report only): see findings.txt; feasible per version; exact pins keep restore working.
PREDICT before cutting: package_info.cs lines per target (GoInternalRoot + EditorBrowsable), csproj lines for
(a), 0 emitted-code lines elsewhere, and the std build's warning count = 0.
