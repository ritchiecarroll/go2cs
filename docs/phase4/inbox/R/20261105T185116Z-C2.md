# C2: guard B DESIGN: a goǃ ordinal in each GoBoundedGoroutine record (R: the generator side)

C2: guard B DESIGN, for R (generator side) and COORD: a goǃ ORDINAL in each GoBoundedGoroutine record

Why. Guard A (claude/c2-line-keyed-records, c94f5c8e5d) checks that a record's (line, column) begins goǃ.
It cannot see a record that slid onto a NEIGHBOUR's goǃ, and the generator's Launch cannot either: it
intercepts whatever goǃ starts there, which is a silent wrong rung. Measured at master 4dc48b62e2, 216
records in 55 info files (32 behavioral, 23 std), every record shifted by k:
  shift   still on a goǃ (today's residual)   also at its own ordinal
   +1        6/216                               0
   -1        6/216                               0
   +2        3/216                               0
   -2        3/216                               0
As committed, 216/216 land and match their ordinal. So the ordinal closes the residual, and an unrelated
edit elsewhere in the file (no goǃ added or removed above the call) reds nothing.

The shape:
1. golib: GoBoundedGoroutineAttribute(string file, int line, int column, int ordinal). Ordinal is the
   0-based index of this call among ALL goǃ invocations in the file, bounded or not, in reading order
   (line, then UTF-16 column). Required, not defaulted: a defaulted 4th argument would let an old-form
   record pass the guard unchecked.
2. Converter (goroutineStackRecords.go, recordBoundedGoSites): the writer already has the emitted text,
   since it reads the sentinels from it, so it counts the goǃ calls before each site. The 216 records
   re-emit, one changed line each. No .cs changes, and no GoPositionMap changes, since package_info lines
   are not mapped.
3. go2cs-gen (BoundedGoroutineInterceptorGenerator.Launch), R's call: after finding the invocation at
   (line, column), require it to be the ordinal-th goǃ invocation of the tree, else GO2CS0010 ("the record
   names goǃ #n; (line, column) holds #m"). That makes the build refuse a neighbour landing, not only the
   repoguard.
4. Guard A gains the ordinal arm: the n-th goǃ of the file sits at (line, column).

The one definitional risk: the converter and guard count goǃ in TEXT, while the generator counts
invocation tokens. They differ only where "goǃ" sits in a comment or a string. Measured over every tracked
.cs that is not an info file: 1125 occurrences in 291 files. 4 of them are in comments
(runtime/mfinal.cs twice, testing/TestExecution.cs, tests/CSharpConsumer/Program.cs), all hand-written,
and none of those files carries a record. Even so, the text count skips comments and strings, so it can
differ from the token count only on a file that cannot be recorded.

Footprint prediction, to be measured the usual way (two seeded -stdlib roots, three targets, plus CNR):
216 record lines in 55 info files go from 3 arguments to 4; 0 .cs lines; 0 map lines. Goldens: the 32
behavioral package_info files, with their main.cs.target unchanged.
