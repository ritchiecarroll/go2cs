## The defect

P3 confirmed it by reading the code at master 1fa80494ee:
- src/core/golib/runtime/RuntimeSemaphore.cs:78 `semaTable`: a static ConcurrentDictionary<ж<uint32>, SemaBucket>.
- bucketFor (:85) is GetOrAdd, used by Acquire (:99) and by Release (:168). Nothing ever removes an entry.
- src/core/internal/poll/runtime_sema_impl.cs:54 has the same shape.

So every semaphore word ever waited on or released stays in the table for the life of the process, with a STRONG reference to its
pointer object. For a WaitGroup, Mutex or RWMutex inside a larger struct, that pointer is a field view, which keeps its owner, and
everything the owner reaches, alive. Go's semaRoot holds an address only while a waiter is queued.

## The fix

- Remove the bucket under its lock when its queue is empty, as Go does, in both files.
- The race the design must close: an acquirer that fetched the bucket before the removal must not queue on a bucket no releaser will
  find. Re-check membership under the lock, or loop.
- Write the design paragraph (the race and how it closes) BEFORE the code.
