1. The marker (converter). `visitStructType.go` stamps `[GoCgoStruct]` beside `[GoValueClone(…)]`. It is movable, so it rides the type's accessibility record, which for a C type is the pseudo-package's (`applyCgoPseudoPackageStamp`). The stamp goes on a struct when both hold:
- the named type is one cmd/cgo declared as a C struct (`cgoTypeKind` is `cgoStruct`, prefix `_Ctype_struct_`);
- at least one field's type is a pointer (`*T`) or `unsafe.Pointer`.
The test is by DECLARATION KIND, never by a spelling the generator reads; the generator reads only the marker. The corpus converts at CGO_ENABLED=0 and declares no `_Ctype_` type, so it moves 0 lines (D-1).
- Out of 1a, by name: a field whose type is a DEFINED pointer typedef (`type _Ctype_xptr *_Ctype_struct_x`). Its C# type is a named pointer wrapper, not `ж<U>`, and keeps today's `ref` property and today's refusal over C memory.
- Also out: unions (18.4, 8a).

2. The accessor (go2cs-gen, `FieldAccessGenerator.Properties`). For a type that carries `[GoCgoStruct]`, a field whose C# type is `ж<U>` gets a GET/SET property in place of the `ref` property:
    public ж<U> f { get => ʗp.cgoPointerField(T.Ꮡf); set => ʗp.cgoPointerField(T.Ꮡf, value); }
- A field whose C# type is `unsafe.Pointer` gets the same shape over S-B1's word doors: `get => global::go.unsafe_package.Pointer.LoadWord(ʗp.Ꮡf)`, and the set is `StoreWord(ʗp.Ꮡf, value)` (unsafe.cs:1397, :1431). `ʗp.Ꮡf` is the existing address property, `ʗp.of(T.Ꮡf)`.
  - ASSUMED, and stated so: over a native receiver, `GoPointerWords.Classify` reports that field-address box as a word of C memory. A GolibTests arm reads that first, and if it does not hold, that is a stop line, posted before any workaround.
  - If it holds, the field needs no new golib door: W1/W2 already decide over a C-memory slot.
- Every other field of the type keeps its `ref` property.
- The field's ADDRESS property (`AddAddress`) is unchanged. So `&l.next` still compiles and still reaches the reference floor: s6next's refusal text is predicted byte-identical.
- A `ref` to a marked pointer field no longer compiles, by design, as for a header-shaped struct.
- A type both header-shaped and marked cannot occur in the corpus. Should one occur, the marker decides its pointer fields, since no golib header box views a C struct.

3. The read (golib, new `ж<T>.cgoPointerField<U>(FieldRefFunc<T, ж<U>>)`).
- A MANAGED receiver reads its slot, `fieldRefFunc(ref Value)`: a C struct value Go allocated.
- A NATIVE receiver (`NativeBox<T>`) reads the address word at the field's Go offset (`FieldRefBox<ж<U>>.GoFieldOffsetOf`, the offset s6field already reads):
  - 0 is nil;
  - a word that `GoPointerWords.NamesGoMemory` reports (a token, an address the exact registry knows, or one inside a live pin) is REFUSED: "cgo struct field load: a Go pointer read out of C memory is refused (C memory must not hold a Go pointer)". That is 18.4 finding 6, worded as S-B1's W1 refusal is.
  - Any other word mints `new NativeBox<U>(word)`, as `GoCgoArgs.PointerMemberBack` mints a pointer C returned.
- A native receiver whose Go offset is unknown (`GoFieldOffsetOf` < 0) is REFUSED by name. It never falls back to the CLR slot, which would read the wrong bytes.

4. The write (`ж<T>.cgoPointerField<U>(FieldRefFunc<T, ж<U>>, ж<U>?)`).
- A MANAGED receiver stores into its slot.
- A NATIVE receiver stores a word:
  - nil (or a nil box) writes 0;
  - a box over C memory alone (`GoPointerWords.IsCMemoryAlone`) writes its `NativeAddress`;
  - anything else is REFUSED: "cgo struct field store: storing a Go pointer into C memory is refused (C memory must not hold a Go pointer)". That is S-B1's W2(a), and 18.4's named deviation (8b) for a Pinner-pinned pointer stands.

5. Public surface. golib gains one attribute type (`GoCgoStructAttribute`, `[EditorBrowsable(Never)]`) and two members on `ж<T>`. PublicSurface.golib.txt gains three lines, and route #7 runs both families.

### 18.10 Record 2026-11-21: the resolver's walk takes the field's ADDRESS (18.2 item 5 and 18.4 finding 1 corrected; no rewrite)
