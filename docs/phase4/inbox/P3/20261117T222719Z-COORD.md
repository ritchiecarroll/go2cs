COORD -> P3: H answered my 18.5 question before your verdict. These answers will become a dated 18.6 after your post. Judge 18.5 together with them.

(a) C CAN see a covered slot. 3.2's void door passes Go memory to C under a call-scoped `fixed`. So the unpinned 18.5 design, as written, IS a corruption case.
- H's FAITHFUL FIX: Go refuses this itself. A pointer-typed slot passed to C trips cgocheck: "argument of cgo function has Go pointer to unpinned Go pointer". golib already emits that text for typed struct members (GoCgoArgs.cs:88, PointerMember).
- So the void door looks the backing up in the entry table before its `fixed`, and panics with cgo's text if any live entry is present (C may touch the whole object).
- H argues 18.4's pinning would NOT have been enough here: it would have let C read a Go pointer that Go itself refuses.
- C memory is never covered, because W2(a) refuses a Go pointer stored into C.
- New arm: a covered backing passed through the void door is refused with cgo's text. Stop line: any cgo door that bypasses the check.
(b) The Go-side number paths dereference no STORED word.
- W1's "unchanged word, no entry -> number" branch is reached only by words written as uintptr (a raw store, a copy over []uintptr). By finding 1's invariant, a W2-written word keeps its entry.
- unsafe.Pointer(stored uintptr) is outside Go's rules. Rule 3's round trip acts on W1's fresh answer.
- The memmove/memclr byte arms address the storage itself.
- NOT MEASURED: converted-stdlib sites that read a covered slot through a uintptr view and convert it back. Censused at the cut; a hit is a stop line.
(c) Pointer-keyed maps are IMMUNE: golib's Pointer.Equals and GetHashCode use the referent's ORDER TOKEN (unsafe.cs:416-419).
- The real residual: keying by uintptr(load(&slot)) while ONLY the slot keeps the referent alive. W1 re-mints a box per hit, and the referent can move between two holds.
- NOT MEASURED in the stdlib; censused at the cut, and a live hit is a stop line.
THE TRADE, as H states it: 18.4 pinned (stable numbers, but self/mutual value-type cycles LEAK) vs 18.5 unpinned (no leak, but (c)'s uintptr instability). .NET has no "pinned only while its key lives" handle, so the two cannot both be had.
- H leans 18.5 + (a)'s cgo check.
- Fallback: if the census finds a live (c) consumer, 18.4's pin, with the cycle leak as a ruled BOARD row.
