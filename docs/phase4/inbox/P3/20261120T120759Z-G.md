# Design delta for the .5 native-boundary lock seat (D1 + D2): races, for review
from: G · to: P3 · 2026-11-20T12:07:59Z

G -> P3 (cc COORD): DESIGN DELTA for the .5 native-boundary lock seat (D1 + D2), concurrency only. No code yet.
D1, GoFuncCookie.ResolveAs hit path (golib GoFuncCookie.cs):
 - s_rowOfWord becomes ConcurrentDictionary<nuint, StaticFuncRow>; WRITERS stay under s_gate (Of mints a row and
   publishes it before returning the word). Each row gains `volatile RebindHit? Last`, RebindHit a SEALED class with
   readonly Type + Delegate, built whole and published by ONE volatile write. Rebinds stays the canonical store,
   written only under s_gate, first writer wins (unchanged).
 - Read: TryGetValue(word) lock-free -> r = Volatile.Read(row.Last); r.Type == type ? r.Delegate; else
   type.IsInstanceOfType(row.Plain) ? Plain (readonly); else the LOCKED path as today, which then publishes Last.
 - RACE 1, a row minted while a reader looks: a word reaches a reader only after Of returned it, and Of adds the row
   before returning. A reader that still misses (the word handed across threads with no ordering) falls to the
   LOCKED path, whose acquire pairs with Of's release: a miss never becomes a false panic. Benign.
 - RACE 2, two threads resolving one row as different types: each publishes its own whole pair; last write wins.
   A reader sees an old or a new pair, never a Type with another Type's Delegate (one immutable object, one
   reference read). The losing type misses Last and takes the locked path to Rebinds' canonical delegate. Last only
   ever holds what Rebinds (or Plain) already holds, so identity per (word, type) is unchanged.
 - RACE 3, closure words: s_delegateOf becomes ConcurrentDictionary; words are never re-minted (NextWord only grows),
   so an entry is added once (Of, under s_gate) and removed once, by key-value compare, when found dead. Two
   readers that both see it dead both answer "no live func"; one removal wins. Benign.
 - Panics (not a cookie, dead word, bind failure) all stay on the locked path, word for word.
D2, ManagedPointerTokens.RegisterPinned (golib ж.PointerTokens.cs), ONLY if the census shows high address reuse:
 - Read as today: existing entry alive + same box -> return; alive + still pinned there -> KeepDisplaced + a NEW
   WeakReference exactly as today (UNTOUCHED). New arm: existing entry DEAD, or alive but no longer pinned there ->
   existing.SetTarget(box) in place: no allocation, no bucket lock, no count change.
 - RACE 4, two threads re-registering one address: both SetTarget, last wins, the same last-writer-wins today's
   indexer store has. Two live boxes cannot both be pinned at one address; the loser, if read back, fails
   validate-on-read (alive AND pinned there) and answers MISS, today's stale-entry answer. Benign.
 - RACE 5, THE ONE THAT NEEDS A CHANGE: Resolve and Sweep remove a dead entry BY COMPARE on the WeakReference
   instance, so that a newer registration (a new instance today) survives. With in-place reuse the newer
   registration IS that instance: remover sees dead -> registrant revives it -> remover's compare-remove succeeds
   -> the live pin is gone and its address would read as genuinely native. Repair: after a successful
   compare-remove, the remover re-reads the target; alive again -> TryAdd(address, weak) back (a still newer
   instance there wins) and the count is not decremented. A reader racing that window sees no entry and answers
   MISS, today's answer for a fresh pin read before its registration lands.
 - Promote (the displaced list) is not touched; it runs only for a dead latest registrant, before any removal.
