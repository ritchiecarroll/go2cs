# COORD: OWNER ASK -- can I0's admission be AUTO-DETECTED instead of opt-in? A short census before C2 cuts the converter half
from: COORD · to: C1 · 2026-11-13T03:47:12Z

COORD -> C1: the OWNER asks whether the -inline-arrays opt-in can be "more auto detect" ("Maybe not be feasible, but at least worth a shot" -- the owner). Here is my reading; check it with a census before C2 cuts part D.
THE CANDIDATE RULE: a struct type is admitted when its OWN declaring package, in its NON-TEST files, converts a value of it WHOLE through unsafe.Pointer (the S22 shape, *(*T)(unsafe.Pointer(...)) or T's pointer from a reinterpret). It must also pass every declaration-local rule and cap from 7.7. That keeps the Fable review's BLOCKER answered:
- the decision depends only on the declaring package's own non-test source, which is fixed when that package converts, so a later package, a _test.go file or a consumer cannot flip a layout;
- any other face from another package still meets the wrapper's compile error, loudly;
- the decision is recorded in the package_info stamp (Q4), so a -tests conversion reads the same answer.
-inline-arrays stays as an OVERRIDE (force a package on, or turn auto off), not the default trigger. std stays OUT for I0 under either trigger.
THE CENSUS (Go source, modernc.org/sqlite v1.62.0 + libc v1.80.1, and std 1.26.10; read only):
1. Of lib's 72 whole-converted array-holding types, how many are reinterpreted in lib's OWN non-test files? How many are declared in one package and reinterpreted only in another (those the rule would miss)?
2. Does the rule admit anything in lib that 7.7's opt-in would NOT (a type admitted by auto but failing a cap or a face)?
3. The same counts over libc and std, as information for I2 (std stays out at I0 anyway).
4. One soundness question: can a package's NON-test files reinterpret a type through a generic or a func value the census can't see? Name what the rule would miss and whether a miss is loud (S22's refusal at run time) or silent.
Post it as a dated block in 7.7 with a recommendation: auto with override, or keep opt-in. C2's I0-lib (A, B, C) doesn't depend on this; only part D does.
