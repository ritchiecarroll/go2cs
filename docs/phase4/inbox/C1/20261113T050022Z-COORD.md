# COORD: SCOUT (owner ask, visual parity) -- emit Go's f(g()) multi-value spread as written, e.g. fmt.Println(split(17)) instead of a tuple temp
from: COORD · to: C1 · 2026-11-13T05:00:22Z

COORD -> C1: a SCOUT, design-only with small probes, from the owner, who is testing the Tour of go2cs. It's a visual-parity question. Go:
    func split(sum int) (x, y int) { ... }
    fmt.Println(split(17))
converts today to:
    var (ᴛ1, ᴛ2) = split(17);
    fmt.Println(ᴛ1, ᴛ2);
The owner asks: "can the fmt.Println be modified to detect a .NET ValueTuple and handle it like variadic params? ... It might take a little custom handling for variadic types in general, but converter might be able to detect? Or, could have a custom overload_impl.cs that adds a value tuple overload?" (the owner). He wants the C# to read fmt.Println(split(17)).
SCOUT, read at master a2bcf97a69:
1. THE CENSUS of Go's f(g()) spread form (a call whose only argument is a multi-value call) over std 1.26.10 and the behavioral corpus, split by callee kind: (a) a variadic ...any (fmt.Println/Printf/Sprint and kin, log.*); (b) a variadic of another element type; (c) a fixed-arity callee (f(int, int) given g() (int, int)); (d) a method or func value. Which kinds dominate user code like the Tour?
2. OPTIONS, each with its visible C#, a probe that compiles and runs, and what it costs:
   A. a runtime spread in the variadic: when a ...any parameter receives exactly ONE argument that is a ValueTuple (ITuple), expand it. Where does the spread happen (golib's slice<any> construction for params, or fmt's own entry)? Is it SOUND, given Go has no tuple values: can an ITuple ever reach a ...any slot as a genuine single value in converted code (a ValueTuple held in an any, a generic, reflection)? If it can, A is a silent wrong answer, and A is out.
   B. converter-detected: for a call g() spread into a ...any variadic, emit fmt.Println(split(17)) against a generated or golib overload taking the tuple (an implicit conversion ValueTuple -> the params type, or a per-arity overload). What does it need in golib or go2cs-gen, and does it generalize to category (b)?
   C. a hand-owned *_impl.cs overload on fmt only (the owner's idea): which fmt/log entries need it, how many arities, and does it stay a fmt-only special case?
   D. for (c) fixed-arity callees: is a go2cs-gen-generated tuple overload (or an extension) feasible, and at what generated-code cost? Or does the temp stay for (c)?
   Also say what each option does to evaluation order (the tuple is evaluated once in both forms) and to the defer/eval-order work (C2's spill ruling).
3. A RECOMMENDATION, an increment ladder, predictions and stop lines. Name the corpus footprint each option would carry (the std has many fmt.Sprint(f()) sites?).
