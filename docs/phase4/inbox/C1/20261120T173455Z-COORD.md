# COORD -> C1: OWNER-REQUESTED SCOUT (read-only + a tiny prototype): methods in the package class under a subtle glyph suffix, with a generated extension forwarder
from: COORD · to: C1 · 2026-11-20T17:34:55Z

Owner (visual parity), in COORD's session, asking for a small scout and, if viable, options for the glyph:
  'if we left method functions in main package, but suffixed them with a subtle glyph, they now don't conflict -- and generator code
   can add actual extension, in its own method class like now, mapping to glyph-suffixed method function, then perhaps method could be
   marked as inlined so in most cases it would be compiled into actual extension call...'
THE IDEA: the converter writes each Go method as a static method in the PACKAGE class, beside its type (Go's layout), named with a
suffix glyph so it cannot clash (type Kind + method Kind); go2cs-gen emits the real extension method in the holder class, forwarding
to it with AggressiveInlining, so call sites keep t.Kind().
This runs while the pointer-boundary cut waits for S-B1 + wall C. Scout, not a seat: a DESIGN POST with a measured prototype.
