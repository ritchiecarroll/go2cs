# COORD: DESIGN (sqlite-cs S1 + S21) -- C function pointers carried as uintptr (the number-to-delegate registry), and assembly bodies in third-party modules
from: COORD · to: C1 · 2026-11-13T06:41:36Z

COORD -> C1: two designs for sqlite-cs (github.com/ritchiecarroll/sqlite-cs; rows file and repros there, d5f60ed and 877c6c2718; modernc.org/sqlite v1.62.0, libc v1.80.1). Design-only, with small probes, read at master 3da19d0e2e. S1 first, then S21.
S1, THE WALL after S22 (503 sites): ccgo carries C function pointers as uintptr. `__ccgo_fp(f)` takes a Go func's address as a number, and func values are rebuilt from struct{ f uintptr } by an unsafe.Pointer reinterpret (`(*(*func(*TLS, ...) ...)(unsafe.Pointer(&struct{ f uintptr }{fp})))(tls, ...)`). go2cs has no number for a delegate today.
DESIGN a golib registry that maps a number to a delegate and back:
- MINT: what __ccgo_fp and similar sites become, and whether a func gets ONE stable number (identity and ==, map keys, sort);
- RECOVERY: the struct{uintptr} -> func reinterpret, by shape, at convert time where possible, and at run time;
- the delegate's SIGNATURE: the ccgo func types and generic delegate shapes, and AOT/trimming (no reflection-emit; a generated table, not reflection, as M:N already requires);
- LIFETIME: numbers kept alive while live, and what a stale number does (loud);
- the ZERO number as nil;
- equality with funcs that never had a number;
- what the converter must recognize, versus what golib handles at run time.
Census lib and libc for every form (__ccgo_fp, the struct{uintptr} reinterpret, xqsort/callback tables, variadic). Name the M:N collision (G's func-value design N3, func values as async twins) and keep the two compatible: post your design to G for a read before I rule. Predictions, stop lines, and a Fable-reviewable summary.
S21 (smaller): an ASSEMBLY function in a third-party module (x/sys/cpu cpuid/xgetbv, called by its init in every program that imports libc) gets only the PartialStubGenerator stub that throws. go2cs's own internal/cpu has a managed body (cpu_x86_impl.cs). Design how a CONVERTED THIRD-PARTY module gets a managed body for an asm function: a shipped overlay (golib or a nugetgo companion package), a converter-side known-function table, or a per-module hand-owned file, and which one scales past x/sys/cpu. Census which asm functions the sqlite closure and the Target Atlas's top modules hit.
Post both as docs/phase4/DESIGN-sqlite-cs-funcptr.md on claude/c1-sqlite-funcptr-design.
