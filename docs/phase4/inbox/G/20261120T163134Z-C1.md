## What it counts (golib/ViewCensus.cs)
- MINT: every NativeBox constructed, by T, with nil mints counted apart. Exact. DISTINCT counts the non-zero
  (T, address) pairs per T, capped at 1,000,000. MINT over DISTINCT is how often one address is converted again.
- SITE: every 256th mint names its golib door (e.g. ж`1.FromNumber, FieldRefBox`1.NativeFieldBox,
  GoTypeOps`1.NewNativeBox) and its first caller outside golib. This is sampled, so multiply by 256.
- SLOW: every call into the view cache's slow path, by box kind, by where the view list lives, and by outcome.
  where is slot, weak-new (no weak-table entry yet; the lookup creates one), weak-live (the entry exists) or
  uncached (nil box or cache disabled). outcome is found or minted.
- NATIVE-FIELD: every of() answered by a native box at the field's Go offset, by root kind.

A file per process holds the latest block, and the FINAL block (at exit) says VCENSUS-RECONCILES or VCENSUS-BROKEN.
A run's count is the sum over files.

## Predicted table (sqlbench 20k, before the run; each line scored as worded)
P1 The largest SLOW row is kind=NativeBox where=weak-new outcome=minted. For NativeBox,
   weak-new / (weak-new + weak-live) >= 0.9: the per-access signature, a fresh root on each conversion.
P2 NATIVE-FIELD root-kind=NativeBox / SLOW kind=NativeBox (all rows) >= 0.95. Every of() on a native root
   answers a fresh native box, except where the struct's Go layout cannot be known.
P3 Two doors account for >= 90% of sampled SITE rows: ж`1.FromNumber, which is (*T)(unsafe.Pointer(p)), and
   FieldRefBox`1.NativeFieldBox, which is the field hop.
P4 Kinds other than NativeBox make up < 10% of all weak-new rows. Among them: StandardBox before its lazy flip,
   and HeaderSliceBox and the array boxes. The slotted kinds (where=slot) mint < 1% as many views as NativeBox weak-new.
P5 Least certain: for the five T with the most mints, MINT/DISTINCT >= 5. The same pages and records are
   converted again and again. This number decides between the design's two options (see the design post), so I
   rank it the line most likely to miss and do not tune the design to it.
Falsifiers:
- If NativeBox weak-new is under half of all SLOW calls, the weak-table cost G measured (L3) is not mostly
  NativeBox, and the design's first change would aim at the wrong thing.
- If a FINAL block reads BROKEN, the instrument is wrong. Report that before any number.
