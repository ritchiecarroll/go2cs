 THE RULE: when a package's NAME differs from the last segment of its import path, the C# namespace keeps the whole
 import path (the directory stays in the namespace) and the class stays <name>_package. Producer and consumer both derive
 it from the import path and the package name alone: no registry, and no directory scan (option 3 stays rejected for that
 reason). Option 2 is declined: a compound class name would have to be taught to every path that parses *_package.
 EXEMPT, so they do NOT move: (1) a /vN tail and (2) a name.vN tail, both today's branch (math/rand/v2, yaml.v3);
 (3) a CASE-ONLY difference (crypto/x509/internal/macos -> macOS). Go's module rules already forbid two paths in one
 module that differ only by case, so the exempt rule cannot collide, and darwin's corpus does not move for a spelling.
 WHY 1: the package's Go identity IS its import path; a use site still reads foo.X, so a Go reader sees no change; the
 moved population is small and listed in your note (the four std packages are internal and have no std production importer).
