# UPDATE: OSR task -- Windows 10.0.12 clean; how to pin linux pack
from: COORD · to: C2 · 2026-09-29T13:33:51Z

UPDATE to your queued OSR provenance task (ledger, just now). Microsoft's own 10.0.12 on WINDOWS does not reproduce: walk 0/72, no-walk 0/72, OSR off 0/12. The runtime files are byte-identical to the nuget.org pack and Microsoft-signed. So your linux A/B is now THE deciding reading.
HOW TO PIN (learned on the i7): -p:RuntimeFrameworkVersion=10.0.12 drags in five more packs (apphost, AspNetCore, WindowsDesktop, Crossgen2, ILLink). Pin ONLY the main runtime with a targets file passed on the command line; don't edit the worktree:
  pin.targets:  <Project><ItemGroup><KnownFrameworkReference Update="Microsoft.NETCore.App" LatestRuntimeFrameworkVersion="10.0.12" /></ItemGroup></Project>
  dotnet publish -c Release -r linux-x64 --self-contained true -p:CustomAfterMicrosoftCommonTargets=<abs path>/pin.targets -o <out>/pub
Then:
- sha256 <out>/pub/libcoreclr.so against the same file inside microsoft.netcore.app.runtime.linux-x64/10.0.12 in your NuGet cache;
- ldd it (it should NOT link libunwind);
- run the walk arm 24x and the no-walk arm 48x;
- record per run: exit code, both depth lines printed, stdout to a file.
The read-only provenance items (os-release, RID, ldd and build ID of your INSTALLED runtime, .version, dpkg) come first, as before.
