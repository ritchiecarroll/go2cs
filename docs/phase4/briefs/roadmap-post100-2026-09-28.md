## 6. Top risks

1. **The objective's tail eats the calendar.** A late freeze pushes hop C into .NET 11 GA, and the no-overlap rule then serializes everything.
2. **Identity-token collisions** make gojq silently mutate the caller's data, and tests rarely catch it.
3. **nuget.org publishes are irreversible.** A version can be unlisted, never deleted. Settle the ID and version scheme first, and always rehearse to a local feed.
4. **Republish burden and security.** 1.24.13 seeds must be republished at 1.25 and 1.26, and they carry no Go security fixes since February.
5. **An uninvited C# 15** on any box or CI image whose default SDK becomes 11.x before the pin lands.
6. **TypeScript expectations.** Every goroutine is an OS thread, and range-over-func runs on a coroutine thread. Lead with fidelity to TS's own conformance baselines, not speed.
7. **Fleet thinness and credits.** Each hop's H10 re-bank of about 230 rows is its longest step.

## Disagreements between the pickers, resolved

**1. "-tests has never run outside GOROOT."** Only partly true.
- It has run outside GOROOT, on an in-repo fixture: `src/tests/PackageTests/ConvertedTestHarness` reached 12/12 at merge 6c6755c0e7.
- It has never run on a fetched module with a dotted path or a module-cache dependency.
- `validationPackBlock` returns "" for any output outside `core\` (`src/go2cs/projectFileWriter.go:213-216`), so no VALIDATION.md is packed for a third-party package.
- `publishesRosterArtifacts` is just `status=="validated" && filter==""` (`src/go2cs/validationProofPages.go:824-826`). It writes a proof page into the `docs/` folder next to the go2cs root found above the OUTPUT path (lines 760-770). So a run whose output sits inside the checkout pollutes the stdlib roster, and a run whose output sits outside it quietly writes nothing.

**2. gojq's dependency step.** The visibility picker says the fallback assumes the dependency was converted in place. It does not, for a module-cache dependency.
- `src/go2cs/importOperations.go:566-579` points a module-cache dependency at `$(go2csPath)pkg/<import-path>`.
- So gojq's step is probably a layout recipe: convert timefmt-go into `<root>\pkg\github.com\itchyny\timefmt-go`, then run -tests on gojq. It may not need a converter seat.
- This is unmeasured. The seat has to check that project names and paths agree.
- `src/pkg` is not gitignored, so this belongs in its own worktree.

**3. GODEBUG defaults (the stdlib picker's seat B).** The gap is real.
- `src/core/internal/godebug/godebug.cs:199-200` reads only the `$GODEBUG` environment variable.
- Nothing in `src/go2cs` handles DefaultGODEBUG.
- The highest `Changed` value in go1.24.13's table is 24 (`GOROOT/src/internal/godebugs/table.go:29-71`). A module with no go line counts as 1.16 (`cmd/go/internal/gover/version.go:24`).
- So a module declaring go 1.24 or later has no GODEBUG drift. It also has no loop-variable drift, because the converter always emits per-iteration variables (`src/go2cs/visitForStmt.go:60-69`).
- That is why gojq and timefmt-go carry the least semantic risk.

## Pick 2: gojq@v0.12.19 + timefmt-go@v0.1.8 (the .NET headline)

**Why:**
- .NET has no mature managed jq. The incumbent, Devlooped.JQ (1,014,099 downloads, re-read from azuresearch-usnc.nuget.org), is "a .NET-friendly distribution of the official JQ implementation", meaning a native binary.
- Both modules declare go 1.24, so there is no GODEBUG or loop-variable drift.
- The root library imports only the stdlib plus timefmt-go (I parsed all 37 root .go files).
- It is a deliberate off-atlas pick: the atlas ranks Go dependents, not .NET need.

**Size:**
- gojq root: 9,654 production lines in 24 files; 13 test files (all `gojq_test`), 51 Test and 11 Example functions.
- timefmt-go: 938 production lines; 2,331 test lines; TestFormat and TestParse are table-driven with t.Run.

**Expected gaps:**
- (a) `TestQueryString` needs `builtin.jq` staged.
- (b) Six `TestCodeCompile_Optimize*` tests (`compiler_test.go:108-278`) read unexported bytecode through reflect FieldByName and `unsafe.Pointer(UnsafeAddr())`. They are likely disclosure candidates.
- (c) **A consumer correctness risk the pickers missed.** gojq's in-place update allocator keys on `reflect.ValueOf(v).Pointer()` and mutates when it believes it owns the value: `if a.allocated(v) { v[k] = u }` (`func.go:1483-1498, 1622`).
  - go2cs tokens a map or slice by `RuntimeHelpers.GetHashCode` of its backing (`src/core/reflect/value_impl.cs:1268-1269, 1191-1196`).
  - CoreCLR keeps only 26 bits of that hash (`HASHCODE_BITS 26`, https://github.com/dotnet/runtime/blob/release/10.0/src/coreclr/vm/syncblk.h#L118). Collisions reach even odds around 10k live objects.
  - The result is silent mutation of the caller's input. Tests will rarely catch it.
  - A small golib seat is needed first: unique identity tokens for map and slice backings, with a GolibTests arm.
- (d) iter.Seq, math/big and a goyacc-generated parser are all covered by banked rows.

**Stdlib exercised:** 27 of 28 banked.
- encoding/json 532, math/big 231, reflect 395+23, regexp 45, iter 28, maps 14, slices 121+2, cmp 4, time 178, net/url 49, path/filepath 61, sort 63, strconv 55+11, unicode 28, unicode/utf8 14+1, and the rest.
- unsafe is test-only and has no row.
- timefmt-go's imports are 7 of 7 banked.

**How it becomes a row:** two rows, timefmt-go first, each through the uuid recipe.
- gojq's 842-case conformance suite (`cli/test.yaml`, driven by `TestCliRun`) is a stage-2 row.
- Stage 2 needs the cli package plus go-yaml, go-cmp, go-isatty, go-runewidth, uax29 and x/sys, and the fixture seat for `test.yaml`.

**For a .NET consumer:** a hand-written C# facade of about 100 lines, kept outside the regenerable tree: `IEnumerable<string> Jq.Eval(string filter, string json)`.
- It parses with the converted encoding/json (UseNumber keeps jq's number fidelity), runs Parse, Compile and Run/Next, and marshals each result.
- That gives in-process jq with no per-RID native binary.

**Nugetgo fit:** gojq's module also contains `cli` (and cmd/gojq). Shipping the root package only raises OQ-4 in a mild form.
