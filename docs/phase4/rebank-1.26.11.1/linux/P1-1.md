read, so the ledger holds 16 runs, one converter build each (the `converter_mtime` column changes per run; the
binary is rebuilt from the same tip, and a fresh build was byte-identical to the first run's). The TSV and ledger
here are the 16 runs' rows in order, 109 rows, no row twice.

(the ledger cannot skip a row once the converter's mtime changes) and was stopped by process group before the row
ended. That restart wrote nothing to the TSV or ledger, but it overwrote row 1's local run log; row 1's
comparison and results JSON are intact.
